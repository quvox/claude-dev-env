## 何が変わったか

**`colabtmux inbox` と `colabtmux board` は、`--json` を付けないかぎり本文の全文を出さない** —
平文で出るのは本文の**1行目**を、切り詰めたときに付く `…` を含めて**全体で80バイト**までに
切った要約である(`orchestration.md` §7.1 が正)。

**作業指示は `--body-file` で送られる複数行のファイルである。** したがって平文の `inbox` で
読んだエージェントは、**1行目しか受け取れない。**

配られる `AGENTS.md` は 2026-08-25 からこの断りを持っている(**2026-09-14 に雛形をやめ、`CLAUDE.md` と同じ位置の配布物になった**)。あわせて、
**colabtmux が同じファイルの末尾に書く管理ブロックが逆のこと**(「`colabtmux inbox --agent
<自分のID>` で全文を読むこと」)**を言っている**ため、雛形の側でそれを打ち消してある。

**2026-09-14 以降、`AGENTS.md` は `CLAUDE.md` へのシンボリックリンクであり、配布物に入っている** —
展開すれば一緒に置き換わるので、この移行を当てる必要はもう無い(残してあるのは、それ以前の版から
上げるプロジェクトのためである)。**当時は導入時に1度だけ複写するファイルだった**ので、
上書き展開では更新されず、既存のプロジェクトには自分で足す必要があった。

## 手順

`AGENTS.md` の「報告と問いは必ず `--body-file`」の行を、雛形の同じ行で置き換える。

```bash
# 2026-09-14 以降は AGENTS.md が配布物なので、展開すればこの断りは入っている。
#   古い写しが残っていないかだけを見る:
grep -c "inbox --json" AGENTS.md
```

**雛形をそのまま上書きしてはならない** — 管理ブロック(`<!-- colabtmux:begin ... -->` から
`<!-- colabtmux:end -->` まで)はこのプロジェクトのもので、雛形は持っていない。
**管理ブロックの中は編集しない**(colabtmux が書き換えるので、直しても次の起動で消える)。

## 移らなかったときに何が起きるか

codex のエージェントが、**作業指示の1行目だけを読んで仕事を始める。** 見出ししか読めていない
ので、対象・手順・様式のどれも渡っていない。**それでも本人は指示を読んだつもりでいる**ので、
黙って違う仕事をする。管理ブロックが「全文を読める」と言っているため、本人は疑わない。
