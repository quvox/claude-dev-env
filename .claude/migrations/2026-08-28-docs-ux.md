## 何が変わったか

2026-08-28 に、UI/UX の記述の置き場として **`docs/ux/`(UX 文書)** が新設された
(正は `.claude/directions/ux.md`)。UI/UX の記述は徐々にしか仕上がらないので、
文書検証・実装整合検証の依存の外に置き、**qa 試験区分の依存にだけ入れる** —
UX 文書を直しても失効するのは qa だけで、qa 試験区分の run(ユーザテストの周回の中なら周回末の `@qa`)が実画面と突き合わせて戻す。
これに伴い、**02 の UI 設計の節は「UI の有無の宣言」だけになり**、画面一覧(`SCR-nn` の台帳)・
画面遷移・各画面の項目と状態・デザイン方針(基調)は `docs/ux/` が持つ。

**移す作業は大半が新規執筆ではなく引っ越しである** — 02 が既に UI の記述を持っており、
02 を薄くする以上、中身はどこかへ移らなければ情報を失う。

## 手順

**何をどこへ移すかに判断が要るので、`/kit-migrate` はこれを自分で当てない**
(報告に「要るが判断待ち」として出る)。UI の無いプロジェクト(02 が「UIなし(理由)」)は、
**この移行を「適用外(UI 無し)」として台帳の報告に1行残して閉じてよい** — `docs/ux/` を作らない
(`detect` は `docs/ux/` の不在を見るので、その1行が済んだ印である。次回以降も並ぶが、
報告の1行が「済んでいる」を運ぶ)。

1. **`docs/ux/` の骨組みを作る。** 雛形は `.claude/templates/ux-policy.md` / `ux-flows.md` /
   `ux-screen.md` / `ux-review.md`。
2. **02 の中身を移す** — デザイン方針 → `policy.md`、画面遷移 → `flows.md`、
   画面一覧(`SCR-nn` の台帳)→ `flows.md` 冒頭の「画面一覧」、各画面の項目と状態 →
   `screens/SCR-nn-<画面>.md`(ファイル名に ID を入れる)。02 の UI 設計の節は
   「UI: あり — 中身は `docs/ux/`」の1行に薄くする。
   **`ui.md` へ切り出し済みのプロジェクトは `ui.md` 丸ごとが移送元である**(移したら畳む —
   ファイルを消し、`source:` と本文の参照を張り替える)。
3. **`docs/README.md` を追随させる** — ID 表の `SCR-nn` の行の定義場所を
   「`ux/flows.md` の画面一覧(台帳)」へ書き換え、「どこから読むか」に `ux/` の2行を足す
   (新しい雛形 `.claude/templates/docs-readme.md` に同じ行が在る — このファイルは導入時に
   一度だけ複写されるもので、上書き展開では直らない)。
4. **02 を触ったぶん、`/verify-docs` と `/verify-impl` を各1回回す** — これが移行の
   **一度きりの検証コスト**である(02 は実装整合検証の依存にも入っているので、
   文書検証だけではデプロイゲートが red のまま残る)。
5. **`reviews/` は空で始める。** 過去の試行錯誤を遡って書き起こさない(経緯の捏造になる。
   移行前の経緯は git と既存の決定の記録が持つ)。`reviews/00.md` には
   「移行でどこから何を移したか」を書く(以後、初めて実装する画面の初期判断もここへ足す —
   移行の記録「だけ」の置き場ではない)。
6. **仕上げの検査**: `python3 .claude/scripts/check-ux.py` が green であること
   (条項参照・画面ファイル・指摘番号の実在)。

**移行時にしないこと**: 全画面ぶんの `screens/` を実装から書き起こさない(02 に無かった細部は、
次にその画面を触る作業指示が書く — 移行直後の薄さはこの層の正常な初期状態である)。
01 の条項 ID の一括付与もしない(紐付けは部分的でよい設計である — `ux.md`)。
**移行を重くすると既存プロジェクトほど移らず、規範が分岐したまま残る。**

## 移らなかったときに何が起きるか

**何も壊れない。** UI の記述は 02 に残ったまま、従来どおり検証連鎖の中に居る。
失うのは効果だけである — UI/UX の小さな修正のたびに 02 の鮮度スタンプが失効し続け、
軽い変更手続き(検証失効ゼロの数行の編集)と `reviews/` の経緯の台帳を得られない。
新しい版の `stamps.py` は qa の依存に `docs/ux/` を足しているが、
`docs/ux/` が無いプロジェクトでは何も変えない(`check-ux.py` も何も見ずに 0 を返す)。
