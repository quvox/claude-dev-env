## 何が変わったか

**`--allowedUrlPattern`(層1)に宛先を書いても、1つも一致していなかった。** 2026-09-01 の実測で
3つ判った(正は `.claude/directions/orchestration.md` の「1.1.2 ブラウザQAの口は MCP で足す」):

1. **突き合わせはスキームまで見る。** `http://…` だけを書くと `ws://…` は一致しない。
   画面は 200 で開くのに**ライブ表示だけ**が死ぬ。
2. **層1 はホスト部の範囲指定を一切通さない。** `http://172.17.*:*/*` のような書き方も、
   正規表現グループも一致しない。**だから宛先の範囲は層2 だけが持つ。**
3. **`EXCLUDE [::1]` は角括弧付きだと一致しない。** `EXCLUDE ::1` と書く。

**キットの持ち方も変わった。** 「宛先は localhost と docker network だけ」という固定の上限を
やめ、**床**(`localhost` / `127.0.0.1` / `::1`)と**天井**(公開インターネットへ出ない)だけを
キットが持ち、**その間のどこに線を引くかは `docs/02-design/environments.md` が宣言する。**

**この設定が住んでいるのは codex の `config.toml`**(`~/.codex/config.toml` か、プロジェクト専用の
`CODEX_HOME`)**であり、配布物には入っていない。** だから上書き展開では直らない。

**`paths` に書けるのはリポジトリの中だけである** ★ — `paths` は「誰かの書きかけを踏まない」
ための関所であり、その判定は `git` に問うので、**リポジトリの外に在る `~/.codex/config.toml`
(や `$CODEX_HOME`)は構造的に守れない。** 書いても守られないものを並べると関所が守っている
ように見えるので、**書かない**(規範の例外は `.claude/skills/kit-migrate/SKILL.md` の
「9. 移行の台帳 — 書式」が持つ)。**この設定はホスト全体で共有される**ので、同じホストで走る別のプロジェクトの
移行とぶつかりうる。だから手順2 では、関所の代わりに**書く前の突き合わせ**を置く:

**控え・候補・現物の3つを分ける** ★ — 現物をその場で直してから控えと比べると、
**自分の編集で必ず差分になり、毎回止まる。** 直すのは候補のほうである:

```bash
c="${CODEX_HOME:-$HOME/.codex}/config.toml"
cp "$c" "$c.snapshot"      # ① 読む前の姿を控える(比べる相手)
cp "$c" "$c.candidate"     # ② 直すのは候補。**現物には触らない**
#                            … ここで "$c.candidate" を編集する …
cmp -s "$c" "$c.snapshot" || {          # ③ 書く直前に、現物が控えのままか見る
  echo "並行して書き換えられている。書かずに止める"; rm -f "$c.candidate"; exit 1; }
mv "$c.candidate" "$c"     # ④ 同じときだけ入れ替える
rm -f "$c.snapshot"
```

**停止条件はこの `cmp` である** — 「気をつける」ではない。控えと現物が違ったら、
**直した候補を捨てて報告する**(相手の書きかけを上書きするより安い)。

## 手順

**ブラウザQAを使っていないプロジェクト**(この節が「適用外(UI 無し)」の1行になっている)
**には、この移行は要らない。**

1. **宣言を直す** — `docs/02-design/environments.md` の「ブラウザQAの宛先 allowlist」の表に
   **スキームの行**を足す(雛形 `.claude/templates/02-environments.md` が形を示す)。
   画面が WebSocket を使うなら **`ws` を必ず書く。**
   床を超えて足す宛先には、**なぜそこへ到達する必要があるのかを1行添える**
   (`.claude/directions/02-design.md` の environments 節)。
2. **設定を直す** — codex の `config.toml` の `[mcp_servers.chrome-devtools]` の `args`:
   - 層1 は**スキームだけ**を1行ずつ(`http://*:*/*`、`ws://*:*/*`)。**`*://` の1行にしない。**
   - 層2 の `EXCLUDE` を、**宣言と1対1で対応するように数え上げ直す。**
     `EXCLUDE 172.*` のような粗い書き方は公開アドレスを巻き込む。
   - IPv6 は `EXCLUDE ::1`(角括弧を付けない)。
3. **設定が宣言より広かったら、そこで止まって決める** ★ — 狭めるのか、宣言を広げるのか。
   **広げるなら宣言が先である**(順序が逆だと、宣言を読んだ人間が実際の到達範囲を知らない)。
   **この判断が在るので、この移行は `judgment` である。**

**`detect` の門は「この節が在り、その中に表が在るか」である** ★ — 見るのは
**節の見出し**(`## ブラウザQAの宛先 allowlist`)と、その節の中に表の行が在ることである。
**行の見出しで判定してはならない** — あれは自由文で、プロジェクトごとに言い直される
(`| ホスト(このマシン) |`、あるいは「ホスト」という語を使わず値だけを並べる形)。
2026-09-01 に実測: 行の見出しを見る門は、**この移行がまさに要るプロジェクトで
「済んでいる」と判定し**、逆に**別の節の無関係な行に当たって開く**という両方の誤りを出した。
**節の見出しは雛形が「見出しは削除しない」と明記して配る文字列**なので、書き換えられない。
UI 無しのプロジェクトはこの節の本文が「適用外(UI 無し)」の1行になって表が消えるので、
門が閉じる。

**`detect` の読み方には3つの手当てが要る** ★ — ①**コメントを落としてから見る**
(`sed "s/#.*//"`。設定の中の説明文が `EXCLUDE [` を含むと、正しく直っているのに「要る」と
出続ける。2026-09-01 に実測)。**全行コメントだけを落とすのでは足りない** — 旗の行末に付いた
注記の `#` が、次の行と繋いだときに正規表現を断ち切り、**旧い宛先付きの値を見逃す。**
(TOML では文字列の中の `#` もこれで落ちるが、この設定の値は宛先の並びなので `#` を含まない。)②**行を1本に繋いでから見る**(TOML の配列はキーの行と値の行に
分けて書けるので、行ごとに見ると `allowedUrlPattern` とその値が別々の行に落ちて
一致しない)。③**スキームは `https` / `wss` まで見る**(`http` / `ws` だけを見る門は、
`https://` で宛先を書いた旧い設定を「移行済み」と誤判定する)。

**`detect` が見ているのは3つだけである** ★ — 角括弧付きの IPv6、層1 に書いた宛先、
   そして層1 の `*://` である。**手順2 の残り、すなわち層2 の `EXCLUDE` が宣言と1対1に
   なっているか(`EXCLUDE 172.*` のような粗さ)は、機械では見ていない** — 宣言との
   突き合わせは CIDR と数え上げの等価判定になり、誤検知が捕捉を上回る。**目で見ること。**

4. **変えたら実際に測る。** `new URLPattern(…).test(…)` を Node 単体で叩いて確かめてはならない
   — **届かない書き方に対して `true` を返す。** MCP サーバを起こして `navigate_page` を打ち、
   **通すべき宛先と拒むべき宛先の両方**を見る。

## 移らなかったときに何が起きるか

**設定を読む時点では何も言われない。** 誤りは実行時に、**拒否か通信断か名前解決の失敗**として
現れる — どれも「設定が古い」とは名乗らないので、気づく契機が無い。

- **層1 に宛先を書いたままなら、その行は防御になっていない。** 一致しないだけであり、
  **宛先を縛っているのは層2 だけ**である。したがって**層2 を宣言より広く書いた箇所だけが、
  余分な宛先を通す**(層2 の**書き漏らし**は逆で、その宛先が `ERR_NAME_NOT_RESOLVED` になる —
  `orchestration.md` の「`EXCLUDE` に書いたものだけが残る」)。
- **`ws` を書いていなければ、WebSocket が丸ごと落ちる。** 画面は開くので、
  **製品の不具合として起票される**(出所ではこの取り違えでブラウザQAが2日止まった)。
- **`EXCLUDE [::1]` のままなら、IPv6 の宛先だけが `ERR_NAME_NOT_RESOLVED` になる。**
  他の行は壊れないので、症状は「IPv6 だけ開かない」という部分的な形で出る。
