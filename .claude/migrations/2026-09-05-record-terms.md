## 何が変わったか

2026-09-05 に、用語集(`.claude/directions/glossary.md`)の禁止表記が増えた。

- 「クロージャ」の行に **「閉包」** と **「closure」(日本語の地の文で書かない)** が入った。(LA3-ok)
  固定の見出し `## 影響範囲(closure)` と用語集の English 欄は原文のままでよい。
- 「共有する実体」の行に **「共有実体」** が入った。(LA3-ok)

きっかけは実測である: 配布先の記録に「閉包」128件・裸の closure 971行・「共有実体」28件が (LA3-ok)
定着しており、同じ概念を検索やレビューで全件拾えなくなっていた。**規範の側とキットの中は
直してあるが、プロジェクトが自分で書いた記録は上書き展開では直らない** — それがこの移行である。

## 何をするか

**判断が要るので、`/kit-migrate` はこれを自分で当てない。** 直すのは**現役の記録だけ**であり、
どれが現役かは人間が決める。

1. **現役の記録**(進行中のミッションの台帳、現役の課題票・棚上げ・残務、これからも読み書きする
   記録)の中の「閉包」「共有実体」、日本語の地の文の裸の「closure」を、正しい語 (LA3-ok)
   (クロージャ / 共有する実体)へ置換する。在り処は
   `grep -rn --exclude-dir=histories -e 閉包 -e 共有実体 docs .claude/missions` で出る(LA3-ok)
   (`docs/histories/` は過去形の経緯なので外す)。
   **裸の closure だけは、上の `detect` もこの検索も見ない** — その綴りは固定の見出し
   `## 影響範囲(closure)` と用語集の English 欄に必ず現れ、機械では地の文と分けられない。
   `grep -rn --exclude-dir=histories closure docs .claude/missions` を人間が読み、
   地の文の行だけを拾って直す。
2. **書き換えないもの**: 閉じたミッションの台帳・過去の逐語引用(引用は当時の姿を写すのが
   役目である)・固定の見出し `## 影響範囲(closure)`。
3. 置換したらコミットする(1つの意図 = 1コミット)。

**`detect` が見るのは現役の範囲だけである** ★(2026-09-16) — `docs/`(`docs/histories/` を除く)と、
`.claude/missions/*/ledger.md` の `状態:` が `進行中` の台帳(通常は1件だが、
`.claude/skills/mission/SKILL.md` は2件以上並ぶ状況も認めており、そのときは全件を見る)。
**閉じたミッションの台帳
(`状態: 完了` / `中断`)と `docs/histories/` は見ない** — どちらも過去形の経緯を持つ場所であり、
そこに残る逐語引用は「書き換えないもの」として残す対象である。除かないと、いつまでも一致し続けて
`kit-migrate.py check` を永久に「要る」へ倒すだけになる(2026-09-16 に実測: 28 ミッションぶんの
逐語引用に加え、`docs/residual.md --resolve-residual` が禁止表記そのものを名指す残務行を
`docs/histories/` へ書き写した直後がまさにこの形だった)。**現役の範囲に一致が無ければ
`detect` は「済んだ」と言う。**

**現役のミッション自身が、この移行を説明する文(この移行の名や `grep` コマンドの逐語)を
台帳や報告など、そのミッションディレクトリ配下のどこかへ書いた場合は、そのミッションが
閉じるまで一時的に「要る」に戻ることがある**(`detect` は `ledger.md` のあるディレクトリ
全体を再帰的に見るので、`reports/` などの他のファイルも対象に入る) —
それは誤判定ではなく、「現役の範囲に一致がある」という字面どおりの読みである。ミッションが
閉じれば(`状態:` が `進行中` でなくなれば)対象から外れ、再び「済んだ」に戻る。

**`paths` から `.claude/missions/` を外した** ★(2026-09-16) — この移行が実際に編集するのは
`docs/` と、そのとき現役だったミッションの台帳の中の該当行だけである。`.claude/missions/`
全体を関所に含めると、**中央エージェントが配車のたびに書く台帳の更新(未コミットの差分)が
毎回この移行を「書きかけ」にし、`/kit-migrate` を毎回すり抜けさせる**(2026-09-13 に3本・
2026-09-16 に2本の作業指示が無駄になった実測)。台帳の書き込みは中央エージェントの正常な
運転であって「誰かがこの移行の対象を今まさに編集している」ことを意味しないので、`paths` の
関所が守るべき状況とは違う。**`docs/` は残す** — あちらは人間や `/build` が実際に文章を
編集する場所であり、関所の意味が生きている。

## 移らなかったときに何が起きるか

- 用語の機械検査は記録を対象にしないので、**別表記は咎められないまま残る**。
- 作業する者は記録を手本に次の記録を書くので、**別表記が世代を越えて増え続ける**。
  検索・レビューで同じ概念を全件拾えない状態が続く。
