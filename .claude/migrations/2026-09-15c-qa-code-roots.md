## 何が変わったか

**製品を実際に触って確かめる確認(探索的QA)の対象が、画面だけでなくサブコマンドにも
広がった**(2026-09-15 の裁定)。

ところが、**その確認が「やり直しになるかどうか」を決めているのは、別の宣言である。**
`.claude/scripts/flow-config.local.json` の次の2つが、それを持っている:

| 宣言 | 何を言っているか |
|---|---|
| `ui_roots` | 探索的QAが見るコードの置き場 |
| `scope_roots` の `qa` | 同じことを、より細かく言うためのもの。**両方在れば、こちらが勝つ** |

**どちらも、画面が在ることを前提に書かれた時期のもの**である。画面のコードの置き場
(`src/ui/` など)だけを指していると、**サブコマンドのコードをいくら変えても、
「確認済み」の表示が消えない。**

**この移行は、確認そのものが既に有効になっている製品だけに当たる。**
確認を外していた製品の直し方は、別の記録(`2026-09-15-qa-cli-lane.md`)が持っている。

## 手順

**判断が要る移行である。** 機械には「どこにサブコマンドのコードが在るか」が分からない。
**だからこの移行は、置き場をあなたに1度はっきり書かせることで終わる。**

**終わりの印は、`scope_roots` の `qa` を明示して書くことである。**
書けば、次からこの移行は「済んだ」と判定される(`ui_roots` のままでは、
覆えているかどうかを機械が確かめられないので、何度でも問われる)。

1. **いまの宣言が何を見ているかを確かめる。**

   ```bash
   python3 .claude/scripts/stamps.py deps verify-tests:qa
   ```

   印字された置き場の一覧に、**サブコマンドのコードの置き場が入っているか**を見る。

2. **`.claude/scripts/flow-config.local.json` に、`scope_roots` の `qa` を書く。**
   **覆えていたなら、いまと同じ内容をそのまま書けばよい**(それが「確かめた」という記録になる)。
   覆えていなかったなら、サブコマンドのコードの置き場を足す。

   ```json
   {
     "scope_roots": { "qa": ["src/ui/", "src/cli/"] }
   }
   ```

   **`ui_roots` は残しておいてよい**(両方在れば `scope_roots` の `qa` が勝つ)。
   紛らわしいと思うなら消してよいが、**他の用途には使われていないことを確かめてから**にする。

3. **書いたら、確認の「済んだ」印は一度消える**(宣言を変えると、その試験区分の記録は
   古いものとして扱われる)。次にその確認を回したときに付き直す。

**コマンドの台帳(`docs/ux/flows.md` の「コマンド一覧」)や `docs/ux/commands/` が
まだ無くても、この移行は当たる** ★ — あれらは「次にサブコマンドを触る作業が作る」もので
あって(`2026-09-15-qa-cli-lane.md` の手順6)、**無いことはサブコマンドが無いことを意味しない。**

## 移らなかったときに何が起きるか

**サブコマンドを書き換えても、確認をやり直させる仕組みが働かない。**
出荷してよいかの判定は「確認済み」と表示し続け、**誰も触っていないサブコマンドの
壊れが、そのまま出ていく。**

**壊れは静かである** — 何も鳴らないので、気づく手がかりが無い。
