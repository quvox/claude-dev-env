# 2026-09-18 運用モードを明示し、選んだプロジェクトだけ移す

## 何が変わったか

**2026-09-20 に、この移行の「未指定なら a1」の部分だけが変わった** ★ —
明示が無いときの既定は、中央エージェントが動いているエンジンで決まるようになった
(claude なら a1、codex なら o1)。**claude で中央を立てている場合は結果が同じ**なので、
この移行の手順と判断はそのまま有効である。codex で中央を立てる場合の扱いは
`.claude/migrations/2026-09-20-default-mode-and-model-limit.md` が持つ。

配車は a1/a2/o1/o2 の4モードに対応した。正は orchestration.md §1.2.1・§1.3、台帳の形は §7。
上書き展開では既存ミッション台帳と専用 CODEX_HOME の設定が変わらないため、この判断手順を持つ。
**/kit-migrate は自動で当てない。** 人間が選択した場合だけ作業指示として配る。
明示が無いプロジェクトとモード欄の無い旧台帳は、**中央が claude であるかぎり** a1 の現行固定表のまま
である(2026-09-20 より前は、中央が codex でもそうだった。上の注記)。
新しいモードと起動値を未選択プロジェクトへ一括適用しない。

## 手順

1. 人間へ「a1 の維持 / a2 / o1 / o2」の選択と、適用するミッション・許可されたパス・
   CODEX_HOME・希望砂箱・モデル/effort/費用上限を確認する。未選択なら**設定と旧台帳を
   変えない**。a1 維持を確認した場合も、判断の記録 `.claude/missions/operating-mode-choice.md` へ
   選択・日時・対象ミッション・適用範囲と `判断完了: <YYYY-MM-DD HH:MM>` を残せる。このファイルは移行判断の済否だけを示し、
   配車設定の正本ではない。将来のミッションで /mission がそこからモードを自動推定しない。
2. 選ばれたミッションだけ、台帳へ選択モード・実効モードを同じ選択値で書き、モード明示: あり とする。
   稼働中なら旧役の結果・書込み・未返信と返信を回収してから切替する。新しい中央の kind が
   選択モードと一致するよう、人間が台帳と掲示板を保持して起こす — 手段は `agent despawn` +
   `agent spawn --id orchestrator`(`colabtmux start` を打ち直さない。同名セッションは拒否され、
   強行すると掲示板ごと作り直されて稼働中のウィンドウとの連絡路が切れる。具体的なコマンドは
   `orchestration.md` §1.2.1)。縮退の復帰は人間が明示する。
3. `.claude/skills/setup/SKILL.md` §2.3 と `.claude/skills/mission/SKILL.md` §0 の確認を行う。
   通常経路を先に実測し、広い経路は許可と外側の
   隔離の確認が在る場合だけ起動行で明示する。CLI の機能フラグだけで継承へ逃げない。
4. 既存 .codex/config.toml と実際の CODEX_HOME/config.toml を TOML として比較し、
   無介入の許可が在るキーだけを変更する。対象は approval_policy=never と、通常経路の
   `sandbox_workspace_write.network_access=true`、許可された正規化パスの `trust_level=trusted`。
   設定層と起動行の優先順位を踏まえ実効値を確認する。sandbox_mode の一括上書きはしない。
   **認証・履歴・MCP 許可先・無関係キーを保持し、雛形で丸ごと上書きしない。**
   許可先や保存先の変更がさらに要るなら、人間が指定した範囲だけを別途扱い、未確認を報告する。
5. ホスト共有の設定が対象なら `.claude/missions/operating-mode-choice.md` に実際の
   CODEX_HOME/config.toml の絶対パスを名指す(既定なら ~/.codex/config.toml)。
   リポジトリ外は paths の関所が守らないので、**①読む前に安全な一時領域へ複写 ②変更を
   準備 ③書く直前に cmp で控えと現物を照合**する。不一致なら書かず止めて報告する。
   プロジェクト専用設定にも同じ照合を行う。控えは所有者だけが読めるようにし秘密を出力しない。
   TOML の構文と変更キーを再確認し、専用ホームは所有者・除外・権限を確認する。
6. 実際の起動経路で短い応答・掲示板往復・役の機能を確認し、台帳へ結果・未確認を記録する。
   o1 なら Codex 主実行と Claude 読取専用レビューの組を確認する。鮮度スタンプの旧形式は
   書き換えない。明示モードで次に検証するときの拡張記録は /verify-docs §2 に従う。
   選択と適用結果を判断の記録へ残し、最後に `判断完了: <YYYY-MM-DD HH:MM>` を書く。
   要るが判断待ち・適用途中なら判断完了を付けて済扱いにしない。

## 移らなかったときに何が起きるか

未選択の既存プロジェクトは a1 の現行配車・免除・デプロイゲートで動き続ける。展開だけでは中心を変えない。
Codex 中心の選択をしたのに台帳と中央が一致しなければ配車を始めない。専用設定の準備不足は
起動前不合格になり、無介入で動くことは未確認のままである。
