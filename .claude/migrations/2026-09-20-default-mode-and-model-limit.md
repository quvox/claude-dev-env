# 2026-09-20 既定の運用モードと、モデルを軽い層に固定する指示

## 何が変わったか

**1つめ。** 人間が a1/a2/o1/o2 を明示しなかったときの既定が、**中央エージェントが実際に
動いているエンジンで決まるようになった** — claude なら a1、codex なら o1 である。
これまではどちらのエンジンで中央を立てても既定は a1 だった。正は
`.claude/directions/orchestration.md` §1.2.1、台帳の形は同 §7 である。

- **claude で中央を立てているプロジェクトは、何も変わらない。** 既定は今までどおり a1 であり、
  配車・F4 の現行動作・旧形式の鮮度スタンプはそのままである。
- **codex で中央を立てるプロジェクトだけが変わる。** これまでは「中央の種別が a1 の中心側と
  違う」として配車そのものを始められなかった。これからは既定が o1 になり、そのまま配車できる。
  ただし**既定の o1 は、人間が明示選択した o1 とまったく同じに扱われる** — 鮮度スタンプの
  拡張記録(`.claude/skills/verify-docs/SKILL.md` §2)と、F4 の判断部分の独立レビュー
  (`.claude/skills/verify-tests/SKILL.md` §1.5)が要るようになる。
- a2 と o2 は、これまでどおり人間の明示でしか選べない(エンジンだけでは a1 と a2、
  o1 と o2 を見分けられないからである)。

**2つめ。** **使うモデルを軽い層に固定する指示**(台帳の `モデル制限:` の欄)が足された。
運用モードとは独立で、**どの役をどちらのエンジンが取るかは1つも変えず、モデルだけ**を
claude は `sonnet`、codex は `gpt-6-luna` に固定する(`opus`・`gpt-6.1-sol` と
規定されているものも全部そうなる)。effort と reasoning は動かさない。
ねらいは利用枠の上限(rate limit)に触る危険を減らすことである。正は
`.claude/directions/orchestration.md` §1.5 の最後の小節である。
**人間が指示したときだけ入り、AI は自分で入らず自分で外さない。**
**欄の無い台帳は「なし」と読む**ので、この移行を当てなくても既存のミッションは今までどおり動く。

## 手順

1. 人間へ2つを確かめる。**未選択なら設定も台帳も変えない。**
   - **中央をどちらのエンジンで立てるか。** codex で立てる予定が在るなら、上の
     「既定の o1 は明示した o1 と同じに扱う」を承知しているか(拡張記録と F4 の判断部分の
     独立レビューが増える)。
   - **モデルを軽い層に固定するか。** 固定するなら、いつから固定するのか。
2. 選択・日時・対象ミッション・適用範囲と `判断完了: <YYYY-MM-DD HH:MM>` を
   `.claude/missions/mode-default-and-model-limit.md` へ残す。**このファイルは移行判断の済否だけを
   示すもので、配車設定の正本ではない。** 将来のミッションで `/mission` がここからモードや
   モデル制限を自動で推定することはない。要るが判断待ち・適用途中のまま `判断完了:` を
   書いて済扱いにしない。
3. **モデルの固定を選んだ場合だけ**、対象の進行中ミッションの台帳
   (`.claude/missions/<mid>/ledger.md`)へ次を足す。**選ばなかったミッションの台帳は触らない。**
   - frontmatter へ `モデル制限: あり` の1行(形は `orchestration.md` §7)。
   - 「モード変更の記録」の表へ、入れた日時・そう指示した人間の言葉を1行。
     この表は列が1つ増えている(`モデル制限`)ので、古い台帳では見出し行も直す。
   - 稼働中のエージェントの確認欄を、実際に渡すモデルの値へ直す。
4. **稼働中のウィンドウのモデルは、起動のときに渡した値のままである** — 走っている相手の
   モデルは後から変えられない。固定を効かせたい相手が在るなら、人間が
   `colabtmux agent despawn` と `agent spawn` で起こし直す(手順は
   `orchestration.md` §1.2.1)。**中央自身も同じ**で、起動行のモデルは人間が渡す。
   起こし直す前に、その相手が返していない結果と書きかけを回収する(同 §1.3 の2と3)。
5. `colabtmux.conf` は配布物なので、上書き展開で新しい注記まで入れ替わっている。
   **この設定ファイルの `command` に書いてあるモデルは「固定しないとき」の値である** —
   固定を常態にするためにここを書き換えない(起動のたびに人間が値を確認するという
   `orchestration.md` §1.5 の規則を、設定の既定が黙って肩代わりしてしまう)。
6. 次の検証フローを配る前に、作業指示へ**実効モードとモデル制限の有無**を書く
   (`.claude/skills/mission/SKILL.md` の配車の段)。記録の側は
   `python3 .claude/scripts/stamps.py record ... --model-limit あり` を添える。
   **台帳の欄が正**なので、食い違う値を添えた記録は拒まれる(終了コード 2)。

## 移らなかったときに何が起きるか

claude で中央を立てている既存プロジェクトは、何も変わらずに動き続ける(この移行を当てなくても
既定は a1 のままである)。codex で中央を立てたい場合に当てないと、既定が o1 になったことと、
そこで拡張記録と F4 の判断部分の独立レビューが要ることを人間が知らないまま配車が始まる。
モデルを軽い層に固定したいのに台帳へ欄を足さないと、**固定したつもりのミッションが
重い層のモデルで走り続け**、鮮度スタンプの証跡にも「軽い層だけで出した green」という事実が
残らない。どちらも黙って起きる。
