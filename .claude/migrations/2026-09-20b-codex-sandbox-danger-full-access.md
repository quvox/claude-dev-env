# 2026-09-20 codex のエージェントを砂箱なしで起こす

## 何が変わったか

**`.claude/scripts/launch-agent.py` が、codex のエージェントに必ず
`--sandbox danger-full-access --ask-for-approval never` を渡すようになった。** 人間の指示である。
役でもホストでも分かれない。正は `.claude/directions/orchestration.md` §1.1.1。

それまでは3通りに分かれていた — 通常の役が `workspace-write`(+ 掲示板の送り込みのための
`-c sandbox_workspace_write.network_access=true`)、`@qa` だけが `danger-full-access`、
bubblewrap の使えないコンテナでは砂箱のオプションを足さない `none`。**その3つはもう選べない**
(古い値を渡すと `launch-agent.py` が止まる。黙って読み替えると、「砂箱が掛かっている」前提で
書かれた起動行がそのまま通ってしまうからである)。

**これは、そのホストで codex が何をできるかを変える。** 砂箱は codex の側で次を止めていたが、
どれももう止まらない:

- **作業ディレクトリの外への書込み**(リポジトリの外、`$HOME`、ホストの設定ファイル)
- **外部への通信**(以前は `network_access` を明示したときだけ開いていた)
- **シェル呼び出しごとのプロセスの隔離**

**代わりに守るものは codex の外側に在る** — このキットを置いたホストそのものの隔離
(コンテナ・専用の利用者・専用の `CODEX_HOME`)と、`.claude/roles/<役>.md` が役ごとに定める
禁止(レビュー役は対象に1バイトも書かない、など)である。**後者は規範であって機構ではない。**

## 手順

1. **人間へ確かめる。** このプロジェクトを動かすホストで、codex が「そのホストの利用者として
   何でもできる」状態を受け入れてよいか。判断の材料は次の3つで、どれも人間しか答えられない。
   - そのホストは何から隔離されているか(コンテナか、共有の開発機か、個人の端末か)。
   - その利用者の権限で届く範囲に、消されると困るもの・秘密が在るか
     (`$HOME` の資格情報、他のプロジェクトの作業ツリー、ホストの設定)。
   - 外部への通信が常に開くことを受け入れてよいか。
2. **受け入れないなら、そのプロジェクトでは codex のエージェントを使わない**
   — 運用モードを a2(claude のみ)にする(`orchestration.md` §1.2.1)。
   **砂箱を狭めて使い続ける道は無い**(起動の口が1つで、そこが固定されたからである)。
   この場合も判断の記録を残し、a2 を選んだことを書く。
3. 選択・日時・対象・そう決めた理由と `判断完了: <YYYY-MM-DD HH:MM>` を
   `.claude/missions/codex-sandbox-choice.md` へ残す。**このファイルは移行判断の済否だけを
   示すもので、配車設定の正本ではない。** 要るが判断待ちのまま `判断完了:` を書かない。
4. **走っている codex のウィンドウは、起こされた時点の砂箱のまま動いている。**
   揃えたいなら、返っていない結果と書きかけを回収してから
   `colabtmux agent despawn` → `agent spawn` で起こし直す(手順は `orchestration.md` §1.2.1)。
   起こし直さなくても壊れはしない — 古いウィンドウが古い制限のまま動くだけである。
5. **`.codex/config.toml`(導入時に1度だけ複写されるので上書き展開では変わらない)** は、
   そのままでも害は無い。`approval_policy = "never"` は引き続き効き、
   `[sandbox_workspace_write]` の欄は**砂箱の掛かる使い方をしたときだけ**効く
   (人間が素の `codex` を打ったときと、艦隊の外の読み取り専用の独立レビュー)。
   コメントを新しい版に合わせたいなら `.claude/templates/codex-config.toml` を見て直す。
   **認証・履歴・MCP の許可先・無関係なキーは保持し、雛形で丸ごと上書きしない。**
6. 起動前確認(`/mission` §0)を1度取り直す。測る値は起動行が渡す値そのものである:
   `codex sandbox -c sandbox_mode=danger-full-access -- /bin/true`。
   **外側の隔離が未確認なら、台帳には「未確認」と書く** — 砂箱が守っているとは書けない。

## 移らなかったときに何が起きるか

**この移行を当てなくても、次に codex のエージェントを起こした時点で砂箱は外れる** —
判断を待ってくれる仕掛けは入っていない(起動の口が固定されたからである)。
だから当てないことの意味は「そのホストで受け入れてよいかを誰も確かめていない」であり、
**受け入れられないホストだった場合、それが分かるのは何かが壊れた後になる。**
逆に、bubblewrap の使えないコンテナで `use_legacy_landlock` の非互換に阻まれていた
プロジェクトは、この変更で codex を起こせるようになる(砂箱の実装を1つも使わないためである)。
