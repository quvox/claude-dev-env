# キットの版を上げた後の据え付け

出力はすべて日本語で書く。

**このスキルは改善ではなく据え付けである。** キットの中身を変えない — 消すのは
**いまの版に無いファイル**(旧版の取り残し)だけであり、書くのは `docs/` と、
**配布物に含まれない設定ファイル**だけである。だから `.claude/directions/core.md` §3 の「キットを直すのは
`/kit-improve` だけ」に抵触しない。**キットを直したくなったら、それは `/kit-improve` である。**

**なぜ要るか。** 上書き展開(`tar -xzf`)は**削除をしないし、`docs/` を作らないし、
配布物に含まれない設定ファイルを1つも更新しない** — プロジェクト自身が持つ宣言
(`*.local.json`)も、**ホスト共有の設定**(`~/.codex/config.toml` など)もそうである。
(**`colabtmux.conf` はこれに当たらない** ★ — あれは配布物に入っており、展開のたびに
上書きされる。2026-09-15 に記述を実物へ合わせた。)展開だけで済むと思っていると、**旧版のスキルが生き残り、記録の行がどの道具からも
見えなくなり、設定が古い書き方のまま残る。** どれも黙って起きる。

**そして、いちばん静かに壊れるのは走っているセッションである。** `CLAUDE.md` と
`.claude/roles/` は**起動時に読み込まれる**ので、入れ替えても**いまの文脈は古い版を
持ったまま**である(スキルの本文は呼ばれるたびに読まれるので、次の呼び出しからは新しい)。
長い作業の途中では再起動できないことが多い。**だから段7 が、効く差分だけを自分の目に入れる。**

## 0. 前提と、読む節

**打つのはキットを展開した直後である。** 展開より前に打っても意味は無い(比べる相手が無い)。

**読む量の多い段は、自分の文脈で読まない** ★ — このスキルは**長い作業の途中で打たれる**ので、
ここで文脈を食うと、そのために据え付けたはずの作業が続けられなくなる。**渡すのは段1(差分を
読む)と段5(残務の突き合わせ)である**(`CLAUDE.md` §1 の委任がまさにこの形である):

- **単独運用**: `bulk-read` のサブエージェントへ渡す(`.claude/agents/bulk-read.md`)。
  あれは**多く読んで少なく返す** — `path:line` と原文の逐語だけを返し、判断はしない。
  **判断はこちらに残る**(何が効くか、どの行を失効させるか)。
- **艦隊運用**: **中央エージェントはこのスキルを自分で打たない** — 作業指示として
  作業エージェントへ配る(`orchestration.md` の中央エージェントの禁止の一覧)。
  配られた側は、上と同じく `bulk-read` へ渡す。codex のウィンドウにサブエージェントは無いので、
  そのときは `@survey` を要求する(`orchestration.md` §1.2 と同じ形の1行)。
- **渡す指示は「読む範囲」と「返す形」だけである。** 20行以内で返させる —
  それがそのまま段7 の報告の材料になる。

**負う規範の節は `.claude/directions/reading.md` のこのスキルの行である。** それは床であり、
**判断がそこから外へ出たら、その節を開いて読む**(原則9)。

**このスキルは、進行中の作業を止めない。** 作業指示とミッションには触らない。
艦隊で走っているなら、**他のウィンドウが走っているあいだに打ってよい** — ただし
コミットは自分が書いたパスを名指して行う(`orchestration.md` §3.4.2)。
**`docs/` のファイルは、未コミットの差分が無いときだけ触る** ★ — 差分が在るのは
**誰かがいまそこを書いている**ということであり、移行で上書きすれば書きかけを壊す
(そのときの扱いは §3)。

**最初の書込みより前に、保護ブランチに居ないことを確かめる** ★ — 消すのも移すのも書込みで
あり、`flows.md` §7.1 は**書き始める前に**判定することを求めている(判定の中身も、同じ名前の
枝が既に在るときの分岐も、そちらが正である。**ここには写さない**):

```bash
python3 .claude/scripts/guard-branch.py --slug kit-migrate
```

**終了コードが `0` でなければ、そこで止まって報告する。1バイトも書かない**
(`1` は、こちらの知らない事情が在るという意味である)。**段1 まではすべて読むだけなので、
判定より前に打ってよい** — だが**段2 から先は書込みである。**

## 1. 段1 — 何が変わったかを取る

**キットは git で追跡されているので、変わったものは git が知っている。** 展開の前後を比べる
唯一の材料がこれである(`.claude/.kit-snapshot.tar.gz` を当てにしない — あれは
`kit-patch.py status` が指紋の変化に気づいた時点で取り直されるので、**先に `status` を
打つと消える**)。

```bash
git status --porcelain -- .claude CLAUDE.md      # 展開がまだコミットされていないとき
git diff --stat -- .claude CLAUDE.md
```

**展開が既にコミットされているなら、そのコミットを見る**(`git show --stat <そのコミット>`)。
どちらも取れないときは**そう報告して止まる** — 何が変わったか判らないまま移行を当てると、
何を移したのかも判らない。

**版の名前を控える。** キットの名前は `.claude/scripts/kit-dist.json` の `kit` である。
**版そのものには名前が無い** — `.claude/kit-manifest.json` は版番号も生成日時も持たない
(自分の冒頭のコメントがそう宣言している。配布物の再現性を壊すからである)。**だから版は
コミットで名指す**: 展開を入れる前の HEAD と、展開を入れたコミット(まだコミットして
いなければ `未コミット`)。段7 の報告の1行目になる。

```bash
python3 -c "import json;print(json.load(open('.claude/scripts/kit-dist.json'))['kit'])"
git rev-parse --short HEAD      # **展開を入れる前に**控える
```

## 2. 段2 — 旧版の取り残しを消す

```bash
python3 .claude/scripts/kit-manifest.py check
```

**現物を4つに割る**(旧版の取り残し / 改造 / 欠落 / キット管理外)。**消すのは
「旧版の取り残し」だけである。**

- **「改造」は消さない。** それはこのプロジェクトが自分で直したキットであり、
  **本流へ戻す価値のある差分**である(`/kit-improve` の持ち物)。**上書き展開で消えていたら、
  それは既に失われている** — 気づいたら報告に1行書く。
- **「欠落」は展開の失敗である。** 消すのではなく、展開をやり直す。
- **「キット管理外」は触らない**(`*.local.json`・`missions/`・`state/` など)。

## 3. 段3 — 移行の台帳を当てる

```bash
python3 .claude/scripts/kit-migrate.py            # 要る/不要を並べる
```

**要ると出た項目の本文を1件ずつ読み、書いてある手順を当てる。**

**状態は4つ出る。当ててよいのは1つだけである:**

| 出た状態 | 意味 | どうするか |
|---|---|---|
| `要る` | 移行がまだ済んでいない | `kind: mechanical` なら**当てる**。`judgment` は当てず、段7 の報告に「要るが判断待ち」として、判断の材料(何が変わったか / 移らないと何が起きるか)を1行で添える |
| `不要` | 済んでいる(`detect` が 1 を返した) | 何もしない |
| `判定不能` | `detect` が 0 でも 1 でもない値を返した / 打ち切られた | **当てる前に、要否を自分で確かめる。** 台帳の `detect` が壊れているなら、それは移行ではなくキットの欠陥である(`/kit-improve`) |
| `書きかけ` | `paths` に**未コミットの差分が在る** | **当てない。** 誰かがいまそこを書いている。段7 の報告にそう書く — **移行はいつでも当て直せるが、書きかけは戻らない** |

当て終わったら、もう一度打って**要るものが無くなったことを確かめる**:

```bash
python3 .claude/scripts/kit-migrate.py check      # 0 = 残っていない
```

**残ったまま先へ進んでよいのは `judgment` だけである。**

## 4. 段4 — 上書きで触られない層を見る

**ここが、展開だけでは決して直らない層である。**

| 見るもの | 何を確かめるか |
|---|---|
| `colabtmux.conf` | **雛形との差**(`c=.colabtmux/colabtmux.conf; test -f "$c" || c=colabtmux.conf; diff "$c" colabtmux.conf`。**置き場は2つありうる** — `colabtmux` は自分の状態の置き場の中に設定を作る版がある)。**配布物に入っているので、展開のたびに上書きされる** ★(2026-09-15 に記述を実物へ合わせた)— プロジェクト固有の値を1つも持たない形にしてあるため(`[project] name` をあえて書いていない)、**そのまま上書きしてよい。雛形に入った行を自分で足す作業は要らない。** **手を入れていたのなら、その差はここで消える** — 差が出たら、入れ直すかどうかを決める |
| `.claude/scripts/*.local.json` | 宣言(`code_roots`・`f4_scopes`・`ui_roots` ほか)が**いまの版のスキーマで読めるか**。読めなければ `stamps.py check` が縮退する(方向は fail-closed) |
| `docs/` の骨格 | 新しい版が要求する置き場が在るか。**`/setup` を打ち直さない** — あれは骨格を作るスキルであって、移行の道具ではない(既存を1バイトも変えないので害は無いが、移行の判断はしない) |
| `AGENTS.md` | **`CLAUDE.md` へのリンクのままか**(`test "$(readlink AGENTS.md)" = CLAUDE.md`)。codex 向けの教え込みは `AGENTS.md` ではなく `.colabtmux/usage-codex.md` へ配られる(`colabtmux.conf` の `[agent_kind.codex] provision_target`。移行 `2026-10-31-colabtmux-codex-provision-target`)— `colabtmux` が配り直すので自分で書かない。**`CLAUDE.md` に `colabtmux:begin` が在れば、その移行が要る** |
| ホスト共有の設定 | 移行が名指したときだけ見る(`~/.codex/config.toml` など)。**リポジトリの外に在るので `paths` の関所が効かない** — 手順は §9 の「外のファイルを触る移行」である |

## 5. 段5 — キットを名指した残務を、新しい版に照らして失効させる ★

**キットの欠陥は `残務` の1行として溜まる**(`issues-pendings.md` §1 の振り分けの行4)。
`/kit-improve` に出せなかった気付き、まだ本流へ渡していない改善、渡したが取り込まれたか
判らないもの — **そのどれもが「まだ直っていない」という顔で残る。**

**版を上げた瞬間、その一部は嘘になる。** 直っているのに行が残っていると、
**次に読む者はキット更新の残務がまだ在ると誤認し続ける**(2026-08-25 の人間の指摘)。
**この段が、その1行1行に決着を付ける。**

1. **キットを名指した行を集める**(読む量が多いので §0 のとおり委任する):

   ```bash
   grep -nE '\.claude/|/kit-improve|キット' docs/residual.md
   ```

2. **1行ずつ判定する。** 新しい版の現物(`.claude/` の中身)と、段1 で取った差分に照らす:
   - **解消されている** → **その行を落とす**(下)。**台帳を直に開いて消さない** ★ —
     落とすのは `doc-health.py --resolve-residual=... --verdict=... --record=...` であり、
     追記・押し出しと同じ錠を通る(`issues-pendings.md` §2.1)。
   - **まだ在る** → 残す。**残す理由を報告に書かない** — 変わっていないことは報告の材料に
     ならない(行がそのまま残っているのが記録である)。
   - **判らない** → 残す。**「たぶん直った」で消さない** — 消えた記録は戻らない。
3. **消した行は履歴へ逐語で残る。** 落とすコマンドの `--record=` に、その run の履歴
   (`docs/histories/<日付>-kit-migrate.md`。書式は `.claude/templates/history.md`)を渡す —
   **コマンドが記録を先に書いてから落とす。** `--verdict=` には
   **「新しい版のどこで解消されたか」**を書く。そのうえで履歴に
   `## 版上げで失効させた残務` の節を作り、落とした行をまとめて読める形にしておく。
   **記録の無い削除はしない**(原則8 が禁じる黙った無視である)。
   **書いた文書のパス(`docs/residual.md`)を履歴の所定の欄に必ず入れる** ★ — 入れないと
   `doc-health.py` の「文書・IDを索引化できない履歴」が毎回1件増える(あの数は逆引きの索引に
   載らない履歴を数えている)。

**この段が消せるのはキットを名指した行だけである** ★ — 製品の残務には触らない。
**権限の根拠は `issues-pendings.md` §2.1** であり、そこがこの段を名指している
(掃き出しの権限を持つのは `/verify-docs` だけ、という規則の**例外がここに1つ在る**)。

**課題票(`docs/issues/`)には触らない。** あちらは `closes_when` を持ち、その発火を見るのは
既にある規則である(`issues-pendings.md` §8)。**同じ判定を2か所でしない。**

## 6. 段6 — 検査

```bash
python3 .claude/scripts/check-kit-refs.py         # キット内の参照が死んでいないか
python3 .claude/scripts/kit-manifest.py check     # 取り残しが消えたか
python3 .claude/scripts/kit-migrate.py check      # 要る移行が残っていないか
python3 .claude/scripts/check-backlog.py          # 記録の置き場が読めるか(移行の取り残しを拒む)
python3 .claude/scripts/stamps.py check           # デプロイゲートの状態が変わっていないか
```

**`stamps.py check` の結果は、版を上げる前と同じであるべきである。** 鮮度スタンプの依存は
`docs/` と `code_roots` の下であって、**`.claude/` は入っていない**(`flows.md` §2 が
設定ファイルについて述べているのと同じ理由)。だから**版を上げても鮮度スタンプは1件も
失効しない。**

**それは「見直さなくてよい」の意味では決してない** ★ — 検査の中身が変わったのに、
その変化は差分として現れないので、**次の増分の run はそれを見ない。** 変わった検査が在るなら、
**その検査だけを1回自分で回す**か、回していないことを段7 の報告に書く。
**黙って green のままにしない。**

## 7. 段7 — いま走っている作業への影響を出す ★

**このスキルの本題である。** 規範の全文を読み直さずに、**効く差分だけ**を自分の目に入れる。
問う順に3つ:

1. **いま書いている層の規範が変わったか**(`directions/<層>.md`・`templates/`)。
   変わったなら、**その節だけ**を開く。書きかけの文書は、その節の形で書き終える。
2. **いま使っている検査や道具の振る舞いが変わったか**(`scripts/`)。
   変わったなら、**次に打つ前に**その道具の docstring か `--help` を見る。
   **前の版の記憶で引数を組み立てない。**
3. **記録の置き場・書式が変わったか**(`templates/`・`docs/` の構造)。
   これは**書きかけの文書と、まだコミットしていない記録に効く。**

**どれも「変わっていない」なら、そう書く。** 変わっていないことは、確かめた人にしか言えない。

報告の様式(**20行以内**。長くすると読まれない):

```
## 移行の報告(<日付>)
版: <kit の名前> <展開前の HEAD> → <展開を入れたコミット | 未コミット>
消した取り残し: <件数>(<名前>)/ 改造の消失: <有無>
当てた移行: <id …>
要るが判断待ち: <id …>(<何を判断するか>)
上書きで触られない層: <直した / 差は無かった>
失効させた残務: <件数>(履歴のパス)/ 判らずに残した: <件数>
変わった規範: <ファイル §節 を、効く順に最大10行>
**いまの作業に効くもの**: <1〜3行。無ければ「無し(理由)」>
回していない検査: <名前と理由。無ければ「無し」>
検査: kit-manifest=<結果> / kit-migrate=<結果> / check-kit-refs=<結果> / stamps=<結果>
```

**この報告が、走っているセッションが持ち越す唯一の記録である。** ファイルには残さない
(残す価値のある判断が出たなら、それは移行ではなく `残務` か課題票である —
`issues-pendings.md` §1)。

## 8. 段8 — コミットする

**書込みが在ったときだけ**、自分が触ったパスを名指してコミットする
(枝の判定は §0 で済んでいる — ここで打ち直さない)。

```bash
git commit --only <触ったパス...> -m "kit-migrate: <版> へ据え付ける"
```

**展開そのもののコミットと、移行のコミットを分ける** — 前者は「配布物を入れ替えた」、
後者は「このプロジェクトを新しい版へ移した」であり、意図が違う。片方だけを戻したくなる。

## 9. 移行の台帳 — 書式(本流側が1件足すときの正)

**置き場は `.claude/migrations/<YYYY-MM-DD>-<slug>.md`。1件 = 1ファイル。**
**足すのは本流側である**(キットの配布元のリポジトリ。その側の規範がそれを義務にしている)。
判定するのは `.claude/scripts/kit-migrate.py`、当てるのはこのスキルである。

frontmatter は6つで、**6つとも必須**(欠けは台帳の不備として `kit-migrate.py` が 2 を返す):

| 欄 | 中身 |
|---|---|
| `id` | ファイル名の拡張子を除いた部分と**同じ**。取り違えと重複を機械で見る |
| `since` | この移行が本流に入った日(`YYYY-MM-DD`) |
| `kind` | `mechanical`(手順が機械的に決まる)/ `judgment`(人間の判断が要る) |
| `detect` | シェル1行。**0 = まだ要る / 1 = 済んでいる / それ以外 = 判定できなかった**(道具は要る側に寄せる)。プロジェクトのルートで走り、30 秒で打ち切る |
| `paths` | その移行が触るパス(空白区切り)。**未コミットの差分が在るあいだ、道具は `書きかけ` を出して当てさせない** |
| `summary` | 1行要約。報告にそのまま載る長さで書く |

本文には3つを書く: **何が変わったか** / **手順** / **移らなかったときに何が起きるか**。

- **手順の正が規範の側に在るなら、そこを指す**(写しを置かない — 写しは片方だけが直る)。
- **`detect` は「済んだか」ではなく「まだ要るか」を書く。** そして**「偽」は 1 で返す** —
  `test` と `grep` はそう作られている。それ以外の値は「判定できなかった」に落ち、道具が
  要る側へ寄せる(判定できないものを「済んだ」と言う方が高くつく)。
- **`paths` は関所であって説明ではない。** 手順が触るファイルを全部書く。書き漏らすと、
  誰かの書きかけを踏む。**例外は1つ、リポジトリの外に在るファイルである** ★ — 関所の判定は
  `git` に問うので、`~/.codex/config.toml` のようなホスト共有の設定は**構造的に見られない。**
  書いても守られないものを `paths` に並べると**関所が守っているように見える**ので、
  **書かない。** 代わりに**本文が、そのファイルと、書く前の確かめ方を名指す**
  (下の「外のファイルを触る移行」)。

- **外のファイルを触る移行は、読んだ姿を控えてから書く** ★ — ホスト共有の設定は、同じホストで
  走る別のプロジェクトの移行と同時に触りうる。手順はこうである: **①読む前に複写を取る
  ②直す ③書く直前に `cmp` で、複写と現物がまだ同じであることを確かめる。** 違っていたら
  **書かずに止めて報告する**(誰かが並行して書いている)。これが、関所の代わりになる
  唯一の観測可能な停止条件である。
- **載せるのは、上書き展開では直らないものだけである。** 展開で直るものを載せると、
  済んだ移行が毎回並び、**並んでいることの意味が失われる。**
