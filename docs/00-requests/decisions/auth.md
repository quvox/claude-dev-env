# 認証の決定事項

## D0-auth-01 認証情報の保管場所とボリューム構成

- 区分: 委任
- 決めた日: 2026-07-31
- 委任範囲: エージェント CLI を追加したときに、その認証情報を既存の共有ボリュームに相乗りさせるか
  専用ボリュームを増やすか。片付け(`logout` / `reset`)で個別に消す分岐を設けるかどうか。
- 制約(ガードレール): 認証情報がプロジェクト間で共有され、セッション・設定はコンテナ固有に保たれる
  こと(`FR-env-03`)。片付け操作で消える範囲が利用者に説明されていること(`logout` は共有
  ボリューム全体を空にするため、同居させた認証も同時に消える)。
- 報告義務: 決めた内容を該当機能の「実装上の判断」表に `D0-auth-01` と共に記録する
- 関連: RQ-env-03 / FR-env-03

## D0-auth-02 認証の受け渡し実装の細部

- 区分: 委任
- 決めた日: 2026-07-31
- 委任範囲: 認証ファイルをコンテナへ渡す実装の細部(どのタイミングでコピーするか、書き戻しを
  どのループに載せるか、ホスト側のどのファイルを読まないか)。
- 制約(ガードレール): **方式は `D0-auth-03` が定める形から変えない**(コピーと定期書き戻しであり、
  共有ボリュームから直接 symlink で参照する形にはしない。**コンテナのホームからコピー先を
  symlink で指すことは `D0-auth-03` が定める形の一部なので、これには当たらない**。
  **形の中身をここへ書き写さない** — 写すと `D0-auth-03` を直したときに片側だけが取り残される)。
  **ホストの認証情報をコンテナへ渡す経路を新設しない**(共有ボリューム経由
  だけにする)。同期方式を 2 つ持たない。
- 報告義務: 決めた内容を該当機能の「実装上の判断」表に `D0-auth-02` と共に記録する
- 関連: FR-env-03

## D0-auth-03 認証はコピーと定期書き戻しで共有する(symlink 不採用)

- 区分: 決定
- 決めた日: 2026-07-30
- 内容: 認証ファイル(Claude: `.credentials.json` / `.claude.json`、Codex: `auth.json`)だけを
  コンテナ間で共有する。**起動時にプロジェクトディレクトリ配下へコピーし、定期的な
  バックグラウンド同期で共有ボリュームへ書き戻す**(周期は 02 が定める)。セッション・設定は
  コンテナ固有に保つ。
- **★2026-08-04 改め(実装が正。`docs/issues/040`)**: 「コンテナローカルへコピー」「symlink は
  使わない」という当初の表現を撤回する。実装は次の形である。
  - コピー先は **`<プロジェクトディレクトリ>/.claude/` と `<同>/.codex/`**、つまり
    **`/workspace` にバインドマウントされたホスト側のプロジェクトディレクトリ**である。
    コンテナローカル(バインドマウント外)ではない。
    `.gitignore` へ `.claude` / `.codex` を自動追記して git の追跡から外す。
  - コンテナ内のホームからは **symlink で参照する**: `~/.claude` → `/workspace/.claude`、
    `~/.codex` → `/workspace/.codex`(ディレクトリ単位)。さらに
    **`~/.claude.json` はファイル単位の symlink** である。
  - **どのファイルのどこでこれを行うかは 02 の契約 `CTR-cli-container` と 03 の実装仕様が持つ**
    (00 は実装の在り処を持たない)。
  - **残るリスク**: ファイル単位 symlink はアトミック書き込み(一時ファイル → rename)で
    実体ファイルに置き換わりうる。当初この形を却下した理由はまさにこれで、**懸念は解消して
    いない**(観測された障害は無い)。ディレクトリ単位の symlink はこの問題を受けない。
  - **この置き場所は `NFR-sec-01` に関わる**: 認証情報がホストのプロジェクトディレクトリ配下に
    平文で存在する。git 追跡からは外れるが、バックアップ・同期ツール・他コンテナからの
    バインドマウントには乗る。
- 理由: Claude Code は認証ファイルをアトミックに書き込む(一時ファイルを作って rename する)ため、
  symlink だと張り替えられて壊れる。トークンのリフレッシュで内容が変わるので書き戻しは必要。
  Codex の `auth.json` はその場書き換えで symlink でも壊れないが、**同期・片付けの経路を 2 方式に
  分けない**ことを優先して同じ形に揃える。
- 却下した案: symlink 共有 — 前述のとおり壊れる。ホストの認証ファイルを直接マウント — ホストの
  クレデンシャルをコンテナへ渡す経路を作ることになる。共有しない(プロジェクトごとにログイン) —
  要求(再ログイン不要)を満たさない。
- 関連: RQ-env-03 / FR-env-03 / AC-06
