# スコープ・実装粒度の決定事項

## D0-scope-01 03-impl の記述粒度と実コードとの対応づけ

- 区分: 委任
- 決めた日: 2026-07-30
- 委任範囲: 各機能の `03-impl/relations/MODULE-*.md` にどこまで詳細を書くか、コードのどの範囲を
  1つの機能として束ねるか。
- 制約(ガードレール): `02-design/system.md` のモジュール分割定義を逸脱しない(モジュールの一覧は
  同表が正本)。同じコードを複数の機能仕様書に重複させない。データ構造・インターフェース・
  ロジックの意図を書き、行単位のコードは書かない。**機能表(`03-impl/features.md`)そのものは
  委任範囲外**で、人間の合意を要する。
- 報告義務: 決めた内容を書いたドキュメントに `D0-scope-01` と共に記録する
- 関連: RQ-env-01 / `.claude/directions/features.md`

## D0-scope-02 実装内部の構造上の判断(観測可能な振る舞いを変えない範囲)

- 区分: 委任
- 決めた日: 2026-07-30
- 委任範囲: ヘルパー関数の分割・統合、処理をどの経路に置くか、資源(プロファイル・ボリューム・
  一時ファイル)をどの単位で分けるか、部分的な失敗を成功として扱うか、後方互換のための残骸掃除を
  するか——といった**実装内部の構造の選択**。
- 制約(ガードレール): 利用者から観測できる振る舞い(コマンドの成否・出力・生成物・ポート・
  ファイル配置)を変えないこと。契約(`CTR-*`)を変えないこと。これらを変える判断は委任範囲外で、
  00 起点の変更として扱う。
- 報告義務: 決めた内容を該当機能の「実装上の判断」表に `D0-scope-02` と共に記録する
- 関連: RQ-env-01 / FR-env-01

## D0-scope-03 macOS 実装の差分の扱い

- 区分: 委任
- 決めた日: 2026-07-30
- 委任範囲: macOS 版(`claude-dev-mac`)で Linux 版と実装が分かれる箇所について、どちらに寄せるか・
  片方にしか置かない関数を作るか・後方互換の残骸を掃除するか。
- 制約(ガードレール): **同じサブコマンドは同じコマンド面(引数・出力・成否)を保つ**こと。
  OS 都合で利用者から見える手順が変わる場合(VM/KVM 非対応など)は、要件
  (`FR-env-10`)に書かれた範囲に限る。
- 報告義務: 決めた内容を該当機能の「実装上の判断」表に `D0-scope-03` と共に記録する
- 関連: RQ-env-06 / FR-env-10

## D0-scope-04 VM モードの運用パラメータと停止・再構築の手段

- 区分: 委任
- 決めた日: 2026-07-30
- 委任範囲: ゲスト VM の監視周期・判定しきい値・サンプリング窓、停止手段の優先順(正常終了と
  強制終了の使い分け)、再構築時にどこまで作り直すか。
- 制約(ガードレール): VM モードはオプトインであり、既定の軽量構成(DooD)の振る舞いを変えないこと。
  利用者のデータ(`/workspace`)を失う操作を自動で行わないこと。完全な作り直しは利用者の明示指定
  (`--vm-fresh`)に限る。
- 報告義務: 決めた内容を該当機能の「実装上の判断」表に `D0-scope-04` と共に記録する
- 関連: RQ-env-05 / FR-env-08

## D0-scope-05 利用者が編集しうる設定ファイルの更新方式

- 区分: 委任
- 決めた日: 2026-07-31
- 委任範囲: 利用者が手で書き換えうる設定ファイル(`config.toml` など)に既定値を補完するときの
  実装方式(行単位の書き換えか、構造としてパースして検証するか)。
- 制約(ガードレール): **利用者が書いた鍵と値を書き換えないこと**、**何度実行しても結果が
  変わらない(冪等)こと**。この 2 つを満たせない実装方式は選べない。
- 報告義務: 決めた内容を該当機能の「実装上の判断」表に `D0-scope-05` と共に記録する
- 関連: FR-env-12

- 決めた日: 2026-07-30
