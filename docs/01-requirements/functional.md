# 機能要件

条項 ID(`FR-<domain>-nn-#`)は**一度振ったら動かさない**: 欠番を埋めない・並べ替えない・廃止した番号を別の基準に再利用しない(02 のカバレッジ表・03 のテスト対応表・`docs/pendings.md` が外部から参照するため。検査は CS16)。

## FR-env-01 コンテナのライフサイクル管理

- 対応要求: RQ-env-01 / AC-01
- **分割可否: 段階可(理由: 段階的に近づくのは条項 `FR-env-01-19`(別ディレクトリの compose 資源を巻き込まない)だけである。compose 資源をプロジェクトごとに一意にしなければ**全プロジェクトが同じ名前を共有して必ず巻き込む**のに対し、一意化が部分的でも取り違えの余地が減った分だけ利用者の作業が守られる。判断の記録は `D1-split-01`。**他の 26 条項は不可分**)**
- 内容: プロジェクトごとに隔離コンテナを起動・再接続・停止・一覧できること。SSH 切断後も作業が
  維持されること。**破壊的操作(`stop` / `logout` / `reset`)が他プロジェクトの資源を巻き込まないこと**
  (`D0-env-08`。共有 docker-proxy と共有ネットワークの停止条件は受入基準9)。
  **共有ボリュームまたは docker-proxy を触るサブコマンドが互いに排他されること**(同項6)。
  **`stop` と `reset` が、そのセッションのコンテナ内から作られた資源(セッション由来の資源)を
  片付けること**(`D0-env-05` 項2。どの資源を対象とするかは `D0-env-08` 項8。**識別の方法は
  02 の契約が定める**)。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-01-1 | 正常系 | WHEN `claude-dev start` を実行したとき、システムはカレントディレクトリを `/workspace` にマウントしたコンテナ(既定はブラウザ確認あり)を起動し、tmux にアタッチしなければならない |
| FR-env-01-2 | 正常系 | WHERE `--no-vnc` が指定された場合、システムはブラウザ確認資産を持たない軽量イメージを使わなければならない |
| FR-env-01-3 | 正常系 | WHILE コンテナが起動している間、SSH 切断や tmux デタッチが起きてもコンテナは動作を継続しなければならない |
| FR-env-01-4 | 正常系 | WHEN 同一ディレクトリで `claude-dev start` を再実行したとき、システムは既存コンテナへ再接続しなければならない(tmux セッションが無ければ再作成する) |
| FR-env-01-5 | 正常系 | WHEN `claude-dev list` を実行したとき、システムは実行中セッションの一覧(noVNC URL とフォワード状況を含む)を表示しなければならない |
| FR-env-01-6 | 正常系 | WHEN `claude-dev stop <name>` を実行したとき、システムは当該コンテナを削除し、当該コンテナ内から起動された compose コンテナ群と当該プロジェクトの compose 既定ネットワークを削除し(名前付きボリュームは保持する)、全 Claude コンテナが停止したときは docker-proxy も停止しなければならない(**compose を経由せずに作られたセッション由来の資源の削除は受入基準22 が定める**。片付けの範囲を compose 資源に限らないことは `D0-env-05` 項2 が決めている) |
| FR-env-01-7 | 境界値 | IF tmux の起動待ちが上限(既定 30 秒 / VM モード 420 秒)を超えたならば、システムは終了コード 0 で状況を案内して終わらなければならず、コンテナを削除してはならない(コンテナは稼働を続け、再実行の再接続経路で合流できる) |
| FR-env-01-8 | 境界値 | IF 停止対象のコンテナが存在しないならば、システムは削除をスキップし、その旨を表示して終了コード 0 で終わらなければならない |
| FR-env-01-9 | 境界値 | IF ホスト上に稼働中の Claude コンテナが1つ以上残っているならば、**`stop` / `logout` / `reset` は** docker-proxy を停止してはならず、**`reset` は共有ネットワークも削除してはならない**(`reset` は残した理由と**完全な初期化になっていない**ことを表示して残りの削除を続行する)。**`stop` と `logout` は遊休かどうかにかかわらず共有ネットワークを削除しない**ので、この基準がネットワークについて課す条件は `reset` にだけ効く(`D0-env-08` 項2 の条件は3コマンド共通だが、共有ネットワークを削除する経路を持つのは `reset` だけである)。**稼働中として数える対象からは、管理ラベルを持たないコンテナも、イメージを再ビルド・再取得した後に起動していたコンテナも、外してはならない**(どちらも数え落とすと、他のセッションが使っている共有資源を止めてしまう。数え方は 02 の契約が定める) |
| FR-env-01-10 | 異常系 | IF 実行に必要な前提コマンドが不足しているならば、システムは**不足しているものを列挙して導入方法を案内**し、終了コード 1 で終わらなければならない(どのコマンドが前提かは 02 が定める。OS によって異なる) |
| FR-env-01-11 | 異常系 | IF compose 既定ネットワークが他から使用中で削除できないならば、システムは処理を続行しなければならない(停止全体を失敗させない。これは `D0-env-08` 項5 が明示する例外である) |
| FR-env-01-12 | 異常系 | IF `claude-dev start` のコンテナ作成が**同名のコンテナが既に存在すること**を理由に失敗したならば、システムはその既存コンテナを削除してはならず、**同名のコンテナが稼働中であること**と**別ディレクトリの同名プロジェクトである可能性**を表示して、終了コード 1 で終わらなければならない(再試行してはならない) |
| FR-env-01-13 | 境界値 | IF コンテナ作成の失敗後に後片付け(作りかけのコンテナの削除)を行うならば、システムは対象が稼働中でないことを確かめてから削除しなければならない。**稼働中のコンテナは、作成の失敗理由を問わず削除してはならない** |
| FR-env-01-14 | 正常系 | WHEN `claude-dev start` が Claude コンテナを作成するとき、システムは本システムが作ったことと起動元のホスト側絶対パスを示す**管理ラベル**を付与しなければならない(名前と値は 02 の契約が定める。**固定名または固定接頭辞を持つ資源にはラベルを付けない**。名前で所有権が読み取れるため。**名前から所有権が読み取れない資源へのラベル付与は、Claude コンテナについては本基準が、セッション由来の資源については `FR-env-07` 受入基準11 が定める**) |
| FR-env-01-15 | 境界値 | IF `claude-dev stop <name>` の対象コンテナが管理ラベルを持たないならば(管理ラベルが付く前に起動されたコンテナなど)、システムはそのコンテナを削除しつつ、**管理ラベルを持たないことを表示**しなければならない(名前で1件を指した削除は `D0-env-08` 項1 の例外である) |
| FR-env-01-16 | 異常系 | IF `start` / `stop` / `logout` / `reset` / `login` / `login-codex` のいずれかが、同じプロジェクト名または同じ共有資源(共有ボリューム・docker-proxy)を対象として既に実行中ならば、システムは**待たずに**、**保持している操作の名前と、その保持者を利用者が特定できる情報**、および再実行の方法を表示して終了コード 1 で終わらなければならない(`D0-env-08` 項6 の「誰が保持しているか」。**保持者をどう表すかは 02/03 が定める**)。**このとき、取得できなかったロックが守る資源に対する削除も作成も行ってはならない**(プロジェクト単位のロックが守るのは当該コンテナとそのプロジェクト配下の生成物、共有資源単位のロックが守るのは共有ボリューム**の中身**・docker-proxy・**共有ボリュームを読んで作られたコンテナ**である。**冪等に作られる共有資源の「用意」は保護対象ではない**: イメージのビルドと、共有ネットワーク・共有ボリュームそのものの作成。既に在れば何も起きず、無いときに作られるのは中身の無い器だけであるため) |
| FR-env-01-17 | 境界値 | IF 排他のためのロックが、既に存在しないプロセスに保持されたまま残っているならば、システムはその事実を表示してからロックを引き継いで処理を続行しなければならない(永久に取得できない状態を作ってはならない) |
| FR-env-01-18 | 境界値 | IF `claude-dev stop <name>` の `<name>` が `[A-Za-z0-9._-]` 以外の文字を含むならば、システムは**何も削除せず**、受理できない文字を含むことを表示して終了コード 1 で終わらなければならない(排他のロックはこの名前をパス要素として使うため、`/` や `..` を含む名前を受理してはならない) |
| FR-env-01-19 | 境界値 | IF 別のディレクトリで起動されたセッションの compose 資源が存在するならば、`stop` はそれを削除してはならない。**起動ディレクトリ名が正規化後に一致する場合も削除してはならない**(compose 資源をプロジェクトごとに一意にする方法は 02 の契約が定める) |
| FR-env-01-20 | 境界値 | IF 本要件の一意化より前に起動された compose 資源が残っているならば、`stop` はそれを削除してはならず、**残っている可能性と手動で片付ける方法を表示**しなければならない(旧い名前は別ディレクトリと衝突しうるため対象に含めない) |
| FR-env-01-21 | 境界値 | IF `claude-dev stop <name>` の対象コンテナから**起動元ディレクトリを読み取れない**(管理ラベルを持たない、または既に存在しない)ならば、システムは**compose 資源の削除を行ってはならず**、compose 資源が残っている可能性と手動で片付ける方法を表示しなければならない(compose 資源をそのプロジェクトのものと決めるにはこの値が要り、他に復元する手段が無い。**推測して削除すると別ディレクトリを巻き込む**。値の持ち方は 02 の契約が定める) |
| FR-env-01-22 | 正常系 | WHEN `claude-dev stop [NAME]` を実行したとき、システムは**当該セッションのコンテナ内から docker-proxy を経由して作られたコンテナとネットワーク**(用語集「セッション由来の資源」)**のうち、所有者ラベルを持つものすべて**を削除しなければならない。**経路が `docker run` / `docker create` / `docker compose up` のいずれであるかを問わない**。**名前付きボリュームとイメージは削除してはならない**。**所有者ラベルを付与できなかった資源は対象外である**(`FR-env-07` 受入基準12 が定める経路で作られたもの。所有者を知る手段が無い)。**所有者の識別方法は 02 の契約が定める**(`D0-env-05` 項2 / `D0-env-08` 項8) |
| FR-env-01-23 | 境界値 | IF `claude-dev stop <name>` の対象コンテナから**起動元ディレクトリを読み取れない**(管理ラベルを持たない、または既に存在しない)ならば、システムは**セッション由来の資源の削除を行ってはならない**(所有者を表す値を他に復元する手段が無く、推測して削除すると別セッションの資源を巻き込む。受入基準21 と同じ根拠である) |
| FR-env-01-24 | 異常系 | IF **`claude-dev stop` が**セッション由来の資源の削除に失敗したならば、システムは処理を続行しなければならない(受入基準11 と同じ扱いであり、`D0-env-08` 項5 の「消えなかった資源を列挙して終了コード 1 で終わる」の対象外である)。**`claude-dev reset` はこの基準の対象ではなく、`FR-env-03` 受入基準18 に従って消えなかった資源を列挙し終了コード 1 で終わらなければならない**(`D0-env-08` 項5 は `logout` / `reset` を対象とし、`stop` だけを例外としている) |
| FR-env-01-25 | 正常系 | WHEN `claude-dev reset` を実行したとき、システムは**所有者を問わずすべてのセッション由来の資源**を削除対象に含め、`FR-env-03` 受入基準14 の削除前の確認の列挙にも表示しなければならない(削除できなかった場合の扱いは `FR-env-03` 受入基準18 に従う) |
| FR-env-01-26 | 正常系 | WHEN `stop` または `reset` がセッション由来の資源を削除したとき、システムは削除した資源の名前を**種別(コンテナ / ネットワーク)とともに1行ずつ**表示しなければならない(`D0-env-08` 項3 が `stop` に確認を求めない代わりの観測点である) |
| FR-env-01-27 | 境界値 | IF セッション由来の資源が1件も無いならば、システムはそれに関する表示を行ってはならない(対象が無いことを毎回表示しない) |

## FR-env-02 UID/GID 追従とホスト資産の共有

- 対応要求: RQ-env-01 / AC-01
- **分割可否: 不可分**
- 内容: コンテナ内のファイル所有権がホストと一致し、git 設定とシェル資産を引き継げること。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-02-1 | 正常系 | WHEN コンテナを起動したとき、システムはコンテナ内ユーザーの UID/GID を `/workspace` の所有者に一致させなければならない |
| FR-env-02-2 | 正常系 | WHERE ホストに `~/.gitconfig` が存在する場合、システムはそれを読み取り専用でマウントしなければならない |
| FR-env-02-3 | 正常系 | WHILE コンテナが稼働している間、システムはシェル設定をコンテナ間で共有し、コマンド履歴を**コンテナを削除しても失われない形で**永続化しなければならない(どの資源に置くかは 02 が定める) |
| FR-env-02-4 | 境界値 | IF 割り当てようとする UID/GID がコンテナ内の既存エントリと衝突するならば、システムは**衝突を解消したうえで割り当てなければならない**(解消の方法は 02/03 が定める。**起動は成功する**) |
| FR-env-02-5 | 境界値 | IF `/workspace` の所有者が root(UID 0)ならば、システムは UID/GID を変更してはならない |
| FR-env-02-6 | 異常系 | IF ホストの設定ファイルが存在しないならば、システムはその項目をマウントせずに起動を続行しなければならない(起動を失敗させない) |

## FR-env-03 認証の共有とセッション分離

- 対応要求: RQ-env-03 / AC-01 / AC-06
- **分割可否: 不可分**
- 内容: 一度のログインで全コンテナが認証を共有し、セッションと設定はコンテナごとに独立すること。
  同梱する両方のエージェント CLI(Claude Code / Codex CLI)について成り立つこと。
  **認証を削除する操作(`logout` / `reset`)が、確認なしに他プロジェクトの作業を落としたり、
  削除できていないのに成功を表示したり、消したつもりの認証をプロジェクト配下に残したりしないこと**
  (`D0-env-08` 項3〜5)。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-03-1 | 正常系 | WHEN `claude-dev login` を実行したとき、システムは一時コンテナで対話認証を行い、完了後に**認証情報を共有ボリュームへ保存**しなければならない(保存する対象と置き場は 02/03 が定める) |
| FR-env-03-2 | 正常系 | WHEN コンテナを起動したとき、システムは**共有ボリュームの認証でコンテナ内の Claude をログイン済みにしなければならず、その認証の実体はプロジェクトディレクトリ配下に置かれなければならない**(`D0-auth-03`。コピーと参照の方法は 02 が定める) |
| FR-env-03-3 | 正常系 | WHILE コンテナが起動している間、システムは**コンテナ内で更新された認証を、次に起動するコンテナから使える状態へ反映**しなければならない(反映の周期は 02 が定める) |
| FR-env-03-4 | 正常系 | WHILE コンテナが稼働している間、システムは**セッションと設定をコンテナ固有に保たなければならない**(別プロジェクトのコンテナから見えず、混ざらないこと。どのファイルがこれに当たるかは 02/03 が定める) |
| FR-env-03-5 | 正常系 | WHEN `claude-dev logout` を実行したとき、システムは共有ボリュームの認証情報を削除し、**管理ラベルを持つ**実行中コンテナを削除しなければならない(共有ボリューム全体を空にするため Claude Code と Codex CLI 双方の認証が消える)。**管理ラベルを持たない実行中コンテナは停止も削除もせず、受入基準17 に従って名前を表示して残す** |
| FR-env-03-6 | 正常系 | WHEN `claude-dev login-codex` を実行したとき、システムは一時コンテナでデバイス認証を行い、完了後に **codex の認証情報を、Claude の認証と混ざらない形で共有ボリュームへ保存**しなければならない(保存する対象と置き場は 02/03 が定める) |
| FR-env-03-7 | 正常系 | WHEN コンテナを起動したとき、システムは **codex を再ログインなしで使える状態にしなければならず、その認証の実体はプロジェクトディレクトリ配下に置かれなければならない**(利用者から見えるのはこの2つで、コピーと参照の方法は 02 が定める) |
| FR-env-03-8 | 正常系 | WHILE コンテナが起動している間、システムは**コンテナ内で更新された codex の認証を、次に起動するコンテナから使える状態へ反映**しなければならない(トークンリフレッシュの伝播。反映の周期は 02 が定める) |
| FR-env-03-9 | 正常系 | WHILE コンテナが稼働している間、システムは **codex の設定とセッション履歴をコンテナ固有に保たなければならない**(別プロジェクトのコンテナと混ざらないこと。どのファイルがこれに当たるかは 02/03 が定める) |
| FR-env-03-10 | 境界値 | IF 共有ボリューム側に codex 認証が存在しないならば、システムは何もコピーせずに起動を完了しなければならない(未ログインのままコンテナを使える) |
| FR-env-03-11 | 境界値 | IF 共有された認証をコンテナ内ユーザーの権限では読み書きできない状態であるならば、システムは**その状態を解消してから処理を進めなければならない**(握りつぶして先へ進んではならない。解消の方法は 02/03 が定める) |
| FR-env-03-12 | 異常系 | IF 利用者が認証を完了せずにログイン操作を終えたならば、システムは共有ボリュームを変更してはならない(次回起動は未ログインのままとなる) |
| FR-env-03-13 | 異常系 | IF ログイン操作が端末を持たない環境で実行されたならば、システムは非0の終了コードで失敗しなければならない(黙って未認証のまま成功を返さない) |

| FR-env-03-22 | 正常系 | WHILE `claude-dev reset` を実行している間、システムは**プロジェクトディレクトリ配下のファイル**(利用者が置いた設定と、起動時にコピーされた認証。対象は 02/03 が定める)を削除してはならない(`reset` は対象を絞る引数を持たず、どのディレクトリを触るべきか決められないため。`logout` との非対称は `D0-env-08` 項4 が明示する) |
| FR-env-03-23 | 異常系 | IF `logout` または `reset` が削除の途中で `INT` または `TERM` を受けたならば、システムは**進行中の1件を終えてから中断**し、**そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙**して**終了コード 130** で終わらなければならない。**「削除しました」「完了」と表示してはならない**(1件の削除を途中で切ると、より中途半端な状態が残る。`D0-env-08` 項5 の「失敗を握りつぶさない」は中断時にも及ぶ) |
| FR-env-03-24 | 境界値 | IF `claude-dev logout` が Claude コンテナを削除したならば、システムは**そのコンテナが所有していたセッション由来の資源を、以後の `claude-dev stop` の削除対象にしてはならず**(所有者を照合する値が失われるため。`FR-env-01` 受入基準23 と同じ根拠)、**それらの資源は `claude-dev reset` でのみ削除できる状態にしなければならない**(`logout` 自身はセッション由来の資源を削除しない — `D0-env-05` 項2)。**この状態を「削除できなかった資源」として表示してはならない**(受入基準18 の対象ではない。意図して範囲の外に置いたものである) |
