# 機能要件

条項 ID(`FR-<domain>-nn-#`)は**一度振ったら動かさない**: 欠番を埋めない・並べ替えない・廃止した番号を別の基準に再利用しない(02 のカバレッジ表・03 のテスト対応表・`docs/pendings.md` が外部から参照するため。検査は CS16)。

## FR-env-01 コンテナのライフサイクル管理

- 対応要求: RQ-env-01 / AC-01
- **分割可否: 段階可(理由: 段階的に近づくのは条項 `FR-env-01-19`(別ディレクトリの compose 資源を巻き込まない)だけである。compose 資源をプロジェクトごとに一意にしなければ**全プロジェクトが同じ名前を共有して必ず巻き込む**のに対し、一意化が部分的でも取り違えの余地が減った分だけ利用者の作業が守られる。判断の記録は `D1-split-01`。**他の 33 条項は不可分**)**
- 内容: プロジェクトごとに隔離コンテナを起動・再接続・停止・一覧できること。SSH 切断後も作業が
  維持されること。**破壊的操作(`stop` / `logout` / `reset`)が他プロジェクトの資源を巻き込まないこと**
  (`D0-env-08`。共有 docker-proxy と共有ネットワークを残す条件は受入基準9)。
  **共有ボリュームまたは docker-proxy を触るサブコマンドが互いに排他されること**(同項6)。
  **`stop` と `reset` が、そのセッションのコンテナ内から作られた資源(セッション由来の資源)を
  片付けること**(`D0-env-05` 項2。どの資源を対象とするかは `D0-env-08` 項8。**識別の方法は
  02 の契約が定める**)。**名前付きボリュームは既定では消さず、利用者が明示したときだけ消すこと**
  (同項2。明示の手段と、残っていることの示し方は受入基準28〜33 が定める)。

| 条項 ID | 種別 | 基準 |

| FR-env-01-4 | 正常系 | WHEN 同一ディレクトリで `claude-dev start` を再実行したとき、システムは既存コンテナへ再接続しなければならない(tmux セッションが無ければ再作成する) |

| FR-env-01-8 | 境界値 | IF 停止対象のコンテナが存在しないならば、システムは削除をスキップし、その旨を表示して終了コード 0 で終わらなければならない |

| FR-env-01-10 | 異常系 | IF 実行に必要な前提コマンドが不足しているならば、システムは**不足しているものを列挙して導入方法を案内**し、終了コード 1 で終わらなければならない(どのコマンドが前提かは 02 が定める。OS によって異なる) |
| FR-env-01-11 | 異常系 | IF compose 既定ネットワークが他から使用中で削除できないならば、システムは処理を続行しなければならない(停止全体を失敗させない。これは `D0-env-08` 項5 が明示する例外である) |
| FR-env-01-12 | 異常系 | IF `claude-dev start` のコンテナ作成が**同名のコンテナが既に存在すること**を理由に失敗したならば、システムはその既存コンテナを削除してはならず、**同名のコンテナが稼働中であること**と**別ディレクトリの同名プロジェクトである可能性**を表示して、終了コード 1 で終わらなければならない(再試行してはならない) |
| FR-env-01-13 | 境界値 | IF コンテナ作成の失敗後に後片付け(作りかけのコンテナの削除)を行うならば、システムは対象が稼働中でないことを確かめてから削除しなければならない。**稼働中のコンテナは、作成の失敗理由を問わず削除してはならない** |
| FR-env-01-14 | 正常系 | WHEN `claude-dev start` が Claude コンテナを作成するとき、システムは本システムが作ったことと起動元のホスト側絶対パスを示す**管理ラベル**を付与しなければならない(名前と値は 02 の契約が定める。**固定名または固定接頭辞を持つ資源にはラベルを付けない**。名前で所有権が読み取れるため。**名前から所有権が読み取れない資源へのラベル付与は、Claude コンテナについては本基準が、セッション由来の資源については `FR-env-07` 受入基準11 が定める**) |
| FR-env-01-15 | 境界値 | IF `claude-dev stop <name>` の対象コンテナが管理ラベルを持たないならば(管理ラベルが付く前に起動されたコンテナなど)、システムはそのコンテナを削除しつつ、**管理ラベルを持たないことを表示**しなければならない(名前で1件を指した削除は `D0-env-08` 項1 の例外である) |
| FR-env-01-16 | 異常系 | IF `start` / `stop` / `logout` / `reset` / `login` / `login-codex` のいずれかが、同じプロジェクト名または同じ共有資源(共有ボリューム・docker-proxy)を対象として既に実行中ならば、システムは**待たずに**、**保持している操作の名前と、その保持者を利用者が特定できる情報**、および再実行の方法を表示して終了コード 1 で終わらなければならない(`D0-env-08` 項6 の「誰が保持しているか」。**保持者をどう表すかは 02/03 が定める**)。**このとき、取得できなかったロックが守る資源に対する削除も作成も行ってはならない**(プロジェクト単位のロックが守るのは当該コンテナとそのプロジェクト配下の生成物、共有資源単位のロックが守るのは共有ボリューム**の中身**・docker-proxy・**共有ボリュームを読んで作られたコンテナ**である。**冪等に作られる共有資源の「用意」は保護対象ではない**: イメージのビルドと、共有ネットワーク・共有ボリュームそのものの作成。既に在れば何も起きず、無いときに作られるのは中身の無い器だけであるため) |
| FR-env-01-17 | 境界値 | IF 排他のためのロックが、既に存在しないプロセスに保持されたまま残っているならば、システムはその事実を表示してからロックを引き継いで処理を続行しなければならない(永久に取得できない状態を作ってはならない) |
| FR-env-01-18 | 境界値 | IF `claude-dev stop <name>` の `<name>` が `[A-Za-z0-9._-]` 以外の文字を含むならば、システムは**何も削除せず**、受理できない文字を含むことを表示して終了コード 1 で終わらなければならない(排他のロックはこの名前をパス要素として使うため、`/` や `..` を含む名前を受理してはならない) |
| FR-env-01-19 | 境界値 | IF 別のディレクトリで起動されたセッションの compose 資源が存在するならば、`stop` はそれを削除してはならない。**起動ディレクトリ名が正規化後に一致する場合も削除してはならない**(compose 資源をプロジェクトごとに一意にする方法は 02 の契約が定める) |
| FR-env-01-20 | 境界値 | IF 本要件の一意化より前に起動された compose 資源が残っているならば、`stop` はそれを削除してはならず、**残っている可能性と手動で片付ける方法を表示**しなければならない(旧い名前は別ディレクトリと衝突しうるため対象に含めない) |
| FR-env-01-21 | 境界値 | IF `claude-dev stop <name>` の対象コンテナから**起動元ディレクトリを読み取れない**(管理ラベルを持たない、または既に存在しない)ならば、システムは**compose 資源の削除を行ってはならず**、compose 資源が残っている可能性と手動で片付ける方法を表示しなければならない(compose 資源をそのプロジェクトのものと決めるにはこの値が要り、他に復元する手段が無い。**推測して削除すると別ディレクトリを巻き込む**。値の持ち方は 02 の契約が定める) |
| FR-env-01-22 | 正常系 | WHEN `claude-dev stop [NAME]` を実行したとき、システムは**当該セッションのコンテナ内から docker-proxy を経由して作られたコンテナとネットワーク**(用語集「セッション由来の資源」)**のうち、所有者ラベルを持つものすべて**を削除しなければならない。**経路が `docker run` / `docker create` / `docker compose up` のいずれであるかを問わない**。**イメージは削除してはならない。名前付きボリュームは受入基準28〜31 が定める条件でのみ削除してよい**。**所有者ラベルを付与できなかった資源は対象外である**(`FR-env-07` 受入基準12 が定める経路で作られたもの。所有者を知る手段が無い)。**所有者の識別方法は 02 の契約が定める**(`D0-env-05` 項2 / `D0-env-08` 項8) |
| FR-env-01-23 | 境界値 | IF `claude-dev stop <name>` の対象コンテナから**起動元ディレクトリを読み取れない**(管理ラベルを持たない、または既に存在しない)ならば、システムは**セッション由来の資源の削除を行ってはならない**(所有者を表す値を他に復元する手段が無く、推測して削除すると別セッションの資源を巻き込む。受入基準21 と同じ根拠である) |
| FR-env-01-24 | 異常系 | IF **`claude-dev stop` が**セッション由来の資源の削除に失敗したならば、システムは処理を続行しなければならない(受入基準11 と同じ扱いであり、`D0-env-08` 項5 の「消えなかった資源を列挙して終了コード 1 で終わる」の対象外である)。**`claude-dev reset` はこの基準の対象ではなく、`FR-env-03` 受入基準18 に従って消えなかった資源を列挙し終了コード 1 で終わらなければならない**(`D0-env-08` 項5 は `logout` / `reset` を対象とし、`stop` だけを例外としている) |
| FR-env-01-25 | 正常系 | WHEN `claude-dev reset` を実行したとき、システムは**所有者を問わずすべてのセッション由来の資源**を削除対象に含め、`FR-env-03` 受入基準14 の削除前の確認の列挙にも表示しなければならない(削除できなかった場合の扱いは `FR-env-03` 受入基準18 に従う)。**名前付きボリュームは受入基準32・33 が定める条件でのみ削除してよい**(受入基準22 と同じ但し書きである) |
| FR-env-01-26 | 正常系 | WHEN `stop` または `reset` がセッション由来の資源を削除したとき、システムは削除した資源の名前を**種別(コンテナ / ネットワーク / ボリューム)とともに1行ずつ**表示しなければならない(`D0-env-08` 項3 が `stop` に確認を求めない代わりの観測点である) |
| FR-env-01-27 | 境界値 | IF セッション由来の資源が1件も無いならば、システムはそれに関する表示を行ってはならない(対象が無いことを毎回表示しない) |
| FR-env-01-28 | 正常系 | WHERE `claude-dev stop` に `--volumes` が指定された場合、システムは受入基準22 と同じ所有者の照合で、そのセッションが作った**名前付きボリューム**を削除しなければならない。**名前を指定せずに作られたボリューム(匿名ボリューム)は、それを抱えるセッション由来のコンテナの削除にともなって削除しなければならない**(所有者を示す印を付けられないため。手段は 02 の契約が定める)。削除した名前付きボリュームの名前は**種別つきで1行ずつ**表示しなければならない(受入基準26 と同じ観測点である) |
| FR-env-01-29 | 正常系 | IF `--volumes` が指定されず、かつそのセッションが作った名前付きボリュームが1件以上残っているならば、システムはそれを**削除してはならず**、**残っているボリュームの名前と、削除する方法**を表示しなければならない(既定で消さないことと、残っていることを伏せることは別である)。**名前を指定せずに作られたボリュームはこの表示の対象外である** [DS-04] 匿名ボリュームを表示しない — 理由: 名前が自動生成の 64 桁の文字列で、利用者はそれを見ても何のデータか見分けられず、行が増えるだけで判断の材料にならない / 見直す条件: 匿名ボリュームを利用者が見分けられる手掛かり(紐づくコンテナ名など)を表示できるようになったとき |
| FR-env-01-30 | 境界値 | IF そのセッションが作った名前付きボリュームが1件も無いならば、システムはそれに関する表示を行ってはならない(受入基準27 と同じ。対象が無いことを毎回表示しない) |
| FR-env-01-31 | 境界値 | IF `claude-dev stop <name>` の対象コンテナから**起動元ディレクトリを読み取れない**ならば、システムは名前付きボリュームの削除も行ってはならない(受入基準23 と同じ根拠。所有者を照合する値を他に復元する手段が無く、推測して削除すると別セッションのデータを失う) |
| FR-env-01-32 | 正常系 | WHERE `claude-dev reset` に `--volumes` が指定された場合、システムは**所有者を問わずすべてのセッション由来の名前付きボリューム**を削除対象に含め、`FR-env-03` 受入基準14 の削除前の確認の列挙にも表示しなければならない(受入基準25 と同じ扱い) [DS-04] `reset` にも `stop` と同じ明示を求める — 理由: 既定で消さないという判断は**資源の種類**についてのものであり、操作ごとに変えると「どの操作なら消えるか」を利用者が覚えることになる / 見直す条件: `reset` の意味を「ホスト全体を初期状態へ戻す」から変えるとき |
| FR-env-01-33 | 境界値 | IF `claude-dev reset` に `--volumes` が指定されなかったならば、システムはセッション由来の名前付きボリュームを削除してはならず、**残したことと、完全な初期化になっていないこと**を表示しなければならない(受入基準9 が共有資源について課すのと同じ表示である) |
| FR-env-01-34 | 異常系 | IF 削除しようとした資源が**そもそも存在しなかった**ならば、システムはそれを「削除できなかった資源」として表示してはならない(存在しないことと削除に失敗したことは別であり、利用者は前者を片付けの失敗と読む) |

## FR-env-02 UID/GID 追従とホスト資産の共有

- 対応要求: RQ-env-01 / AC-01
- **分割可否: 不可分**
- 内容: コンテナ内のファイル所有権がホストと一致し、git 設定とシェル資産を引き継げること。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-02-1 | 正常系 | WHEN コンテナを起動したとき、システムはコンテナ内ユーザーの UID/GID を `/workspace` の所有者に一致させなければならない |
| FR-env-02-2 | 正常系 | WHERE ホストに `~/.gitconfig` が存在する場合、システムはそれを読み取り専用でマウントしなければならない |
| FR-env-02-3 | 正常系 | WHILE コンテナが稼働している間、システムはシェル設定をコンテナ間で共有し、コマンド履歴を**コンテナを削除しても失われない形で**永続化しなければならない(どの資源に置くかは 02 が定める) |
| FR-env-02-4 | 境界値 | IF 割り当てようとする UID/GID がコンテナ内の既存エントリと衝突するならば、システムは**衝突を解消したうえで割り当てなければならない**(解消の方法は 02/03 が定める。**起動は成功する**) |
| FR-env-02-5 | 境界値 | IF `/workspace` の所有者が root(UID 0)ならば、システムは UID/GID を変更してはならない |
| FR-env-02-6 | 異常系 | IF ホストの設定ファイルが存在しないならば、システムはその項目をマウントせずに起動を続行しなければならない(起動を失敗させない) |

## FR-env-03 認証の共有とセッション分離

- 対応要求: RQ-env-03 / AC-01 / AC-06
- **分割可否: 不可分**
- 内容: 一度のログインで全コンテナが認証を共有し、セッションと設定はコンテナごとに独立すること。
  同梱する両方のエージェント CLI(Claude Code / Codex CLI)について成り立つこと。
  **認証を削除する操作(`logout` / `reset`)が、確認なしに他プロジェクトの作業を落としたり、

## FR-env-07 Docker アクセスの制限

| FR-env-13-6 | 異常系 | IF 用意された同梱外部バイナリの設置に失敗したならば、システムは**イメージのビルドを失敗させなければならない**(設置されないまま完了したイメージを公開してはならない) [DS-02] 設置の失敗を握りつぶさない — 理由: 欠けたイメージが公開されると、利用者はコマンドが見つからない理由に到達できず、公開したものは回収できない(`D0-dist-05` 項2)/ 見直す条件: 同梱物が任意であることを利用者が実行時に判別できる手段ができたとき |

## FR-env-14 プロジェクトごとの環境変数の受け渡し

- 対応要求: RQ-env-07 / AC-08
- **分割可否: 不可分**(理由: 渡せる変数と渡せない変数が混ざる状態は、利用者から見て「書いた値が
  効いているかどうか分からない」状態であり、何も渡さない状態より価値が高いとは言えない)
- 内容: プロジェクトごとに用意した**プロジェクト環境ファイル**(用語集)の内容を、そのプロジェクトの
  コンテナへ環境変数として渡せること。**秘密の値が版管理へ入らないこと**(`D0-sec-11`)。
  **本システム自身が使う名前を利用者の指定で差し替えられないこと**
  (`request.md`「やらないこと」7)。**指定の書式と、本システムが使う名前の集合は 02 の契約が定める。**

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-14-1 | 正常系 | WHERE プロジェクト直下の設定でプロジェクト環境ファイルの場所が指定された場合、システムはそのファイルに書かれた組を、そのプロジェクトのコンテナへ環境変数として渡さなければならない(設定の置き場・指定の書式・ファイルの書式は 02/03 が定める) |
| FR-env-14-2 | 正常系 | WHILE コンテナが稼働している間、システムは渡した環境変数を**そのプロジェクトのコンテナの中だけ**で見える状態に保たなければならない(別プロジェクトのコンテナからは見えない) |
| FR-env-14-3 | 正常系 | WHEN プロジェクト環境ファイルを渡して起動したとき、システムは**渡した値そのものを端末にも起動ログにも常駐プロセスのログにも出力してはならない**(`D0-sec-11` 項4。名前を出すことは許す。値を出さない規則の正は 02 のログ仕様である) |
| FR-env-14-4 | 正常系 | WHEN プロジェクト環境ファイルの場所が指定されたとき、システムはそのファイルを**版管理の追跡から外さなければならない**。外せなかった場合は、外せなかったことを表示して起動を続けなければならない(`D0-sec-11` 項2) |
| FR-env-14-5 | 境界値 | IF プロジェクト直下の設定にプロジェクト環境ファイルの指定が**無い**ならば、システムは環境変数を渡さずに起動しなければならず、**そのことを表示してはならない**(指定していないことは正常な省略であり、毎回表示しない) |
| FR-env-14-6 | 異常系 | IF 指定されたプロジェクト環境ファイルが**存在しない**ならば、システムは環境変数を渡さずに起動を続け、**そのファイルを読めなかったことを表示**しなければならない(起動を止めない) [DS-02] 起動を止めずに続行する — 理由: 補助機能の失敗が主機能(コンテナ起動)を止めないことは本システムの一貫した倒し方であり、`NFR-avail-03` がその成功率を 100% と定めている / 見直す条件: 環境変数が渡らないまま起動して利用者が気づけない事故が観測されたとき |
| FR-env-14-7 | 境界値 | IF プロジェクト環境ファイルに**組として解釈できない行**が在るならば、システムはその行だけを採用せず、**採用しなかった行が何行目か**を表示して、残りの行で起動を続けなければならない |
| FR-env-14-8 | 境界値 | IF プロジェクト環境ファイルに**本システムが使う名前**が書かれているならば、システムはその1件だけを採用してはならず、**採用しなかった名前**を表示して起動を続けなければならない(どの名前が本システムのものかは 02 の契約が定める。理由は `request.md`「やらないこと」7 が持つ) |
| FR-env-14-9 | 境界値 | IF 指定された場所が**プロジェクトディレクトリの外**を指すならば、システムはその指定を採用してはならず、受理しないことと受理する範囲を表示して、環境変数を渡さずに起動を続けなければならない [DS-04] 受理する範囲をプロジェクトディレクトリの中に限る — 理由: 外を指せるとコンテナへ渡る値の出どころがプロジェクトの外に散り、`D0-sec-11` 項2 の「版管理の追跡から外す」が効かない / 見直す条件: 複数プロジェクトで1つのプロジェクト環境ファイルを共有したいという要望が出たとき |
| FR-env-14-10 | 異常系 | IF 同じ名前が**2回以上**書かれているならば、システムは**後に書かれたほうを採用**し、採用しなかった名前を表示しなければならない [DS-04] 後勝ちにする — 理由: 利用者が1つのファイルを編集して値を差し替える使い方でそのまま動き、行を消し忘れても最後に書いた値が効く / 見直す条件: 複数のプロジェクト環境ファイルを指定できるようにするとき(ファイルをまたぐ優先順を別に決める必要が生じる) |
