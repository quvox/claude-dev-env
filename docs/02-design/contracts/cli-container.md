# CTR-cli-container ホスト CLI → コンテナ/entrypoint

- 当事者: MOD-cli-start(および同じ起動経路を使う MOD-cli-code / MOD-cli-orchestrate) → MOD-entrypoint
- 対応要件: FR-env-01, FR-env-02, FR-env-03, FR-env-05, FR-env-06, FR-env-07, FR-env-08, FR-env-11, FR-env-12
- 責任モジュール(結合テスト): MOD-entrypoint

## 渡す環境変数

**真偽を表す変数は厳密一致で判定する**が、**既定が有効か無効かで見る値が違う**: 既定が無効のものは
**`1` に厳密一致したときだけ有効**(`true` / `yes` / `TRUE` は無効)、既定が有効のものは
**`0` に厳密一致したときだけ無効**(それ以外の任意の値は有効のまま)。どちらに属するかは下表の
「型・値域」に書く。判定はすべて受け側(entrypoint)が行い、**値の検証で起動を止めることはしない**。

| 変数 | 型・値域 | 付与するのは誰か | 必須 | 既定値 | 想定外の値のときの扱い |
|---|---|---|---|---|---|
| `DOCKER_HOST` | `tcp://<ホスト名>:<ポート>` 形式の URL | CLI(ホストに Docker ソケットがあるときだけ) | 条件付き | 付与しない | 形式を検証しない。到達できなければコンテナ内から Docker が使えないだけで、起動は続く。**VM モードでは entrypoint が上書きする** |
| `COMPOSE_PROJECT_NAME` | 小文字英数と `_` `-` のみ | CLI | **必須** | 起動ディレクトリ名を**小文字化してから**正規化した値(`[a-z0-9_-]` 以外の1文字を `-` に置換) | 付与しない経路が無いので発生しない。**正規化の結果が衝突しうる**(例: 大文字違いだけのディレクトリ名は同じ値になる) |
| `CLAUDE_DEV_VM` | `1` のみが有効 | CLI(VM モード指定時) | 任意 | 付与しない(= 無効) | **`1` 以外はすべて無効**として扱う |
| `VM_PORTS` / `VM_MEM` / `VM_SMP` / `VM_DISK` / `VM_SWAP` | 文字列(ゲスト VM のパラメータ) | CLI(VM モードで、かつホスト側の同名変数が空でないときだけ転送) | 任意 | 付与しない(ゲスト側の既定に従う) | 値を検証しない。ゲスト VM の起動に失敗した場合は VM 無しで続行する |
| `CLAUDE_DEV_DOOD_PORTSYNC` | `0` で無効、それ以外は有効 | 利用者(CLI は付与しない) | 任意 | 未設定 = 有効 | **`0` の厳密一致のときだけ無効**。他の値は有効として扱う |
| `CLAUDE_DEV_VNC` | `1` のみが有効 | **イメージの `ENV`**(CLI は付与しない) | 任意 | ブラウザ確認資産を含むイメージでは `1` | `1` 以外はすべて無効として扱う |
| `CLAUDE_DEV_SSH_BRIDGE_PORT` | ポート番号の文字列 | CLI(**macOS のみ**) | 条件付き | 付与しない | **範囲も数値かどうかも検証しない。** 非空なら TCP ブリッジの接続先として使う。ソケットが用意できなくても起動は続く |
| `SSH_AUTH_SOCK` | コンテナ内の固定パス | CLI(**Linux のみ**、ホストに agent ソケットがあるとき) | 条件付き | 付与しない | 受け側はソケットの実在で判定する。無ければ agent 転送なしで続行する |
| `NODE_OPTIONS` | Node の起動オプション文字列 | CLI | **必須** | `--max-old-space-size=4096` | 付与しない経路が無い |
| `container` | `docker` | **イメージの `ENV`**(起動時ではない) | **必須** | `docker` | コンテナ内であることの判定マーカー。上書きは想定しない |

**VM モードと DooD ポート同期は排他**である: VM モードのときポート同期は起動しない
(ポート同期はホスト共有 daemon 経路のときだけ意味を持つため)。

## 渡すマウント

| マウント元 | マウント先 | モード | 必須 | 付与する条件 |
|---|---|---|---|---|
| カレントディレクトリ | `/workspace` | 読み書き | **必須** | 常に。ここの所有者が UID/GID 追従の基準になる |
| 共有ボリューム(認証) | ホームディレクトリ配下の共有先 | 読み書き | **必須** | 常に。認証の受け渡しと書き戻しに使う。**Codex の認証も同じボリュームの `codex/` に相乗りする**(`D0-auth-01`) |
| 共有ボリューム(シェル設定) | 同上 | 読み書き | **必須** | 常に |
| 共有ボリューム(コマンド履歴) | 同上 | 読み書き | **必須** | 常に |
| tmux 設定 | ホームディレクトリ配下の固定パス | 読み取り専用 | **必須** | 常に |
| キット同梱の `CLAUDE.md` | ホームディレクトリ配下の固定パス | 読み取り専用 | **必須** | 常に |
| ホストの git 設定(`~/.gitconfig`) | コンテナ内の同名パス | 読み取り専用 | 任意 | **ファイルとして存在するときだけ** |
| ホストの gh 設定(`~/.config/gh`) | コンテナ内の同名パス | 読み取り専用 | 任意 | **ディレクトリとして存在するときだけ**。読み取り専用なのでホストの認証は書き換わらない |
| SSH agent ソケット | コンテナ内の固定パス | 読み取り専用 | 任意 | Linux で agent のソケットが存在するときだけ。**秘密鍵ファイルは渡さない** |
| `~/.ssh/known_hosts` | コンテナ内の同名パス | 読み取り専用 | 任意 | ファイルとして存在するときだけ |
| `~/.ssh/config` を加工した一時コピー | コンテナ内の同名パス | 読み取り専用 | 任意 | ファイルとして存在するときだけ。**`IdentityFile` / `IdentitiesOnly` / `IdentityAgent` の行を除去**してから渡す(コンテナ内に鍵ファイルが無く、ホスト固有の agent パスは agent を不通にするため) |
| ブラウザプロファイル用ボリューム | ホームディレクトリ配下 | 読み書き | 任意 | ブラウザ確認資産を使うときだけ |
| ゲスト VM 用ボリューム | ホームディレクトリ配下 | 読み書き | 任意 | VM モードのときだけ。**プロジェクトごとに別ボリューム**にして同時起動の競合を避ける |

## 渡す起動オプション

| 項目 | 値 | 必須 | 理由 |
|---|---|---|---|
| 実行形態 | デタッチ(`-d`)+ 疑似 TTY 割り当て | **必須** | 常駐させ、後から接続する |
| コンテナ名 / ホスト名 | 起動ディレクトリ名から決めた同一の名前 | **必須** | 名前で再接続する |
| ネットワーク | キット専用のユーザー定義ネットワーク | **必須** | docker-proxy と名前解決で繋ぐ |
| 追加ケーパビリティ | ネットワーク管理に必要なもの(`NET_ADMIN` / `NET_RAW`)のみ | **必須** | ファイアウォールを適用するため |
| `--security-opt` | **付けない** | — | Docker 既定の seccomp / AppArmor を有効なまま使う(`NFR-sec-01`) |
| 再起動ポリシー | 明示的に停止するまで再起動 | **必須** | SSH 切断でコンテナを失わない |
| 公開ポート | ブラウザ確認資産を使うときだけ、空きポート → 固定のコンテナ側ポート | 任意 | 同時起動で衝突させない |
| デバイス | CPU 仮想化・高速ネットワーク・TUN/TAP のうち**ホストに実在するものだけ** | 任意 | 明示指定時のみ。存在しないデバイスは黙って外す。**CPU 仮想化デバイスの扱いは指定の仕方で分かれる**: デバイスを渡すだけの指定なら警告して続行し、**VM モードの指定なら中止する**(下の「エラーケース」参照) |

## 認証の受け渡し

- CLI が起動前に用意し、entrypoint が引き取る。
- Claude: 共有ボリューム直下 → プロジェクトディレクトリ配下の作業用ディレクトリ。
- Codex: 共有ボリュームの `codex/` → プロジェクトディレクトリ配下の作業用ディレクトリ。
- 共有ボリュームを増やさない(`D0-auth-01`)。所有者はホストの UID/GID に合わせる。

## エラーケース

| 条件 | 期待する振る舞い |
|---|---|
| 共有ボリュームに認証が無い | 何もコピーせず起動を完了する(未ログインのまま使える) |
| ホストの git 設定 / gh 設定が無い | そのマウントを省いて起動する |
| SSH 鍵が選択されていない | agent ソケットを渡さず、指定方法を案内して起動する |
| Docker ソケットが無い(macOS) | `DOCKER_HOST` を設定せずに起動する |
| 環境変数が想定外の値 | **上表の「想定外の値のときの扱い」に倒し、起動を止めない**。既定が無効の変数(`CLAUDE_DEV_VM` / `CLAUDE_DEV_VNC`)は無効のまま、既定が有効の変数(`CLAUDE_DEV_DOOD_PORTSYNC`)は**有効のまま**になる |
| 公開ポートが競合して起動に失敗した | ブラウザ確認資産を使う場合に限り、**稼働していない作りかけのコンテナだけを削除して**別のポートを取り直して再試行する(上限 20 回)。上限に達したか、競合以外の失敗なら、エラーを表示して終了コード 1 で終わる |
| **コンテナ名が衝突して起動に失敗した**(同名のコンテナが既に存在する) | **既存のコンテナを削除しない。** 同名のコンテナが稼働中であることと、別ディレクトリの同名プロジェクトである可能性を表示し、**再試行せずに**終了コード 1 で終わる。同名の稼働中コンテナは利用者の作業中セッションでありうるため、後片付けの対象にしてはならない |
| **CPU 仮想化デバイスを渡す指定(`--kvm`)をしたが、そのデバイスが無い** | **警告を出して続行する**(渡せるデバイスだけを渡す) |
| **VM モードの指定(`--vm` / `--vm-fresh`)をしたが、CPU 仮想化デバイスが無い** | **中止して終了コード 1 で終わる。** ソフトウェアエミュレーションでは実用的な速度が出ないため、VM 無しで続行させるのではなく、利用者に通常起動を選ばせる |
| ゲスト VM の**起動**に失敗した(デバイスはあるが provision / ブートが失敗) | **VM 無しで続行する**(起動そのものは失敗させない)。調査手段を案内する |
| 常駐セッションの起動が待ち時間内に完了しない | コンテナは起動したまま残し、状況と再実行の方法を案内して**終了コード 0** で戻る(黙って接続失敗にしない) |
| macOS で SSH の TCP ブリッジのソケットが用意できない | 待ち時間(最大 4 秒)を過ぎたら agent 転送なしで続行する |

## 設計判断

### DSN-auth-01 の適用

認証を**共有ボリュームからの symlink 参照ではなくコピー**で渡すのはこの契約の帰結である
(理由は `architecture.md` の `DSN-auth-01`)。コピー先はプロジェクトディレクトリ配下
(`/workspace/.claude/` `/workspace/.codex/`)で、**コンテナのホームからそのコピー先を symlink で
指すのは `DSN-auth-01` が定める形の一部である**(共有ボリュームを直接指すのではない)。
CLI は「置く」だけで、書き戻しは entrypoint の同期ループが担う。

## 順序性・冪等性・並行性の背景

- **冪等**: 同じディレクトリで再実行しても、再接続経路に入るため二重にコンテナを作らない。
- **並行**: 異なるディレクトリでの同時起動を前提とする。名前・ポート・プロファイルの一意化で
  衝突を避ける(`NFR-scale-01`)。空きポートの選定から起動までは原子的でないため、競合時は
  再試行で吸収する。

## 認可の考え方

ホスト CLI を実行できるユーザ(= ホストの Docker を操作できるユーザ)だけがこの契約を発行できる。
コンテナ内から本契約を書き換える経路は無い。
