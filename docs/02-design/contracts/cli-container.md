# CTR-cli-container ホスト CLI → コンテナ/entrypoint

- 当事者: MOD-cli-start(および同じ起動経路を使う MOD-cli-code / MOD-cli-orchestrate) → MOD-entrypoint
- 対応要件: FR-env-01, FR-env-02, FR-env-03, FR-env-05, FR-env-06, FR-env-07, FR-env-08, FR-env-11, FR-env-12
- 責任モジュール(結合テスト): MOD-entrypoint

## 渡す環境変数

| 変数 | 型・値域 | 必須 | 既定値 | 意味 |
|---|---|---|---|---|
| `DOCKER_HOST` | URL 文字列 | 条件付き必須(ホストに Docker ソケットがあるとき) | 設定しない | docker-proxy を指す。設定されない場合、コンテナ内から Docker は使えない |
| `CLAUDE_DEV_DOOD_PORTSYNC` | `0` / `1` | 任意 | `1` | DooD 経路のポート同期を起動するか |
| `CLAUDE_DEV_VM` | `0` / `1` | 任意 | `0` | VM モードで動作するか |
| `CLAUDE_DEV_VNC` | `0` / `1` | 任意 | イメージに応じて設定 | ブラウザ確認資産を起動するか |
| `CLAUDE_DEV_SSH_BRIDGE_PORT` | ポート番号 | 条件付き(macOS のみ) | なし | SSH agent の TCP ブリッジのポート |
| `COMPOSE_PROJECT_NAME` | compose 互換の名前 | 必須 | 起動ディレクトリ名を正規化した値 | プロジェクト間で compose 生成物を衝突させない |
| `container` | `docker` | 必須 | イメージに焼き込む | コンテナ内であることの判定マーカー |

## 渡すマウント

| マウント元 | マウント先 | モード | 必須 | 意味 |
|---|---|---|---|---|
| カレントディレクトリ | `/workspace` | 読み書き | 必須 | 作業対象。ここの所有者が UID/GID 追従の基準になる |
| 共有ボリューム(認証) | コンテナ内の共有先 | 読み書き | 必須 | 認証の受け渡し。書き戻し先でもある |
| 共有ボリューム(シェル設定 / 履歴) | 同上 | 読み書き | 必須 | コンテナ間で共有する |
| ホストの git 設定 | コンテナ内の同名パス | 読み取り専用 | 任意(存在するときのみ) | git の identity を引き継ぐ |
| SSH agent ソケット | コンテナ内の固定パス | 読み取り専用 | 任意(鍵が選択されているときのみ) | 秘密鍵ファイルは渡さない |

## 渡す起動オプション

| 項目 | 値 | 理由 |
|---|---|---|
| 追加ケーパビリティ | ネットワーク管理に必要なもののみ | ファイアウォールを適用するため |
| `--security-opt` | **付けない** | Docker 既定の seccomp / AppArmor を有効なまま使う(NFR-sec-01) |
| 再起動ポリシー | 明示的に停止するまで再起動 | SSH 切断でコンテナを失わない |

## 認証の受け渡し

- CLI が起動前に用意し、entrypoint が引き取る。
- Claude: 共有ボリューム直下 → プロジェクトディレクトリ配下の作業用ディレクトリ。
- Codex: 共有ボリュームの `codex/` → プロジェクトディレクトリ配下の作業用ディレクトリ。
- 共有ボリュームを増やさない(`D0-auth-01`)。所有者はホストの UID/GID に合わせる。

## エラーケース

| 条件 | 期待する振る舞い |
|---|---|
| 共有ボリュームに認証が無い | 何もコピーせず起動を完了する(未ログインのまま使える) |
| ホストの git 設定が無い | そのマウントを省いて起動する |
| SSH 鍵が選択されていない | agent ソケットを渡さず、指定方法を案内して起動する |
| Docker ソケットが無い(macOS) | `DOCKER_HOST` を設定せずに起動する |
| 環境変数が想定外の値 | entrypoint は既定値として扱い、起動を止めない |

## 設計判断

### DSN-auth-01 の適用

認証を symlink ではなくコピーで渡すのはこの契約の帰結である(理由は `architecture.md` の
`DSN-auth-01`)。CLI は「置く」だけで、書き戻しは entrypoint の同期ループが担う。

## 順序性・冪等性・並行性の背景

- **冪等**: 同じディレクトリで再実行しても、再接続経路に入るため二重にコンテナを作らない。
- **並行**: 異なるディレクトリでの同時起動を前提とする。名前・ポート・プロファイルの一意化で
  衝突を避ける(`NFR-scale-01`)。空きポートの選定から起動までは原子的でないため、競合時は
  再試行で吸収する。

## 認可の考え方

ホスト CLI を実行できるユーザ(= ホストの Docker を操作できるユーザ)だけがこの契約を発行できる。
コンテナ内から本契約を書き換える経路は無い。
