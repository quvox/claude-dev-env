# CTR-orchestrator-prompt orchestrator → worker / 対話 Claude

- 当事者: MOD-orchestrator → worker(非対話のエージェント)/ 対話 Claude
- 対応要件: FR-orch-01, FR-orch-03, FR-orch-04, FR-orch-05, FR-orch-06, FR-orch-08
- 責任モジュール(結合テスト): MOD-orchestrator

## 渡すもの

| 相手 | 渡し方 | 内容 |
|---|---|---|
| worker | 非対話実行の引数とプロンプト | タスクの完了条件・必要な文脈・作業ディレクトリ(git worktree)。**「必要な文脈」「構造化された結果」はフィールド単位で定義していない**(必須性・型・列挙値・欠落時の判定を本契約からは導出できない)。この深度不足は `docs/issues/004-modify-03-impl-lacks-reimplementation-depth.md` で追跡する。モデルと effort はポリシー表から決める |
| worker(再開時) | セッション ID を指定した再開 | 同一 Attempt の続きから再開する |
| 対話 Claude(ブレインストーミング / 介入) | システムプロンプトの追記 | イメージ同梱の指示テンプレート |
| 双方 | プロンプト先頭への前置 | リポジトリルートに `ORCHESTRATOR.md` があればその内容 |

## 受け取るもの

| 経路 | 内容 | 形式 |
|---|---|---|
| worker の出力 | 実装結果 | 構造化された結果。解釈できない場合は失敗として扱う |
| レビューの出力 | 判定と指摘 | 構造化出力(スキーマ強制)。散文で返った場合の再整形は1回まで |
| 制御ファイル | モードの引き渡しと介入回答 | 機械のみが読み書きする |

## エラーケース

| 条件 | 期待する振る舞い |
|---|---|
| worker の出力が期待する形式でない | 失敗として扱う(成功と解釈しない) |
| レビューが構造化出力で返らない | 1回だけ再整形を試みる。判定内容は変えない |
| 同一フォーマットエラーが2回続いた | 自動リトライを打ち切り、介入へ回す |
| 古い制御ファイルが残っている | 対話を起こす直前に破棄する(古い指示を誤って消費しない) |
| 通知トークン等の秘密情報 | 子プロセスの環境から除去する(worker と対話 Claude へ渡さない) |

## 設計判断

### DSN-prompt-01 指示テンプレートはイメージへ同梱し、プロジェクト側に置かない

- 判断: ブレインストーミング・介入・worker・レビューの指示テンプレートをイメージに同梱し、プロジェクトの
  リポジトリには置かない。プロジェクト固有の方針だけを `ORCHESTRATOR.md` として前置する。
- 理由: テンプレートをプロジェクトに置くと、プロジェクトごとに古い版が残り、挙動が揃わなくなる。
  一方でプロジェクト固有の方針は必要なので、前置という限定した口を1つだけ開ける。
- 却下した案: すべてプロジェクト側に置く — 版が揃わない。前置の口も設けない — プロジェクト固有の
  制約を伝えられない。

### DSN-prompt-02 採点基準はタスクの完了条件のみとする

- 判断: レビューの採点をタスクの完了条件だけで行い、プラン全体のゴールへフォールバックしない。
- 理由: 基準が曖昧になると差し戻しが恣意的になり、改訂ループが終わらない。
- 却下した案: ゴールでも採点する — 個々のタスクでは達成しえない基準で不合格が出る。

## 順序性・冪等性・並行性の背景

- **並行**: worker は並行に走る。統合(マージ)はコントローラが直列に行う。
- **順序**: 介入の突合は実行中の実体に対して行う(ディスクの別コピーに対して行うと乖離して
  実行が恒久停止する)。
- **冪等**: 同一 Attempt の再開は、完了済みのタスクを再実行しない。

## 認可の考え方

プロンプトを組み立てるのはコントローラだけである。worker と対話 Claude は指示の受け手であり、
通知や状態更新の発信源にはしない(`NFR-sec-03`)。
