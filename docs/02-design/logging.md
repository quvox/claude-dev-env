# ログ戦略・ログ仕様

本システムのログは性格の異なる2種類がある。**利用者向けの端末出力**(ホスト CLI・entrypoint)と、
**常駐プロセスのログ**(docker-proxy)である。出力先も寿命も違うため、まとめて1つの基盤に載せない。

## ログレベルの定義と使い分け

| レベル | 何を出すか | 出さないもの |
|---|---|---|
| ERROR | 処理を続けられず終了する失敗。原因と、利用者が次に取るべき操作をセットで出す | 想定内の分岐(対象が無い・未ログイン・鍵が未選択) |
| WARN | 主機能は続くが、期待した状態になっていないこと(ファイアウォールの適用失敗、既定設定の補完失敗、補助情報の取得失敗、到達性スモークテストの想定外) | 正常な省略(存在しない任意ファイルを飛ばした等) |
| INFO | 利用者が状況を追うために必要な進捗(使用イメージとバージョン、接続 URL、割り当てたポート、待機の経過) | 内部の関数呼び出し |
| DEBUG | 開発時の調査用。既定では出さない | 常時出力 |

**利用者向けの端末出力は日本語**とする(`NFR-ops-05`)。常駐プロセスのログは機械可読性を
優先する。

## 出力先と保持期間

| 環境 | 出力先 | 形式 | 保持期間 |
|---|---|---|---|
| ホスト CLI | 標準出力 / 標準エラー | テキスト(日本語) | 残さない(端末の履歴のみ) |
| entrypoint(コンテナ起動時) | コンテナの標準出力(`docker logs` で参照) | テキスト(日本語) | コンテナの寿命と同じ |
| docker-proxy | コンテナの標準出力 | テキスト | コンテナの寿命と同じ(共有常駐のため全プロジェクト分が混ざる) |

## 出してはならない情報

- 認証情報の中身: OAuth の資格情報、`auth.json` の中身、API キー。
  **存在するかどうか・どこに置いたかは出してよい**が、値は出さない。
- **プロジェクト環境ファイルに書かれた値**(`FR-env-14-3`)。**名前は出してよい**
  — 採用しなかった名前を利用者へ示すのに要る。**値は、採用したものも採用しなかったものも出さない**
  (この置き場は秘密の値の置き場だと `D0-sec-11` 項1 が定めており、名前だけでは中身が漏れない)。
- SSH の秘密鍵の内容。鍵の**名前**は選択の案内に必要なので出してよい。
- ホストの絶対パスのうち、利用者のホームディレクトリ配下の構造。**「必要な範囲」の判定と、
  それを超える例は「主要イベントのログ仕様」の「起動ディレクトリの絶対パスの扱い」が定める**
  (利用者が次に取るべき操作を決めるために必要なパスは出す。無関係なディレクトリの列挙・
  ホーム配下の探索結果・削除対象でないパスの表示は出さない)。

## 主要イベントのログ仕様

| イベント | レベル | 出力内容 | 対応要件 |
|---|---|---|---|
| コンテナ起動の開始 | INFO | 使用イメージ名とバージョン | FR-env-01 |
| **コンテナ名の衝突による起動の中止** | ERROR | 同名のコンテナが稼働中であること、別ディレクトリの同名プロジェクトである可能性、次に取るべき操作(そのディレクトリで再接続するか、`stop` してから起動し直すか)。**既存のコンテナには触れていないことが分かる表現にする**。管理ラベル `claude-dev.project-dir` があれば、可能性ではなく**どのディレクトリで起動されたかという事実**を出す | FR-env-01(受け入れ基準12) |
| **排他ロックを取得できず中止** | ERROR | 保持している**操作名**と**プロセス ID**、再実行の方法。**削除も作成も行っていないことが分かる表現にする**。待たずに終わったことを示す(固まっていない) | FR-env-01(受け入れ基準16) |
| **ロック残骸の引き継ぎ** | WARN | 残っていたロックの操作名と PID、引き継いで処理を続けること。**処理は中断しない** | FR-env-01(受け入れ基準17) |
| **破壊的操作の削除対象の確認** | INFO | **削除する資源を種別ごとに**1行ずつ列挙し、共有ボリュームの認証が消えることを明示して同意を求める。同意が得られなければ**何も削除せずに終わったことが分かる表現**を出して終了コード 0。**この行が列挙対象の全体の正である**(`FR-env-03` 受入基準14 がここを指す)。**`logout` が列挙するもの**: 削除対象の Claude コンテナ名 / プロジェクト配下の認証ファイルのパス。**`reset` が列挙するもの**: 削除対象の Claude コンテナ名 / `fwd-*` 中継コンテナ / **セッション由来の資源(コンテナ / ネットワークの種別つき。削除を明示する指定があるときは名前付きボリュームも同じ種別つきで含める — `FR-env-01-32`)** / 共有ボリューム(`claude-dev-auth` / `-history` / `-config` / `claude-dev-chrome-*` / **`claude-dev-vm-*`**)/ イメージ3本 / **docker-proxy と `claude-dev-net`(「遊休のときだけ」の但し書き付きの候補行として、実在を確かめずに常に出す)**。**実在するものだけを挙げる**(docker-proxy と `claude-dev-net` の2つを除く) | FR-env-03(受け入れ基準14)/ FR-env-01(受け入れ基準25) |
| **端末が無く `--yes` も無いための中止** | ERROR | プロンプトを出さずに中止したこと、`--yes` の指定方法。**何も削除していないことが分かる表現にする**。終了コード 1 | FR-env-03(受け入れ基準15) |
| **遊休判定に使う Docker への問い合わせが失敗した** | WARN | 判定できなかったこと、**安全側に倒して docker-proxy(と `claude-dev-net`)を残した**こと。処理は続行する | FR-env-01(受け入れ基準9) |
| **管理ラベルを持たないため削除しなかったコンテナ** | INFO | 残したコンテナの**名前**と、「管理ラベルが付く前に起動した可能性がある」こと、**停止中のものは列挙していない**という限界。削除は行っていないことが分かる表現にする。**削除対象が0件で確認を求めずに終わる経路でも出す**(受入基準19。削除する集合が空でも、残したコンテナが在るという事実は変わらない) | FR-env-03(受け入れ基準17・19) |
| **管理ラベルを持たないコンテナを残したことによる認証の巻き戻り** | WARN | 残したコンテナが稼働している限り、コンテナ内の同期ループ(30 秒周期)が共有ボリュームへ認証を**書き戻す**こと、そのため `logout` の効果が最大 30 秒で失われうること、確実に消すには先に `claude-dev stop <name>` で止めること。**削除対象が0件で確認を求めずに終わる経路でも出す**(受入基準19。**この経路は何も削除しないので、他に警告を出す機会が無い** — 削除を行う経路では削除結果とともに同じ警告が出る。書き戻しが済んで共有ボリュームが埋まった状態はこの経路に入らない(空であることを確認できないため)ので、**この経路に入るのは書き戻しの前、共有ボリュームが空である瞬間である**) | FR-env-03(受け入れ基準17・19 と受け入れ基準3 の帰結) |
| **削除対象の Claude コンテナの集合を引けなかった** | WARN | 引けなかったこと(**「0件だった」ではない**)、したがって削除対象0件の経路には入らず受入基準14 のとおり列挙して確認を求めること、そして**引けなかったこと自体を「消えなかった資源」として列挙し終了コード 1 で終わること**。処理は続行する(共有ボリュームとプロジェクト配下の認証は削除を試みる) | FR-env-03(受け入れ基準18・19) |
| **ラベルを持たないコンテナの列挙に必要な問い合わせが失敗した** | INFO | 引けなかったこと(**「0件だった」ではない**)と、どちらが引けなかったか。(a) 共有ネットワークへの問い合わせが失敗した場合は列挙そのものができなかったこと、(b) セッション由来の資源の一覧が引けなかった場合は**除外を行っていないので、セッション由来のコンテナが混じっている可能性**があること(**ラベル無しコンテナを1件以上表示するときに添える**。除外を行わないことは表示集合を過大にする方向にしか働かないので、表示するものが無ければ添えない)。処理は続行する(削除には影響しない) | FR-env-03(受け入れ基準17・19) |
| **共有ボリュームが空であることを確認できなかった** | WARN | 空かどうかを確かめられなかったこと(**「空だった」ではない**)、したがって削除対象0件の経路には入らず、受入基準14 のとおり削除対象を列挙して確認を求めることを示す。処理は続行する | FR-env-03(受け入れ基準19) |
| **共有資源(docker-proxy / `claude-dev-net`)を残した理由** | INFO | 稼働中の Claude コンテナが残っていること(**その名前**)。`reset` の場合はあわせて**「完全な初期化になっていない」**旨 | FR-env-01(受け入れ基準9) |
| **セッション由来の資源を削除した** | INFO | 削除した資源の名前を**種別(コンテナ / ネットワーク / ボリューム)つきで1行ずつ**出す。**削除が0件のときは何も出さない**(対象が無いことを毎回表示しない)。`stop` は削除前の確認を求めない(`D0-env-08` 項3)ので、**この事後の列挙が「何が消えたか」を利用者が知る唯一の観測点である** | FR-env-01(受け入れ基準26・27) |
| **セッション由来の名前付きボリュームを残した** | INFO | 残っているボリュームの**名前**と、**削除する方法**(削除を明示する指定)を出す。**0件のときは何も出さない**(`FR-env-01-29`・`-30`)。`reset` の場合はあわせて**完全な初期化になっていない**旨を出す(`FR-env-01-33`)。**「削除できなかった資源」の一覧には入れない** — 削除しないと決めたものであって、消えなかったものではない | FR-env-01-29・-30・-33 |
| **プロジェクト環境ファイルを読めなかった** | WARN | 指定された場所を読めなかったこと、環境変数を渡さずに起動を続けること。**指定そのものが無いときは出さない**(正常な省略である。`FR-env-14-5`・`-6`) | FR-env-14-5・-6 |
| **プロジェクト環境ファイルの行を採用しなかった** | INFO | 採用しなかった理由ごとに出す: 組として読めない行は**何行目か**、予約した名前は**その名前**、同じ名前が重なったときは**採用しなかったほうの名前**。**値は出さない**(上の「出してはならない情報」)(`FR-env-14-7`・`-8`・`-10`) | FR-env-14-7・-8・-10 |
| **プロジェクト環境ファイルを版管理の追跡から外せなかった** | WARN | 外せなかったこと、起動は続けること。**利用者が自分で追跡から外す必要がある**ことが分かる表現にする(`FR-env-14-4`) | FR-env-14-4 |
| **セッション由来の資源の削除に失敗した** | WARN | 消えなかった資源の名前と種別。**`stop` は握って続行する**ので、処理を続けたことが分かる表現にする(受け入れ基準24)。**`reset` はこの行ではなく下の「削除できなかった資源」(ERROR)に従う**(`D0-env-08` 項5 の対象であるため) | FR-env-01(受け入れ基準24) |
| **セッション由来の資源の片付けを行わなかった** | INFO | 管理ラベル `claude-dev.project-dir` を読めないため所有者を再現できず、片付けを行わなかったこと。**残っている可能性と、所有者ラベルで利用者自身が一覧できること**。compose 資源について同じ理由で出す既存の案内と**1つにまとめてよい**(原因が同じ1つのラベルであるため) | FR-env-01(受け入れ基準23) |
| **削除できなかった資源** | ERROR | 消えなかった資源(コンテナ名・docker-proxy・共有ボリューム内のパス・プロジェクト配下のパス・**セッション由来の資源**)を**1件ずつ**列挙する。**「削除しました」「完了」「全リセット完了」の文言を出してはならない** | FR-env-03(受け入れ基準18) |
| **削除したプロジェクト配下の認証コピー** | INFO | 削除した**パス**を列挙する。他のディレクトリのコピーには触れていないという限界もあわせて出す | FR-env-03(受け入れ基準20・21) |
| **削除の途中で `INT` / `TERM` を受けた** | ERROR | 進行中の1件を終えてから中断したこと、**そこまでに削除した資源と未削除のまま残った資源を1件ずつ**列挙する。成功時の文言は出さない | FR-env-03(受け入れ基準23) |
| **旧い名前の compose 資源 / ラベルを持たない `stop` 対象** | INFO | 片付けの対象に含めなかったこと、残っている可能性、**手動で片付ける方法**(compose のプロジェクト名で絞り込んで停止する手順。具体的なコマンドは 03 が持つ) | FR-env-01(受け入れ基準20・21) |
| **`stop <name>` の名前が受理できない文字を含む** | ERROR | 受理できない文字を含むこと、受理する文字集合(`[A-Za-z0-9._-]`)。**何も削除していないことが分かる表現にする** | FR-env-01(受け入れ基準18) |
| noVNC の URL 提示 | INFO | 接続 URL(未公開なら出さない) | FR-env-11 |
| ポート割当 | INFO | ホスト側ポートと転送先 | FR-env-06 |
| ファイアウォールの適用結果 | INFO / WARN | 適用サマリ(**設定に列挙したドメインの件数と、実際に登録できた宛先 IP の件数**)。失敗時は警告 | FR-env-05(受け入れ基準5・7) |
| 到達性スモークテスト | WARN | 想定外の到達性が出た場合のみ警告行 | FR-env-05(受け入れ基準6) |
| 既定設定の補完 | INFO / WARN | 生成・追記した鍵。書き換えを見送った場合は警告 | FR-env-12(受け入れ基準8・10) |
| Docker 要求の拒否 | INFO | 拒否理由(bind / 特権 / ホスト空間のいずれか)と対象 | FR-env-07, NFR-sec-01 |
| **所有者ラベルの付与** | INFO | 付与した資源の種別(コンテナ / ネットワーク / ボリューム)と**所有者(起動ディレクトリの絶対パス)**。bind の書き換えを出す既存のログと同じ粒度で、要求1件につき1行 | FR-env-07(受け入れ基準11) |
| **所有者ラベルを付与せずに中継した** | INFO | 付与しなかった理由(呼び出し元を特定できない / ボディを解釈できない)。**拒否ではなく中継したこと**、およびその資源が `stop` / `reset` の片付け対象から外れることが分かる表現にする | FR-env-07(受け入れ基準12) |
| Docker 中継の失敗 | ERROR | 上流エラーの概要 | FR-env-07 |
| VM の資源逼迫 | WARN | 検知した指標と閾値(**QEMU プロセスの CPU 使用率と、割り当て上限に対する比率の閾値 60%**。用語集「資源逼迫」) | FR-env-08(受け入れ基準4) |

**起動ディレクトリの絶対パスの扱い**: 上の表のうち「コンテナ名の衝突による起動の中止」と
「削除したプロジェクト配下の認証コピー」**および「所有者ラベルの付与」**は、
**ホストの絶対パス**(管理ラベル `claude-dev.project-dir` / `claude-dev.owner-project-dir` の値、
および削除したファイルのパス)を出す。これは
「出してはならない情報」の**「ホームディレクトリ配下の構造」の例外ではなく、同項が本節へ委ねた
「必要な範囲」の判定そのものである**: いずれも**利用者が次に取るべき操作(そのディレクトリへ
移動して再接続する / どのファイルが消えたかを確認する / どのセッションの資源かを見分ける)を
決めるために、そのパス自体が必要**だからである。**必要な範囲を超える例**: 無関係なディレクトリの
列挙、ホーム配下の探索結果、削除対象でないパスの表示。これらは出さない。

**破壊的操作の出力に共通して課す制約**(`D0-env-08` 項5): **削除に失敗した資源がある状態で
成功の文言を出してはならない。** **成功を表す文言**(`FR-env-03` 受入基準18 が禁じる「削除しました」「完了」を含む)は、
**列挙した削除対象がすべて消えたことを確認したときにだけ**出す。
判定は削除コマンドの終了コードではなく**削除後の列挙結果**で行う(契約
`CTR-cli-container` の「エラーケース」)。
**この制約は見出しの文言だけでなく、資源ごとの一覧にも及ぶ**:
**「削除した資源」に挙げてよいのは、消えたことを確認できた資源だけである。**
消去を確認できなかった資源と、削除しないと決めた資源(管理ラベルを持たないコンテナ・遊休でない
docker-proxy)は挙げてはならない。**同じ資源を「削除した資源」と「削除できなかった / 未削除のまま
残った資源」の両方に挙げてはならない** — 利用者はその2行から何が起きたかを決められない。
**そもそも存在しなかった資源は、どちらの一覧にも挙げてはならない**(`FR-env-01-34`)。
存在しないことと削除に失敗したことは別であり、**利用者は前者を片付けの失敗と読む**。
判定は削除操作の終了コードではなく、対象の実在を確かめて行う(手段は 03 が持つ)。
**残したものの表示は削除の成否で条件づけない**: 管理ラベルを持たないコンテナを残した事実は
削除が失敗した実行でも変わらないので、**失敗して終了コード 1 で終わる実行でも表示する**
(`FR-env-03` 受入基準17 は成否で条件づけていない)。
**`stop` のセッション由来の資源はこの制約の対象外である**(`FR-env-01` 受入基準24 が
「握って続行する」と定めており、`D0-env-08` 項5 自身がその例外を明示している)。

## 監視・アラート

本システムは常時監視の対象ではない(開発者の手元で動く開発環境である)。

| 条件 | 通知先 | 対応の期待 |
|---|---|---|
| VM の資源逼迫 | tmux の表示とヘルスファイル | 利用者が負荷を下げるか VM を作り直す |

## 設計判断

### DSN-log-01 ログ基盤を統一せず、性格ごとに出力先を分ける

- 判断: 利用者向けの端末出力と常駐プロセスのログを、それぞれ別の出力先・別の形式で扱う。
  共通のログライブラリや集約基盤を持たない。
- 理由: 2種類は寿命も読み手も違う。端末出力は人間が今読むもの、常駐プロセスのログは `docker logs`
  で追うものである。統一すると、人間向けの日本語出力に構造化の制約がかかる。
- 却下した案: 全ログを JSON で統一する — 利用者向けの案内が読みにくくなる。集約基盤へ送る —
  開発者の手元で動く環境に常時稼働の依存を増やすことになる。
