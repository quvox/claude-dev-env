# MODULE-cli-common-container-project-dir 起動元ディレクトリの読み取り

## 目的

`stop` が compose 資源とセッション由来の資源を片付けるには、**そのコンテナがどのホスト側
ディレクトリで起動されたか**が要る(compose 一意化名のハッシュ源と、所有者ラベル
`claude-dev.owner-project-dir` の照合値)。その値は管理ラベル `claude-dev.project-dir` にしか無く、
**本体コンテナを削除すると失われる**。`start` は名前衝突時に「どのディレクトリで起動されたか」を
推測ではなく事実として表示するためにこれを読む(`FR-env-01-12`)。

## 処理の流れ

1. `docker inspect <コンテナ名> --format '{{index .Config.Labels "claude-dev.project-dir"}}'` を
   実行する(`claude-dev:562`-`:568`)。
2. **`docker inspect` が非0で終わった場合(コンテナが存在しない・daemon 断)は `return 0` で
   空文字列を返す** — 呼び出し元から見て「ラベルが無い」と同じ経路に入る。
3. **ラベルが無いときに `docker inspect` が返す `<no value>` を空文字列へ潰す。**
   これにより「ラベルが無い」「値が空」「コンテナが存在しない」の3つが**1つの判定**にまとまる。
4. 値を改行なしで標準出力へ返す。

## 呼び出され方

- 契機: `stop` の管理ラベル読み取り(`claude-dev:1589`。**本体コンテナの削除より前**)と、
  `start` の名前衝突時の表示(`claude-dev:1436`)。
- 前提条件: なし(対象が存在しなくてもエラーにしない)。
- 引数: コンテナ名。
- 認可: CLI を実行できるホストユーザ。

## 連携先と連携内容

`callees` は「なし」。ホストの Docker Engine へ `docker inspect` を1回発行するだけである。

## 戻り値・副作用

| 種別 | 内容 |
|---|---|
| 戻り値 | 標準出力へ**起動時のホスト側の絶対パス**、または**空文字列**(ラベルが無い / 値が空 / コンテナが存在しない / 問い合わせに失敗した)。**終了ステータスは常に 0** |
| 永続化 | なし(読み取りのみ) |
| 発火するイベント | なし |
| ログ | なし(呼び出し元が「読めなかったこと」を表示する) |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| **対象コンテナが存在しない** | `docker inspect` が非0で終わり、空文字列を返す(終了ステータスは 0) | `stop` は compose 資源とセッション由来の資源の削除を**行わず**、残っている可能性と手動の片付け方を表示する(`FR-env-01-21` / `FR-env-01-23`) |
| **管理ラベルが無い**(ラベル導入より前に起動されたコンテナ) | `<no value>` を空文字列へ潰して返す | 同上 |
| **ラベルの値が空文字列である** | そのまま空文字列を返す | 同上。**「ラベルが無い」と区別しない**(どちらも片付けに使えないため) |
| **Docker daemon が応答しない** | `docker inspect` が非0で終わり、空文字列を返す | 同上。**「ラベルが無い」と区別しない** |
| **値に空白や多バイト文字が含まれる**(利用者のパス) | そのまま返す。呼び出し元は引用付きで受け取る | なし |

## 実装上の判断

- [DS-02] `docker inspect` の失敗を握って**空文字列 + 終了ステータス 0** を返す — 理由: 呼び出し元の関心は「片付けに使える値が得られたか」の1点だけであり、「コンテナが無い」「ラベルが無い」「daemon が応答しない」を分けても取れる行動は同じ(推測せず片付けを中止する)である。分けると呼び出し元に同じ分岐が2つ増える / 見直す条件: 呼び出し元が失敗の種類ごとに違う表示を出す必要が生じたとき
- [DS-02] `<no value>` を空文字列へ潰す — 理由: `docker inspect --format` は存在しないラベルに対してこの literal を返すので、潰さないと呼び出し元が `[ -n "$v" ]` で真と判定し、`<no value>` という文字列をハッシュ源や照合値に使ってしまう / 見直す条件: `docker inspect` の未設定ラベルの出力が変わったとき
- [DS-05] ラベル名を引数にせず `claude-dev.project-dir` に固定する — 理由: 他の管理ラベル(`claude-dev.managed`)は真偽の判定であり別関数(`container_is_managed`)が持つ。汎用の「ラベルを読む」関数にすると、値の潰し方(`<no value>` の扱い)を呼び出し元ごとに決め直すことになる / 見直す条件: 値として読むラベルが3つ以上になったとき
- [D0-scope-03] Linux 版・macOS 版の両方に同じ形で置く — 理由: 同じサブコマンドの成否と出力を OS で変えないため / 見直す条件: 片方の OS でしか成立しない実装手段が必要になったとき

## 既知の制限

| 制限 | 影響 | 関連 issue |
|---|---|---|
| **問い合わせの失敗と「ラベルが無い」を区別しない** | daemon が一時的に応答しなかっただけでも、`stop` は「管理ラベルを持たない」経路の案内を出す | なし(閾値の外: どちらでも取れる行動は同じ。実装上の判断1) |
| **本体コンテナを削除するとこの値は二度と読めない** | 読み取りを削除より後に置くと compose 資源とセッション由来の資源が片付けられなくなる | なし(閾値の外: 順序の固定は `MODULE-cli-stop` 手順4 と `CTR-cli-container`「compose 資源の識別」が持つ) |
