# MODULE-cli-common-net-other-running-containers 遊休判定の集合

## 目的

共有 docker-proxy と共有ネットワーク `claude-dev-net` は全プロジェクトで共有されるので、
**他のセッションが使っている間は止めてはならない**(`FR-env-01-9`)。
その判定に使う集合 —「`claude-dev-net` に接続している稼働中のコンテナから、
本システムの固定名・固定接頭辞のものを除いたもの」— を求めるのがこの機能である。
`stop` / `logout` / `reset` の3機能が同じ判定に依存する。

## 処理の流れ

1. `docker network inspect <NETWORK> --format '{{range .Containers}}{{println .Name}}{{end}}'` で
   **接続しているコンテナ名**を得る。**失敗したら `return 1`。**
2. `docker ps --format '{{.Names}}'` で**稼働中のコンテナ名**を得る。**失敗したら `return 1`。**
3. 手順1 の各名前について、次を順に落とす(`claude-dev:600`-`:611`)。
   - 空行
   - 名前が `$DOCKER_PROXY_CONTAINER`(固定名 `claude-dev-docker-proxy`)のもの
   - 名前が `fwd-` で始まるもの(固定接頭辞の中継コンテナ)
   - 手順2 の集合に**含まれないもの**(接続情報には残るが稼働していない)
4. 残った名前を1行ずつ標準出力へ返す。**空なら遊休である。**

**`docker ps --filter ancestor=<イメージ>` を判定に使わない。** イメージを再ビルド・再取得すると
それ以前に起動したコンテナを数え落とし、稼働中の他プロジェクトから Docker が使えなくなる
(イメージを再取得した後に「稼働中なのに一覧に出ない」セッションが生じる欠陥として実際に観測され、
解消済みである)。**管理ラベルにも依存しない** — ラベルが付く前に起動された
既存コンテナを数え落とすためである(`D0-env-10`)。ネットワークへの接続は起動オプションの
必須項目なので、起動経路によらず必ず成立する。

## 呼び出され方

- 契機: `stop` の `stop_proxy_if_idle`(`claude-dev:616`。本機能の呼び出し元は `stop` に畳み込み)、
  `logout` の手順9(`claude-dev:974` / `:1049`)、`reset` の手順7(`claude-dev:1995` / `:2116`)。
- 前提条件: なし(ネットワークが存在しなくてもエラーにせず非0で返る)。
- 引数: なし(対象ネットワークは定数 `$NETWORK` を読む)。
- 認可: CLI を実行できるホストユーザ。

## 連携先と連携内容

`callees` は「なし」。ホストの Docker Engine へ問い合わせを2回発行するだけである。

## 戻り値・副作用

| 種別 | 内容 |
|---|---|
| 戻り値 | 標準出力へコンテナ名を1行ずつ(空 = 遊休)。**終了ステータス**: 0 = 判定できた / **1 = `docker network inspect` または `docker ps` が失敗した**(ネットワークが存在しない場合を含む) |
| 永続化 | なし(読み取りのみ) |
| 発火するイベント | なし |
| ログ | なし(呼び出し元が「判定できなかったこと」と「残した理由(コンテナ名)」を表示する) |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| **`docker network inspect` が失敗した**(`claude-dev-net` が存在しない / daemon 断) | `return 1`。標準出力は空 | 3機能とも**遊休でないと判定して共有資源を残す**(安全側)。判定できなかったことを表示する。**`reset` は「完全な初期化になっていない」も表示する** |
| **`docker ps` が失敗した** | `return 1`。標準出力は空 | 同上 |
| **接続情報に残っているが稼働していないコンテナがある** | 手順3 で落とすので集合に入らない | 停止中のコンテナは Docker を使っていないため、共有資源を消しても壊れない |
| **管理ラベルを持たない Claude コンテナが稼働している** | **集合に入る**(ラベルを見ないため) | 共有資源を残す。`logout` / `reset` はそのコンテナを削除しないので、この判定は空にならないことがある |
| **利用者がコンテナ内から作った compose コンテナが `claude-dev-net` に繋がっている** | **集合に入る** | 共有資源が回収されにくくなる。**過剰に数える = 消さない側**なので `FR-env-01-9` は破らない(2026-08-04 の決定シート #1 で人間が案A=現状のままと裁定) |
| **停止中のコンテナしか無い** | 集合は空 | 遊休と判定して共有資源を削除する |

## 実装上の判断

- [D0-env-10] 遊休判定を**`claude-dev-net` への接続**で行い、管理ラベルにもイメージにも依存させない — 理由: ラベルは付く前に起動された既存コンテナを、イメージ(`--filter ancestor`)は再ビルド・再取得より前に起動したコンテナを、それぞれ**数え落とす**。数え落とすと稼働中の他プロジェクトから Docker が使えなくなる。ネットワークへの接続は起動オプションの必須項目なので起動経路によらず成立する / 見直す条件: `claude-dev-net` に接続しないコンテナを起動する経路ができたとき
- [DS-02] 問い合わせの失敗を**握らずに `return 1`** で返し、判定そのものは呼び出し元に委ねる — 理由: 「遊休である」は共有資源を消す判断なので、確かめられなかったときに安全側(遊休でない)へ倒す責任は削除を行う側にある。この機能が勝手に「遊休でない」を意味する出力を作ると、0件との区別が消える / 見直す条件: 契約 `CTR-cli-container`「エラーケース」が変わったとき
- [DS-05] 除外を**固定名と固定接頭辞**(`claude-dev-docker-proxy` / `fwd-`)で行う — 理由: どちらも本システムが決めた名前なので所有権が名前から読み取れ、ラベルを足しても情報が増えない一方、既存分がラベルを持たないという移行問題を作り込むことになる / 見直す条件: 中継コンテナの命名規則が変わったとき
- [DS-05] 対象ネットワークを引数に取らず定数 `$NETWORK` を読む — 理由: 共有ネットワークは1本だけであり、引数にすると呼び出し元3箇所で同じ定数を書き写すことになる / 見直す条件: 共有ネットワークが複数になったとき
- [D0-scope-03] Linux 版・macOS 版の両方に同じ形で置く — 理由: 同じサブコマンドの成否と出力を OS で変えないため / 見直す条件: 片方の OS でしか成立しない実装手段が必要になったとき

## 既知の制限

| 制限 | 影響 | 関連 issue |
|---|---|---|
| **利用者の compose コンテナを「稼働中」に数える** | docker-proxy が回収されにくい。**過剰に数える = 消さない側**なので `FR-env-01-9` は破らない | なし(2026-08-04 の決定シート #1 で人間が案A=現状のままと裁定) |
| **`claude-dev-net` が存在しないと「問い合わせ失敗」になる** | ネットワークを手で消したあとは、共有資源が1つも残っていなくても docker-proxy が回収されない | なし(閾値の外: 契約「エラーケース」が明示。安全側に倒れる) |
| **停止中のコンテナは接続情報に現れない** | 停止中のコンテナがあっても遊休と判定する | なし(閾値の外: 停止中のコンテナは Docker を使っておらず、共有資源を消しても壊れない) |
