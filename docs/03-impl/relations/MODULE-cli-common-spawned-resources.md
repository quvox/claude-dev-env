# MODULE-cli-common-spawned-resources セッション由来の資源の列挙

## 目的

`stop` と `reset` が「そのセッションのコンテナ内から docker-proxy を経由して作られた資源」を
片付けるための列挙(`DSN-env-04` の規則 D。`FR-env-01-22` / `FR-env-01-25`)。
**`stop` は所有者の絶対パスで、`reset` は所有者を問わず `claude-dev.role=spawned` で引く**が、
**違うのはフィルタ式だけ**であり、種別ごとの引き方(コンテナとネットワークで別コマンド・
別の `--format`)は共通である。分けて書くと綴りの間違いの機会が2倍になる。

## 処理の流れ

`spawned_resources <container|network> <ラベルフィルタ式>`(`claude-dev:586`-`:592`)。

1. 第1引数が `container` なら
   `docker ps -a --filter "label=<式>" --format '{{.Names}}'` を実行する。
   **`-a` を付けるので停止中のコンテナも含む。**
2. `network` なら `docker network ls --filter "label=<式>" --format '{{.Name}}'` を実行する。
3. **どちらでもなければ `return 2`** で終わる(呼び出し元の綴り間違いを 0 件と区別する)。
4. 名前を1行ずつ標準出力へ返す。

**`--format` で名前だけを取るのは、既定の表形式がヘッダ行を含み、`-q` が ID を返すためである** —
どちらもそのままでは表示にも `docker rm` にも使えない。

**問い合わせ自体に失敗したら非0を返す**(`docker` の終了コードがそのまま返る)。
0件(消すものが無い)と引けなかったことを同一視してはならない
(契約 `CTR-cli-container`「エラーケース」)。

## 呼び出され方

- 契機: `stop` の手順8-1・8-2(`claude-dev:1697` / `:1707`)と、
  `reset` の手順3(`claude-dev:2035` / `:2040`)と、
  **`logout` の手順4**(ラベル無しコンテナの表示集合から `claude-dev.role=spawned` を除くため。
  `logout` はこの一覧を**削除には使わない** — 規則 D を使わないので削除対象には入れない)
  からの関数呼び出し。
- 前提条件: `stop` の経路では**起動元ディレクトリの絶対パスが読めていること**
  (`MODULE-cli-common-container-project-dir`)。読めなければ呼び出し元がこの機能を呼ばずに
  片付けを中止する(`FR-env-01-23`)。
- 引数: 第1引数は `container` / `network` のいずれか。第2引数はラベルフィルタ式
  (`claude-dev.owner-project-dir=<絶対パス>` または `claude-dev.role=spawned`)。
  **ラベルの名前と値の正は契約 `CTR-cli-container` の規則 D。**
- 認可: CLI を実行できるホストユーザ。

## 連携先と連携内容

`callees` は「なし」。ホストの Docker Engine へ問い合わせを1回発行するだけである。

## 戻り値・副作用

| 種別 | 内容 |
|---|---|
| 戻り値 | 標準出力へ資源の名前を1行ずつ。**終了ステータス**: 0 = 引けた(0件を含む)/ 非0 = 問い合わせに失敗した / **2 = 第1引数が `container` でも `network` でもない** |
| 永続化 | なし(読み取りのみ。削除は呼び出し元が `MODULE-cli-common-destructive` 経由または直接 `docker rm -f` で行う) |
| 発火するイベント | なし |
| ログ | なし(呼び出し元が引けなかったことを表示する) |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| **問い合わせが失敗した**(`docker ps` / `docker network ls` が非0) | 非0を返す。標準出力は空 | `stop` は失敗した側の削除を行わずに続行し、引けなかったことを表示する(`FR-env-01-24` の対象外の扱い)。`reset` は**失敗として記録**し、消えなかった資源として列挙して終了コード 1 で終わる(`FR-env-03-18`)。**どちらも 0 件とは区別する** |
| **該当する資源が0件だった** | 0 を返す。標準出力は空 | 削除対象が無いだけ。`stop` / `reset` は何も表示しない(`FR-env-01-27`) |
| **第1引数が `container` / `network` 以外** | `return 2`。標準出力は空 | 呼び出し元は非0として扱う(現行の呼び出し元は2値しか渡さないので到達しない) |
| **所有者ラベルを持たないセッション由来の資源がある** | 列挙に現れない | 片付けられず、表示もされない(`D0-env-08` 項8 が明示した範囲) |
| **利用者がホスト側から手で同じラベルを付けた資源がある** | 列挙に現れる | 削除対象に入る(`docs/pendings.md` P-007 で受容。前提は `SR-05`) |

## 実装上の判断

- [DS-05] 種別(`container` / `network`)とフィルタ式を引数に取る1関数にまとめる — 理由: `stop` と `reset` で違うのはフィルタ式だけで、`docker ps -a --format '{{.Names}}'` と `docker network ls --format '{{.Name}}'` という種別ごとの引き方は共通である。分けると綴りの間違いの機会が2倍になる / 見直す条件: 種別が3つ以上に増え、種別ごとに戻り値の形が変わったとき
- [DS-02] 問い合わせの失敗を**握らずに非0で返す** — 理由: 0件と引けなかったことを同一視すると、`reset` が「削除するものが無かった」として完了を表示しうる。`D0-env-08` 項5 は失敗を握りつぶすことを禁じている / 見直す条件: 契約 `CTR-cli-container`「エラーケース」が変わったとき
- [DS-02] 不正な種別に **`return 2`** を返す(0 でも 1 でもない) — 理由: 呼び出し元の綴り間違いを「問い合わせに失敗した」(非0)と値の上で区別できるようにするため。**現行の呼び出し元はいずれも `if v=$(spawned_resources …); then … else … fi` の二分岐で、2 とその他の非0 を区別していない**(`stop` の `claude-dev:1697` / `:1707`、`reset` の `:2035` / `:2040`、および `logout` の表示用の除外)ので、これは将来の呼び出し元と調査のための診断値である / 見直す条件: 呼び出し元が種別を変数から組み立てるようになり、綴り間違いが実行時に起きうるようになったとき(そのときは区別を仕様として要求する)
- [DS-02] `--format '{{.Names}}'`(ネットワークは `'{{.Name}}'`)で名前だけを取る — 理由: 既定の表形式はヘッダ行を含み、`-q` は ID を返すので、どちらも表示にも `docker rm` にも直接使えない / 見直す条件: `docker` の出力形式が変わったとき
- [DS-02] コンテナの列挙に `-a` を付けて**停止中も含める** — 理由: セッション由来のコンテナは停止したまま残ることがあり、片付けの範囲は「セッションが作ったものは全部」である(`D0-env-05` 項2) / 見直す条件: 停止中の資源を残す方針へ変わったとき
- [D0-scope-03] Linux 版・macOS 版の両方に同じ形で置く — 理由: 同じサブコマンドの成否と出力を OS で変えないため / 見直す条件: 片方の OS でしか成立しない実装手段が必要になったとき

## 既知の制限

| 制限 | 影響 | 関連 issue |
|---|---|---|
| **所有者ラベルを持たない資源は列挙できない** | `DSN-env-04` の導入より前に作られた資源と、ボディを解釈できない要求で作られた資源は片付けられず、**存在を知る手段が無いので表示もされない** | なし(閾値の外: `D0-env-08` 項8 が明示。関連する残存リスクは `docs/issues/005`) |
| **ラベルの発行者を検証しない** | 利用者がホスト側から `docker run --label` で同じラベルを付けた資源も列挙に入る | `docs/pendings.md` **P-007**(`SR-05` の前提の下で受容) |
| **列挙と削除のあいだに作られた資源は取りこぼす** | 呼び出し元が削除する時点で新しく作られた資源は次回の `stop` / `reset` まで残る | なし(閾値の外: ロックはホスト CLI のプロセス間だけで有効で、コンテナ内の Docker クライアントには届かない。`CTR-cli-container`「ロックが守れない範囲」) |
