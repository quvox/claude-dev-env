# MODULE-cli-common-write-project-ssh-keys プロジェクト設定の書き出し

## 目的

「このプロジェクトで転送する鍵」の唯一の記録先である `.claude-dev.yaml` の `ssh_keys` 節を書く
(FR-env-04)。書式を決めているのはこの機能であり、読み取り側(`_parse_ssh_keys_yaml`)は
ここが出す書式に依存している。**このファイルは `ssh_keys` 以外のキー(`env_file`)も持つように
なったため、本機能は自分の節だけを書き換え、他のキーとその配下の行を保存する**
(契約 `CTR-cli-container`「プロジェクト設定ファイルとプロジェクト環境ファイル」)。

## 処理の流れ

1. 第1引数を書き出し先パスとして受け取り、残りの引数を鍵パスの並びとして扱う。
2. **既存ファイルがあれば読み、`ssh_keys` 節だけを差し替えた内容を組み立てる。**
   節の範囲は「`ssh_keys:` の行から、次に現れる**字下げの無い行**(別のキーまたはコメント)の
   直前まで」とする。**空行は「字下げの無い行」に数えず節の中とみなす**ので、
   `ssh_keys:` の直後に置かれた空行は節と一緒に落ちる(`claude-dev:239`-`:243` /
   `claude-dev-mac:267`-`:271`)。**この範囲の外にある行は、コメントも含めて1行も落とさない。**
3. 差し替える `ssh_keys` 節の内容:
   - `ssh_keys:`
   - 各鍵について `  - <パス>`(0 件なら行を出さない = 空のセクション)
4. 既存ファイルが無いときだけ、先頭に案内のコメント3行を出す(`claude-dev:262`-`:264` /
   `claude-dev-mac:290`-`:292`):
   - `# claude-dev プロジェクト設定(claude-dev が ssh_keys 節を管理します)`
   - `# 再選択は 'claude-dev ssh-keys'、初期化は 'claude-dev ssh-keys reset'`
   - `# 環境変数を渡すときは env_file: <このディレクトリからの相対パス> を書く`
5. **一時ファイルへ書いてから元の名前へ差し替える**(書き込みの途中で落ちても、
   元のファイルが半分になった状態を残さない)。

## 呼び出され方

- 契機: 鍵選択の確定時(`MODULE-cli-common-select-ssh-keys`)、および非 TTY で
  `.claude-dev.yaml` を空作成するとき(`ensure_project_config`。`MODULE-cli-start` に畳み込み)。
- 前提条件: 書き出し先ディレクトリに書き込み権限があること。
- 引数:

| 引数 | 型 | 必須 | 制約 |
|---|---|---|---|
| `$1` | 文字列 | 必須 | 書き出し先のファイルパス |
| `$2...` | 文字列の並び | 任意 | 鍵の絶対パス。0 件可 |

- 認可: CLI を実行できるホストユーザ。

## 戻り値・副作用

| 種別 | 内容 |
|---|---|
| 戻り値 | なし |
| 永続化 | プロジェクト直下の `.claude-dev.yaml` の **`ssh_keys` 節だけ**を書き換える。**他のキー(`env_file`)とその配下の行、および利用者が書いたコメントは保存する。** 書式(`ssh_keys:` と `  - <path>`)はこの機能が決め、`_parse_ssh_keys_yaml` がそれに依存する |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| 書き込み権限が無い | リダイレクトが失敗し `set -e` でスクリプト全体が非0終了する | サブコマンドが中断する |
| 既存の `.claude-dev.yaml` に他のキーがある | **保存する**(`ssh_keys` 節の外は書き換えない) | `env_file` を書いた利用者の設定が鍵の再選択で失われない |
| **既存ファイルに `ssh_keys:` が2回以上現れる** | **最初の1つを差し替え、2つ目以降はそのまま残す**(利用者が壊した形を勝手に整えない) | 重複は残るが、読み取り側は最初の節を採る |
| 一時ファイルを作れない | リダイレクトが失敗し `set -e` でスクリプト全体が非0終了する。**元のファイルは無変更** | サブコマンドが中断するが、設定は壊れない |

## 既知の制限

| 制限 | 影響 | 関連 issue |
|---|---|---|
| **節の判定を字下げの有無で行うため、YAML の入れ子には対応しない** | `ssh_keys` の下に入れ子の写像を書くと節の終わりを誤る。**現在の書式は1階層のリストだけであり、契約がその形を定めている** | なし(閾値の外: 契約が書式を1階層に限っている) |

- [DS-05] **節を取り除く処理を `_strip_ssh_keys_section` という私的ヘルパ1つに切り出し、書く側とこの機能・`MODULE-cli-ssh-keys-reset` の双方から呼ぶ。機能表の1機能へは昇格させない** — 理由: 利用者から見た入口を持たず、**1つのファイルの1つの節の書式**という実装内部の詳細である(`DSN-mod-01` の「モジュールは利用者から見た入口と1対1」に当たる単位ではない)。2箇所で別々に判定を書くと「書けるが消せない/消せるが書けない」状態を作る、というのが切り出しの理由であって、共有そのものが機能である理由ではない / 見直す条件: この判定を `start` / `ssh-keys` 以外の入口からも必要とするようになったとき
- [DS-05] **節の範囲を「`ssh_keys:` から次の字下げ無しの行の直前まで」で判定し、YAML の解析器を持ち込まない** — 理由: ホスト CLI は Bash 実装で、追加のランタイムを要求しないことが `SR-20` の技術前提である。契約が設定ファイルの書式を1階層のリストに限っているので、この判定で必要十分である / 見直す条件: 設定ファイルが入れ子構造を必要とするようになったとき
