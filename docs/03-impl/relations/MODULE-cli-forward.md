# MODULE-cli-forward ポートフォワードの追加

## 目的

`start` の時点では Web アプリ用のポートを公開せず(noVNC の 6080 だけを公開する)、必要に
なった時点で明示的に開ける(FR-env-06)。既に稼働中のコンテナを再作成せずにポートを足せる
ようにするため、socat の使い捨てコンテナを中継に使う。

## 処理の流れ

1. 第1引数(`<cport>`)が**空または未指定なら**使い方を表示して `exit 1`。**それ以外の検証は行わない。**
2. `MODULE-cli-common-container-name` で対象コンテナ名を決める(第2引数 `NAME` があればそれを優先)。
3. `MODULE-cli-common-is-running` で稼働を確認する。未起動なら日本語エラーで `exit 1`。
4. `fwd-<name>-<cport>` が**稼働中**なら、`docker port` で現在のホストポートを表示して `exit 0`。
   **停止状態で残っている**なら `docker rm -f` してから作り直す。
5. `find_available_host_port`(本機能に畳み込み)で 8100〜8999 の空きポートを探す。
6. `docker run -d --rm -p <hport>:<cport> --network claude-dev-net --name fwd-<name>-<cport>
   --entrypoint socat <IMG_CLAUDE> TCP-LISTEN:<cport>,fork,reuseaddr TCP:<name>:<cport>` で
   中継コンテナを起動する。
7. Linux 版は SSH トンネルの例を、macOS 版は `http://localhost:<host-port>` の直結案内を表示する。

**`find_available_host_port` の探索規則**: `8100` から `8999` まで(`FWD_PORT_BASE` から +900 未満)を
1ずつ上げながら、`docker ps --format '{{.Ports}}'` の出力に `0.0.0.0:<port>->` を含む行が無い
最初の値を返す。**空きが無ければ基準値 `8100` を返す**(失敗を返さない)。

## 呼び出され方

- 契機: 利用者が `claude-dev forward <cport> [NAME]` を実行したとき。
- 前提条件: 対象コンテナが稼働中であること。
- 引数:

| 引数 | 型 | 必須 | 実装が行う検証 | 受理/拒否と結果 |
|---|---|---|---|---|
| `<cport>` | 文字列(整数を想定) | 必須 | **空文字・未指定かどうかだけ**を見る | 空・未指定 → 使い方を表示して `exit 1`。**それ以外はすべて受理**し、そのままコンテナ名と `-p` の値に使う |
| `NAME` | 文字列 | 任意 | 検証しない | 省略時はカレントディレクトリ名を小文字化し `[a-z0-9._-]` 以外を `-` に置換した値。指定時はその文字列をそのまま使う。**稼働中のコンテナ名でなければ手前の稼働確認で `exit 1` になる**ため、実在する名前しか通らない |
| 第3引数以降 | — | — | — | **黙って無視する**(エラーにしない) |

**`<cport>` の境界値の実際の扱い**(検証が無いため、いずれも docker まで到達する):

| 入力 | 実際の結果 |
|---|---|
| 空 / 未指定 | 使い方を表示して `exit 1`(唯一の自前エラー) |
| `0` / 負数 / `65536` 以上 | `docker run` がポート番号として拒否し、docker のエラーメッセージが出る。`set -e` によりスクリプトは非0終了する |
| 非数値(`abc`) | 同上。`docker run` の失敗として現れる |
| 先頭ゼロ(`0080`) | **受理される**。`80` とは**別のフォワード**(別のコンテナ名 `fwd-<name>-0080`)として扱われ、同じコンテナポートに二重の中継が立つ |
| 空白・記号を含む | コンテナ名として不正なら `docker run` が拒否して非0終了する |

- 認可: CLI を実行できるホストユーザ。

## 連携先と連携内容

### MODULE-cli-common-container-name

- 何のために呼ぶか: 中継コンテナ名 `fwd-<name>-<cport>` と接続先ホスト名の決定。
- 何を渡すか: なし。 / 何を受け取るか: コンテナ名。
- **失敗したときどうなるか**: 想定されない。

### MODULE-cli-common-is-running

- 何のために呼ぶか: 未起動のコンテナへ中継を張らないため。 / 何を渡すか: コンテナ名。 / 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: 日本語エラーを出して `exit 1`。

### MODULE-cli-common-container-exists

- 何のために呼ぶか: 同じポートのフォワードが既にあるかを判定するため。
- 何を渡すか: `fwd-<name>-<cport>`。 / 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: 「無い」と判定して `docker run` し、名前衝突で失敗する。

## 戻り値・副作用

| 種別 | 内容 |
|---|---|
| 戻り値 | 0(未起動時は 1) |
| 永続化 | コンテナ `fwd-<name>-<cport>`(`--rm` なので停止と同時に消える)。ホスト側ポート 8100〜8999 の1つを占有する |
| 発火するイベント | なし |
| ログ | 標準出力へ割り当てたホストポートと接続方法の案内 |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| `<cport>` が空・未指定 | 使い方を表示して `exit 1` | 利用者が引数を付け直す |
| `<cport>` が docker の受理しない値 | `docker run` が失敗し、docker のエラーがそのまま出る。**日本語の案内は出ない** | `set -e` により非0終了する |
| コンテナが未起動 | 日本語エラーを出して `exit 1` | 利用者は `start` する |
| 同じポートのフォワードが**稼働中** | 現在のホストポートを表示して 0 で終わる(二重に作らない) | なし |
| 同じ名前の中継コンテナが**停止状態で残っている** | `docker rm -f` してから作り直す | なし |
| 8100〜8999 に空きが無い | `find_available_host_port` が基準値 8100 を返し、`docker run` がポート衝突で失敗する。**再試行しない** | 非0終了する |
| 空きポート判定から `docker run` までの間に他者がそのポートを取った | `docker run` がポート衝突で失敗する。**再試行しない** | 非0終了する(`docs/issues/010`) |
| ホスト側の**非 Docker プロセス**がそのポートを使っている | 判定は `docker ps` の公開ポートしか見ないため空きと誤判定し、`docker run` が失敗する | 同上 |
| `docker port` が値を返さない(稼働中判定の直後に消えた等) | ホストポートが空欄のまま案内が出る | 利用者が再実行する |
| コンテナ側でそのポートが待ち受けていない | **待受けを確認しない。** 中継コンテナは起動し、`✅ host:<hport> → <name>:<cport>` と表示して 0 で終わる(**報告しているのは「中継の作成に成功した」ことだけ**。`FR-env-06` 受入基準8)。接続時に socat が接続拒否を返す | ブラウザ側で接続エラーになる。到達性の確認は利用者が行う |

## 実装上の判断

| # | 判断内容 | 根拠(委任ID) |
|---|---|---|
| 1 | コンテナを再作成せずに socat 中継コンテナで足す(稼働中セッションを壊さないため) | D0-scope-02 |
| 2 | 中継コンテナは `--rm` で作る(残骸を残さない。`stop` も `fwd-<name>-*` を掃除する) | D0-scope-02 |

## 既知の制限

| 制限 | 影響 | 関連 issue |
|---|---|---|
| 空きポート探索から `docker run` までが非アトミックで、**再試行が無い**(`start` は再試行する) | 同時実行・他プロセスとの競合でそのまま失敗する | `docs/issues/010-modify-forward-host-port-selection-is-racy.md` |
| 空き判定が `docker ps` の `0.0.0.0:<port>->` の文字列一致 | ホストの非 Docker プロセスが使うポート、`127.0.0.1` だけに公開されたポート、IPv6 のみの公開は**空きと誤判定する** | `docs/issues/010-modify-forward-host-port-selection-is-racy.md` |
| `<cport>` を検証しない | 先頭ゼロ違いで同一ポートに二重の中継が立つ。不正値のときは docker のエラーがそのまま利用者に出る | なし(起票の閾値の外: **利用者がその場で失敗に気づける**。ポート選択の競合は `docs/issues/010` が追跡) |
| 中継コンテナ名の一意性が `<name>` と `<cport>` の文字列だけで決まる | `NAME` を明示指定すると、稼働中の別プロジェクトの中継と名前が衝突しうる | `docs/issues/028-modify-name-uniqueness-does-not-satisfy-nfr-scale-01.md`(**`NFR-scale-01` との不一致**) |
| コンテナ側の待受けを確認しない | 到達できないケースと区別が付かないため、切り分け(アプリ未起動 / ポート違い / 中継失敗)は利用者に委ねられる。**要件もそう定めている**(`FR-env-06` 受入基準8。起票の閾値の「利用者がその場で失敗に気づける」側なので issue にしない) | なし(閾値の外: **`FR-env-06` 受入基準8 がこの振る舞いを要件として定めている**) |
