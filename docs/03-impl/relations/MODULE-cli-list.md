# MODULE-cli-list セッション一覧の表示

## 目的

複数プロジェクトを同時に開けるため、どのセッションが動いているかを横断的に見られるように
する(FR-env-01)。各セッションの noVNC URL も出す(FR-env-11)。

## 処理の流れ

1. 稼働中の Claude コンテナを列挙する。**条件は `--filter label=claude-dev.managed=1` と
   `--filter ancestor=claude-dev-claude` / `--filter ancestor=claude-dev-claude-vnc` の**
   **和集合**(問い合わせ2回。重複するコンテナ ID は1件に畳む)であり、そこから**名前が `fwd-` で
   始まる中継コンテナを除く**(集合の求め方は `CTR-cli-container`「稼働中セッションの一覧の列挙」が
   正。`FR-env-01-35`・`FR-env-01-36`)。**2回の問い合わせのどちらかが失敗したら、一覧が不完全で
   ある可能性を表示する**(0件と同一視しない)。
2. 各コンテナについて NAME / STATUS / WORKSPACE(マウント元)を表示する。
3. `MODULE-cli-common-get-novnc-url` で noVNC URL を求めて表示する。
4. `fwd-<name>-*` のフォワードを併記する。
5. 最後に `MODULE-cli-common-is-running` で `claude-dev-docker-proxy` の稼働状態を確認して表示する。

## 呼び出され方

- 契機: 利用者が `claude-dev list` を実行したとき。

## 連携先と連携内容

### MODULE-cli-common-get-novnc-url

- 何のために呼ぶか: 各セッションの接続先を提示するため。 / 何を渡すか: コンテナ名。 / 何を受け取るか: URL または空。
- **失敗したときどうなるか**: 空が返り、そのセッションの URL 行を出さない。

### MODULE-cli-common-is-running

- 何のために呼ぶか: 共有 docker-proxy の稼働状態を表示するため。 / 何を渡すか: `claude-dev-docker-proxy`。 / 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: 非稼働と表示される。

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| 稼働中のセッションが0件 | 一覧が空で、proxy の状態だけを表示する | なし |
| GHCR 版とローカルビルド版でイメージ名が同じ | `ancestor` フィルタは名前一致なので両方列挙される | なし |
| **2回の問い合わせのどちらかが失敗した**(Docker が応答しない) | 引けた側の結果を一覧に出し、**「一覧が不完全である可能性」を表示する**。終了コードは 0 のまま | なし(0件と読み違えない) |
| **管理ラベルを持たない既存コンテナが稼働している** | イメージ側の条件で引けるので一覧に出る(ラベル導入より前に起動され、**かつ**その後イメージを作り直した場合だけ出ない) | なし |
| **中継コンテナ(`fwd-*`)が稼働している** | セッションの行としては出さず、当該セッションの `FORWARD:` 行として併記する | なし |

## 実装上の判断

<!-- 2026-08-20 に既存1行を読み直した: 「列挙条件を ancestor(イメージ由来)にする」は**更新**した
     (見直す条件にあたる事象が起きた — `docs/histories/2026-08-20-fix-session-list-undercount.md`)。書式は delegation.md §3 へ揃えた。 -->

- [D0-env-10] 列挙条件を**管理ラベル `claude-dev.managed=1` とイメージ(`ancestor`)の和集合**にし、名前が `fwd-` で始まる中継コンテナを除く(**2026-08-20 に更新**。従来はイメージだけで引いていた) — 理由: イメージだけでは `latest` が別のイメージ ID を指した後に、それ以前に起動したコンテナを数え落とす(`docs/histories/2026-08-20-fix-session-list-undercount.md`)。ラベルだけではラベルが付く前に起動された既存コンテナを数え落とす。和集合はどちらの取りこぼしも埋め、かつ本システムが作ったもの以外を新たに含めない。コンテナ名の接頭辞では判定できない(コンテナ名 = 起動ディレクトリ名のため) / 見直す条件: 管理ラベルが付く前に起動された既存コンテナがホストから無くなったとき(そのときイメージ側の条件は落とせる)
- [DS-05] 共通関数を新設せず、`list` の分岐に直接書く — 理由: 同じ列挙を必要とするのは `claude-dev` / `claude-dev-mac` / `Makefile` に1箇所ずつで、シェル関数はファイルをまたいで共有できない(`Makefile` は呼べない)。関数にしても再利用は生まれず、機能表に1機能増える / 見直す条件: 同一ファイル内で2箇所以上が同じ列挙を必要としたとき
- [DS-02] 問い合わせの失敗を握らず、一覧が不完全である可能性を表示して終了コード 0 で終わる — 理由: `CTR-cli-container`「エラーケース」が 0 件と引けなかったことの同一視を禁じている。一覧は読み取りだけなので、引けた分を出さずに失敗させると利用者は何も得られない / 見直す条件: 同契約の「エラーケース」が変わったとき

## 既知の制限

| 制限 | 影響 | 関連 issue |
|---|---|---|
| **管理ラベルを持たず、かつ現在のイメージからでもないコンテナは列挙されない** | ラベル導入(2026-08-04)より前に起動され、その後イメージを作り直した場合に限る。該当するコンテナが1つも無くなればイメージ側の条件は落とせる | なし |
| **停止中のコンテナは列挙されない** | `list` は「実行中セッション」を出すもの(`FR-env-01-5`)なので、意図した範囲である | なし |
