# MODULE-cli-logout 認証の削除

## 目的

共有ボリュームに残っている認証を消し、以後のコンテナが未ログイン状態で起動するようにする
(FR-env-03)。claude と codex の認証が同じボリュームに同居しているため、両方が同時に消える。

## 処理の流れ

1. 引数を解析する(`--yes` のみ。それ以外は無視する)。
2. `MODULE-cli-common-require-setup` で削除用の一時コンテナに使うイメージをそろえる。
3. `MODULE-cli-common-lock` で**共有資源単位**のロック(キー `shared`、操作名 `logout`)を取る。
   取得できなければ**削除を一切行わずに**非0で終わる(`FR-env-01` 受入基準16)。
   **手順2 の `require_setup` によるイメージのビルドはロックの保護対象外**である
   (契約の「排他(ロックキー)」)。
4. 削除対象を列挙する(契約 `CTR-cli-container` の規則A)。
   - **Claude コンテナ**: **管理ラベル `claude-dev.managed=1` を持つものだけ**(稼働中・停止中の
     両方、プロジェクトを問わない)。**この問い合わせの成否を捨てない**: 引けなかったときは
     0件と同一視せず、**引けなかったことを記録して手順6 の0件判定に入らないようにし、
     手順11 で「消えなかった資源」として列挙して終了コード 1 で終わる**
     (`FR-env-03` 受入基準19・18 / 契約の「`logout` が削除対象の Claude コンテナ
     (管理ラベルを持つもの)の集合を引けなかった」)。引けなかった集合の中に削除対象が
     残っている可能性を、成功と同じ終了コードで隠さないためである。**ラベルを持たないものは削除対象に入れず**、その名前と
     「本変更より前に起動した可能性がある」ことを別枠で表示する(`FR-env-03` 受入基準17)。
     表示する集合の求め方は契約の「残したものをどう列挙するか」に従い、
     `claude-dev-net` に接続している稼働中コンテナから**契約が定める4つ**を除外する:
     固定名 `claude-dev-docker-proxy` / 固定接頭辞 `fwd-` / 管理ラベル `claude-dev.managed=1` を持つもの /
     **`claude-dev.role=spawned` を持つもの**。4つ目は
     `MODULE-cli-common-spawned-resources` に `container` と `label=claude-dev.role=spawned` を
     渡して得た名前の一覧と突き合わせて除く(`reset` と同じ引き方である)。
     **この一覧は表示から除くためだけに使い、削除対象には入れない**(`logout` は規則 D を
     使わない — `D0-env-05` 項2)。除かないと、セッション由来のコンテナが
     「本変更より前に起動した可能性がある」として現れ、**事実に反する表示になる**
     (契約が名指しで禁じている)。**停止中のラベル無しコンテナは列挙できないので、その旨も表示する。**
   - **docker-proxy**: 固定名 `claude-dev-docker-proxy` で識別する(ラベルを見ない)。
     ただし削除してよいかは手順8 の遊休判定で決める。
   - **`fwd-*` 中継コンテナは対象にしない**(現行実装の対象範囲を広げない。`logout` は認証を
     消すコマンドであり、中継コンテナの片付けは `stop` / `unforward` / `reset` の担当である)。
   - **`docker ps --filter ancestor=<イメージ>` による逆引きは使わない**(イメージ更新前に
     起動したコンテナを取りこぼし、かつラベルを持たない他人の資源を巻き込むため)。
5. **カレントディレクトリのプロジェクト配下の認証コピー**を削除対象に加える
   (`FR-env-03` 受入基準20)。対象は `$(pwd)/.claude/.credentials.json` /
   `$(pwd)/.claude/.claude.json` / `$(pwd)/.codex/auth.json` の**3ファイルだけ**である。
   ディレクトリ(`.claude/` `.codex/`)は消さない(`settings.json` や `host-hooks.json` など
   認証以外のものが入っている)。**他のディレクトリのコピーには触れない**
   (どこにあるかを本システムは知らず、知る手段も持たない)。
   存在しないファイルは対象から外す(`FR-env-03` 受入基準21)。
6. 手順4・5 の削除対象が0件で、**かつ手順4 の Claude コンテナの集合を引けており**、かつ共有ボリューム
   `claude-dev-auth` が**空であることを確認できた**ならば、削除対象が無いことを表示して終了コード 0 で
   終わる(`FR-env-03` 受入基準19。確認は求めない)。
   **「0件」は引けた結果が0件だったことであり、引けなかったことではない** — 引けなかった場合は
   この経路に入らず、その旨を表示して手順7 の確認へ進み、手順11 が失敗として列挙する。
   **「空であることを確認できた」の判定は3条件の論理積である**: 一時コンテナで
   **列挙の直前に印(`__CLAUDE_DEV_AUTH_LISTED__`)を出してから** `/auth` を列挙し、
   (i) **印が出ている**(= 一時コンテナが起動できた)、
   (ii) **一時コンテナの終了ステータスが 0**(= 列挙そのものが成功した)、
   (iii) **2行目以降が1行も無い**、の3つがすべて成り立つときだけ「空」と判定する。
   **印は一時コンテナの標準出力の1行目に現れる**(列挙の直前に1回だけ出し、`docker` 自身の警告は
   標準エラーへ出るので混ざらない)。したがって (i) は**1行目が印と一致すること**、
   (iii) は**2行目以降が空であること**で判定する。**行の位置で判定し、行の内容では判定しない**:
   内容で除くと `/auth/__CLAUDE_DEV_AUTH_LISTED__` という名前のファイル(またはディレクトリ)が
   印と区別できず、**中身があるのに空と判定される**。
   **どれか1つでも欠ければ「空」と判定しない**(daemon 断・イメージ欠落・マウント不能・
   `/auth` を読めない権限)。そのときは**この経路に入らず**、
   確かめられなかったことを表示して手順7 の確認へ進む(以後は手順7〜11 の経路であり、
   消去を確認できなければ手順10・11 が失敗として列挙し終了コード 1 で終わる)。
   **(ii) の終了ステータスは「列挙できたか」を表す**: 一時コンテナに渡すコマンドの**最後が列挙**なので、
   コンテナの終了ステータスは列挙の終了ステータスである。**手順10 も同じ条件を持つ**
   (手順10 は消去のあとに列挙するが、`rm -rf` は最後のコマンドではないのでその終了コードは
   コンテナの終了ステータスに現れない)。
   **印だけを見て終了ステータスを見ないと、印が出た直後に列挙が失敗した場合に
   「空だった」と読み替えてしまう**(印は一時コンテナの起動しか証明しない)。
   **印の有無を見ないと、起動できなかった場合と「空だった」場合がどちらも空出力になり、
   共有ボリュームに認証が残ったまま「削除対象がありません」を表示して 0 で終わる**
   (`FR-env-03` 受入基準19 が前提とする「共有ボリュームも空」を確かめないままこの経路に入る)。
   **docker-proxy はこの0件判定に数えない**(数えるのは手順4 の Claude コンテナと手順5 の
   認証ファイル、および共有ボリュームの中身だけである)。したがって**遊休の docker-proxy だけが
   残っている状態では、`logout` は手順9 の遊休判定に到達せずに 0 で終わり、proxy を残す**。
   害は「使われていない proxy が1つ残る」だけで、次回の `stop` / `reset` が回収する。
   **この経路に入る場合でも、手順4 で集めたラベル無しコンテナが1件以上あるなら、その名前と
   認証の書き戻しの警告を表示してから終わる**(受入基準19)。**表示するのは手順11 の出力のうち
   ラベル無しコンテナに関する部分だけ**(名前の列挙・停止中は列挙していない旨・書き戻しの警告)で、
   **削除結果の見出しと成功の文言は出さない** — 何も消していないためである。
   **手順4 の集合の問い合わせ自体が失敗していた場合は、その旨を表示する**
   (`claude-dev:1026` と同じ文言。**0件だったことと引けなかったことを同一視しない** —
   黙って何も出さないと、ラベル無しコンテナが無かったのか引けなかったのか区別できない)。
   **ラベル無しコンテナだけが稼働している状態は、書き戻しの前にこの経路へ入る** —
   前回の `logout` が共有ボリュームを空にした直後はまだ空なので0件と判定され、
   稼働中のコンテナが 30 秒ごとに認証を書き戻すと以後は空でなくなる(**書き戻しが済んだ後は
   共有ボリュームが空であることを確認できないので、この経路には入らず手順7 の確認へ進む**)。
   ここで黙ると利用者は `logout` の効果が戻る理由に到達できない。
7. 確認を取る(`FR-env-03` 受入基準 14〜16)。
   - 手順4 で列挙した**削除対象のコンテナ名**と、手順5 で挙げた**プロジェクト配下の認証ファイルの
     パス**を1行ずつ表示し、共有ボリュームの認証が消えることを明示して `(y/N)` を求める。`y` / `Y` 以外の入力なら**何も削除せず**終了コード 0 で終わる。
   - **標準入力が TTY でなく、`--yes` も指定されていないなら中止する**: `--yes` の指定方法を
     表示して終了コード 1 で終わる(黙って 0 を返さない)。
   - `--yes` が指定されていれば確認を飛ばす。
8. 手順4 の Claude コンテナを1件ずつ `docker rm -f` し、**1件ごとに終了コードを記録する**
   (`|| true` で握るだけにしない)。
9. **docker-proxy は遊休判定を通してから消す**(契約の規則C。`FR-env-01` 受入基準9)。
   `claude-dev-net` に接続している稼働中コンテナから、名前が `claude-dev-docker-proxy` のものと
   名前が `fwd-` で始まるものを除いた集合が**空のときだけ** docker-proxy を削除する。
   空でなければ docker-proxy を残し、**残した理由(稼働中のコンテナ名)を表示する**。
   手順8 で管理ラベルを持たない Claude コンテナを消さずに残しているため、**この判定は空にならない
   ことがある**。判定の問い合わせが失敗したときは遊休でないと判定して残す(安全側)。
   **削除を試みた場合はその終了コードを記録する**(`FR-env-03` 受入基準18)。
   **遊休でないと判定して残した場合は失敗に数えない**(削除しないと決めたものである)。
10. `claude-dev-auth` をマウントした一時コンテナで `rm -rf /auth/* /auth/.*` を実行する。
   続けて同じ一時コンテナで、**列挙の直前に印(`__CLAUDE_DEV_AUTH_LISTED__`)を出してから**
   `/auth` の中身(隠しファイルを含む)を列挙する。**残ったものの判定は手順6 と同じく行の位置で行う**
   (1行目が印、2行目以降が残ったもの。内容で除くと印と同名のファイルを見落とす)。
   **印が出ていなければ一時コンテナ自体が起動できていない**(daemon 断・イメージ欠落・マウント不能)ので、
   「消去を確認できなかった」として**失敗に数え、その資源を「削除した資源」には記録しない**
   (消えたことを確認できていないため。契約の「破壊的操作の削除結果の記録」と `logging.md` の
   「破壊的操作の出力に共通して課す制約」)。**同じ資源を削除済みと失敗の両方に記録してはならない。**印の有無を見ないと、
   起動できなかった場合と「消去に成功して空になった」場合がどちらも空出力になり、
   **認証が1バイトも消えていないのに成功と報告される**。
   **判定は手順6 と同じ3条件の論理積である**: (i) 1行目が印である、
   (ii) **一時コンテナの終了ステータスが 0**(= 列挙そのものが成功した)、
   (iii) 2行目以降が1行も無い。**どれか1つでも欠ければ「消去を確認できた」と判定せず、失敗に数える**。
   **(ii) が `rm -rf` の終了コードでないことに注意する**: 渡すコマンドは
   `rm -rf …; echo 印; ls -A /auth` の順で、`rm -rf /auth/* /auth/.*` は `.` と `..` に当たって
   非0を返しうるが**最後のコマンドではない**ので、コンテナの終了ステータスには現れない。
   したがって終了ステータスは「列挙できたか」をそのまま表す。**列挙そのものが失敗した場合も
   「消去を確認できなかった」として扱う**(契約の「エラーケース」が課している。印が出た直後に
   列挙が失敗すると出力が印だけになり、**消去に成功して空になった場合と区別できない**)。
   **(iii) で2行目以降があれば、残ったパスを1件ずつ記録する。**
11. 手順**4**・5・8・**9**・10 で記録した失敗が1件以上あれば、**消えなかった資源(コンテナ名・
    docker-proxy・ボリューム内のパス・プロジェクト配下のパス・**引けなかった問い合わせ**)を1件ずつ
    列挙**し、終了コード 1 で終わる。成功時の文言は出さない
    (`FR-env-03` 受入基準18)。失敗が0件なら削除結果を表示して 0 で終わる。
    **「削除した資源」に挙げるのは消えたことを確認できた資源だけ**であり、消去を確認できなかった資源と
    削除しないと決めた資源は挙げない(`logging.md` の共通制約)。
    **手順4 で集めたラベル無しコンテナの表示は、失敗が1件以上あっても出す**(受入基準17 は削除の成否で
    条件づけていない。**まさに認証が書き戻される状況で警告が出ないことになる**ため、
    失敗の列挙とあわせて表示する)。
    手順5 のファイル削除も**1件ごとに終了コードを記録し、削除したパスを表示する**
    (`FR-env-03` 受入基準20)。
    **手順4 で削除対象から外したラベル無しコンテナは「失敗」に数えない**(削除しないと決めたもので
    あり、消えていないのは意図した結果である)。
12. **削除中に `INT` / `TERM` を受けた場合**は、進行中の1件を終えてから中断し、
    **この検査は手順10 の共有ボリューム消去の直後にも置く**(最後の削除のあとに検査が無いと、
    そこで中断しても成功の文言を出して 0 を返してしまう)。
    **そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙**して**終了コード 130** で終わる
    (契約の「エラーケース」)。成功時の文言は出さない。
13. ロックを解放する(`trap` により異常終了時も解放される)。

## 呼び出され方

- 契機: 利用者が `claude-dev logout [--yes]` を実行したとき。
- 前提条件: なし。
- 引数:

| 引数 | 型 | 必須 | 制約 | 実装が行う検証 |
|---|---|---|---|---|
| `--yes` | フラグ | 任意 | 確認プロンプトを飛ばす。**端末を持たない環境で実行する唯一の手段**である | 存在するかどうかだけを見る(値は取らない) |
| 上記以外の引数(位置引数 / 未知のフラグ) | — | — | **すべて無視する** | 検証しない |

**確認プロンプトが受理する入力**(`--yes` が無く、標準入力が TTY で、かつ削除対象が1件以上
あるときだけ出す。`read -p "実行しますか？ (y/N) " -n 1 -r`。**1文字だけ読む**。
**`reset` と同じ読み方に揃える** — 同じ受入基準(`FR-env-03` 受入基準14〜16)が両方に掛かるため):

| 入力 | 結果 |
|---|---|
| `y` / `Y` | 削除を実行する |
| それ以外の1文字(`n` / Enter / 空 / 任意の文字) | 「キャンセルしました」と表示して `exit 0`。**何も削除しない**(`FR-env-03` 受入基準14) |
| **非 TTY(標準入力がパイプ・リダイレクト)で `--yes` が無い** | **プロンプトを出さずに中止**し、`--yes` の指定方法を表示して **`exit 1`**(`FR-env-03` 受入基準15) |
| **削除対象が0件**(手順6。**共有ボリュームが空であることを印で確認できた場合に限る**) | プロンプトを出さない。対象が無い旨と、ラベル無しの稼働中コンテナがあればその名前と書き戻しの警告を表示して `exit 0`(`FR-env-03` 受入基準19) |

- 認可: CLI を実行できるホストユーザ。

## 連携先と連携内容

### MODULE-cli-common-lock

- 何のために呼ぶか: `start` の認証コピーと重なって**認証が空のままコンテナが起動する**
  (`docs/issues/020`)のを防ぐため。共有ボリュームを空にする操作なので共有資源単位のキーを取る。
- 何を渡すか: キー `shared` と操作名 `logout`。
- 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: **何も削除せず**、保持している操作名と再実行の方法を表示して非0で終わる。

### MODULE-cli-common-require-setup

- 何のために呼ぶか: 削除用の一時コンテナに使うイメージを保証するため。
- 何を渡すか: なし。
- 何を受け取るか: なし。
- **失敗したときどうなるか**: `set -e` で非0終了し、認証は消えない。ロックはまだ取っていない。

### MODULE-cli-common-container-exists

- 何のために呼ぶか: 列挙した各コンテナ(遊休判定を通した docker-proxy を含む)が削除の直前に実在するか
  を確かめ、既に消えているものを「削除できなかった」と誤って数えないため。
- 何を渡すか: コンテナ名。
- 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: 「存在しない」と判定され、その1件は削除をスキップする
  (**失敗としては数えない**)。

### MODULE-cli-common-destructive

- 何のために呼ぶか: 削除の予定・成功・失敗を1件ずつ記録し、最後にまとめて列挙するため
  (`FR-env-03` 受入基準18)。あわせて `INT` / `TERM` を進行中の1件を終えてから受けるため(同23)。
- 何を渡すか: 削除対象の表示名(手順4・5 で列挙したもの)と、`destructive_rm` へ渡す削除コマンド。
  呼び出し順は `destructive_plan`(手順4・5 の対象を出そろえる。`claude-dev:1120`-`:1123`)→
  `destructive_arm_interrupt`(`:1131`)→ `destructive_rm` → 区切りごとの
  `destructive_abort_if_interrupted`(最後は `:1206`)→ `destructive_report`。
  **`plan` が先である** — 中断の遅延を仕掛けるのは、対象が出そろって実際の削除に入る直前でよい。
- 何を受け取るか: 記録された結果。**`destructive_rm` は成否によらず 0 を返す**ので、
  失敗の有無は `_DESTRUCTIVE_FAILED` の要素数で判定する(手順11)。
- **失敗したときどうなるか**: 削除コマンドが失敗しても呼び出し元は落ちず、失敗が記録される。
  中断要求が来ていれば次の検査点で `exit 130` になり、**この機能がプロセスを終える**。

### MODULE-cli-common-net-other-running-containers

- 何のために呼ぶか: docker-proxy を消してよいかの遊休判定に使う集合を得るため(手順9)。
- 何を渡すか: なし(対象ネットワークは定数)。
- 何を受け取るか: `claude-dev-net` に接続している稼働中のコンテナ名。空なら遊休である。
- **失敗したときどうなるか**: 非0が返る。**遊休でないと判定して docker-proxy を残し**、
  判定できなかったことを表示する(安全側)。**残したものは失敗に数えない。**

### MODULE-cli-common-spawned-resources

- 何のために呼ぶか: **手順4 のラベル無しコンテナの表示集合から、セッション由来のコンテナを
  除くため**(契約の「残したものをどう列挙するか」が定める4つ目の除外)。**削除のためには呼ばない** —
  `logout` は規則 D を使わない(`D0-env-05` 項2)。
- 何を渡すか: 第1引数 `container`、第2引数 `label=claude-dev.role=spawned`
  (`reset` が同じ一覧を引くときと同じ引数である)。
- 何を受け取るか: `claude-dev.role=spawned` を持つコンテナ名の一覧。
- **失敗したときどうなるか**: 非0が返る。**除外を行わずに表示へ進み、ラベル無しコンテナを
  1件以上表示するときに、セッション由来のコンテナが混じっている可能性を添える**
  (安全側 — 引けなかったことを「0件」と読み替えない)。**表示するラベル無しコンテナが1件も無ければ
  添えない**: 除外を行わないことは表示集合を**過大にする方向にしか働かない**ので、集合が空なら
  引けなかったことの影響が無い。
  **削除には一切影響しない**ので失敗には数えない。**この扱いを定めるのは契約の
  「セッション由来の資源を引く問い合わせそのものが失敗した」であり、表示の内容は
  `logging.md`「ラベルを持たないコンテナの列挙に必要な問い合わせが失敗した」が正である。**

### 破壊の範囲と順序

**確認プロンプトがある**(`--yes` で飛ばせる。端末が無く `--yes` も無ければ何も削除せず
終了コード 1)。同意すると次の順で進む。

1. `require_setup`(イメージが無ければビルド。**ロックより前**で、失敗すると `set -e` で中止する)
2. **共有資源単位のロックを取る**(取れなければ何も削除せずに終了コード 1)
3. 削除対象を列挙する — **管理ラベル `claude-dev.managed=1` を持つ Claude コンテナだけ**
   (稼働中・停止中の両方、プロジェクトを問わない)、カレントディレクトリの認証3ファイル、
   共有ボリュームの中身。**ラベルを持たない Claude コンテナは対象に入れず、名前を表示して残す**
4. 確認を取る(対象が0件なら確認を求めず終了コード 0)
5. 管理ラベルを持つ Claude コンテナを1件ずつ `docker rm -f` し、**成否を1件ずつ記録する**
6. **遊休判定を通ったときだけ** docker-proxy を削除する
7. カレントディレクトリの認証3ファイルを削除する
8. 一時コンテナで `rm -rf /auth/* /auth/.*` を実行し、**印を出してから列挙**して成否を判定する

**手順5 の対象は「本システムが作った」Claude コンテナに限る**(イメージからの逆引きはしない)。
**`fwd-*` 中継コンテナと共有ネットワークには触れない。**

### 並行性

**共有資源単位のロックを、取得(手順3)から解放(手順13)まで保持する**
(`CTR-cli-container` の「排他(ロックキー)」)。**手順2 の `require_setup`(イメージのビルド)は
ロックより前なので保護されない**(冪等に作られる資源であり、契約が明示的に保護対象外としている)。
**待たない**ので、取得できなければ何も削除せずに終了コード 1 で終わる。

| 同時に起きること | 実際の結果 |
|---|---|
| 他プロジェクトのセッションが稼働中 | **管理ラベルを持つものは確認のうえ削除する**(削除対象として名前を列挙してから同意を求める)。**ラベルを持たないものは削除せず名前を表示して残す** |
| `logout` と `start` | **同じキーのロックで直列化される**。`start` は認証コピーからコンテナ作成の確定まで保持するので、**認証が空のまま起動する経路は閉じた**(`docs/issues/020`) |
| `logout` と `login` / `login-codex` | **同じキーのロックで直列化される**。ログインは対話の全区間で保持するため、その間 `logout` は取得できずに終了コード 1 で終わる |
| **ラベルを持たないコンテナを残したまま `logout` した** | **保護されない。** コンテナ内の同期ループが 30 秒ごとに認証を共有ボリュームへ書き戻すため、**最大 30 秒で認証が復活する**。ロックはホスト CLI のプロセス間だけで有効でコンテナ内のループには届かない。**この可能性を警告として表示する**(確実に消すには先に `claude-dev stop <name>` で止める) |
| 利用者が直接 `docker rm -f` する | **保護されない** |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| **共有資源単位のロックを取得できない** | 保持している操作名と PID、再実行の方法を stderr へ出し、**何も削除せずに** `exit 1` | `start` の認証コピーと重なって**認証が空のまま起動する**ことを防ぐ(`docs/issues/020`) |
| **標準入力が TTY でなく `--yes` も無い** | **プロンプトを出さずに中止**し、`--yes` の指定方法を stderr へ出して `exit 1` | 自動実行で「何もしなかった」ことに気づける(`FR-env-03` 受入基準15) |
| 確認プロンプトで `y` / `Y` 以外を入力した | 「キャンセルしました」と表示して `exit 0`。**何も削除しない** | なし(受入基準14) |
| **削除対象が0件**(管理ラベル付きコンテナが無く、**共有ボリュームが空であることを確認でき**、カレントの認証コピーも無い) | **確認を求めず**、対象が無い旨を表示し、**ラベル無しの稼働中コンテナが1件以上あればその名前と書き戻しの警告も表示して** `exit 0`。**削除結果の枠と成功の文言は出さない** | 消すものが無いのに確認を求めない。かつ `logout` が効かない理由に到達できる(受入基準19) |
| **手順6 で共有ボリュームが空かどうかを確かめられなかった**(印が出ない = 一時コンテナを起動できなかった / 印は出たが列挙の終了ステータスが非0) | **「空」と判定しない。** 確かめられなかった旨を表示し、**0件の経路に入らず**手順7 の確認へ進む。非 TTY で `--yes` が無ければそこで `exit 1`、`--yes` があれば削除を試み、手順10 が消去を確認できないので `exit 1` | 認証が残っているのに `exit 0` で終わらない(受入基準19。**列挙が空で返ったことと確かめられなかったことを同一視しない** — 契約の「エラーケース」) |
| **セッション由来のコンテナの一覧を引けなかった**(`spawned_resources` が非0) | **除外を行わずにラベル無しコンテナの列挙を表示し**、セッション由来のコンテナが混じっている可能性を表示する。**失敗には数えない**(削除に影響しない) | 引けなかったことを「0件」と読み替えない(契約の「セッション由来の資源を引く問い合わせそのものが失敗した」) |
| **管理ラベルを持たない Claude コンテナがある** | **削除対象に入れない。** 名前と「本変更より前に起動した可能性がある」ことと「停止中のものは列挙していない」限界を表示して残す | 他プロジェクトの作業中セッションを落とさない(受入基準17) |
| 削除対象のコンテナが削除の直前に既に消えていた | `MODULE-cli-common-container-exists` が偽になり、その1件はスキップする。**失敗には数えない** | なし |
| **1件以上の削除に失敗した** | 消えなかった資源(コンテナ名・docker-proxy・ボリューム内のパス・プロジェクト配下のパス)を**1件ずつ列挙**して `exit 1`。**「削除しました」を出さない** | 認証が残っていることに気づける(受入基準18) |
| 一時コンテナの `rm -rf` が非0を返した | **終了コードを見ない。** 判定は削除後の `/auth` の列挙結果だけで行う(`rm -rf /auth/* /auth/.*` は `.` と `..` に当たって非0を返しうるが、`.` と `..` 以外のファイルは消えている) | 常に失敗扱いになることを避ける |
| `/auth` 直下に消せないものが残った | 残ったパスを1件ずつ列挙して `exit 1` | 認証が残っている |
| **手順4 の削除対象の Claude コンテナの集合を引けなかった** | **「0件」と判定しない。** 引けなかったことを表示し、0件の経路に入らずに手順7 の確認へ進む。手順11 で「消えなかった資源」として列挙して `exit 1` | 引けなかった集合の中に削除対象が残っている可能性を、成功と同じ終了コードで隠さない(受入基準19・18) |
| **手順10 の列挙そのものが失敗した**(印は出たが終了ステータスが非0) | 「消去を確認できなかった」として失敗に数える。**空出力を「消去に成功して空になった」と読み替えない** | 認証が残っていても成功と報告しない(契約の「エラーケース」) |
| **手順10 で消去を確認できなかった** | 「消去を確認できなかった」として失敗に数え、**その資源を「削除した資源」には記録しない**。同じ資源を削除済みと失敗の両方に出さない | 消えていないものを消したと表示しない(`logging.md` の共通制約) |
| **`/auth` に印(`__CLAUDE_DEV_AUTH_LISTED__`)と同名のファイルがある** | **中身として数える**(判定は印の行より後ろという**位置**で行い、行の内容では行わない) | 中身があるのに「空」と判定しない(手順6・手順10 の両方) |
| **削除に失敗した実行にラベル無しコンテナがある** | **失敗の列挙とあわせて名前と書き戻しの警告を表示する**(受入基準17 は削除の成否で条件づけていない) | 認証が書き戻される状況で警告が出ないことを防ぐ |
| **遊休判定の問い合わせが失敗した** | **遊休でないと判定して docker-proxy を残す**。判定できなかったことを表示する。**残したものは失敗に数えない** | 安全側に倒れる |
| **`claude-dev-net` に接続している稼働中コンテナが残っている** | docker-proxy を残し、残した理由(コンテナ名)を表示する。**失敗に数えない** | 残したコンテナの中から Docker が使え続ける(`FR-env-01` 受入基準9) |
| **削除中に `INT` / `TERM` を受けた** | **進行中の1件を終えてから**中断し、そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙して **`exit 130`**。成功の文言を出さない | 中途半端な状態が可視化される(受入基準23) |
| カレントディレクトリに認証コピーが無い | その項目を対象から外して続行する。**存在しないことを失敗に数えない** | なし(受入基準21) |
| ボリュームが存在しない | `docker run` がボリュームを自動作成し、空のまま終わる | なし |
| イメージが無い | `require_setup` がビルドする。ビルドに失敗すると `set -e` で非0終了し、**認証は消えない**(ロックはまだ取っていない) | 利用者はイメージを用意する |
