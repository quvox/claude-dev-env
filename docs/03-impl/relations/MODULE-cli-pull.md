# MODULE-cli-pull 配布イメージの取得

## 目的

ローカルビルドを避け、GHCR に日次で publish されたマルチアーキイメージを取得して使えるように
する(FR-env-09)。取得後に `latest` へ retag することで、以降の `start` /
`MODULE-cli-common-require-setup` がビルドを走らせずに済む。

## 処理の流れ

1. `.env` の `CLAUDE_DEV_REGISTRY`(既定 `ghcr.io/quvox`)と、タグ(**第1引数 > `CLAUDE_DEV_IMAGE_TAG` >
   `latest`** の優先順)から参照を組み立てる。**どちらも書式を検証しない。**
2. `claude-dev-claude` / `claude-dev-claude-vnc` / `claude-dev-docker-proxy` の3イメージを
   **この順に1本ずつ** `docker pull` する。manifest によりホストのアーキが自動選択される。
   **`docker pull` の成否だけを見る**(`if docker pull …; then`)。
3. 成功したものだけ `${name}:latest` へ `docker tag` し、成功フラグを立てる。
4. **失敗したものは警告1行を出して次のイメージへ進む**(中断しない)。
   警告文は `⚠️ <参照> の取得に失敗（存在しない/未ログイン/権限？）` の1種類だけで、
   **失敗の理由を区別しない**。
5. **1つでも成功していれば** 完了メッセージを出して 0 で終わる。**全部失敗した場合だけ**
   `docker login ghcr.io` を案内して `exit 1` する。

**タイムアウト・再試行・バックオフをこの機能は持たない。** `docker pull` の1回の実行に委ね、
その内部挙動(レイヤ単位の再試行など)は docker の実装に従う。

## 呼び出され方

- 契機: 利用者が `claude-dev pull [TAG]` を実行したとき。
- 前提条件: ネットワークが到達可能であること。private パッケージなら `docker login ghcr.io` 済み。
- 引数:

| 引数 | 型 | 必須 | 実装が行う検証 | 受理/拒否と結果 |
|---|---|---|---|---|
| `TAG` | 文字列 | 任意 | **検証しない** | 省略時は `CLAUDE_DEV_IMAGE_TAG`(既定 `latest`)。指定した文字列はそのまま参照に連結する |
| 第2引数以降 | — | — | — | **黙って無視する** |

**`TAG` の境界値の実際の扱い**:

| 入力 | 実際の結果 |
|---|---|
| `latest`(既定) | 日次ビルドの最新を取得する |
| `YYYYMMDDHHmm`(固定版) | その版を取得する |
| 存在しないタグ | 3本とも `manifest unknown` で失敗し、**全失敗の経路**(`exit 1`)になる |
| 空文字(`CLAUDE_DEV_IMAGE_TAG=""`) | シェルの `:-` 既定値が効き `latest` になる |
| タグとして不正な文字(`:` や空白を含む) | `docker pull` が参照の解析に失敗する。**他の失敗と同じ警告文**になる |

- 認可: CLI を実行できるホストユーザ。

## 連携先と連携内容

連携先なし(GHCR への `docker pull` は外部コマンド実行であり機能間の辺には現れない)。

## 戻り値・副作用

| 種別 | 内容 |
|---|---|
| 戻り値 | 1つ以上成功で 0、全失敗で 1 |
| 永続化 | ローカルイメージ `claude-dev-claude` / `claude-dev-claude-vnc` / `claude-dev-docker-proxy`(いずれも `:latest` タグ) |
| 発火するイベント | なし |
| ログ | 標準出力へ取得結果。失敗時は stderr へ `docker login ghcr.io` の案内 |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| **未ログイン / 権限不足(401 / 403)** | 警告1行を出して次のイメージへ。**タグ不存在・通信断と区別しない** | 全失敗なら `docker login ghcr.io` を案内して `exit 1` |
| **タグが存在しない(manifest unknown)** | 同上 | 同上 |
| **レート制限(429)** | 同上。**待ち直しも再試行もしない** | 同上 |
| **通信断・名前解決失敗・タイムアウト** | 同上。**この機能はタイムアウトを設定しない**(docker の既定に従う) | 同上 |
| 一部のイメージだけ取得できた | 取得できたものだけ retag し、**完了扱い(0)**にする | 残りは `require_setup` がローカルビルドする。**その結果、GHCR 版とローカルビルド版が混在しうる** |
| 全イメージの取得に失敗 | `docker login ghcr.io` を案内して `exit 1` | 利用者はログインするかローカルビルドへ切り替える |
| `docker tag` が失敗した | 戻り値は検査しないが、**`set -e`(`claude-dev:8`)により失敗した時点でスクリプトが非0終了する**(`_pull_ok=1` にも完了メッセージにも到達しない) | 非0終了する。**どのイメージの付け替えが失敗したかを示す専用メッセージは出ない** |
| 取得の途中で中断した(Ctrl-C) | 取得済みのレイヤは docker のキャッシュに残る。retag は行われない | 再実行でキャッシュから続きを取得する |

## 既知の制限

| 制限 | 影響 | 関連 issue |
|---|---|---|
| retag のためローカルビルド版と GHCR 版が同名で混在しうる | 稼働中コンテナのユーザ差異は `MODULE-cli-common-resolve-container-user` が吸収する | なし(閾値の外: `start` が使用イメージのバージョンを表示する=**気づける**) |
| 失敗の理由を区別しない | レート制限や一時的な通信断でも「存在しない/未ログイン/権限？」と表示され、利用者が誤った対処をする | なし(閾値の外: 失敗そのものは警告行と非0終了で**その場で気づける**) |
| 部分成功を成功として扱う | 3イメージのバージョンが揃わないまま `start` できる(`docs/03-impl/infra/local/ghcr.md` の「部分取得」) | なし(閾値の外: **`FR-env-09` 受入基準10 が要件として明文化した**(2026-08-04 の裁定=実装が正)) |
| 付け替えの失敗に専用のメッセージが無い | `set -e` で非0終了はするが、どのイメージで失敗したかは表示されない(docker のエラーがそのまま出る) | なし(閾値の外: **非0終了するので利用者はその場で気づける**。`FR-env-09` 受入基準11 は満たしている) |
| 再試行・バックオフを持たない | 一時的な失敗でも即座に案内へ倒れる | なし(閾値の外: 失敗は表示され非0終了する=**その場で気づける**) |
