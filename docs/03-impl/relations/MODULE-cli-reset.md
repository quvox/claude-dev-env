# MODULE-cli-reset 全リセット

## 目的

環境を作り直したいときに、本システムが作った Docker 資源をまとめて消す(FR-env-01)。
認証も共有ボリュームごと消える(FR-env-03)。

## 処理の流れ

1. 引数を解析する(`--yes` のみ。それ以外は無視する)。
2. `MODULE-cli-common-lock` で**共有資源単位**のロック(キー `shared`、操作名 `reset`)を取る。
   取得できなければ**削除を一切行わずに**非0で終わる(`FR-env-01` 受入基準16)。
3. 削除対象を列挙して表示する。**コンテナ・`fwd-*`・ボリューム・イメージは実在するものだけを
   1行ずつ挙げる**が、**docker-proxy と `claude-dev-net` の2つは実在を確かめずに常に
   「(遊休のときだけ)」という但し書き付きの候補行として出す**(`claude-dev:1997`〜`:1998`)。
   実在しなければ手順6・7 で `skipped` になり失敗には数えない。
   - **Claude コンテナ**: 管理ラベル `claude-dev.managed=1` を持つものだけ(契約 `CTR-cli-container` の
     規則A)。**イメージからの逆引きは使わない。** 管理ラベルを持たないものは削除対象に入れず、
     その名前と「本変更より前に起動した可能性がある」ことを別枠で表示する
     (`FR-env-03` 受入基準17)。
   - **`fwd-*` 中継コンテナと docker-proxy**: 名前(接頭辞 `fwd-` / 固定名
     `claude-dev-docker-proxy`)で識別する。ラベルを見ない。**docker-proxy の削除は手順6 の
     遊休判定を通ったときだけ**。
   - **ボリューム**: `claude-dev-auth` / `claude-dev-history` / `claude-dev-config` と
     `claude-dev-chrome-*`(名前が本システムのものであることは名前で一意に決まるため、ラベルによる
     絞り込みの対象にしない)。
   - **ネットワーク**: `claude-dev-net`(**ただし削除は手順6 の遊休判定を通ったときだけ**)。
   - **イメージ**: `claude-dev-claude` / `claude-dev-claude-vnc` / `claude-dev-docker-proxy`。
4. 確認を取る(`FR-env-03` 受入基準 14〜16)。
   - 手順3 の一覧を表示して `(y/N)` を求める。`y` / `Y` 以外の入力なら**何も削除せず**
     終了コード 0 で終わる。
   - **標準入力が TTY でなく、`--yes` も指定されていないなら中止する**: `--yes` の指定方法を
     表示して終了コード 1 で終わる(`claude-dev:2007`〜`:2011`)。自動実行で「何もしなかった」ことに
     気づけるようにするためである(`FR-env-03` 受入基準15)。
   - `--yes` が指定されていれば確認を飛ばす。
5. 手順3 の**コンテナ**を削除し、**1件ごとに終了コードを記録する**(`|| true` で握るだけにしない)。
6. **docker-proxy と共有ネットワーク `claude-dev-net` は遊休判定を通してから消す**
   (契約 `CTR-cli-container` の規則C。`FR-env-01` 受入基準9)。
   `claude-dev-net` に接続している稼働中コンテナから、名前が `claude-dev-docker-proxy` のものと
   名前が `fwd-` で始まるものを除いた集合が**空のときだけ**両方を削除する。
   **手順3 でラベルを持たない Claude コンテナを残しているため、この判定は空にならないことがある。**
   空でなければ docker-proxy と `claude-dev-net` を残し、**残した理由(稼働中のコンテナ名)と
   「完全な初期化にはなっていない」ことを表示**して、残りの削除(ボリューム・イメージ)を続行する。
   判定の問い合わせが失敗したときは遊休でないと判定して残す(安全側)。
7. **ボリューム → イメージ**の順に削除し、**1件ごとに終了コードを記録する**。
   全体の順序は コンテナ → docker-proxy と `claude-dev-net`(遊休なら)→ ボリューム → イメージ で
   固定する(使用中の参照を先に外す)。
8. 記録した失敗が1件以上あれば、**消えなかった資源を1件ずつ列挙**し、終了コード 1 で終わる。
   **このとき**成功時の文言(「全リセット完了」)は出さない(`FR-env-03` 受入基準18)。
   **手順6 で意図して残した docker-proxy と `claude-dev-net` は「失敗」に数えない**
   (残すと決めたものである)。**失敗が0件なら完了を表示して 0 で終わる**: 手順6 で共有資源を
   削除できた(= 遊休だった)なら「全リセット完了」、残したなら「削除を完了しました
   (共有資源を残したため、完全な初期状態には戻っていません)」を出す。
9. **削除中に `INT` / `TERM` を受けた場合**は、進行中の1件を終えてから中断し、
   **そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙**して**終了コード 130** で終わる
   (契約の「エラーケース」)。成功時の文言は出さない。
10. ロックを解放する(`trap` により異常終了時も解放される)。

## 呼び出され方

- 契機: 利用者が `claude-dev reset [--yes]` を実行したとき。
- 前提条件: なし。**対象を絞る引数は無く、常にホスト全体の claude-dev 資源(管理ラベルを持つもの)が
  対象**である(カレントディレクトリは関係しない)。
- 引数:

| 引数 | 型 | 必須 | 制約 | 実装が行う検証 |
|---|---|---|---|---|
| `--yes` | フラグ | 任意 | 確認プロンプトを飛ばす。**端末を持たない環境で実行する唯一の手段**である | 存在するかどうかだけを見る(値は取らない) |
| 上記以外の引数(位置引数 / 未知のフラグ) | — | — | **すべて無視する** | 検証しない |

**確認プロンプトが受理する入力**(`--yes` が無く、標準入力が TTY のときだけ出す。
`read -p "実行しますか？ (y/N) " -n 1 -r`。**1文字だけ読む**。現行実装の読み方を変えない
= `D0-scope-02`。`logout` も同じ読み方に揃える):

| 入力 | 結果 |
|---|---|
| `y` / `Y` | 削除を実行する |
| それ以外の1文字(`n` / Enter / 空 / 任意の文字) | 「キャンセルしました」と表示して `exit 0`。**何も削除しない**(`FR-env-03` 受入基準14) |
| **非 TTY(標準入力がパイプ・リダイレクト)で `--yes` が無い** | **プロンプトを出さずに中止**し、`--yes` の指定方法を表示して **`exit 1`**(`FR-env-03` 受入基準15)。**`yes y \| claude-dev reset` のように標準入力へ流し込む形は受け付けない**(端末を持たない環境で実行する手段は `--yes` だけである) |

- 認可: CLI を実行できるホストユーザ。

## 連携先と連携内容

### MODULE-cli-common-lock

- 何のために呼ぶか: `start` の**認証コピーから `docker run` の完了まで**の区間と重なって、
  認証コピー済みのコンテナが直後に消される・認証が空のまま起動する(`docs/issues/020`)のを防ぐため。
  共有ボリュームとイメージまで消す操作なので共有資源単位のキーを取る。
  `start` が同じキーを `docker run` の完了まで保持する(`MODULE-cli-start` 判断9)ので、
  **`reset` はコンテナ作成との競合まで防げる**。
- 何を渡すか: キー `shared` と操作名 `reset`。
- 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: **何も削除せず**、保持している操作名と再実行の方法を表示して非0で終わる。

### MODULE-cli-common-container-exists

- 何のために呼ぶか: 列挙した各コンテナが削除の直前に実在するかを確かめ、既に消えているものを
  「削除できなかった」と誤って数えないため(手順5)。
- 何を渡すか: コンテナ名。 / 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: 「存在しない」と判定され、その1件は削除をスキップする
  (**失敗としては数えない**)。

### MODULE-cli-common-image-exists

- 何のために呼ぶか: 削除対象のイメージを列挙するとき、存在しないイメージを対象に入れないため
  (手順3)。`docker rmi` は存在しないイメージに対して非0を返すので、入れると常に失敗扱いになる。
- 何を渡すか: イメージ名(`claude-dev-claude` / `claude-dev-claude-vnc` / `claude-dev-docker-proxy`)。
  / 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: 「存在しない」と判定され、そのイメージは削除対象から外れる。

## 戻り値・副作用

| 種別 | 内容 |
|---|---|
| 戻り値 | **0**(列挙した削除対象がすべて消えたか、意図して残したものだけが残ったとき)。**1**: ロックを取得できない / 端末が無く `--yes` も無い / **削除できなかった資源が1件以上ある**。**130**: 削除中に `INT` / `TERM` を受けた。**0**: 確認プロンプトで `y`/`Y` 以外を入力した(何も削除しない) |
| 永続化 | **破壊的**: **管理ラベル `claude-dev.managed=1` を持つ Claude コンテナ**と `fwd-*` 中継コンテナを削除する(ラベルを持たない Claude コンテナは残す)。**遊休のときだけ** `claude-dev-docker-proxy` と共有ネットワーク `claude-dev-net` を削除する。docker volume `claude-dev-auth` / `claude-dev-history` / `claude-dev-config` / `claude-dev-chrome-*` を削除する。イメージ `claude-dev-claude` / `claude-dev-claude-vnc` / `claude-dev-docker-proxy` を削除する。ロックのシンボリックリンク `${HOME}/.claude-dev/locks/shared.lock` を作成・削除する。**プロジェクト配下のファイルには触れない** |
| 発火するイベント | なし |
| ログ | 標準出力へ削除対象の一覧・確認プロンプト・削除した資源の列挙・残したラベル無しコンテナの名前・共有資源を残した理由と「完全な初期化になっていない」旨。削除失敗の列挙と中断の報告、ロックの取得失敗は stderr |

### 並行性

**共有資源単位のロックを全区間で保持する**(`CTR-cli-container` の「排他(ロックキー)」)。
**待たない**ので、取得できなければ何も削除せずに終了コード 1 で終わる。
削除は次の順で行い、**各ステップは失敗を1件ずつ記録して次へ進む**(握りつぶさない)。

1. 管理ラベルを持つ Claude コンテナ → 2. `fwd-*` → 3. **遊休なら** docker-proxy と
`claude-dev-net` → 4. 共有ボリューム3本と `claude-dev-chrome-*` → 5. イメージ3本

| 同時に起きること | 実際の結果 |
|---|---|
| 他プロジェクトのコンテナが稼働中 | **管理ラベルを持つものは削除する**(確認プロンプトで対象を列挙してから)。**ラベルを持たないものは削除せず名前を表示して残す**。**そのため docker-proxy と `claude-dev-net` は遊休判定を通らず残り、「完全な初期化になっていない」ことを表示する** |
| `reset` と `start` | **同じキーのロックで直列化される**。`start` は認証コピーからコンテナ作成の確定まで保持するので、**認証コピー済みのコンテナが直後に消される経路は閉じた**(`docs/issues/020`) |
| `reset` と `login` / `login-codex` | **同じキーのロックで直列化される**。ログインは対話の全区間で保持するため、その間 `reset` は取得できずに終了コード 1 で終わる |
| `reset` を2つ同時 | **後発はロックを取得できず、何も削除せずに終了コード 1 で終わる** |
| 利用者が直接 `docker rm -f` / `docker volume rm` する | **保護されない**(ロックはホスト CLI のプロセス間だけで有効) |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| **共有資源単位のロックを取得できない** | 保持している操作名と PID、再実行の方法を stderr へ出し、**何も削除せずに** `exit 1` | `start` の認証コピー〜コンテナ作成の区間と重なる削除を防ぐ(`docs/issues/020`) |
| **標準入力が TTY でなく `--yes` も無い** | **プロンプトを出さずに中止**し、`--yes` の指定方法を stderr へ出して `exit 1`(`claude-dev:2007`〜`:2011`)。**何も削除しない** | 端末を持たない環境で `reset` を実行する手段は `--yes` だけである(`FR-env-03` 受入基準15) |
| 確認プロンプトで `y` / `Y` 以外を入力した | 「キャンセルしました」と表示して `exit 0`。**何も削除しない** | なし(受入基準14) |
| **管理ラベルを持たない Claude コンテナがある** | **削除対象に入れない。** 名前と「本変更より前に起動した可能性がある」ことを表示して残す | 他プロジェクトの作業中セッションを落とさない(受入基準17) |
| **`claude-dev-net` に接続している稼働中コンテナが残っている** | **docker-proxy と `claude-dev-net` を残し**、残した理由(コンテナ名)と**「完全な初期化になっていない」**旨を表示して、ボリューム・イメージの削除を続行する。**残したものは失敗に数えない** | 残したコンテナの中から Docker が使え続け、名前解決も壊れない(`FR-env-01` 受入基準9) |
| **遊休判定の問い合わせが失敗した** | **遊休でないと判定して docker-proxy と `claude-dev-net` を残す**。判定できなかったことと「完全な初期化になっていない」旨を表示して続行する | 安全側に倒れる |
| 削除対象のボリュームやイメージが存在しない | 列挙の時点で対象から外す(`docker volume inspect` / `MODULE-cli-common-image-exists` で実在を確かめる)。**失敗に数えない** | 存在しないものを「削除できなかった」と誤って数えない |
| 削除対象のコンテナが削除の直前に既に消えていた | `MODULE-cli-common-container-exists` が偽になり、その1件はスキップする。**失敗には数えない** | なし |
| **1件以上の削除に失敗した**(使用中のボリュームなど) | 消えなかった資源を**1件ずつ列挙**して `exit 1`。**「全リセット完了」を出さない** | 残骸に気づける(受入基準18) |
| **削除中に `INT` / `TERM` を受けた** | **進行中の1件を終えてから**中断し、そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙して **`exit 130`**。成功の文言を出さない | 中途半端な状態が可視化される(受入基準23) |
| VM モードのボリューム `claude-dev-vm-<name>` | **削除対象に含まれない** | ゲストディスクは残る(`docs/issues/047`) |
| macOS の専用 agent / ブリッジ | **削除対象に含まれない**(掃除は `ssh-keys reset` が担う) | 残骸が残る |
| プロジェクト側の `.claude/` `.codex/` `.claude-dev.yaml` | **削除対象に含まれない**(`FR-env-03` 受入基準22。`logout` との非対称は `D0-env-08` 項4 が明示する) | 認証ファイルのコピーはプロジェクト配下に残る |

## 実装上の判断

| # | 判断内容 | 根拠(委任ID) |
|---|---|---|
| 1 | 破壊的操作なので確認プロンプトを必須にする | D0-scope-02 / D0-env-08 項3 |
| 2 | プロジェクト側の `.claude/` `.codex/` `.claude-dev.yaml` は消さない(`FR-env-03` 受入基準22)。**`logout` は認証3ファイルを消すようになったので非対称が生じるが、意図した非対称である**: `reset` は対象を絞る引数を持たず「ホスト全体」を対象にするため、**どのディレクトリのコピーを消すべきかを決められない**(カレントディレクトリは `reset` の対象範囲と無関係である)。全ディレクトリを探索するのは利用者のファイルシステム全体の走査になる。この非対称は `D0-env-08` 項4 が明示している | D0-scope-02 / D0-env-08 項4 |
| 3 | **Claude コンテナ**の列挙だけを管理ラベルで行う(イメージからの逆引きをやめる)。**`fwd-*` / docker-proxy / ボリューム / ネットワーク / イメージは名前で列挙する**: これらは本システムが決めた固定名または固定接頭辞であり名前だけで一意に決まるため、ラベルを足す意味が無い(既存のものにラベルが無いという移行問題も起こさない) | D0-env-10 |
| 4 | 削除の成否を**1件ごとに記録**し、最後にまとめて判定する(1件目の失敗で止めない)。**ただし失敗を握って「完了」と表示することはしない** | D0-env-08 項5 が定める形の実装。分岐の置き方は D0-scope-02 |
| 5 | 非 TTY で `--yes` が無い場合の終了コードを **1 とする**(0 で終わると自動実行で「何もしなかった」ことに気づけず、`D0-scope-07` の観測点の定義で「利用者が失敗に気づけない」に当たる)。**端末を持たない環境で実行する手段は `--yes` に限る**(標準入力へ `y` を流し込む形は受け付けない) | D0-env-08 項3 / `FR-env-03` 受入基準15 |
| 6 | 削除順序を **コンテナ → docker-proxy と `claude-dev-net`(遊休なら)→ ボリューム → イメージ**に固定する(使用中の参照を先に外さないと後段が必ず失敗するため)。**この順序は固定** | D0-scope-02 |
| 7 | **docker-proxy と `claude-dev-net` に遊休判定を通す**(手順6)。`reset` は「全消し」コマンドだが、手順3 で**ラベルを持たない Claude コンテナを残す**ため、共有資源を無条件に消すと残したコンテナの中から Docker が使えなくなり名前解決も壊れる(`FR-env-01` 受入基準9 違反)。`D0-env-08` 項2 は例外を書いておらず、`logout` に同じ理由で既に広げてある。**代償として `reset` が完全な初期状態に戻らないことがある**ので、その旨を表示する | `D0-env-08` 項2 / `FR-env-01` 受入基準9 / D0-env-10 |
| 8 | **`INT` / `TERM` は進行中の1件を終えてから受ける**(手順9)。1件の削除を途中で切ると、より中途半端な状態が残る。終了コード 130 は SIGINT の慣行値 | `D0-env-08` 項5 / 契約の「エラーケース」 |
| 9 | Linux 版・macOS 版の**両方に同じ形で**入れる(同じサブコマンドの成否・出力を OS で変えないため) | D0-scope-03 |
| 10 | **削除コマンドを `( trap '' INT TERM; ... )` のサブシェルで起動する**(理由は `MODULE-cli-logout` 判断13 と同じ) | `D0-env-08` 項5 / D0-scope-03 |
| 11 | **遊休判定の問い合わせに失敗したときは、ラベル無しコンテナの列挙ができなかったことを明示する**。何も出さないと、利用者は「管理ラベルを持たないコンテナは1つも無かった」と読み違える(`logout` は同じ状況で告知しており、揃えないと同じ判断で表示が変わる) | D0-scope-03 の趣旨 / `/implement` の独立レンズが検出 |
| 12 | **削除対象の列挙を「実在するものだけ」に絞る**(ボリュームは `docker volume inspect`、イメージは `MODULE-cli-common-image-exists`、コンテナは削除直前に `MODULE-cli-common-container-exists`)。`docker volume rm` / `docker rmi` / `docker rm` は存在しない対象に対して非0を返すため、実在確認を挟まないと**毎回「削除できなかった資源」が列挙されて終了コード 1 になり**、受入基準18 の判定が常に真になって成功の判定が成立しない | D0-env-08 項5 が定める形の実装。判定手段は D0-scope-02 |

## 既知の制限

| 制限 | 影響 | 関連 issue |
|---|---|---|
| **VM ボリューム `claude-dev-vm-*` と macOS の agent 残骸を消さない** | 完全な初期化にはならない | `docs/issues/047`(対象範囲の拡大は別の判断) |
| **管理ラベルを持たない Claude コンテナを消さない** | 管理ラベルが付く前に起動されたコンテナが残り、そのぶん共有資源も残るので**「全リセット」にならないことがある** | なし(閾値の外: 名前を**表示する**ので気づけ、`claude-dev stop <name>` で1件ずつ消せる) |
| **共有資源(docker-proxy / `claude-dev-net`)を遊休でないときに残す** | `reset` を実行しても完全な初期状態に戻らないことがある。**その旨を表示する** | なし(閾値の外: 残したコンテナの足元を抜かないための意図した代償。`MODULE-cli-reset` 判断7) |
| **遊休判定に利用者の compose コンテナが入る** | 利用者がコンテナ内から `docker compose` を使っていると**毎回**「完全な初期化になっていない」になる。**過剰に数える=消さない側**なので受入基準9 は破らない | なし(2026-08-04 の決定シート #1 で人間が案A=現状のままと裁定) |
| **共有ネットワーク `claude-dev-net` が存在しないと遊休判定が「問い合わせ失敗」になり、docker-proxy を消せない** | ネットワークだけを手で消した状態では、`reset` を何度実行しても docker-proxy が残る | なし(閾値の外: 契約「エラーケース」が「ネットワークが存在しない」を失敗として扱うと定めており、実装はそのとおり。残した理由を表示する) |
| **集合削除の各要素は他プロセスのプロジェクト単位ロックと排他になっていない** | 並行する `stop <name>` が同じコンテナを先に消すと「削除できなかった」と報告しうる | なし(閾値の外: `MODULE-cli-logout` の同項と同じ理由) |
| **プロジェクト配下の認証コピーを消さない**(`logout` との非対称) | `reset` 後も古い認証がプロジェクト側に残る | なし(閾値の外: `reset` は対象を絞る引数を持たず、どのディレクトリを触るべきか決められない。`D0-env-08` 項4 が明示。`logout` で消せる) |
