# MODULE-makefile-clean make clean

## 目的

ホスト側からの全リセット(FR-env-01)。認証ボリュームも消えるため再ログインが要る(FR-env-03)。

## 処理の流れ

1. 削除対象の種別を列挙して表示し、`read -p "実行しますか？ (y/N) "` で確認する。`y` 以外なら
   「キャンセル」と表示して `exit 1`(**種別の列挙であり、個々のコンテナ名は挙げない**。
   名前の列挙を求めるのは `D0-env-08` 項3 で、対象は `logout` / `reset` の2つである)。
2. Claude コンテナ(停止中を含む)を `docker rm -f` する。**列挙の条件は
   `--filter label=claude-dev.managed=1` と `--filter ancestor=claude-dev-claude` /
   `--filter ancestor=claude-dev-claude-vnc` と `--filter name=^fwd-` の和集合**である
   (いずれも `docker ps -a`。集合の求め方は `CTR-cli-container`「稼働中セッションの一覧の列挙」が
   正)。**`claude-dev-net` への接続は条件にしない**(利用者が手で繋いだコンテナを消すことになる)。
3. `claude-dev-docker-proxy` を `docker rm -f` する。
4. `claude-dev-auth` / `claude-dev-history` / `claude-dev-config` / `claude-dev-chrome-data` を
   `docker volume rm -f` する。
5. docker network `claude-dev-net` を削除する。
6. 3イメージを `docker rmi -f` する。
7. 手順2〜6 はすべて `2>/dev/null || true` で握りつぶす。

## 呼び出され方

- 契機: 利用者が `make clean` を実行したとき。
- 前提条件: リポジトリのルートで実行すること(`BASE_DIR` は Makefile の位置から解決する)。
- 引数: なし(変数で調整する場合は下表)。

- 認可: リポジトリを操作できるホストユーザ。

## 戻り値・副作用

| 種別 | 内容 |
|---|---|
| 戻り値 | 0(キャンセル時は 1) |
| 永続化 | **破壊的**: 全 Claude コンテナ・docker-proxy・共有4ボリューム(認証を含む)・docker network・3イメージの削除 |
| 発火するイベント | なし |
| ログ | 削除対象の一覧と完了メッセージ |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| 確認に `y` 以外を入力 | 「キャンセル」と表示して `exit 1` | 何も削除されない |
| 削除が失敗する(使用中など) | 握りつぶして次へ進み、最後に「✅ 全リセット完了」と表示する(**誤った成功表示**) | 残骸が残る |
| `fwd-*` の中継コンテナ | **名前の接頭辞で引くため削除される**(`$IMG_CLAUDE` から起動するのでイメージ条件にも合致するが、イメージを作り直した後は名前だけが残る条件である) | なし |
| コンテナ別 Chrome ボリューム `claude-dev-chrome-<name>` | **削除対象に含まれない**(消すのは `claude-dev-chrome-data` のみ) | 残骸が残る |

## 実装上の判断

<!-- 2026-08-20 に既存1行を読み直し、**継続**と判断した(書式は delegation.md §3 へ揃えた)。 -->

- [D0-scope-02] Makefile はホスト側の開発者向け入口に限定し、日常操作は `claude-dev` CLI に寄せる(2026-08-02 の判断を継続) — 理由: 2026-08-02 の記録に理由は残っていない。継続する理由は、同じ操作を `claude-dev` 側が既に持っており、両方を保守すると同じ振る舞いを2箇所で決めることになるためである / 見直す条件: Makefile にしか無い操作が日常操作になったとき
- [D0-env-10] 削除対象の列挙を**管理ラベルとイメージと固定接頭辞 `fwd-` の和集合**にする(**2026-08-20 に追加**) — 理由: イメージだけでは `latest` が別のイメージ ID を指した後に、それ以前に起動したコンテナを削除し残す(`docs/histories/2026-08-20-fix-session-list-undercount.md`)。`make clean` は `D0-env-08` の破壊的操作(`stop` / `logout` / `reset`)ではないため規則 A(ラベルを持たないものは残す)は掛からないが、**和集合が新たに加えるのは本システムが付けた印を持つコンテナだけ**であり、削除の範囲は「本システムが作ったもの」から広がらない / 見直す条件: `make clean` を `D0-env-08` の破壊的操作の定義に加えると 00 が決めたとき(そのときは規則 A に従い、印を持たないものは名前を表示して残す)
- [DS-05] 問い合わせ3回の結果を `awk` で畳んで和集合を作る — 理由: `docker ps` は同じ `--filter` キーの複数指定を論理和にするが、キーが違うものは論理積にするため、ラベル・イメージ・名前接頭辞の和集合は問い合わせを分けて畳む以外に得られない。`Makefile` はシェル関数を呼べない(レシピの各行が別のシェルである) / 見直す条件: `docker ps` がフィルタ間の論理和を直接受け付けるようになったとき
