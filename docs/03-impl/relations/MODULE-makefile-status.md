# MODULE-makefile-status make status

## 目的

ホスト側から現在の状態を1コマンドで俯瞰する(FR-env-01)。

## 処理の流れ

1. `docker images` を3イメージの `reference` フィルタで絞って表示する。
2. 実行中の Claude セッションを表示する。**列挙の条件は `--filter label=claude-dev.managed=1` と
   `--filter ancestor=claude-dev-claude` / `--filter ancestor=claude-dev-claude-vnc` の和集合**で
   あり、そこから**名前が `fwd-` で始まる中継コンテナを除く**(集合の求め方は `CTR-cli-container`
   「稼働中セッションの一覧の列挙」が正。`claude-dev list` と同じ集合である)。該当が0件のときは
   その旨を1行表示する。
   **2つの問い合わせはそれぞれ別の変数へ受け、代入の終了コードを1つの旗(`q_failed`)へ畳む**
   (パイプへ直接つなぐと `awk` の終了状態が `docker ps` の非ゼロを消す)。
   **旗が立っているときは一覧より前に警告を1行出し、引けた分の表示は続ける**
   (同契約「エラーケース」。文言は `claude-dev list` と同一である)。
3. `docker ps --filter "name=^claude-dev-docker-proxy$"` で proxy の状態を表示する。
4. `docker volume ls --filter "name=claude-dev"` でボリュームを表示する。
5. いずれも失敗しても停止しない。**ただしセッションの列挙だけは終了コードを読む**(手順2)。他の3つは `2>/dev/null || true` で握る。

- 前提条件: リポジトリのルートで実行すること(`BASE_DIR` は Makefile の位置から解決する)。
- 引数: なし(変数で調整する場合は下表)。

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| Docker デーモンに接続できない | イメージ・proxy・ボリュームの3つは握りつぶされて空の見出しが並ぶ。**セッションの列挙は2回の問い合わせの終了コードを読み、どちらかが非ゼロなら見出しの直下に `⚠️  Docker への問い合わせが失敗したため、この一覧は不完全である可能性があります。` を1行出す**(文言は `claude-dev list` と同一)。そのうえで引けた分を表示し、0件なら「(実行中のセッションはありません)」を続けて出す | **警告の行が出るので、0件と失敗を利用者が読み分けられる**(`claude-dev list` と同じ答えになる)。終了コードは 0 のまま(表示の欠落は停止させる理由にしない) |
| **セッションの列挙が0件** | 「(実行中のセッションはありません)」と1行表示する(空の表を出さない) | なし |
| **管理ラベルを持たない既存コンテナが稼働している** | イメージ側の条件で引けるので表示される | なし |

## 実装上の判断

<!-- 2026-08-20 に既存3行を読み直した: [D0-scope-02] 継続 / [D0-env-10] 継続 / [DS-05] 継続(集合の畳み方は変えていない — 畳む前に問い合わせを別々の変数へ受ける形になっただけである)。 -->

- [D0-scope-02] Makefile はホスト側の開発者向け入口に限定し、日常操作は `claude-dev` CLI に寄せる(2026-08-02 の判断を継続) — 理由: 2026-08-02 の記録に理由は残っていない。継続する理由は、同じ操作を `claude-dev` 側が既に持っており、両方を保守すると同じ振る舞いを2箇所で決めることになるためである / 見直す条件: Makefile にしか無い操作が日常操作になったとき
- [D0-env-10] セッションの列挙を**管理ラベルとイメージの和集合**にし、名前が `fwd-` で始まる中継コンテナを除く(**2026-08-20 に追加**) — 理由: `claude-dev list` と同じ数え落とし(`docs/histories/2026-08-20-fix-session-list-undercount.md`)が `make status` にも在った。両者は同じ集合を表示するものなので、条件を別にすると同じホストで件数が食い違う / 見直す条件: 管理ラベルが付く前に起動された既存コンテナがホストから無くなったとき
- [DS-05] `Makefile` の中でシェルを1行につなげて集合を求め、コンテナ ID を `awk 'NF && $$2 !~ /^fwd-/ && !seen[$$1]++'` で畳む(重複除去と `fwd-` の除外を同じ1回の走査で行う) — 理由: `Makefile` はシェル関数を呼べず(レシピの各行が別のシェルである)、`docker ps` は同じ `--filter` キーの複数指定を論理和にするがキーが違うものは論理積にするため、ラベルとイメージの和集合は問い合わせ2回を畳む以外に得られない / 見直す条件: `docker ps` がフィルタ間の論理和を直接受け付けるようになったとき
- [DS-02] Docker への2回の問い合わせのどちらかが非ゼロで終わったとき、**一覧より前に警告を1行出し、処理は続けて引けた分を表示する**(止めない。終了コードは 0 のまま) — 理由: `CTR-cli-container`「稼働中セッションの一覧の列挙」が「問い合わせが失敗したときは 0 件と同一視しない」と定めており、`claude-dev list`(`claude-dev:2206`-`:2211`)が同じ形を既に採っている。引けた分を隠すと、片方の問い合わせだけが通る状況で情報が減る。`make status` は状態を見るための読み取り専用の入口なので、非ゼロで返して呼び出し側を止める価値が無い / 見直す条件: `make status` の終了コードを別の処理が合否として読むようになったとき
