## テスト設計の判断

- [DS-01] **名前付きボリュームの確認を「消えないこと」から先に流す**(手順8-21-1 → 8-21-2) — 理由: 既定で消さないことがこの変更の核であり、先に `--volumes` を流すと「消えないこと」を確かめる対象が残らない / 見直す条件: 既定が「消す」に変わったとき
- [DS-01] **存在しなかった資源を「削除できなかった」と出さないことを、compose 既定ネットワークを作らない構成で確かめる**(手順8-22) — 理由: この欠陥は `services` が自前のネットワークだけを宣言する compose ファイルで**毎回**再現し、逆にその構成を使わないと再現しない(2026-08-18 の実測。既定ネットワークが作られる構成では偽の失敗が出ない)/ 見直す条件: 実装が実在確認ではなく終了コードの区別で判定するようになったとき
- [DS-01] テスト識別子は **E2E-01 の部分手順の粒度**で書く(`手順8-14` ではなく `手順8-14-3`) — 理由: 手順全体を指すと、その手順が実際には検証しない条項でも表が成立してしまう / 見直す条件: `03-impl/tests/e2e.md` の部分手順の番号が改訂で動き、参照が指す先を失ったとき
- 判断なし: 状態列は `03-impl/tests/strategy.md`「状態列の語彙の定義」に従う(実機確認の手順が定義されていても `未検証(テスト未実装)` に入る)。この5条項に固有の判断は無い
- [DS-01] `FR-env-01-23` は**対象を手順の中で用意する形**にする(既存の手順の副産物では作れないため) — 理由: 用意の仕方を手順の外に置くと、確認する人が前提を作らないまま流して検証が空振りする / 見直す条件: 手順8-14-6 を手順8 の途中からではなく単独で流す必要がなくなったとき。**手順8-12 が残す `legacy2` を流用しない**のは、手順8-14-6 だけを取り出して再実行できる形を保つためである(流用すると手順8-12 を先に流さないと成立しない)
