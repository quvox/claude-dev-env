# テスト資産は機能表・コールグラフの対象外にする

## 状況

task-docs-restructure のフェーズ2で機能表を起案していたとき、`scripts/e2e6-codex.sh`
(E2E-6 の実機検証スクリプト)がコールグラフのエントリポイントとして検出された。
`callgraph-check.py` の FT2 は「コールグラフのエントリポイントが、いずれかの機能の入口に
なっているか」を重大度「高」で検査するため、放置すると不合格になる。

## AI の提案

`MOD-e2e` を新設して `MODULE-e2e-codex-check` として機能表に載せる。理由として
「検証スクリプトも製品の一部」「除外すると callgraphs/index.md に毎回明示が必要になる」を挙げた。

## 人間の判断とその理由

**却下。** `callgraph-config.local.json` の excludes に入れて解析対象外にする。
理由は「**テスト資産は仕様の対象外**」。機能表と機能間連携仕様書は**製品コードの境界**を
書く場所であり、テストコードの記述は `03-impl/tests/` が担う。

## 今後どう活かすか

- **FT2 の「高」を消すために機能表へ行を足す、を反射的にやらない。** FT2 が指しているのは
  「この入口に責任者がいない」であって、行き先は2つある — 機能表に載せるか、そもそも
  **解析対象から外すか**。どちらが正しいかは「それは製品コードか、テスト資産か」で決まる。
- 判定基準: **利用者に価値を届けるために動くもの = 製品コード**(機能表に載せる)。
  **製品が正しいことを確かめるために動くもの = テスト資産**(excludes に入れ `tests/` で書く)。
  `scripts/orch-sample.sh` や `examples/orch-sample/` のように、テスト用に見えても製品として
  配布・実行されるものは製品コード側である(この境界は毎回考える必要がある)。
- 除外したものは `callgraphs/index.md` の excludes 一覧に出るので、「黙って落とした」ことには
  ならない。**除外はコストではなく、境界の宣言のひとつ**として扱ってよい。
