## 状況

Claude Code と Codex CLI をイメージへ同梱する決定(`D0-dist-03` / `D0-dist-04`、旧 D-26 / D-27)を
書き、実装まで通したあと、同じ種類の穴で**5回**人間に確認が必要になった。

## AI の提案

決定台帳には「同梱するか」「どのバージョンか」「認証をどう共有するか」「ログイン導線」
「スコープ」を書けば足りると考えていた。

## 人間の判断とその理由

そのつど人間が判断を示したが、いずれも**決定台帳に項目が無かったために発生した質問**だった。

| 何が抜けていたか | 実際に起きたこと |
|---|---|
| 版の追随ポリシー(どのチャネル・自動追随の範囲・切り戻し手段) | `latest` を直書きしてキャッシュが永久ヒットし、**同梱版が凍結**した |
| その依存が要求する実行権限 | codex のサンドボックスがコンテナ内で起動できず、**シェルコマンドが例外なく失敗**した |
| 既定設定を上書きしうる呼び出し経路 | `--sandbox read-only` を明示する経路が config の既定を上書きし、監査だけ壊れたままだった |
| 既定が後から増えたときの既存ファイルへの反映規則 | 方針を足すたびに「既存 `config.toml` をどうするか」を聞き直すことになった |
| deprecated 機能へ依存する場合の回帰検知 | 版追随した瞬間に静かに壊れる経路が誰の責務でもなかった |
| CI とローカルビルドの両経路 | ローカルの `make update-claude` だけ版が制御されない状態が残った |

## 今後どう活かすか

**外部依存(CLI・ライブラリ・ベースイメージ)を導入する決定を書くときは、次の6項目を必ず埋める。**
埋まらないものは「要確認」として明示的に残す。空欄のまま決定にしない。

1. 版の追随方針(チャネル / 解決タイミング / ピン留めの有無 / 切り戻し手段)
2. **その依存が実行環境に要求する権限**と、現行の隔離設定でそれを満たせるか
3. 設定の既定値と、**それを上書きしうる呼び出し経路**の一覧
4. 既定が後から増えたときの既存ファイルへの反映規則(上書き禁止 / 不足補完 / 移行手順)
5. deprecated 機能へ依存する場合の**回帰検知をどこに置くか**
6. CI とローカルの**両方**の経路

あわせて、受け入れ基準は「起動する」「コマンドが解決できる」で止めず、**実行が成功する**ことを
要求する。
