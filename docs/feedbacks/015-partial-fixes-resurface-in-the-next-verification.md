# 015 範囲を最小化すると同じ乖離が次の検証で再浮上する

## 状況

`/doc-check ssot` の独立レンズが、**影響範囲外**の orchestrator relations 7本から20件の
コードとの乖離を見つけた(`issue 032`)。私は「高2件だけを影響範囲へ取り込み、残り18件は別タスク」
という選択肢を推奨として提示し、人間はそれを選んだ。

## AI の提案

「合格証を止めているのは高2件なので、それだけ取り込めばタスクを閉じられる。
一度書き切ったタスクに20件を足すと粒度を超える」という推論。

## 人間 / 検証の反応

次の `/doc-check` が、**影響範囲内の 21 本**から約34件の乖離を見つけた(`issue 038`。高5件)。
乖離は**変更指示の `sections` に入れなかった節**(`## 処理の流れ` / `## 連携先と連携内容` /
`## 戻り値・副作用` / frontmatter の `callers` `callees`)に集中していた。

つまり `issue 032` で「高だけ」と切った判断と、変更指示で「必要な節だけ」と切った判断が、
**同じ失敗の2つの現れ**だった。人間に前提(「案A では `03-impl/index.md` を認証できず
タスクを閉じられない」)を示して再確認したところ、案B(高5件を今直す)へ切り替わった。

## 一般化した教訓

**「同じ層・同じ性質の乖離」は層ごと片付ける。** 重大度で切ると、残した中低が次の検証で
再浮上し、そのたびに issue が増えて追跡コストが上がる。

- 影響範囲を relations で切るときは、**その1本の全節**を対象にする。
  一部の節だけ置換すると、置換しなかった節が古い記述を主張し続ける
  (機械検査は本文の叙述を見ないので通ってしまう)。
- 「範囲を小さくすれば早く閉じられる」は**閉じられる場合にだけ**正しい。
  合格証・削除ゲートが層単位で効くなら、層の一部だけ直しても閉じられない。
- **選択肢を人間に出すとき、「その案を選ぶと何が閉じられなくなるか」を必ず書く。**
  今回それを書かずに案Aを推奨し、後で前提を示して選び直してもらう手戻りを生んだ。
