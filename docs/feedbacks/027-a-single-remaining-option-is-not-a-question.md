# 選択肢が1つしか残らないものは「問い」ではない

## 何が起きたか

フェーズ2 のドライランで、`docs/issues/097`(CLI の `help|*)` 入口)を本タスクへ畳み込む
という人間の回答が**実施不能**であることが分かった。原因はシェル抽出器の決定 D
(catch-all を含むラベルを丸ごと入口から外す)で、機能表に行を足すと FT1 が重大度「高」で落ちる。

回避策は2つしかなく、**どちらも塞がっていた**:

- コードで `help)` と `*)` を分ける → 本タスクの「やらないこと」(コード変更)
- 抽出器を直す → CLAUDE.md §3 によりキットは製品 DoD 未達の間は凍結

にもかかわらず、AI はこれを**決定シートの論点4 として人間に差し戻した**。
根拠(上流・同層・下流)も戻し方も書いた、形式上は整った1ブロックである。

人間の反応:

> 論点4について、そんなに問題なのか?helpコマンドの内容にそこまで時間をかける意味がわからない。
> もっとシンプルにできないのか?

## 何を間違えたか

**選べる選択肢が1つしか残っていないものは、決定ではない。** 事実である。
`.claude/directions/delegation.md` §1 は「『決められない』は問う理由にならない」と定めており、
「決められる相手が居ない」も同じことである。問う基準の2つの関門(外から見えるか /
後から戻しにくいか)以前に、**選択の余地があるか**を見ていなかった。

補助的な間違いが2つ重なっていた:

1. **形式が整っていることを、問う資格があることと取り違えた。** 根拠3方向・崩れる条件・
   戻し方を全部埋めたブロックは、埋めた labour のぶんだけ「載せる価値がある」ように見える。
   実際には、それらは**問うと決めたあとに満たす条件**であって、問うかどうかの判定ではない。
2. **人間の以前の回答(「097 を畳み込む」)を、宙に浮かせたくなかった。** 前提が崩れたことは
   報告すべきだが、**報告と、判断の差し戻しは別のものである**。事実として1行報告すれば足りた。

## どうすべきだったか

- 実施不能と分かった時点で、**closure から外し、issue に実測を追記し、進捗メモに1行**書く。
- 決定シートには載せない。報告の中で「回答の前提が崩れたので外した。理由はこれ」と述べる。
- 論点として載せてよいのは、**人間が別の答えを選べるとき**だけである。

## 一般化

**問う基準を適用する前に、選択肢の数を数える。** 1つなら、それは事実の記録であって
決定シートの行ではない。ゼロなら、それは実施不能の報告である。

同型の失敗が起きやすい場所: 上流の決定・凍結・「やらないこと」に阻まれて回避策が全部塞がった
とき。塞がれていること自体が答えなので、**塞がれた経緯を書けば終わる**。
