# 030 転記した回答は、まだ適用された回答ではない

## 何が起きたか

決定シートの「概念1」で、AI推奨の本文は
**「含める = そのセッションの中から作られた名前付きボリュームと匿名ボリューム」**と書いていた。
人間は「それ以外は推奨で良い」と答え、AI はその発言を逐語引用+日付で memo.md へ転記した
(`task-memo.md` §1.2 の第3の形は満たしている)。

**ところが、そのあと書いた変更指示 25 件は、00 の用語集から 03 の実装仕様まで
すべて「名前付きボリューム」だけを対象にしていた。** 「匿名」の語は 25 件のどこにも現れず、
**承認された回答の一部が、誰にも気づかれずに狭まっていた**。

見つけたのは `/doc-check`(フェーズ2)の独立レビュー(Codex)で、**転記行の文面と
変更指示の全文を突き合わせた**結果である。機械検査は1つも落ちていない
(`check-sheet.py` SH4 は転記行の**件数**を数え、`check-changeset.py` は
**指示どうしの整合**を見るが、**転記行の中身が指示に降りたか**を見る検査は無い)。

## なぜ外れたか(AI の見立ての側)

**転記した時点で「回答を扱い終えた」と感じてしまった。** 転記は
「人間の発言を失わないための記録」であって、**降下の入力に変換する作業はそのあとに在る**。
推奨本文が2つの要素(名前付き / 匿名)を含んでいたのに、降下では**主題として目立つほうだけ**を
拾った — 「ボリュームを片付ける」という一語で要約できてしまう変更だったことが、
取りこぼしを見えなくした。

## 次に効かせる形

- **転記行を書いたら、その行の中の**名詞を1つずつ**変更指示側で `grep` する。**
  今回なら「匿名」で 0 件が出た時点で気づけた。要約可能な変更ほど危ない。
- **推奨本文が列挙(A と B)を含むときは、列挙のまま転記する。**
  「推奨のとおり」で承認された範囲は推奨本文そのものであって、その要約ではない。
- `task-memo.md` §1.2 は既に **「Transcription is not application」** と明言しており、
  `反映先` 列を全行必須にしている。**今回はその列に着地先を書いていたのに、
  着地先の中身が推奨の一部を欠いていた** — 列が埋まっていることは、
  中身が揃っていることの証拠にならない。
- **この検査を担ったのは独立レビューである。** 自分の書いたものを自分で読むと、
  書いたつもりのものが見える(`/doc-check` §0A が新しい文脈を要求する理由そのもの)。
