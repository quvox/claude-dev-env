# 2026-08-04 `start` の後片付けが他方の稼働中コンテナを消すのを止める

## 変更理由

`docs/issues/036`(severity 高・**データの破壊**)。`claude-dev` の `start` は `docker run` が
失敗すると再試行の前に**無条件で** `docker rm -f "$NAME"` を実行していた。この後片付けは
「自分が作りかけたコンテナか」を確認しないため、**同名コンテナの衝突で失敗した側が、
先に成功した側の稼働中コンテナを作業中の tmux セッションごと強制削除する**。
`/workspace` はバインドマウントなのでソースは残るが、tmux のスクロールバック・実行中の
`claude` / orchestrator・コンテナ内の一時生成物は失われ、失敗表示は「コンテナ起動に失敗しました」
だけで他方を消したことを述べなかった。

起点層は **01**(「同名の稼働中コンテナを消してはならない」は観測可能な振る舞いであり、
受入基準の欠落だった)。

## 変更内容の要約

- **01 に受入基準を2件追加**(`FR-env-01` #12 異常系 / #13 境界値)。名前衝突で失敗したときは
  既存コンテナを削除せず、稼働中である旨・別ディレクトリの同名プロジェクトである可能性を表示して
  終了コード 1。後片付けは対象が稼働中でないことを確かめてから行う。
- **02 の契約にエラーケースを1件追加**(`CTR-cli-container`「コンテナ名が衝突して起動に失敗した」)。
  既存の「公開ポートが競合して起動に失敗した」行も「稼働していない作りかけだけを削除」へ明示。
- **02 のログ仕様に1行追加**(`logging.md`「コンテナ名の衝突による起動の中止 / ERROR」)。
- **コードを両 CLI で修正**(`claude-dev` / `claude-dev-mac` の各2箇所。44行追加・6行削除)。
- **実機確認の手順を新設**(`03-impl/tests/e2e.md` の `E2E-01` 手順7)。**手順そのものの誤りを
  実機で発見して書き直した**(下記)。

## 実機確認(FR-env-01 受入基準12・13)

**★手順そのものの誤りを実機で発見した。** 当初書いた「basename が同じ2つのディレクトリで順に
`start` する」では衝突が起きない — 同名コンテナが稼働中なら**手順6 の再接続経路に入って
`exit 0`** するからである(`claude-dev:715`)。衝突は**手順6 の稼働判定を通り抜けたあと、
手順13 の `docker run` に達するまでの数秒の窓**に限られる。手順をその窓を意図的に作る形へ
書き直し(`SSH 鍵が未設定` の行が出た直後に代役コンテナを立てる)、
`MODULE-cli-start` の「並行性」「異常系」「処理の流れ」も実態へ合わせた。

| 確認 | 結果 |
|---|---|
| **修正前のコード**(`git show HEAD:claude-dev`)で同じ手順 | 稼働中の代役コンテナ `50ec825bcd21` が `docker rm -f` で**削除された**(データ破壊を再現) |
| 修正後 (a) 終了コード | **1** |
| 修正後 (b) 表示内容 | 稼働中である旨 / 別ディレクトリの同名プロジェクトの可能性 / **既存に手を触れていないこと** / 次に取るべき操作 |
| 修正後 (c) 代役 `40d224b3c9ed` | **稼働継続**(ID 不変) |
| 修正後 (d) `docker exec web ls /tmp/marker-a` | **成功**(作り直されていない) |
| 回帰 | 衝突なしの通常起動は成功(終了コード 0)、再実行で再接続経路(`FR-env-01` #4) |
