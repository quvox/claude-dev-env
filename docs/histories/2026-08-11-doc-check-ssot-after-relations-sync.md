# 2026-08-11 `/doc-check ssot`(relations 同期の後)

## 変更理由

同日の `/relations all --apply` で `docs/03-impl/index.md` が 1.20.0 へ上がり、合格証(1.19.1)が
失効した。原則6 により、合格証の有効性は自分の版の MAJOR.MINOR 一致だけで決まるため、
再発行が必要だった。あわせて独立レビュー(Codex)が同日の修正の**再監査**で
終了コード 130 の記述の不正確さを4件見つけた。

## 変更内容の要約

- **終了コード 130 の記述を4本で正確にした。** 同日の `/relations` の修正は、`logout` / `reset`
  では**過剰主張**(最後の `destructive_abort_if_interrupted` より後は 130 にならない)、
  `start` / `stop` では**過少主張**(`trap` はロックの取得を試みる前に張られるので、取得に
  失敗する経路も 130 の区間に入る)だった。**どちらもコードで裏取りして直した。**
- `docs/03-impl/index.md` の集計3件を事実に合わせた: コードとの乖離 0件 → **1件**
  (`docs/issues/097`)、起票済みの実装欠陥 11件 → **12件**(`055` の数え漏れ)、
  01 との差異「すべて人間が裁定済み」→ **1件が未裁定**(`055`)。
- `relations-coverage.py` の「要確認 66 件」が層の状態に載っていなかったので追記した。
- `tests/e2e.md` の `[DS-01]` 開示行の**見直す条件が既に発生していた**(1つの部分手順が2条項を
  兼ねている)。判断を現状に合わせて書き直し、`tests/cli-stop.md` の識別子が確認単位
  ((a)(c) / (b))を指すようにした。
- `docs/issues/075` を**解消として削除した**。キット側の生成器 `.claude/scripts/cgx/features.py:486`
  が既に条件付き出力(対処案B)を実装しており、同日の `feature-graph.md` 再生成で
  `check-changeset.py --ssot` の CS11 から消えた。
- **コードは1行も変更していない。**
