# 2026-08-11 `logout` の削除対象0件の経路を直す

## 変更理由

**起点層は 01(`FR-env-03` 受入基準19)。** `claude-dev logout` の「削除対象0件」の早期終了経路が、
利用者が `logout` の効果を誤解する状態を作っていた。`D0-env-08` の目的
「消したつもりで残る状態を作らない」と項5「削除の失敗を握りつぶさない」に反する。

受入基準19 の文言そのものが原因である。「共有ボリュームも空」が**空であることを確認できた状態**を
意味していなかったため、実装は一時コンテナを起動できない場合も「空」と判定でき、
認証が残っていても終了コード 0 で終わっていた(`docs/issues/053`)。また受入基準17 の
「ラベル無しコンテナの名前を表示する」義務が「集合として列挙するとき」に条件づいており、
削除する集合が空の経路が条件から外れていた(`docs/issues/052`)。あわせて 02 契約が
`logout` と `reset` の双方に課している4つの除外のうち、`logout` だけが4つ目
(`claude-dev.role=spawned`)を持たず、セッション由来のコンテナを「管理ラベルを持たない」と
事実に反して表示していた(`docs/issues/089`。実装が 02 契約に追いついていない = origin 03)。

## 変更内容の要約

- `FR-env-03-19` を3点書き換えた: (a) 0件の数え方を「稼働中コンテナが無く」から
  「**管理ラベルを持つコンテナ(停止中を含む)が無く**」へ、(b) 「共有ボリュームも空」を
  **空であることを確認できた**へ改め、確認できなければこの経路に入ってはならないと定め、
  (c) この経路でもラベル無しの稼働中コンテナがあれば名前と認証の書き戻しを表示する義務を課した。
  **条項 ID は1つも動かしていない。**
- 02 に3つの記述を足した: 契約のエラーケース「`logout` が共有ボリュームが空かどうかを
  確かめられなかった」、`logging.md` の既存2行への「0件の経路でも出す」の明示と
  「共有ボリュームが空であることを確認できなかった」の新設。
- 実装(`claude-dev` / `claude-dev-mac` の `logout` 分岐、両 OS でバイト単位で同一)で
  手順6 の「空」判定を**3条件の論理積**(印 `__CLAUDE_DEV_AUTH_LISTED__` が出ている /
  一時コンテナの終了ステータスが 0 / 印以外の行が無い)へ差し替え、確かめられなければ
  0件の経路に入らず確認へ落とすようにした。0件の経路でもラベル無しコンテナの表示を出し、
  手順4 の表示集合から `claude-dev.role=spawned` を除いた。
