# 2026-08-18 同梱外部バイナリ(externals/)の導入

## 変更理由

### R-01 別リポジトリで作った社内ツールを、開発者の追加作業なしにコンテナで使いたい

- 起点層・根拠: **人間の依頼**(2026-08-18)「../colabtmux のツールをclaudeコンテナのイメージに
  追加したい。別リポジトリなので、Linux用のバイナリだけを取得して、パスの通っているところに
  おいてイメージを作るようにして欲しい」。要求として `RQ-dist-02` を新設した。
- 変更が必要になった条件: 同梱したいツール(`colabtmux`)が別リポジトリ(非公開)で作られており、
  既存の同梱経路(`RQ-env-03` = エージェント CLI の同梱)はバージョン解決と認証共有を一体で
  持つため、そのままでは載せられなかった。

### R-02 反映の過程で見つかった、既存記述の3つの誤り

- 起点層・根拠: 独立レビュー(Codex)と実測。`NFR-perf-01` が同梱外部バイナリの差し替えで
  必ず不合格になること、`FR-env-13-2` の「書き換えられない」が `NOPASSWD:ALL` の sudo の
  存在に対して偽であること、`03-impl/infra/local/ghcr.md` の公開範囲「組織内」が事実と違うこと。
- 変更が必要になった条件: R-01 の変更が既存の条文の前提を動かした(前2つ)、および
  R-01 の決定(公開イメージへ焼く)の根拠を読むために正しい事実が要った(3つ目)。

## 変更内容の要約

- **`externals/` を新設した。** 直下 = 全アーキ共通 / `amd64/` `arm64/` = そのアーキのみ /
  `README.md` は対象外。設置先は `/usr/local/bin`、権限 0755・所有者 `root:root`。
- **配布ステージ2つ(`claude-cli` / `claude-vnc`)の最終レイヤー**へ設置処理を置いた。
  アーキテクチャ判定は `dpkg --print-architecture`(BuildKit の `TARGETARCH` は使わない)。
- **`Makefile` と CI ワークフローは変更していない** — ビルド文脈が既にリポジトリルートで、
  `.dockerignore` も無いため `externals/` は自動的にビルド文脈に入る。
- 実機で `AC-07` を確認した(手順16〜21 の6件すべて合格。人間が置いた `colabtmux` 実物でも確認)。
