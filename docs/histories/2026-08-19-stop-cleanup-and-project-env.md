# 2026-08-19 stop の片付け範囲とプロジェクト環境変数

## 変更理由

### R-01 `stop` の片付けが「セッションが作ったものは全部」になっていなかった

- 起点層・根拠: 人間の依頼「claude-dev のコンテナを stop した時に、そのコンテナ内で起動した
  コンテナ群およびネットワークや mount を削除する機能が正しく動作していない」(2026-08-18)。
  `D0-env-05` 項2 / `FR-env-01`。
- 変更が必要になった条件: **実機で再現して測ったところ、指摘は3つに分かれた** —
  (a) コンテナとネットワークは実際に削除されていた、
  (b) **名前付きボリュームは仕様として対象外だった**(`D0-env-05` 項2 が「削除しない」と決めていた)、
  (c) **存在しなかった compose 既定ネットワークを「削除できませんでした」と毎回表示していた**。
  (b) は 00 の決定を人間が動かす判断、(c) は明確な欠陥である。

### R-02 プロジェクトごとの環境変数をコンテナへ渡す手段が無かった

- 起点層・根拠: 人間の依頼「任意の環境変数を claude-dev のコンテナに設定できるように
  .claude-dev.yaml に設定を書けるようにして欲しい」(2026-08-18)。新設 `RQ-env-07`。
- 変更が必要になった条件: `request.md`「やること」に無い新しい能力であり、
  **秘密の値の置き場をこちらから用意することになる**ため、置き場と守り方を 00 で決める必要があった。

### R-03 docker-proxy を「停止」と書く層と「削除」する実装が食い違っていた

- 起点層・根拠: `docs/issues/092` の 2026-08-07 の人間の裁定(案 A で確定。ただし影響範囲に
  02 が抜けていたので `DSN-*` を新設すること。コードに触るので独立したタスクにすること)。
- 変更が必要になった条件: 本タスクの closure が `stop` の出力・00 の決定・01 の条項・
  02 の設計判断・03 の実装仕様をすべて含んだため、**同じ降下で直せる状態になった**
  (人間が 2026-08-19 に決定シート 論点3 で「一緒に直す」を承認)。

## 変更内容の要約

- **`stop` / `reset` の片付けに名前付きボリュームと匿名ボリュームを加えた。既定では消さず、
  `--volumes` を明示したときだけ消す。** 指定が無ければ残っている名前と消し方を表示する。
- **匿名ボリュームは所有者ラベルを持てない**(作成要求が docker-proxy を通らず、Docker が
  コンテナ作成の中で直接作る)ので、**紐づくコンテナの削除に `-v` を添えて**消す。列挙には出さない。
- **docker-proxy がボリューム作成要求にも所有者ラベルを注入する**(単体テスト4本を追加)。
- **存在しなかった資源を「削除できなかった」と表示しない。**
- **プロジェクト環境ファイル**を新設。`.claude-dev.yaml` の `env_file` が指すファイルの
  `名前=値` をコンテナへ渡し、値は出力せず、そのファイルを版管理の追跡から外す。
  **本システムが使う名前(予約名)は採用しない。**
- `.claude-dev.yaml` の書き出しを全面上書きから **`ssh_keys` 節の差し替え**へ、
  `ssh-keys reset` の行削除を**節境界を見る形**へ(`docs/issues/002` の解消)。
- 遊休時の docker-proxy の表示を「停止しました」から**削除したことが分かる言葉**へ
  (`docs/issues/092` の解消)。あわせて `DSN-arch-05` を新設して理由を 02 に置いた。
