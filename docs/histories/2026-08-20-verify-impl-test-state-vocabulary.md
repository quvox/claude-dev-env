# 2026-08-20 テストの状態列を自動テストの実在で判定し直す

## 変更理由

### R-01 実機確認の手順しか無い行が `実装済み` を名乗っていた

- 起点層・根拠: `docs/03-impl/tests/strategy.md`「状態列の語彙の定義」が `実装済み` を
  「自動テストが存在し、上記のコマンドで実行できる」と定義し、`未検証(テスト未実装)` の側に
  「**実機確認の手順が定義されていてもここに入る**(手順は自動実行されないため)」を明記している。
  MOD-cli-list / MOD-cli-start / MOD-makefile には自動テストが1本も存在しない
  (`DSN-test-01` / `SR-32`。指し先の `E2E-01` 自身も `docs/03-impl/tests/e2e.md` で
  `未検証(テスト未実装)` である)。したがって6行の `実装済み` は事実に反しており、
  正解は語彙の定義から機械的に定まる(CLAUDE.md 原則2)。
- 変更が必要になった条件: F3 実装整合フロー(`/verify-impl all`)の独立レビュー(claude / reviewer-4)が
  `tests/makefile.md:43`・`:50` を検出し、同型が `tests/cli-list.md`・`tests/cli-start.md` にも
  在ることを確認したため。`docs/03-impl/tests/index.md` の進捗が実態より6行分進んで見えていた。

## 変更内容の要約

- 6行の状態列を `実装済み` → `未検証(テスト未実装)` に戻し、各ファイルの
  「未検証(テスト未実装)の全件」表へ対応する6行を足して全件を成立させた(通番を振り直した)。
- `tests/makefile.md` の「テスト設計の判断」から、表と矛盾する記述(2行を `実装済み` へ移したという
  文と、指す表が一意に決まらない「16 行」)を取り除き、実機確認の手順が在っても状態が
  `未検証(テスト未実装)` である理由を語彙の定義で示す形に置き換えた。
- `docs/03-impl/index.md` の合格証を現在の版(1.35.1)で再発行した(03 層の代表。CLAUDE.md §6)。
