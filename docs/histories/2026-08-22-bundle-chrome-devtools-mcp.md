# 2026-08-22 chrome-devtools MCP を配布イメージへ同梱する

## 変更理由

### R-01 ブラウザ確認の可否が、起動のたびのネットワーク取得に依存していた

- 起点層・根拠: 00(決定台帳)。人間の要望(2026-08-22)「コンテナイメージで、chrome-devtools-mcp
  をインストールするようにして欲しい。codexやclaudeで利用する」。決定は `D0-dist-06` として記録した。
- 変更が必要になった条件: entrypoint が `.mcp.json` へ書いていた値が
  `npx -y chrome-devtools-mcp@latest ...` であり、コンテナ起動のたびに取得が走っていた。
  `D0-dist-03`・`D0-dist-04` は Claude Code と Codex CLI について「実行時のダウンロードに
  依存しない」と既に決めており、この1件だけが例外として残っていた。

### R-02 codex からブラウザ操作の MCP が使えなかった

- 起点層・根拠: 00。同じ要望の後半(「codexやclaudeで利用する」)。`RQ-env-03` は
  エージェント CLI を2つ同梱すると定めており、どちらで作業するかでブラウザ確認の可否が
  変わることを説明できない。
- 変更が必要になった条件: 起動時の登録先が Claude Code の設定(`.mcp.json` /
  `.claude.json`)だけで、codex の `config.toml` には何も書いていなかった。

## 変更内容の要約

- 配布イメージ2種の終端ステージへ `chrome-devtools-mcp` を**版を固定して**導入し、
  `codex` と同じ形の `/usr/local/bin` ランチャーを置いた(fnm 初期化の無いシェルから解決するため)。
- entrypoint が `.mcp.json` に書く値を同梱物(`chrome-devtools-mcp --browserUrl …`)へ変え、
  **以前この処理が書いた値と完全一致するときだけ**同梱物へ向け直す移行を足した。
- ブラウザ確認ありの初期化から `ensure_codex_mcp_entry` を呼び、codex の `config.toml` へ
  `[mcp_servers.chrome-devtools]` を**書かれていないときだけ**追記するようにした。
- 日次ビルドの CI が版を npm registry から解決して build-arg で渡すようにし、手動実行の入力も足した。

## 検討した代替案

| 論点 | 採用した案 | 棄却した代替案 | 棄却の理由 / 崩れる条件 |
|---|---|---|---|
| 同梱するかどうか | 決定台帳へ加えてピン留め同梱する(人間が承認) | 実行時取得のまま据え置く | 取得先の可用性とファイアウォールにブラウザ確認の成否が依存し続ける |
| どのイメージへ入れるか | 配布2イメージの両方 | ブラウザ確認ありのイメージだけ | 配布物ごとに中身の規則が変わり、既存の一貫した扱い(両方へ入れる)から外れる |
| どの経路で同梱するか | npm でピン留め導入(エージェント CLI と同じ扱い) | `externals/` の同梱外部バイナリの仕組みへ相乗り | 出所も更新のされ方も違い、キャッシュキーの由来が2種類混ざる |
| 既存の設定をどう扱うか | 以前この処理が書いた値と完全一致するときだけ置き換える | 常に上書きする / 一切触れない | 常に上書きは利用者の指定を確認なく壊す。一切触れないと既存プロジェクトが取得依存のまま残る |
| codex への登録をどこに置くか | 別関数にし、ブラウザ確認ありのときだけ呼ぶ | 既定3鍵と同じ関数に置く | 既定3鍵は構成に関わらず要るが、ブラウザ操作の登録は接続先が在るときだけ意味を持つ |
