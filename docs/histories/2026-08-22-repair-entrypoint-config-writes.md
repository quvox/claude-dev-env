# 2026-08-22 設定ファイルの書き方を直す(課題票 098・099)

## 変更理由

### R-01 root が利用者の書き換えられる固定名パスへ書いていた(課題票 098)

- 起点層・根拠: 03。F3(実装整合)の独立レビュー(Codex)が指摘し、`docs/issues/098` として起票した。
- 変更が必要になった条件: `/workspace` は利用者が自由に書けるディレクトリであり、
  `${...}.tmp` の固定名リダイレクトと `-h` の無い `chown` は、あらかじめ張られたシンボリック
  リンクの先を root が壊す経路になっていた。

### R-02 `null` が書かれたエントリを「未登録」とみなして上書きしていた(課題票 099)

- 起点層・根拠: 03。同じ独立レビューの指摘。`docs/issues/099` として起票した。
- 変更が必要になった条件: `jq -e` は値が `null` / `false` のとき終了コード 1 を返すため、
  2026-08-22 に足した `FR-env-11-9`(それ以外の値は変更してはならない)を破っていた。

## 変更内容の要約

- `update_json_file` を新設し、`/workspace` 配下の JSON を書く5経路
  (`.mcp.json` ×3・`.claude.json`・`settings.json`)をすべてそこへ通した。
  `mktemp` で同じディレクトリに作り、書けたときだけ差し替える。対象がシンボリックリンクなら
  何も書かずに警告する。`chown` は `-h` を付けた。
- 登録の有無の判定を `has()` へ変えた(`chrome-devtools` と `computer-use` の2箇所)。
- `.mcp.json` / `.claude.json` の**新規作成**の経路にもリンクの拒否を足した。

## 検討した代替案

| 論点 | 採用した案 | 棄却した代替案 | 棄却の理由 / 崩れる条件 |
|---|---|---|---|
| 一時ファイルの作り方 | `mktemp` で同じディレクトリに作り、書けたときだけ差し替える | 書く前に `[ -L ]` だけを見る | 判定と書き込みのあいだにリンクを張り替えられる。`mktemp` なら名前が予測できない |
| 対象がリンクだったとき | 何も書かずに警告して続行する | リンクを消して実体を作る | 利用者が意図して張った構成を壊す。起動を止めないのはこのスクリプトの一貫した倒し方である |
| 登録の有無の判定 | `has()` でキーの有無を見る | `jq -e` のままにして `null` を正常値として扱う | `FR-env-11-9` が「それ以外の値は変更してはならない」と定めており、実装をそれへ合わせるのが正 |
