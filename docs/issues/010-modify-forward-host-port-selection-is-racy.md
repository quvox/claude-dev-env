# 010 forward のホストポート選択が競合に弱い

## 事象

`find_available_host_port`(`claude-dev:283-294` / `claude-dev-mac` も同一)は次のように空きを探す。

```
port = FWD_PORT_BASE (8100)
while port < FWD_PORT_BASE + 900:
    docker ps --format '{{.Ports}}' に "0.0.0.0:<port>->" が無ければ port を返す
    port += 1
返せなければ FWD_PORT_BASE (8100) を返す
```

ここから3つの欠陥が出る。

1. **非 Docker プロセスのポートを検出しない。** 判定材料が `docker ps` の公開ポートだけなので、
   ホスト上の別プロセス(開発サーバ・SSH フォワードなど)が 8100 番台を使っていても「空き」と判定する。
   結果 `docker run -p` が bind に失敗する。
2. **TOCTOU レースがある。** 判定(`docker ps`)から `docker run`(`claude-dev:1177-1184`)までの間に
   別の `claude-dev forward` が同じポートを取ると衝突する。**リトライは無い。**
3. **範囲が埋まったときに衝突する値を返す。** 8100〜8999 に空きが無いと基準値 8100 を返すため、
   ほぼ確実に衝突して失敗する(「空きが無い」という専用のエラーを出さない)。

いずれの場合も `set -e`(`claude-dev:8`)により `docker run` の失敗でその場で非0終了する。
利用者に見えるのは docker の bind エラーで、原因(範囲が埋まった / 競合した)は区別できない。

## 影響

- 複数プロジェクトを同時に起動する運用(`NFR-scale-01` は同時 5 プロジェクトを目標値としている)で、
  同時に `forward` を叩くと確率的に失敗する。
- 失敗メッセージが docker のものなので、利用者は原因を切り分けられない。
- severity を「中」とした根拠: データを壊さず、再実行すれば別のポートが選ばれて成功しうる。
  ただし自動化された手順の中では再現性のない失敗になる。

## 原因の見当

空きポートの探索を「宣言」ではなく「事前判定」で実装しているため。Docker に空きポートの割り当てを
任せる(`-p 0:<cport>` で公開して `docker port` で確認する)方式なら 1 と 2 は原理的に起きない。
**これは推測ではなく、同じスクリプト内で `docker port` を使ってホストポートを読み出す経路が
既に存在する**(`claude-dev:1169`)ことから、実装手段としては到達可能である。

## 正はどちらか

| 観点 | 実装(03)はどう言っているか | 要件・設計(00〜02)はどう言っているか | 判定 |
|---|---|---|---|
| 割り当て範囲 | 8100〜8999 を走査 | `FR-env-06` 受入基準2「8100 番台から動的に割り当て」 | 一致 |
| 空きが無いとき | 8100 を返して衝突させる | `FR-env-06` 受入基準6「作成に失敗し非0で終わる」 | 観測結果は一致するが、**専用のエラーを持たない**点が未記載だった(本タスクで 03 に明記) |
| 競合したとき | 未定義(リトライ無し) | 記述なし | **要確認**。現状維持でよいか、Docker に割り当てを任せる方式へ変えるかは人間の判断 |

## 対処案

| 案 | 内容 | 影響範囲の見込み |
|---|---|---|
| A | `-p 0:<cport>` で Docker に空きポートを割り当てさせ、`docker port` で確定値を読む | `claude-dev` / `claude-dev-mac` の forward ハンドラ各1箇所。`find_available_host_port` は不要になる。`FR-env-06` 受入基準2「8100 番台」を満たさなくなるので **要件の変更を伴う** |
| B | 現行方式のまま、`docker run` 失敗時に次の候補ポートで N 回リトライする | 同2箇所。要件は変わらない。1(非 Docker プロセス)と 2(レース)の両方に効く |
| C | 現状維持し、`FR-env-06` に「競合時は失敗する。再実行で回復する」と明記する | ドキュメントのみ |

推奨は **B**(要件を変えずに 1 と 2 の両方が閉じる)。ただし**コードの変更を伴うため本タスクでは
扱わない**(task-impl-depth の「やらないこと」)。
