## 影響

受け入れ基準でも契約でもなく `目的` / `連携先と連携内容` の散文なので、
実装者に値や方針を発明させる箇所ではない。読み手が「何をもって安全か」を推測する余地が残るだけで、
再実装可能性は損なわれていない。よって severity は「低」。

ただし CLAUDE.md §8 は層を限定せず曖昧語を禁じており、放置すると
「禁止語ゼロ」という機械的な検査を将来 CI に載せられない。

## 原因の見当

`docs/issues/008` は**オーケストレーションの要件**の判定語(「軽微な判断」「意味のあるまとまり」)を
対象としており、`03-impl/relations/` の散文は走査範囲に入っていなかった。
`task-impl-depth` の調査メモ #1 も「他の測定不能語は 01/02/03 に 0 件」と記録しているが、
これは `適切に` / `正しく` / `高速に` / `柔軟に` を対象とした走査であり、
`安全に` / `素早く` を含んでいなかった(推測ではなく、走査語の一覧から確認できる事実)。

## 正はどちらか

**ドキュメントが誤り**(実装は正しい)。3箇所とも実装の振る舞いを言い換えれば足りる。

## 対処案

| 案 | 内容 |

| B | あわせて `docs/` 全体を CLAUDE.md §8 の禁止語で機械走査する検査を `.claude/scripts/` に追加する(`/kit-improve` 案件) |

B と同時に行うと、以後の再発を機械で止められる。
