## 事象

`docs/pendings.md` の **P-003**「QA レーン(独立QA)の各設定を未定のままにする」は、
なぜ今は OK かの欄で次を主張している。

> 独立監査(`docs` / `readiness`)は有効で、**そちらに必要な設定は確定している**。

しかし `docs/02-design/environments.md`「Codex実行設定」(version 1.0.0、合格証あり)は、
**監査にも効く行を「未定」のまま持っている**。

| 行 | 現在の値 | 監査に効くか |
|---|---|---|
| プロファイル | 未定(`docs-audit` / `qa` は未作成。codex 既定設定で走らせる) | 効く |
| モデル・reasoning(**増分監査 / full監査** / QA) | **未定(codex 既定)** | 効く |
| タイムアウト / 最大出力 | 監査 900 秒 / QA 未定。**最大出力は未定** | 効く |
| 最大調査ステップ | 未定 | 効く |

`.claude/skills/codex-audit/SKILL.md` §0-1 は
「**節が存在しても行が未記入(プレースホルダ)のままなら、その行は不在として扱い既定を使う**」
「既定はモデル `gpt-5.6-terra` / reasoning `max` であり、**これは意図的に最強設定**である。
codex 自身の既定は `gpt-5.6-sol` / reasoning `none`(最弱)なので、未設定のまま放置すると
黙って最弱のレンズになる」と定めている。

`task-impl-depth` の進捗メモが記録している過去の監査は、すべて
`model: gpt-5.6-sol` / `reasoning effort: none` で実行されている
(反復1〜5 および新実行のすべてで「`environments.md` は『未定(codex 既定)』なので
申告との不一致は無い」と記録されている)。つまり**規範が定める既定ではなく codex 既定が使われ、
最弱のレンズで PASS 判定に至っていた**。

2026-08-03 の `/doc-check ssot` は規範どおり `-m gpt-5.6-terra -c model_reasoning_effort=max` を
明示して実行した(codex の起動バナーで `model: gpt-5.6-terra` / `reasoning effort: max` を確認)。

## 影響

2つの別々の問題がある。

1. **P-003 の記述が事実に反する。** 「独立監査に必要な設定は確定している」を根拠に
   「QA レーンの設定だけが未定」と読ませているが、監査のモデル・reasoning・プロファイル・
   最大出力・最大調査ステップは未定である。棚上げの範囲が実際より狭く見える。
2. **独立レンズの強度が実行ごとに揺れる。** `codex-audit` の予算表は「モデルと reasoning は
   実行種別ごとに `environments.md` で固定する。都度チューニングしない(結果が比較可能でなくなる)」
   と定める。未定のままだと、規範の既定に従う実行と codex 既定に従う実行が混在し、
   **過去の監査結果と今後の監査結果が比較できない**。フェーズ1(観測モード)の目的である
   「このプロジェクトの誤検知率と増えた壁時計の実測」も、レンズが変わると成立しない。

コードの振る舞いには影響しないので severity は「中」。ただし品質ゲートの強度に直接効くため、
`docs/issues/` の他の「中」より優先度は高い。

## 原因の見当

`task-docs-restructure` が `environments.md`「Codex実行設定」を作った時点では
`/codex-audit` の「未記入行は不在として扱い既定(最強)を使う」という規則が無かった、
あるいは「未定(codex 既定)」という書き方が**明示的に codex 既定を選んだ決定**として読まれていた、
という**推測**。規範側は「明示的に下げるのは構わないが、既定のまま放置するのは違う」と書いており、
「未定」は明示的な引き下げには当たらない。

## 正はどちらか

- P-003 の記述は **ドキュメントが誤り**(訂正すれば足りる)。
- モデル・reasoning をどの値に固定するかは **人間の判断**(コストと監査強度のトレードオフであり、
  委任のガードレール内で AI が決める性質のものではない)。**要確認**。

## 対処案

| 案 | 内容 |
|---|---|
| A | `environments.md`「Codex実行設定」の「モデル・reasoning」行を実値へ確定する(例: 増分監査 = `gpt-5.6-terra` / `max`、full監査 = 同、QA = 未定のまま)。MINOR 変更。あわせて P-003 の「そちらに必要な設定は確定している」を「監査のモデル・reasoning は規範の既定(`gpt-5.6-terra` / `max`)に従う」へ訂正する |
| B | 「未定」を保つが、P-003 に「監査のモデル・reasoning も未定であり、`/codex-audit` の既定が適用される」と明記して矛盾だけを解消する。強度の揺れは残る |
| C | コストを理由に明示的に弱いモデルへ下げる(規範が「明示的に下げるのは構わない」と認めている)。その場合は**下げたという事実と理由を `environments.md` に書く**こと。過去の実行が実際に使っていた値に合わせるならこれ |

いずれの案でもコードは1行も変わらない。A / C はどちらも `environments.md` の
verified 済み SSOT を触るので、通常のフェーズ(`/task-new` → `/task-doc` → …)を回す必要がある。
