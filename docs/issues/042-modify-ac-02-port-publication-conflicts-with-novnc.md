# 042 AC-02 の「ポート非公開」が noVNC のポート公開と両立しない

## 事象

`docs/00-requests/` の中で、既定起動時にホストへポートが公開されるかどうかが一意に決まらない。

| 出どころ | 記述 |
|---|---|
| `AC-01`(`docs/00-requests/acceptances.md:39` 付近) | 「ブラウザ確認ありの構成なら、**起動時に noVNC の URL が表示される**」 |
| `AC-02` | 「`claude-dev start` しただけの時点では**ホストにポートが公開されていない**」 |
| `D0-env-01` | 「noVNC のポートは **6080 番台から動的に割り当てる**」 |

noVNC の URL がホストのブラウザから開けるものであるなら、その時点で**ホストにポートが公開されて
いる**。したがって AC-02 をそのまま読むと AC-01 と衝突する。

**AC-02 の意図はおそらく「利用者のアプリケーション用ポートは公開しない」(= `D0-env-02`
「ポートは起動時に公開せず、必要なときだけ開く」= `claude-dev forward` を使う)であって、
noVNC のような補助 UI のポートを除外していない**、というだけの記述漏れだと考えられる。
しかし**そう書かれていない**ため、同じ既定起動に対する合否が読み手によって変わる。

## 影響

- check A0(00-requests の内部整合: request / 受け入れ基準 / 決定事項の間に矛盾が無いこと)に反する。
- `AC-02` は `FR-env-04`(ポートフォワード)系の上流であり、E2E の受け入れ判定にも使われる。
  「起動直後に `docker ps` の公開ポートが空であること」を試験にすると、
  **ブラウザ確認ありの構成では必ず落ちる**。

## 原因の見当

**推測**: `AC-02` は VM モードやブラウザ確認が入る前に書かれた受け入れ基準で、
noVNC(`D0-env-01`)が後から入ったときに例外が追記されなかった。

## 正はどちらか

**人間判断。** `docs/00-requests/` の受け入れ基準の意味を変える編集は
`/doc-check` の委任範囲外(CLAUDE.md 原則4 / 「meaningful edits to layer 00」)。

| 案 | 内容 |
|---|---|
| A | `AC-02` に適用範囲を明記する(「**利用者のアプリケーションが待ち受けるポート**は公開されない。noVNC 等の補助 UI のポートはこの限りではない」)。実装・振る舞いは変わらない |
| B | `AC-02` をブラウザ確認なしの構成に限定する |
| C | noVNC も既定では公開せず `forward` 経由にする(**コード変更 → 別タスク**。`D0-env-01` の変更を伴う) |

推奨は A(記述漏れの補い)だが、**00 層なので人間が決める**。

## ★2026-08-04 追記: コードで確定した事実(指摘は起票時より強い)

**noVNC は既定で有効であり、既定の `claude-dev start` はホストへポートを公開する。**

| 場所 | 事実 |
|---|---|
| `claude-dev:695` | `USE_VNC=1` — **VNC ありが既定**。`:701` の `--no-vnc` を明示したときだけ 0 になる |
| `claude-dev:846`〜`:848` | `USE_VNC=1` のとき `NOVNC_PORT_OPT="-p ${NOVNC_PORT}:6080 …"` を `docker run` に付ける |
| `claude-dev:269`〜`:279` | ホスト側ポートは 6080 から100個の範囲で空きを探して決める(`D0-env-01` どおり) |
| `claude-dev:929`〜`:934` | ポート競合時は別のポートを選んで最大20回まで再試行する(= 公開は必須経路であり、失敗時に「公開しない」へは倒れない) |

したがって `AC-02` の「期待される結果」の一文
「`claude-dev start` しただけの時点ではホストにポートが公開されていない」は、
**既定構成で literally 成立しない**(記述漏れではなく**反例が既定**である)。
なお「こうなったら不合格」の側は「`start` しただけで**意図せず**ポートがホスト公開される」と
書かれており、noVNC は意図された公開なので**不合格条件そのものは破れていない**。
壊れているのは期待結果の文だけなので、**案A(適用範囲の明記)で振る舞いを変えずに解消できる**。

**severity は「中」で妥当**: `AC-02` を機械検査している箇所は無い
(`docs/03-impl/tests/` に「起動直後の公開ポートが空」を検査する行は存在しない)。
