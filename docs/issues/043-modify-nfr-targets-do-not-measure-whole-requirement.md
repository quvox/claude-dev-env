# 043 非機能要件の目標値・測定方法が要件本文の一部しか測っていない

## 事象

`docs/01-requirements/non-functional.md` は `| ID | 要件 | 目標値 | 測定方法 |` の4列で書かれている。
次の5件は「要件」列が複数の条件を述べているのに、「目標値」「測定方法」列が**そのうち1つだけ**を
対象にしている。曖昧語(CLAUDE.md §8 の禁止語)は使われていないため C7 では検出されず、
**列の対応を突き合わせないと見えない**種類の欠落である。

| ID | 要件が述べていること | 目標値・測定方法が測っていること | 測られていない部分 |
|---|---|---|---|
| `NFR-perf-02` | ベースレイヤーを共有し、**追加ディスクを VNC/Chrome 分に限定する** | 2イメージのベース層が同一ダイジェストであること | 「追加ディスクが VNC/Chrome 分に限定されている」ことの判定。VNC/Chrome 以外の追加物が入った場合に落ちない |
| `NFR-sec-03` | 秘密情報の到達範囲が必要な発信源に限られ、**エージェント(worker・対話 Claude)の環境に含まれない** | worker プロセスの環境変数に通知トークンが存在しないこと | **対話 Claude** とレビューアーの環境。通知トークン**以外**の秘密情報 |
| `NFR-ops-01` | **資源逼迫・レート制限・通知**の状況を利用者が把握できる | 4種のログ(タスク委譲・実行結果・仮定・介入)が出ていること | 資源逼迫・レート制限・通知そのものの把握。**受入基準が存在しない** |
| `NFR-ops-04` | 運用状態を**機械だけが読み書きし人間が編集しない**前提を含む | モデル/effort ポリシーが1ファイルであること | 運用状態の読み書き主体に関する部分(重大度: 低) |
| `NFR-scale-02` | `logout` / `reset` の**分岐が増えない** | (同旨) | 比較基準となる版、分岐の数え方、追加する CLI の条件が無いため一意に測れない(重大度: 低) |

あわせて `NFR-sec-02` の「ブロック対象ドメイン」が未定義である件は
**`docs/issues/041` に分離**した(集合そのものが仕様に無いという別種の欠落なので)。

## 影響

- check C8「受け入れ基準が…テスト可能な粒度であること」に反する。
- CLAUDE.md 不変則3 により**重大度「中」は PASS をブロックしない**ため、
  `non-functional.md` は 2026-08-04 に 1.2.0 で合格証を得ている。
  **本 issue はその合格証と両立する既知の品質欠落**である。
- とくに `NFR-ops-01` は「受入基準が存在しない」ため、実装が要件を満たしているかを
  現状の記述では一切判定できない。

## 原因の見当

**推測**: 要件列を後から加筆したときに、目標値・測定方法の列が追随しなかった。
`task-impl-depth` は 01 について**境界値・異常系の受入基準の追加**と**測定不能語の置換**を
対象にしており、「4列の対応が取れているか」という観点は影響範囲に入っていなかった。

## 正はどちらか

**ドキュメントが誤り**(要件の意図は妥当で、測定方法が追いついていない)。
ただし**測定方法を書き足すことは新しい目標値を決めること**であり、
`D0-scope-07` の委任範囲外(「読み取れない=決めなければならないものは書かず issue 起票」)。

## 対処案

| 案 | 内容 |
|---|---|
| A | 5件それぞれに目標値・測定方法を追記する(要件レベルの判断を伴うので**人間の合意が必要**) |
| B | 測れない部分を要件から外し、設計判断へ降ろす(`NFR-perf-03` 第2文で採った形。`docs/issues/035` と同じ処理) |
| C | 「4列の対応」を機械検査するスクリプトを `.claude/scripts/` に追加する(`/kit-improve` 案件。**この種の欠落は目視では繰り返し取りこぼされる**) |

A と C を組み合わせるのが妥当と考えられる(C だけでは既存の5件が閉じない)。
