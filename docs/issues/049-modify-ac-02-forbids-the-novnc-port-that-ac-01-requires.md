## 事象

`docs/00-requests/acceptances.md` の2つの受け入れ基準が、既定構成について食い違う。

| 出どころ | 記述 |
|---|---|
| **AC-01** の期待される結果 | 「ブラウザ確認ありの構成なら、起動時に noVNC の URL が表示される」 |
| **AC-02** の期待される結果 | 「**`claude-dev start` しただけの時点ではホストにポートが公開されていない**」 |
| **AC-02** の不合格条件 | 「**`start` しただけで意図せずポートがホスト公開される**」 |
| `D0-env-02`(決定) | 「`claude-dev start` の時点では Web アプリ用のポートマッピングを行わない(**ブラウザ確認ありの noVNC ポートを除く**)」 |
| `02-design/environments.md` | 「Claude コンテナ(ブラウザ確認あり)… noVNC のみ 6080 番台から動的割当」 |

**ブラウザ確認ありが既定である**(`claude-dev start` の既定。`--no-vnc` で外す)。
したがって**既定の `start` は必ずホスト側 6080 番台を1つ公開する**。

`D0-env-02` は「noVNC を除く」と例外を明記しているが、**`AC-02` にはその例外が書かれていない**。
AC-02 の文面をそのまま受け入れテストにすると、**既定構成が不合格になる**。

## 影響

- **受け入れ基準どうしが矛盾している**(`AC-01` を満たすと `AC-02` に反する)。
- AC-02 を機械的にテスト化すると、正常な既定動作を不具合として検出する。
- 現実には `D0-env-02` の例外が効いているので**実装は正しい**。壊れているのは 00 層の記述だけである。

## どちらが正か

**`D0-env-02` が正**(noVNC は意図した例外)。`AC-02` の文面が例外を落としている。

修正案: `AC-02` の期待される結果と不合格条件を「**Web アプリ用のポート**は公開されない」に
限定し、noVNC ポートは `D0-env-02` の例外である旨を添える。
`AC-02` の主題は「Web アプリをクライアントのブラウザで確認」なので、対象を Web アプリのポートに
絞っても基準の意図は変わらない。

## なぜ task-fix-destructive-scope で直さないか

同タスクは `AC-02` を影響範囲に含まない(closure 表で「`00-requests/acceptances.md` は変更なし」と
判定済み)。**00 層の意味のある編集**であり、CLAUDE.md 原則8「本タスクの範囲外の修正を混ぜない」に
従って起票にとどめる。

**`task-spec-measurability`(3本連続タスクの3本目)が `AC-02` を影響範囲に含む**
(同タスクの memo.md)。**そこで一緒に直すのが効率的**である。
