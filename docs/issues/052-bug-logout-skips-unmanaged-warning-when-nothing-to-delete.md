# 052 logout の削除対象0件の経路がラベル無しコンテナの警告を出さない

## 事象

`claude-dev logout` は、削除対象(管理ラベルを持つ Claude コンテナ / カレントディレクトリの
認証3ファイル)が0件で、かつ共有ボリューム `claude-dev-auth` が空のとき、
「削除対象がありません」を表示して終了コード 0 で終わる(`claude-dev:981`〜`:986`)。

この経路は、**その手前で集めた管理ラベルを持たない稼働中コンテナ(`_unmanaged`)を一切参照しない**。
したがって次の2つが表示されない。

- 管理ラベルを持たないため削除しなかったコンテナの名前(`claude-dev:1090`〜`:1094` にある表示)
- **「これらのコンテナは 30 秒ごとに認証を共有ボリュームへ書き戻すため、
  稼働したままだと共有ボリュームの認証が復活する」という警告**(`claude-dev:1095`〜`:1097`)

再現手順:

1. 本変更より前に起動した(= 管理ラベルを持たない)Claude コンテナを1つ稼働させておく。
2. `claude-dev logout` を実行する。削除対象があるので通常経路を通り、
   ラベル無しコンテナの名前と書き戻しの警告が表示される。
3. 30 秒待つ。手順2 で消した認証が、稼働中のコンテナの同期ループによって共有ボリュームへ
   書き戻される(`FR-env-03` 受入基準3)。
4. もう一度 `claude-dev logout` を実行する。**このときカレントディレクトリの認証コピーは
   手順2 で消えており、管理ラベルを持つコンテナも無い。共有ボリュームの中身の有無で分岐は
   変わりうるが、空になるタイミングでは手順6 の早期終了に入り、
   「削除対象がありません」だけが表示される。**
5. 利用者は、稼働中のラベル無しコンテナが原因であることを知る手段を持たない。

## 影響

利用者(とくに本変更より前から起動しっぱなしのコンテナを持つ人)が、
**`logout` が効かない理由に到達できない**。`docs/issues/025` が閉じた「消したつもりで残る」
という失敗の、残った一形態である。データは失われないので severity は「中」。

## 原因の見当

`FR-env-03` 受入基準17 は「`logout` / `reset` が削除対象を**集合として列挙する**とき、
…管理ラベルを持たない Claude コンテナは削除せず、その名前と…を表示して残さなければならない」と
条件づけている。**列挙する集合が空の経路はこの条件に掛からない**ため、実装は受入基準に違反していない。
受入基準19(削除対象0件なら確認を求めずに終了コード 0)も満たしている。

つまりこれは実装の逸脱ではなく、**受入基準17 と19 の隙間**である(推測ではなく、
両基準の字面から導ける)。
