# 053 logout が列挙できない共有ボリュームを「空」と判定する

## 事象

`claude-dev logout` は手順6 で「削除対象が0件で、かつ共有ボリューム `claude-dev-auth` が空」なら
早期に終了コード 0 で終わる(`FR-env-03` 受入基準19)。その「空」の判定は次の1行だけで行っている
(`claude-dev:975`〜`:979` / `claude-dev-mac` の同一箇所)。

```sh
_auth_empty=1
if [ -n "$(docker run --rm --entrypoint bash -v "${VOL_AUTH}:/auth" "$IMG_CLAUDE" -c 'ls -A /auth 2>/dev/null' 2>/dev/null)" ]; then
    _auth_empty=0
fi
```

標準出力が空文字列かどうかしか見ておらず、**一時コンテナが起動できなかった場合(daemon 断・
ボリュームをマウントできない・イメージが壊れている)も出力は空になる**。その結果
`_auth_empty=1` のまま早期終了の分岐に入り、共有ボリュームに認証が残っているのに
「削除対象がありません(…共有ボリュームの認証…のいずれも見つかりませんでした)」を表示して
**終了コード 0** で終わる。

同じ文書の手順10(共有ボリュームの消去)は、この取り違えを避けるために
**印 `__CLAUDE_DEV_AUTH_LISTED__` を列挙の直前に出す**方式を採っている。
**手順6 にはその防護が無い。**

再現手順:

1. `claude-dev login` で共有ボリュームに認証を置く。
2. 管理ラベルを持つ Claude コンテナを1つも動かさず、カレントディレクトリに認証コピーも
   置かない状態にする(削除対象が0件になる状態)。
3. `docker run -v claude-dev-auth:/auth` が失敗する状態を作る(例: ボリュームを別プロセスが
   排他的に使用している、Docker daemon が応答しない)。`require_setup` は通る必要がある。
4. `claude-dev logout` を実行する。→ 「削除対象がありません」と表示して 0 で終わる。
   共有ボリュームの認証は残ったままである。

## 影響

利用者は `logout` が完了したと解釈するが、共有ボリュームの認証は消えていない。
次に別のコンテナを起動すると認証済みで起動する(`docs/issues/025` が閉じた
「消したつもりで残る」の残った一形態)。

**severity を「中」とした理由**(独立レンズ Codex は「高」と報告した):

- 発現には Docker 側の失敗が要る。しかも手順2 の `require_setup`(`docker image inspect` と
  必要ならビルド)を通り抜けたうえで `docker run -v` だけが失敗する、という狭い窓である。
- 表示は「削除しました」ではなく「見つかりませんでした」なので、`FR-env-03` 受入基準18 が
  禁じる**成功の文言**は出していない。
- 認証が失われる方向の破壊は起きない(安全側に倒れているのは削除の方)。

ただし**受入基準19 が前提とする「共有ボリュームも空」を確かめられていない状態でこの経路に
入る**ことは事実であり、`D0-env-08` の目的(消したつもりで残る状態を作らない)からは外れている。

## 原因の見当

手順10 で導入した「印による成否判定」を、同じ文書内の手順6 の判定へ展開していない。
実装の順序としては手順6 の方が先に書かれており、後から手順10 を堅くしたときに取り残された
(推測。コミット履歴上、印の導入は独立レンズの指摘への対応として後から入っている)。

## 正はどちらか

| 観点 | 実装(03)はどう言っているか | 要件(01)はどう言っているか | 判定 |
|---|---|---|---|
| 「共有ボリュームが空」の判定 | `MODULE-cli-logout` 手順6 が「列挙の標準出力が空かどうかだけで判定し、一時コンテナが起動できなかった場合も空と判定する」と実装どおりに記述した(2026-08-05 に `/doc-check` が実態へ揃えた) | `FR-env-03` 受入基準19 は「共有ボリュームも空」を条件に置くだけで、確かめられなかったときの扱いを定めていない | **要確認**(実装は受入基準の字面には違反していないが、確かめていない事実を前提として使っている) |

## 対処案

| 案 | 内容 | 影響範囲の見込み |
