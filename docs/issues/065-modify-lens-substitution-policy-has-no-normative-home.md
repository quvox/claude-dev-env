# 065 レンズ代替の可否を書く欄が仕様ドキュメントに無い

## 事象

CLAUDE.md 不変則7 は、独立レンズ(`/codex-audit` / `/codex-qa`)の代替を
**人間の判断**と定め、決定シートで問うこと・既定は代替しないことを規定する。
これは**キット共通の規範**であり、プロジェクトごとの答えは持たない。

2026-08-05、人間は `/implement` の開始時に次を**常設で**指示した。

> 今後、codex が利用できない時は subagent を使って。

この指示は当該セッションの会話にしか存在しない。書き込める先を探すと:

- `docs/02-design/environments.md`「Codex実行設定」は、プロファイル・モデル・タイムアウト・
  書き込み許可ディレクトリなど**プロジェクト固有の実行設定**を持つ表だが、
  **「Codex が使えないときにどうするか」の行が無い**(2026-08-05 実測)。
- `docs/feedbacks/022` に経緯として記録したが、feedbacks は仕様ドキュメントではなく
  `source` にもならないため、**規範として参照できない**。
- `.claude/directions/external-agent.md` はキット側の文書で、プロジェクト固有の答えは書けない。

結果として、**次のセッションの AI は同じ質問を人間へ問い直す**(または、常設承認を知らずに
既定の「代替しない」で止まる)。

## 影響

- Codex の復旧は 2026-08-11。それまでの `/task-close` を含む全実行が、同じ承認を取り直す。
- より一般に、**人間が与えた運用方針が構造的に保存されない**。
  CLAUDE.md 原則1 の趣旨(仕様ドキュメントが現状の唯一の正)から漏れている領域である。

severity を「低」とした根拠: 実装も要件も壊れていない。承認の取り直しが発生するだけで、
安全側(既定 = 代替しない)に倒れるため、誤った代替が起きる方向の危険は無い。

## 原因の見当

推測: `environments.md`「Codex実行設定」は **Codex が動く前提**で項目を設計しており、
**動かないときの縮退方針**という軸が最初から無かった。QA レーンの行が
「無効(未運用)」と書けているのは、それが**機能の有無**であって縮退方針ではないためである。

## 正はどちらか

実装との矛盾ではなく、**仕様ドキュメントの欄の欠落**である。
どちらが正かを問う対象が無い(要確認ではない)。

## 対処案

| 案 | 内容 | 影響範囲の見込み |
|---|---|---|
| A | `environments.md`「Codex実行設定」に **「レンズが使えないときの代替」** の行を1行足し、値を「サブエージェントで代替してよい(人間の常設承認。2026-08-05)。レポートに `lens: subagent` と実モデル名を明記する」とする | `docs/02-design/environments.md`(MINOR)。02 が起点なので下降先は無い |
| B | 同じ内容を `docs/00-requests/decisions/` の新しい決定(`D0-*`)として起こす | 00 起点。`environments.md` は参照するだけ |
| C | 常設化せず、実行ごとに決定シートで問う現状を維持する | 変更なし |

推奨は **A**。不変則7 が問うのは「代替してよいか」という**プロジェクトの運用判断**であり、
`environments.md` は既に「Codex実行設定」としてその種の値を集めている場所だからである。
ただし **B が正しい可能性もある**(独立性を下げる判断は要求の水準だという読み方)。
起点層の判断そのものを含むので、**人間に問うこと**。
