# 068 用語集「介入トリガー」の5条件が発火経路を網羅していない

## 事象

`docs/00-requests/terminology.md` の定義:

> | 介入トリガー | **人間の判断を仰ぐ5条件**(重大判断/曖昧さ/行き詰まり/方針分岐/前提崩れ) | … |

`docs/01-requirements/functional.md` の `FR-orch-04` 受入基準1 も同じ5語を使う。

一方 `docs/00-requests/decisions/orch.md` の `D0-orch-18` は、介入を**発火させる条件**を
4行の表で定めており、さらに「射程」で別経路の存在を明示している。

| D0-orch-18 の発火条件 | 用語集の「5条件」に含まれるか |
|---|---|
| ディスパッチ前: タスクが不可逆と印付けされており、かつ人間の承認がまだ無い | **含まれない** |
| ディスパッチ後: 同一タスクの試行回数が `stuck_limit`(既定 3)以上に達した | 「行き詰まり」に読めるが、`D0-orch-18` は別行として分けている |
| ディスパッチ後: その試行で行き詰まりが検出された | 含まれる(「行き詰まり」) |
| ディスパッチ後: worker が「人間が必要」を 曖昧さ / 方針分岐 / 前提崩れ / 重大判断 のいずれかで申告した | 含まれる(残り4語) |
| (射程の但し書き)レビューゲートの不具合 = `review_gate_defect`(`FR-orch-06` 受入基準6) | **含まれない**。`D0-orch-18` 自身が「worker の判断ではないため上表に含めず、それ自体で介入へ回る」と書いている |

つまり **「人間の判断を仰ぐ」経路は5つより多い**。`FR-orch-04` 受入基準7(不可逆タスクの
事前承認)と受入基準5(`stuck_limit`)は、受入基準1 の「介入トリガー」とは別の基準として
書かれており、01 の内部では矛盾していない。**食い違うのは用語集の定義文の「5条件」という
言い切りだけ**である。

## 影響

読み手が「介入が起きるのはこの5つのときだけ」と受け取る。実装(`orchestrator/trigger.go::Evaluate`)
と `D0-orch-18` を読めば正しい集合が分かるので、**振る舞いにも実装にも影響しない**。
severity は「低」: 用語の説明の網羅性の問題であり、要件・設計・実装のどれも誤っていない。
`severity: 高` ではないので認証を妨げない。

なお `docs/01-requirements/usecases.md` の UC-04 代替フロー A1 が「`D0-orch-18` が列挙する
**4理由**(曖昧さ・方針分岐・前提崩れ・重大判断)」と書いているのは**正しい**
(`D0-orch-18` の第4行=worker の自己申告の4理由を正確に指している)。
独立レンズはこれを「用語集の5条件と食い違う」と挙げたが、A1 の記述は誤っていない。
**誤っているのは用語集の側の網羅性**である。

## 原因の見当

`D0-orch-18`(2026-08-03)が「軽微な判断」という程度語を廃して発火条件を4行の表へ書き直したとき、
`FR-orch-04` 受入基準4 と `UC-04` 代替フロー A1 は表を参照する形へ更新されたが、
**用語集の「介入トリガー」行は 5 語の列挙のまま残った**(推測ではなく、
`D0-orch-18` の「影響」欄が更新対象として `FR-orch-04` 受入基準4 / `UC-04` 代替フロー A1 /
`NFR-perf-03` の3つだけを挙げ、`terminology.md` を挙げていないことから読める)。

## 正はどちらか

| 観点 | 実装(03)はどう言っているか | 要件・設計(00〜02)はどう言っているか | 判定 |
|---|---|---|---|
| 介入の発火経路 | `MODULE-orchestrator-trigger` は `D0-orch-18` の表どおり(不可逆・試行回数・行き詰まり・申告4理由)+ `MODULE-orchestrator-review` の `review_gate_defect` | `D0-orch-18` の表と射程が同じことを述べている | **一致**(用語集だけが古い) |

## 対処案

| 案 | 内容 | 影響範囲の見込み |
|---|---|---|
| A | 用語集の定義を「**`D0-orch-18` が定める発火条件**(および `FR-orch-06` 受入基準6 の `review_gate_defect`)」という**参照**へ改め、5語は「含む例」列へ移す | `terminology.md` 1ファイル(00 なので人間の合意が要る)+ 下流の合格証の再発行 |
| B | 「5条件」を「worker の判断に起因する5条件」と**範囲を明示**し、他の経路が別にあることを1文足す | 同上。変更量は最小 |
| C | 直さない(`D0-orch-18` を読めば分かる) | なし。ただし用語集の役割(語の意味を一意にする)を果たさない行が残る |

**推奨は B**(最小の追記で言い切りの誤りだけを消せる。`D0-orch-18` の 射程 が既に同じ整理を
述べているので、新しい判断を要しない)。**00 層の本文変更なので人間の合意が要る。**
