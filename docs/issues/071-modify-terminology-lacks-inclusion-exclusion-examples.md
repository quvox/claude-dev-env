# 071 用語集 17 語に「含む例」「含まない例」が無い

## 事象

`.claude/directions/00-requests.md` は用語集の各行に「含む例」「含まない例」を必須と定め、
`/doc-check` の check A0 は **full モード限定**でこの欠落を重大度「中」で検出すると定めている
(モードを限定しているのは、タスクが触れた用語から順に埋める運用を許すためである)。

2026-08-06 に `docs/00-requests/terminology.md` の用語表 23 行を機械走査した結果、
**両列が空なのは次の 17 行**である。

`claude-dev` / `Claude コンテナ` / `Codex CLI` / `Codex サンドボックス` / `docker-proxy` /
`forward プロキシ` / `DooD` / `VM モード` / `オーケストレーター` / `コントローラ` / `worker` /
`ブレインストーミングモード` / `実行モード` / `介入` / `介入トリガー` / `運用状態` / `ORCHESTRATOR.md`

埋まっているのは `安全` / `公開ポート` / `ブロック対象ドメイン` / `破壊的操作` / `管理ラベル` /
`資源逼迫` の 6 件で、**いずれも過去のタスクが境界を争点にしたことがある語**である。

## 影響

**語の外延が定義文の解釈だけに委ねられる。** 「含まない例」が無い語は、境界の争いが起きたときに
「その語に含まれるか」を決める材料が文書内に無く、判断が実行ごとに揺れる。

現に本実行では、この欠落と同じ根から出た指摘が別に1件出ている:
独立レビューが `D0-env-02` の「socat のプロキシコンテナ」という表記を、用語 `forward プロキシ` の
「使ってはいけない言い方(docker-proxy と混同する書き方)」に当たりうると報告した
(`docs/00-requests/decisions/env.md:35`)。`forward プロキシ` に「含む例」「含まない例」があれば、
これは機械的に判定できた。

severity は「中」とする(規範自身が「PASS をブロックしない」と定めているため)。

## 原因の見当

用語表は 2026-07-30 の初版で 23 語をまとめて起こしており、
以後のタスクが**争点になった語だけ**に例を書き足してきた(推測。埋まっている 6 語がいずれも
`D0-env-08` / `D0-sec-*` / `NFR-perf-*` の議論と対応することが根拠)。

## 正はどちらか

要件・設計の側だけの問題であり、実装との食い違いではない(**00 層の記述の不足**)。

## 対処案

| 案 | 内容 | 影響範囲の見込み |
|---|---|---|
| A | 17 行すべてに「含む例」「含まない例」を1件ずつ書く | `terminology.md` 1ファイル。MINOR。下流の再認証が要る。**17 語ぶんの外延を決めるのは人間の判断**であり、AI が勝手に決めてよい範囲ではない |
| B(推奨) | 現状の運用(タスクが触れた語から埋める)を追認し、本 issue を「埋まるまで残す台帳」として使う。`/doc-check full` は毎回この 17 件を数え直す | 変更なし。ただし「full を掛けるたびに同じ『中』が出る」ことを受け入れる |
| C | `.claude/directions/00-requests.md` の「必須」を「境界が争点になった語には必須」へ緩める | キット側の変更(`/kit-improve` 案件) |
