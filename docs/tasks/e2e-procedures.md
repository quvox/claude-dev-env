# タスク:E2E シナリオに再現可能な実施手順を与える

## 目的

`03-impl/e2e.md` のテスト対応表は各 E2E シナリオの**検証内容**を述べるが、**実施手順**を持たない。
そのため実施者によって入力・観測点・合否判定・後始末が変わり、「実機確認した」と言えても再現性がない。
E2E-1〜6 のそれぞれに、第三者が同じ条件で再実施できる手順（固定の入力／実行コマンド／期待成果物／
合否判定の根拠／後始末）を与える。

## 起票の経緯

`/doc-check full`（2026-07-31）の独立監査 `readiness`（Codex）が **重大度 高** で指摘した。
その場で E2E-6 だけ D-19（03-impl の記述粒度）の委任として手順を書き下ろしたが、絞り込み再監査を
2 回かけても毎回新規の重大度 高 が出続けた（合否判定の自己矛盾 → 実行コマンド未指定と次コンテナ
引継ぎの観測欠落 → `login-codex` 手順の欠落・複数プロジェクトの生成手順とコンテナ間 `cmp` が
実行不能な記法・人工的なファイル差分がトークン更新の代理になっていない）。

そこから得た結論が本作業の前提である——**「再現可能な E2E 手順を書き下ろす」ことは記述粒度の調整
ではなく新規の仕様記述であり、D-19 の委任範囲外**。加えて E2E-1〜5 も同様に手順を持たないため、
E2E-6 だけを詳細化するのは文書として不均衡。よって撤回し、6 シナリオを一括で扱う独立作業として
起票した（人間判断・決定シート #2 = 案A。feedback/log.md [15]→[16]）。
