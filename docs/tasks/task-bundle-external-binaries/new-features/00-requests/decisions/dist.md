## D0-dist-05 外部実行ファイルは保守者が externals/ へ手で置き、公開イメージへ同梱する

- 区分: 決定
- 決めた日: 2026-08-18
- 内容:
  1. **置き場と主体**: 配布イメージへ同梱する外部実行ファイルは、**保守者がリポジトリ直下の
     `externals/` へ手でコピーする**。イメージのビルドはそこに在るものを設置するだけで、
     ビルド時に外部から取得しない(`request.md`「やらないこと」6)。
     **`externals/` の中の規約(アーキテクチャ別の置き分け、同梱しないファイル)と、
     イメージ内の設置先は 02/03 が定める。**
  2. **公開範囲**: **CI が公開する GHCR イメージにも同梱する。** その帰結として、
     `externals/` に置いたものは (a) 公開リポジトリにコミットされ、(b) 公開イメージを
     `docker pull` した誰もが取り出せる。**この2点を承知のうえで採る。**
  3. **ガードレール**(置く側が守る。置いてよいものの条件):
     - **認証情報・秘密鍵・API キーを置かない。** `SR-03` と `NFR-sec-01` が既に禁じている
       ことを、この新しい経路について名指しで再掲する。
     - **公開配布してよいものに限る。** 再配布が許されているかどうかを、置く前に置く側が確認する。
  4. **スコープ**: 本決定は「保守者が置いた実行ファイルが、開発者のコンテナ内でコマンド名だけで
     起動できる状態」までである。版の記録・署名・チェックサムの検証は含まない。
- 理由: 同梱したい社内ツールは別リポジトリで作られており、その多くは非公開である。
  ビルド時の自動取得(配布サイトやリリース資産からの取得、ソースリポジトリを取得してのビルド)は、
  **取得元の資格情報をビルドへ持ち込む経路を作る**うえ、取得元の可用性にビルドの成否が依存する。
  手で置く形にすると、同梱物の出所と版を決めるのは常に人間になり、ビルドは
  「在るものを設置するだけ」の決定論的な処理に留まる。
  公開イメージへも焼くのは、**チーム全員が pull だけで同一構成を得る**という `RQ-dist-01` の
  約束を、同梱物についても崩さないためである。ローカルビルド限定にすると、
  `claude-dev pull` で入れた人と `make build` した人で中身が違うイメージができる。
  ガードレールを置くのは、**公開イメージへ焼いたものは回収できない**からである。
- 却下した案:
  - **配布サイトやリリース資産から取得する**(2026-08-18 に人間が採らなかった) —
    非公開の取得元では資格情報をビルドへ渡すことになる。取得元にリリースを作る運用を
    先に整える必要もある。
  - **ソースリポジトリを取得してビルドする**(同日) — 同じく資格情報が要り、
    「バイナリだけを同梱する」という要求とも合わない。同梱物のビルド環境を
    このリポジトリが抱えることにもなる。
  - **ローカルビルドにだけ同梱し、公開イメージには入れない**(同日) — pull した人と
    ビルドした人で中身が違うイメージができ、`RQ-dist-01` の「同一構成」が崩れる。
  - **アーキテクチャを区別せず1つの置き場に平らに置く**(同日) — 配布イメージは
    amd64 と arm64 の2つあり、片方のアーキ向けの実行ファイルがもう片方のイメージにも入って
    実行できない状態になる。
- 見直す条件: (a) 配布先が公開 GHCR でなくなったとき(項2 の帰結と項3 の2条目の前提が消える)/
  (b) 同梱物が増えて手で置く運用が回らなくなったとき(そのときは自動取得の是非を
  `request.md`「やらないこと」6 から見直す)/ (c) 同梱物の版を利用者が知る必要が生じたとき
  (項4 のスコープ外を範囲へ入れる)。
