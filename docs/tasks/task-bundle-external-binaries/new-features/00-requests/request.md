## 対象ユーザー

| 呼称 | 誰か | この人の目的 |
|---|---|---|
| 開発者 | 社内の開発者(日本語話者)。本ツールの主たる利用者 | プロジェクトのコンテナを起動して Claude Code で開発する |
| 保守者 | 本ツール自体を保守する社内の開発者 | イメージの配布・更新を行う。**イメージに同梱する外部実行ファイルを用意する** |

前提として**信頼できる社内開発用途に限定**する(信頼できないコードを扱う用途・本番に近い環境は対象外)。

## やること

| ID | 要求 | 補足 |
|---|---|---|
| RQ-env-01 | ホスト CLI によるコンテナのライフサイクル管理・ポートフォワード・認証・SSH 鍵転送 | Linux は `claude-dev`、macOS は `claude-dev-mac` |
| RQ-env-02 | 開発ツール入りコンテナイメージ(VNC あり/なし)と、noVNC 経由のブラウザ確認 | クライアント PC のブラウザからコンテナ内 Chrome を見る |
| RQ-env-03 | エージェント CLI の同梱(Claude Code と OpenAI Codex CLI)と、認証のホスト共有 | プロジェクト間で再ログインを不要にする |
| RQ-env-04 | ホストの Docker を制限付きで使うための Docker Socket Proxy | 生ソケットを渡さずに `docker` を使えるようにする |
| RQ-env-05 | 重い Docker 案件向けの VM モード(オプトイン) | QEMU+virtiofs、VM 内ネイティブ Docker |
| RQ-env-06 | macOS(Docker Desktop)対応 | OS 依存はホスト CLI に閉じる |
| RQ-dist-01 | イメージの GHCR 配布(マルチアーキ) | チーム全員が pull で同一構成を得る |
| RQ-dist-02 | **保守者が用意した外部実行ファイルの配布イメージへの同梱** | 別リポジトリで作られた社内ツールを、開発者が追加の導入作業なしにコンテナ内で使えるようにする。**用意するのは保守者で、ビルドより前の手作業である**。置き場と規約は 02/03 が定める |

## やらないこと

     4・5 は 2026-08-08 に削除した(対象の機能そのものを廃止したため)。 -->

| # | やらないこと | 理由 |
|---|---|---|
| 1 | **コンテナ内で動くプロセスごとの個別隔離**(microVM 等によるプロセス単位の隔離) | 本構成は単一コンテナ同居型とし、隔離境界はコンテナ/ホスト間にのみ置く。個別隔離が要る用途は別構成(Docker Sandboxes 等)で検討する |
| 2 | **信頼できないコード・本番に近い環境での利用** | 信頼できる社内開発用途に限定するという前提を置いたうえで、隔離の強度を決めているため |
| 3 | ホストの Docker 生ソケットをコンテナへ直接マウントする運用 | ホスト掌握のリスクがあり、原則採用しない |
| 6 | **同梱する外部実行ファイルをビルド時に自動取得すること**(配布サイトやリリース資産からの取得、ソースリポジトリを取得してのビルド) | 同梱物は保守者が手で用意すると決めた(`D0-dist-05`)。自動取得は取得元の資格情報をビルドへ持ち込むことになり、`SR-03`(認証情報をイメージへ焼き込まない)を守るべき経路が1本増える。取得元の可用性にビルドの成否が依存することも避ける |
