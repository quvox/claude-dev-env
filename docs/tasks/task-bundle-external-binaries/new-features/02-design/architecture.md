## コンポーネントの責務

| コンポーネント | 責務 | 対応要件 |
|---|---|---|
| claude-dev(ホスト CLI) | コンテナのライフサイクル・ポート・認証・SSH 鍵の操作 | FR-env-01, FR-env-03, FR-env-04, FR-env-06 |
| Makefile | ビルド・セットアップ・CLI の導入/除去 | FR-env-09, FR-env-10 |
| コンテナイメージ | 開発ツール・エージェント CLI・ブラウザ確認資産・**保守者が用意した同梱外部バイナリ**を同梱した実行基盤 | FR-env-09, FR-env-11, FR-env-12, FR-env-13 |
| entrypoint | コンテナ起動時の初期化(UID/GID・認証・既定設定・ファイアウォール・VNC・tmux・同期ループ) | FR-env-02, FR-env-03, FR-env-05, FR-env-11, FR-env-12 |
| firewall | コンテナ内の外向き通信制御 | FR-env-05 |
| docker-proxy | Docker API の検査・書き換え・拒否。全コンテナで共有。**あわせてコンテナ作成要求とネットワーク作成要求へ所有者ラベルを注入し、セッション由来の資源に「誰が後で片付けてよいか」の印を付ける**(`DSN-env-04`。**印を読んで削除するのはホスト CLI 側**である) | FR-env-01, FR-env-07, NFR-sec-01 |
| portsync | 公開ポートの検出と転送(DooD / VM の両経路) | FR-env-06 |

| VM モード | ゲスト VM の起動・provision・ポート同期・資源逼迫の監視 | FR-env-08 |

## 設計判断

### DSN-dist-01 エージェント CLI の導入は「内容由来キー」で配布ステージの終端レイヤーに置く

- 判断(**2026-08-18 に同梱外部バイナリまで射程を広げた。見出しの文言は変えていない** — `DSN-*` の ID が識別子であり、見出しの改名は反映の座標を動かすため): イメージを4ステージに分ける——重い共通層の `base`、ブラウザ確認資産を積む
  `vnc-base`(`FROM base`)、配布する2つの終端ステージ(`FROM base` / `FROM vnc-base`)。
  **中身が入れ替わりうる同梱物は、すべて終端ステージの最終レイヤーにのみ置く。**
  対象は2種類ある。
  1. **エージェント CLI**(Claude Code / Codex CLI): キャッシュキーには CI が解決した具体
     バージョンを使う。
  2. **同梱外部バイナリ**(`FR-env-13`): キャッシュキーはファイルの内容そのものである
     (保守者が置き換えれば層が失効し、置き換えなければ失効しない)。**設置層はエージェント
     CLI の導入層より後ろに置き**、**両方の終端ステージへ等しく置く**。
     置き場の規約と設置先は `03-impl/environments/images.md` が定める。
- 理由: `vnc-base` は `base` に連なるため、`base` 途中の層を失効させるとブラウザ確認資産の高コスト層
  (VNC 一式・Chrome)まで巻き込んで再ビルド・再 push・再 pull になる。終端レイヤーへ移すと失効の
  波及先がその同梱物の層だけになり、鮮度(`FR-env-09` 受け入れ基準3・4)と取得の増分性
  (`NFR-perf-01`)を同時に満たせる。
  **同梱外部バイナリを CLI の導入層より後ろに置くのは、同じ理由を2つの同梱物のあいだにも
  適用したもの**である: 保守者による差し替えは CLI の更新より頻度が読めないので、
  失効の波及を受ける側ではなく受けない側(より終端)に置く。
  **両方の終端ステージへ等しく置くのは `NFR-perf-02` の帰結**である: 同要件は
  「ブラウザ確認ありイメージ**だけ**が持つ追加層にビルド済み成果物が現れないこと」を求めており、
  片方のステージにだけ置くとその不合格条件にそのまま当たる。両方が等しく持つ層は
  同要件の対象外であり、エージェント CLI の導入層が既にその扱いである。
- 却下した案: `base` の途中で導入し日次タイムスタンプで無効化する — 新版が無い日も毎日失効する。
  `base` の途中で導入しバージョンで無効化する — 波及範囲が VNC 層まで及ぶ。実行時に自動更新させる —
  ファイアウォール下・オフライン起動で不確定になり「同一構成の保証」を失う。
  **同梱外部バイナリを `vnc-base` にだけ置く**(2026-08-18 に却下した) — ブラウザ確認なしの
  配布イメージに入らず `FR-env-13-1` を満たさないうえ、`NFR-perf-02` の不合格条件に当たる。
  **同梱外部バイナリをエージェント CLI の導入層より前に置く**(同日に却下した) —
  保守者が同梱物を差し替えるたびにエージェント CLI の層まで失効し、利用者の `docker pull` が
  増分でなくなる。
  **アーキテクチャごとにステージを分ける**(同日に却下した) — 終端ステージが4つになり
  `--target` の指定と CI のマトリクスが倍になる。アーキテクチャ別の置き分けは設置層の中で
  解決できる(`FR-env-13-3`)。
- 一般原則: レイヤーチェーンに入れてよいのは**内容由来**の値(実バージョン・ファイルの内容等)だけで
  あり、時刻など内容と無関係に動く値を入れてはならない。内容由来であっても、失効の波及範囲を
  最小化できる位置——依存される側ではなく終端——に置く。**同じ終端に複数の同梱物が並ぶときは、
  差し替えの頻度が読めないものほど後ろに置く。**
- 影響する要件: FR-env-09, FR-env-12, FR-env-13, NFR-perf-01, NFR-perf-02
