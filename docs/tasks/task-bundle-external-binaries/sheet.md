## 今回 AI が決めたこと(回答不要。開示)

- [DS-05] externals の設置レイヤーは、配布ステージ(`claude-cli` / `claude-vnc`)の**最終**レイヤー、すなわちエージェント CLI の導入層より**後ろ**に置く — 理由: `DSN-dist-01` の一般原則(失効の波及範囲を最小化できる終端に置く)。CLI 層より前に置くと、`externals/` を差し替えるたびにエージェント CLI の層まで失効して利用者の `docker pull` が増分でなくなる(`NFR-perf-01`)/ 見直す条件: externals の中身がエージェント CLI の動作に必要になったとき(記録先: `docs/03-impl/environments/images.md`)
- [DS-05] 設置は**両方の配布ステージへ等しく**行う(`claude-vnc` だけに置かない)— 理由: `NFR-perf-02` の測定方法が「ブラウザ確認ありイメージだけが持つ追加層」に**ビルド済み成果物**が現れることを不合格としており、片方だけに置くと不合格になる。両方に等しく置けば同梱エージェント CLI の層と同型になる / 見直す条件: ブラウザ確認ありのイメージにだけ必要な実行ファイルを同梱したくなったとき(記録先: `docs/03-impl/environments/images.md`)
- [DS-04] 設置するファイルのパーミッションは `0755`、所有者は `root:root` とする — 理由: `/usr/local/bin` にある既存の同梱物(`terraform` / `claude-dev-chrome` / gcloud の symlink)と同じで、非 root の利用者から実行でき書き換えられない / 見直す条件: 利用者が書き換える前提の資産を置く要求が出たとき(記録先: `docs/01-requirements/functional.md` の `FR-env-13` 受入基準)
- [DS-02] `externals/` にコピー対象のファイルが1件も無いときは、ビルドを失敗させず何も設置せずに続行する — 理由: externals は任意の仕組みで、**空が正常な初期状態である**(本タスクが納めるのはまさにその状態)。ここで失敗させると、外部バイナリを使わない利用者の `make build` が壊れる / 見直す条件: 特定のファイルの同梱を要件が必須と定めたとき(記録先: `docs/01-requirements/functional.md` の `FR-env-13` 受入基準)
- [DS-02] 片方のアーキのディレクトリにだけファイルが在るときは、そのアーキのイメージにだけ設置し、もう片方のビルドは警告も失敗もさせない — 理由: あなたが 2026-08-18 に決めた「`externals/amd64/` と `externals/arm64/` があればそのアーキのイメージにだけ入る」の直接の帰結であり、片側だけを用意する運用(amd64 サーバだけで使う)を仕様として認めるもの / 見直す条件: 「両アーキに同じものが入っていること」を要件が求めるようになったとき(記録先: `docs/01-requirements/functional.md` の `FR-env-13` 受入基準)
