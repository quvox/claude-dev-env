# 分割可否の決定事項

## D1-split-01 全要件の既定を不可分とし、段階可は性能・規模の3件に限る

- 区分: 決定
- 決めた日: 2026-08-07
- 内容: 機能要件 21 件・非機能要件 13 件の全 34 件に `分割可否` を明記する。既定は `不可分` とし、
  `段階可(理由)` は次の3件だけとする。
  1. `NFR-perf-01`(pull の増分取得) — 再取得される層が減るだけでも取得時間の短縮という利用者価値があり、目標「再取得ゼロ」へ層単位で段階的に近づけるため。
  2. `NFR-perf-02`(イメージの層共有) — 共有されるベース層が増えるほど追加ディスクが減る形で目標へ段階的に近づけ、部分達成にもディスク削減の価値があるため。
  3. `NFR-scale-01`(同時起動の衝突ゼロ) — 衝突源(コンテナ名・ネットワーク名・公開ポート・Chrome プロファイル)は互いに独立で1つずつ解消でき、解消済みの資源の分だけ同時起動の安全が増すため。
- 理由: 規範の既定が「未記載 = 不可分」というフェイルクローズであり、全件に `不可分` を明記することは
  現状の意味を変えない(現状を明示するだけ)。段階可にする3件は、いずれも目標値へ段階的に近づく
  ことが意味を持つ性能・規模の要件である。機能要件に段階可は無い(部分状態が利用者の作業やログイン
  状態を壊しうる操作系の要件が大半で、「半分満たす」ことに価値が無い)。
- 却下した案: 34 件を1件ずつ人間が仕分ける — 既定(不可分)から変わる可能性があるのは性能・規模の
  数件だけで、全件の個別判断は決定シートの往復を増やすだけである(タスク task-clause-ids-and-split-policy
  決定シート概念1で人間が「委任」と回答し、この3件構成に合意済み)。
- 関連: 機能要件の全21件(FR-env-01〜12 / FR-orch-01〜09)と非機能要件の全13件
  (NFR-perf-01〜03 / NFR-avail-01〜03 / NFR-sec-01・03 / NFR-ops-02〜04 / NFR-scale-01・02)。
  うち段階可は NFR-perf-01, NFR-perf-02, NFR-scale-01 の3件 / `docs/issues/060`(起点)

## D1-split-02 段階可を増やす・不可分へ戻す判断は委任しない

- 区分: 委任
- 決めた日: 2026-08-07
- 委任範囲: `分割可否` の値を**変えない**編集(要件の追加時に既定の `不可分` を明記すること、
  表記の位置・列の体裁)。
- 制約(ガードレール): 既存要件の `分割可否` の値を変える(不可分 → 段階可、またはその逆)判断は
  委任範囲外であり、決定シートで人間に問う(D1-split-01 の3件構成を AI の判断で崩さない)。
  新設要件を `段階可` として起こす場合も同様に人間の回答を要する。`段階可` には理由を必ず併記する
  (理由の無い段階可は重大度「高」の指摘 — `.claude/directions/01-requirements.md`)。
- 報告義務: 変えた場合は該当の変更指示と決定シートに `D1-split-02` と共に記録する。
- 関連: `D1-split-01`
