# 機能要件

条項 ID(`FR-<domain>-nn-#`)は**一度振ったら動かさない**: 欠番を埋めない・並べ替えない・廃止した番号を別の基準に再利用しない(02 のカバレッジ表・03 のテスト対応表・`docs/pendings.md` が外部から参照するため。検査は CS16)。

## FR-env-01 コンテナのライフサイクル管理

- 対応要求: RQ-env-01 / AC-01
- **分割可否: 不可分**
- 内容: プロジェクトごとに隔離コンテナを起動・再接続・停止・一覧できること。SSH 切断後も作業が
  維持されること。**破壊的操作(`stop` / `logout` / `reset`)が他プロジェクトの資源を巻き込まないこと**
  (`D0-env-08`。共有 docker-proxy と共有ネットワークの停止条件は受入基準9)。
  **共有ボリュームまたは docker-proxy を触るサブコマンドが互いに排他されること**(同項6)。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-01-1 | 正常系 | WHEN `claude-dev start` を実行したとき、システムはカレントディレクトリを `/workspace` にマウントしたコンテナ(既定はブラウザ確認あり)を起動し、tmux にアタッチしなければならない |
| FR-env-01-2 | 正常系 | WHERE `--no-vnc` が指定された場合、システムはブラウザ確認資産を持たない軽量イメージを使わなければならない |
| FR-env-01-3 | 正常系 | WHILE コンテナが起動している間、SSH 切断や tmux デタッチが起きてもコンテナは動作を継続しなければならない |
| FR-env-01-4 | 正常系 | WHEN 同一ディレクトリで `claude-dev start` を再実行したとき、システムは既存コンテナへ再接続しなければならない(tmux セッションが無ければ再作成する) |
| FR-env-01-5 | 正常系 | WHEN `claude-dev list` を実行したとき、システムは実行中セッションの一覧(noVNC URL とフォワード状況を含む)を表示しなければならない |
| FR-env-01-6 | 正常系 | WHEN `claude-dev stop <name>` を実行したとき、システムは当該コンテナを削除し、当該コンテナ内から起動された compose コンテナ群と当該プロジェクトの compose 既定ネットワークを削除し(名前付きボリュームは保持する)、全 Claude コンテナが停止したときは docker-proxy も停止しなければならない |
| FR-env-01-7 | 境界値 | IF tmux の起動待ちが上限(既定 30 秒 / VM モード 420 秒)を超えたならば、システムは終了コード 0 で状況を案内して終わらなければならず、コンテナを削除してはならない(コンテナは稼働を続け、再実行の再接続経路で合流できる) |
| FR-env-01-8 | 境界値 | IF 停止対象のコンテナが存在しないならば、システムは削除をスキップし、その旨を表示して終了コード 0 で終わらなければならない |
| FR-env-01-9 | 境界値 | IF ホスト上に稼働中の Claude コンテナが1つ以上残っているならば、**`stop` / `logout` / `reset` は** docker-proxy を停止してはならず、**`reset` は共有ネットワーク `claude-dev-net` も削除してはならない**(`reset` は残した理由と**完全な初期化になっていない**ことを表示して残りの削除を続行する)。**`stop` と `logout` は遊休かどうかにかかわらず `claude-dev-net` を削除しない**ので、この基準がネットワークについて課す条件は `reset` にだけ効く(`D0-env-08` 項2 の条件は3コマンド共通だが、`claude-dev-net` を削除する経路を持つのは `reset` だけである)。**この判定は、対象コンテナが本システムの管理ラベル(`D0-env-08`)を持つかどうか、およびどのイメージ ID から作られたかに依存してはならない**(イメージを再ビルド・再取得した後に起動していたコンテナを数え落としてはならない。管理ラベルを持たない既存コンテナも稼働中として数える) |
| FR-env-01-10 | 異常系 | IF 前提コマンド(`docker` / `jq`、macOS では `socat` も)が不足しているならば、システムは不足を列挙して導入方法を案内し、終了コード 1 で終わらなければならない |
| FR-env-01-11 | 異常系 | IF compose 既定ネットワークが他から使用中で削除できないならば、システムは処理を続行しなければならない(停止全体を失敗させない。これは `D0-env-08` 項5 が明示する例外である) |
| FR-env-01-12 | 異常系 | IF `claude-dev start` のコンテナ作成が**同名のコンテナが既に存在すること**を理由に失敗したならば、システムはその既存コンテナを削除してはならず、**同名のコンテナが稼働中であること**と**別ディレクトリの同名プロジェクトである可能性**を表示して、終了コード 1 で終わらなければならない(再試行してはならない) |
| FR-env-01-13 | 境界値 | IF コンテナ作成の失敗後に後片付け(作りかけのコンテナの削除)を行うならば、システムは対象が稼働中でないことを確かめてから削除しなければならない。**稼働中のコンテナは、作成の失敗理由を問わず削除してはならない** |
| FR-env-01-14 | 正常系 | WHEN `claude-dev start` が Claude コンテナを作成するとき、システムは本システムが作ったことと起動元のホスト側絶対パスを示す**管理ラベル**を付与しなければならない(名前と値は `CTR-cli-container` が定める。**Claude コンテナ以外の資源にはラベルを付けない**。名前が固定であり名前で識別できるため) |
| FR-env-01-15 | 境界値 | IF `claude-dev stop <name>` の対象コンテナが管理ラベルを持たないならば(管理ラベルが付く前に起動されたコンテナなど)、システムはそのコンテナを削除しつつ、**管理ラベルを持たないことを表示**しなければならない(名前で1件を指した削除は `D0-env-08` 項1 の例外である) |
| FR-env-01-16 | 異常系 | IF `start` / `stop` / `logout` / `reset` / `login` / `login-codex` のいずれかが、同じプロジェクト名または同じ共有資源(共有ボリューム・docker-proxy)を対象として既に実行中ならば、システムは**待たずに**、保持している操作の名前と再実行の方法を表示して終了コード 1 で終わらなければならない。**このとき、取得できなかったロックが守る資源に対する削除も作成も行ってはならない**(プロジェクト単位のロックが守るのは当該コンテナとそのプロジェクト配下の生成物、共有資源単位のロックが守るのは共有ボリューム**の中身**・docker-proxy・**共有ボリュームを読んで作られたコンテナ**である。**冪等に作られる共有資源の「用意」は保護対象ではない**: イメージのビルドと、共有ネットワーク `claude-dev-net`・共有ボリューム3本そのものの作成。既に在れば何も起きず、無いときに作られるのは中身の無い器だけであるため) |
| FR-env-01-17 | 境界値 | IF 排他のためのロックが、既に存在しないプロセスに保持されたまま残っているならば、システムはその事実を表示してからロックを引き継いで処理を続行しなければならない(永久に取得できない状態を作ってはならない) |
| FR-env-01-18 | 境界値 | IF `claude-dev stop <name>` の `<name>` が `[A-Za-z0-9._-]` 以外の文字を含むならば、システムは**何も削除せず**、受理できない文字を含むことを表示して終了コード 1 で終わらなければならない(排他のロックはこの名前をパス要素として使うため、`/` や `..` を含む名前を受理してはならない) |
| FR-env-01-19 | 境界値 | IF 別のディレクトリで起動されたセッションの compose 資源が存在するならば、`stop` はそれを削除してはならない。**起動ディレクトリ名が正規化後に一致する場合も削除してはならない**(compose プロジェクト名は起動ディレクトリの絶対パスを含めて一意化する。方法は `CTR-cli-container` が定める) |
| FR-env-01-20 | 境界値 | IF 本要件の一意化より前に起動された compose 資源が残っているならば、`stop` はそれを削除してはならず、**残っている可能性と手動で片付ける方法を表示**しなければならない(旧い名前は別ディレクトリと衝突しうるため対象に含めない) |
| FR-env-01-21 | 境界値 | IF `claude-dev stop <name>` の対象コンテナが管理ラベル `claude-dev.project-dir` を持たない、または既に存在しないならば、システムは**compose 資源の削除を行ってはならず**、compose 資源が残っている可能性と手動で片付ける方法を表示しなければならない(compose 一意化名は起動ディレクトリの絶対パスから作られ、その値はこのラベルにしか無い。**推測して削除すると別ディレクトリを巻き込む**) |

## FR-env-02 UID/GID 追従とホスト資産の共有

- 対応要求: RQ-env-01 / AC-01
- **分割可否: 不可分**
- 内容: コンテナ内のファイル所有権がホストと一致し、git 設定とシェル資産を引き継げること。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-02-1 | 正常系 | WHEN コンテナを起動したとき、システムはコンテナ内ユーザーの UID/GID を `/workspace` の所有者に一致させなければならない |
| FR-env-02-2 | 正常系 | WHERE ホストに `~/.gitconfig` が存在する場合、システムはそれを読み取り専用でマウントしなければならない |
| FR-env-02-3 | 正常系 | WHILE コンテナが稼働している間、システムはシェル設定を `claude-dev-config` ボリュームでコンテナ間共有し、コマンド履歴を `claude-dev-history` ボリュームで永続化しなければならない |
| FR-env-02-4 | 境界値 | IF 割り当てようとする UID/GID がコンテナ内の既存エントリと衝突するならば、システムは既存エントリを一時的な空き ID へ退避してから割り当てなければならない(起動は成功する) |

| FR-env-02-6 | 異常系 | IF ホストの設定ファイルが存在しないならば、システムはその項目をマウントせずに起動を続行しなければならない(起動を失敗させない) |

## FR-env-03 認証の共有とセッション分離

- 対応要求: RQ-env-03 / AC-01 / AC-06
- **分割可否: 不可分**
- 内容: 一度のログインで全コンテナが認証を共有し、セッションと設定はコンテナごとに独立すること。
  同梱する両方のエージェント CLI(Claude Code / Codex CLI)について成り立つこと。
  **認証を削除する操作(`logout` / `reset`)が、確認なしに他プロジェクトの作業を落としたり、
  削除できていないのに成功を表示したり、消したつもりの認証をプロジェクト配下に残したりしないこと**
  (`D0-env-08` 項3〜5)。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-03-1 | 正常系 | WHEN `claude-dev login` を実行したとき、システムは一時コンテナで対話認証を行い、完了後に認証ファイル(`.credentials.json` / `.claude.json`)を `claude-dev-auth` ボリュームへ保存しなければならない |
| FR-env-03-2 | 正常系 | WHEN コンテナを起動したとき、システムは認証ファイルを共有ボリュームから**プロジェクトディレクトリ配下(`/workspace/.claude/`)へ**コピーし、コンテナ内のホームからは symlink で参照させなければならない(`D0-auth-03`) |
| FR-env-03-3 | 正常系 | WHILE コンテナが起動している間、システムは 30 秒ごとに認証ファイルの変更を検知し、共有ボリュームへ書き戻さなければならない |
| FR-env-03-4 | 正常系 | WHILE コンテナが稼働している間、システムはセッション・設定(`settings.json` / `projects/` / `sessions/`)をコンテナ固有に保たなければならない |
| FR-env-03-5 | 正常系 | WHEN `claude-dev logout` を実行したとき、システムは共有ボリュームの認証情報を削除し、**管理ラベルを持つ**実行中コンテナを停止しなければならない(共有ボリューム全体を空にするため Claude Code と Codex CLI 双方の認証が消える)。**管理ラベルを持たない実行中コンテナは停止も削除もせず、受入基準17 に従って名前を表示して残す** |
| FR-env-03-6 | 正常系 | WHEN `claude-dev login-codex` を実行したとき、システムは一時コンテナでデバイス認証を行い、完了後に `auth.json` を `claude-dev-auth` ボリュームの `codex/` サブディレクトリへ保存しなければならない |

| FR-env-03-8 | 正常系 | WHILE コンテナが起動している間、システムは 30 秒ごとに codex 認証ファイルの変更を検知し共有ボリュームへ書き戻さなければならない(トークンリフレッシュの伝播) |
| FR-env-03-9 | 正常系 | WHILE コンテナが稼働している間、システムは codex の設定(`config.toml`)とセッション履歴をコンテナ固有に保たなければならない |
| FR-env-03-10 | 境界値 | IF 共有ボリューム側に codex 認証が存在しないならば、システムは何もコピーせずに起動を完了しなければならない(未ログインのままコンテナを使える) |
| FR-env-03-11 | 境界値 | IF 共有ボリュームのファイル所有者がコンテナ内ユーザーと異なるならば、システムは所有者を修復してから処理を進めなければならない |
| FR-env-03-12 | 異常系 | IF 利用者が認証を完了せずにログイン操作を終えたならば、システムは共有ボリュームを変更してはならない(次回起動は未ログインのままとなる) |
| FR-env-03-13 | 異常系 | IF ログイン操作が端末を持たない環境で実行されたならば、システムは非0の終了コードで失敗しなければならない(黙って未認証のまま成功を返さない) |

| FR-env-03-18 | 異常系 | IF `logout` または `reset` の削除対象のうち1つ以上が削除できなかったならば、システムは**消えなかった資源を1件ずつ列挙**し、終了コード 1 で終わらなければならない。**「削除しました」「完了」と表示してはならない** |
| FR-env-03-19 | 境界値 | IF `logout` の削除対象が0件(稼働中コンテナが無く、共有ボリュームも空、プロジェクト配下の認証コピーも無い)ならば、システムは確認を求めずに、削除対象が無いことを表示して終了コード 0 で終わらなければならない |
| FR-env-03-20 | 正常系 | WHEN `claude-dev logout` を実行したとき、システムは共有ボリュームに加えて**カレントディレクトリのプロジェクト配下にコピーされた認証**(`.claude/.credentials.json` / `.claude/.claude.json` / `.codex/auth.json`)も削除し、**削除したパスを表示**しなければならない。**他のディレクトリのコピーには触れてはならない** |
| FR-env-03-21 | 境界値 | IF カレントディレクトリにプロジェクト配下の認証コピーが存在しないならば、`logout` はその項目をスキップして処理を続行しなければならない(存在しないことを失敗として数えない) |
| FR-env-03-22 | 正常系 | WHILE `claude-dev reset` を実行している間、システムはプロジェクトディレクトリ配下のファイル(`.claude/` / `.codex/` / `.claude-dev.yaml`)を削除してはならない(`reset` は対象を絞る引数を持たず、どのディレクトリを触るべきか決められないため。`logout` との非対称は `D0-env-08` 項4 が明示する) |
| FR-env-03-23 | 異常系 | IF `logout` または `reset` が削除の途中で `INT` または `TERM` を受けたならば、システムは**進行中の1件を終えてから中断**し、**そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙**して**終了コード 130** で終わらなければならない。**「削除しました」「完了」と表示してはならない**(1件の削除を途中で切ると、より中途半端な状態が残る。`D0-env-08` 項5 の「失敗を握りつぶさない」は中断時にも及ぶ) |

## FR-env-04 SSH 鍵の限定転送

- 対応要求: RQ-env-01 / AC-01
- **分割可否: 不可分**
- 内容: プロジェクトごとに必要な SSH 鍵だけをコンテナへ渡し、秘密鍵ファイルは露出させないこと。

受け入れ基準(EARS):
