## UC-06 Codex CLI をコンテナで使う

- 形式化した受け入れ基準: AC-06
- アクター: 開発者
- 目的: 一度のデバイス認証で、どのプロジェクトのコンテナでも codex を使う
- 事前条件: 初回セットアップ済み。OpenAI 側アカウントを持っている
- 事後条件: 別プロジェクトのコンテナでも再ログインなしで codex が使え、通常依頼ではシェル実行と
  読み書きが成功し、読み取り専用指定では読み取り成功かつ書き込み拒否になる
- 関連要件: FR-env-03, FR-env-12

基本フロー:

1. 開発者がホストで `claude-dev login-codex` を実行する。
2. システムは一時コンテナでデバイス認証を起動し、認証 URL とコードを表示する。
3. 開発者がブラウザでデバイス認証を完了する。
4. システムは認証ファイルを共有ボリュームへ保存する。
5. 開発者がプロジェクトディレクトリで `claude-dev start` し、tmux 内で `codex` を実行する。
6. 開発者が codex に、ファイルの読み書きとコマンド実行を伴う作業を依頼する。システムは既定設定
   (条項 `FR-env-12-5`)のもとでシェルコマンドを実行し、`/workspace` を読み書きする。
7. 開発者がサンドボックスを明示指定した読み取り専用で調査を依頼する。システムは landlock
   バックエンドで読み取りを成功させ、書き込みは拒否する。

代替フロー:

| # | 分岐条件 | 振る舞い |
|---|---|---|
| A1 | 共有ボリュームに既に codex 認証がある | `login-codex` は不要(`start` 時にコピーされる) |
| A2 | 利用者が `config.toml` を書いている | 既存の鍵と値を変えず、不足している既定鍵だけを追記する |
| A3 | `workspace-write` を明示指定した | landlock では書き込みが成立しないため本 UC の対象外(書き込みを伴う自動化は既定設定で実行する) |

例外フロー:

| # | 例外条件 | 振る舞い |
|---|---|---|
| E1 | デバイス認証を完了せず終了した | 認証は保存されず、次に `codex` を実行しても未認証のままとなる |
| E2 | 端末を持たない環境で実行した | 非0終了する |
| E3 | `config.toml` が解釈できない | 既存ファイルを書き換えず、警告のみを出して起動を続ける |
