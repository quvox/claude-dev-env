### 1. 不可分/段階可 —「分割可否」を 34 要件へどう入れるか

- **場所**: `docs/01-requirements/functional.md`(21要件)/ `docs/01-requirements/non-functional.md`(13要件)
- **明確にしたいこと**: 全件に `不可分` を既定として一括で入れ、`段階可(理由)` にするものだけを名指しするのか、
  34 件を1件ずつ人間が決めるのか。**`段階可` には理由が必須**で、理由の無い `段階可` は重大度「高」の指摘になる
  (`.claude/directions/01-requirements.md:41-48`)。
- **AI推奨**: **一括 `不可分` + 例外を名指し**。例外候補は `NFR-perf-01`(増分取得)・`NFR-perf-02`(層の共有)・
  `NFR-scale-01`(5プロジェクト同時起動)の**性能・規模の3件**で、いずれも「目標値に段階的に近づく」ことが
  意味を持つ。理由: 規範の既定が「未記載 = 不可分」というフェイルクローズなので、
  **一括 `不可分` は現状の意味を1ミリも変えない**(現状を明示するだけ)。
  崩れる条件: 将来「一部の条項だけ先に満たして出す」運用を始めたい要件が出たとき。
  そのときは当該要件だけ `段階可` へ変える(MINOR 1箇所)。
- **未回答時の既定**: **委任**(制約: 全件 `不可分` を入れ、`段階可` にするのは上の3件のみ。
  それ以外を `段階可` にしたくなったら人間へ問う)
- **波及**: FR 21件 / NFR 13件 / 02 のカバレッジ表 59行 / `D1-split-*` の新設

### 4. 語の外延 —「充足」(02 のカバレッジ表の `充足` 列が何を言うのか)

- **明確にしたいこと**: `完全` / `部分(P-nn)` / `対象外(理由)` / `-` の4値が言うのは

  検証状態は 03 を見ないと分からない。崩れる条件: 「設計と実装の乖離を1つの表で見たい」と
