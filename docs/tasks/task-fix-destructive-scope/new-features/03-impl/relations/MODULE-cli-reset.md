## 処理の流れ

1. 引数を解析する(`--yes` のみ。それ以外は無視する)。
2. `MODULE-cli-common-lock` で**共有資源単位**のロック(キー `shared`、操作名 `reset`)を取る。
   取得できなければ**削除を一切行わずに**非0で終わる(`FR-env-01` 受入基準16)。
3. 削除対象を列挙して表示する。
   - **Claude コンテナ**: 管理ラベル `claude-dev.managed=1` を持つものだけ(契約 `CTR-cli-container` の
     規則A)。**イメージからの逆引きは使わない。** 管理ラベルを持たないものは削除対象に入れず、
     その名前と「本変更より前に起動した可能性がある」ことを別枠で表示する
     (`FR-env-03` 受入基準17)。
   - **`fwd-*` 中継コンテナと docker-proxy**: 名前(接頭辞 `fwd-` / 固定名
     `claude-dev-docker-proxy`)で識別する。ラベルを見ない。**docker-proxy の削除は手順6 の
     遊休判定を通ったときだけ**。
   - **ボリューム**: `claude-dev-auth` / `claude-dev-history` / `claude-dev-config` と
     `claude-dev-chrome-*`(名前が本システムのものであることは名前で一意に決まるため、ラベルによる
     絞り込みの対象にしない)。
   - **ネットワーク**: `claude-dev-net`(**ただし削除は手順6 の遊休判定を通ったときだけ**)。
   - **イメージ**: `claude-dev-claude` / `claude-dev-claude-vnc` / `claude-dev-docker-proxy`。
4. 確認を取る(`FR-env-03` 受入基準 14〜16)。
   - 手順3 の一覧を表示して `(y/N)` を求める。`y` / `Y` 以外の入力なら**何も削除せず**
     終了コード 0 で終わる。
   - **標準入力が TTY でなく、`--yes` も指定されていないなら中止する**: `--yes` の指定方法を
     表示して終了コード 1 で終わる(現行実装は 0 を返すが、自動実行で「何もしなかった」ことに
     気づけないため 1 に改める)。
   - `--yes` が指定されていれば確認を飛ばす。
5. 手順3 の**コンテナ**を削除し、**1件ごとに終了コードを記録する**(`|| true` で握るだけにしない)。
6. **docker-proxy と共有ネットワーク `claude-dev-net` は遊休判定を通してから消す**
   (契約 `CTR-cli-container` の規則C。`FR-env-01` 受入基準9)。
   `claude-dev-net` に接続している稼働中コンテナから、名前が `claude-dev-docker-proxy` のものと
   名前が `fwd-` で始まるものを除いた集合が**空のときだけ**両方を削除する。
   **手順3 でラベルを持たない Claude コンテナを残しているため、この判定は空にならないことがある。**
   空でなければ docker-proxy と `claude-dev-net` を残し、**残した理由(稼働中のコンテナ名)と
   「完全な初期化にはなっていない」ことを表示**して、残りの削除(ボリューム・イメージ)を続行する。
   判定の問い合わせが失敗したときは遊休でないと判定して残す(安全側)。
7. **ボリューム → イメージ**の順に削除し、**1件ごとに終了コードを記録する**。
   全体の順序は コンテナ → docker-proxy と `claude-dev-net`(遊休なら)→ ボリューム → イメージ で
   固定する(使用中の参照を先に外す)。
8. 記録した失敗が1件以上あれば、**消えなかった資源を1件ずつ列挙**し、終了コード 1 で終わる。
   成功時の文言(「全リセット完了」)は出さない(`FR-env-03` 受入基準18)。
   **手順6 で意図して残した docker-proxy と `claude-dev-net` は「失敗」に数えない**
   (残すと決めたものである)。失敗が0件なら完了を表示して 0 で終わる。
9. **削除中に `INT` / `TERM` を受けた場合**は、進行中の1件を終えてから中断し、
   **そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙**して**終了コード 130** で終わる
   (契約の「エラーケース」)。成功時の文言は出さない。
10. ロックを解放する(`trap` により異常終了時も解放される)。

## 呼び出され方

- 契機: 利用者が `claude-dev reset [--yes]` を実行したとき。
- 前提条件: なし。**対象を絞る引数は無く、常にホスト全体の claude-dev 資源(管理ラベルを持つもの)が
  対象**である(カレントディレクトリは関係しない)。
- 引数:

| 引数 | 型 | 必須 | 制約 | 実装が行う検証 |
|---|---|---|---|---|
| `--yes` | フラグ | 任意 | 確認プロンプトを飛ばす。**端末を持たない環境で実行する唯一の手段**である | 存在するかどうかだけを見る(値は取らない) |
| 上記以外の引数(位置引数 / 未知のフラグ) | — | — | **すべて無視する** | 検証しない |

**確認プロンプトが受理する入力**(`--yes` が無く、標準入力が TTY のときだけ出す。
`read -p "実行しますか？ (y/N) " -n 1 -r`。**1文字だけ読む**。現行実装の読み方を変えない
= `D0-scope-02`。`logout` も同じ読み方に揃える):

| 入力 | 結果 |
|---|---|
| `y` / `Y` | 削除を実行する |
| それ以外の1文字(`n` / Enter / 空 / 任意の文字) | 「キャンセルしました」と表示して `exit 0`。**何も削除しない**(`FR-env-03` 受入基準14) |
| **非 TTY(標準入力がパイプ・リダイレクト)で `--yes` が無い** | **プロンプトを出さずに中止**し、`--yes` の指定方法を表示して **`exit 1`**(`FR-env-03` 受入基準15。**現行の「キャンセル扱いで 0」から改める**。従来の `yes y \| claude-dev reset` は `--yes` に置き換わる) |

- 認可: CLI を実行できるホストユーザ。

## 連携先と連携内容

### MODULE-cli-common-lock

- 何のために呼ぶか: `start` の**認証コピーから `docker run` の完了まで**の区間と重なって、
  認証コピー済みのコンテナが直後に消される・認証が空のまま起動する(`docs/issues/020`)のを防ぐため。
  共有ボリュームとイメージまで消す操作なので共有資源単位のキーを取る。
  `start` が同じキーを `docker run` の完了まで保持する(`MODULE-cli-start` 判断9)ので、
  **`reset` はコンテナ作成との競合まで防げる**。
- 何を渡すか: キー `shared` と操作名 `reset`。
- 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: **何も削除せず**、保持している操作名と再実行の方法を表示して非0で終わる。

## 実装上の判断

| # | 判断内容 | 根拠(委任ID) |
|---|---|---|
| 1 | 破壊的操作なので確認プロンプトを必須にする | D0-scope-02 / D0-env-08 項3 |
| 2 | プロジェクト側の `.claude/` `.codex/` `.claude-dev.yaml` は消さない(`FR-env-03` 受入基準22)。**`logout` は認証3ファイルを消すようになったので非対称が生じるが、意図した非対称である**: `reset` は対象を絞る引数を持たず「ホスト全体」を対象にするため、**どのディレクトリのコピーを消すべきかを決められない**(カレントディレクトリは `reset` の対象範囲と無関係である)。全ディレクトリを探索するのは利用者のファイルシステム全体の走査になる。この非対称は `D0-env-08` 項4 が明示している | D0-scope-02 / D0-env-08 項4 |
| 3 | **Claude コンテナ**の列挙だけを管理ラベルで行う(イメージからの逆引きをやめる)。**`fwd-*` / docker-proxy / ボリューム / ネットワーク / イメージは名前で列挙する**: これらは本システムが決めた固定名または固定接頭辞であり名前だけで一意に決まるため、ラベルを足す意味が無い(既存のものにラベルが無いという移行問題も起こさない) | D0-env-10 |
| 4 | 削除の成否を**1件ごとに記録**し、最後にまとめて判定する(1件目の失敗で止めない)。**ただし失敗を握って「完了」と表示することはしない** | D0-env-08 項5 が定める形の実装。分岐の置き方は D0-scope-02 |
| 5 | 非 TTY で `--yes` が無い場合の終了コードを **0 から 1 へ改める**。現行の「空入力=キャンセル扱いで 0」は、自動実行で「何もしなかった」ことに気づけない(`D0-scope-07` の観測点の定義で「利用者が失敗に気づけない」に当たる)。`yes y \| claude-dev reset` で流し込む既存の使い方は `--yes` に置き換わる | D0-env-08 項3 / `FR-env-03` 受入基準15 |
| 6 | 削除順序を **コンテナ → docker-proxy と `claude-dev-net`(遊休なら)→ ボリューム → イメージ**に固定する(使用中の参照を先に外さないと後段が必ず失敗するため)。**この順序は固定** | D0-scope-02 |
| 7 | **docker-proxy と `claude-dev-net` に遊休判定を通す**(手順6)。`reset` は「全消し」コマンドだが、手順3 で**ラベルを持たない Claude コンテナを残す**ため、共有資源を無条件に消すと残したコンテナの中から Docker が使えなくなり名前解決も壊れる(`FR-env-01` 受入基準9 違反)。`D0-env-08` 項2 は例外を書いておらず、`logout` に同じ理由で既に広げてある。**代償として `reset` が完全な初期状態に戻らないことがある**ので、その旨を表示する | `D0-env-08` 項2 / `FR-env-01` 受入基準9 / D0-env-10 |
| 8 | **`INT` / `TERM` は進行中の1件を終えてから受ける**(手順9)。1件の削除を途中で切ると、より中途半端な状態が残る。終了コード 130 は SIGINT の慣行値 | `D0-env-08` 項5 / 契約の「エラーケース」 |
| 9 | Linux 版・macOS 版の**両方に同じ形で**入れる(同じサブコマンドの成否・出力を OS で変えないため) | D0-scope-03 |
