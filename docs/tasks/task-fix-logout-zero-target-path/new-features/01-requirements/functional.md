## FR-env-03 認証の共有とセッション分離

- 対応要求: RQ-env-03 / AC-01 / AC-06
- **分割可否: 不可分**
- 内容: 一度のログインで全コンテナが認証を共有し、セッションと設定はコンテナごとに独立すること。
  同梱する両方のエージェント CLI(Claude Code / Codex CLI)について成り立つこと。
  **認証を削除する操作(`logout` / `reset`)が、確認なしに他プロジェクトの作業を落としたり、
  削除できていないのに成功を表示したり、消したつもりの認証をプロジェクト配下に残したりしないこと**
  (`D0-env-08` 項3〜5)。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-03-1 | 正常系 | WHEN `claude-dev login` を実行したとき、システムは一時コンテナで対話認証を行い、完了後に**認証情報を共有ボリュームへ保存**しなければならない(保存する対象と置き場は 02/03 が定める) |
| FR-env-03-2 | 正常系 | WHEN コンテナを起動したとき、システムは**共有ボリュームの認証でコンテナ内の Claude をログイン済みにしなければならず、その認証の実体はプロジェクトディレクトリ配下に置かれなければならない**(`D0-auth-03`。コピーと参照の方法は 02 が定める) |
| FR-env-03-3 | 正常系 | WHILE コンテナが起動している間、システムは**コンテナ内で更新された認証を、次に起動するコンテナから使える状態へ反映**しなければならない(反映の周期は 02 が定める) |
| FR-env-03-4 | 正常系 | WHILE コンテナが稼働している間、システムは**セッションと設定をコンテナ固有に保たなければならない**(別プロジェクトのコンテナから見えず、混ざらないこと。どのファイルがこれに当たるかは 02/03 が定める) |
| FR-env-03-5 | 正常系 | WHEN `claude-dev logout` を実行したとき、システムは共有ボリュームの認証情報を削除し、**管理ラベルを持つ**実行中コンテナを削除しなければならない(共有ボリューム全体を空にするため Claude Code と Codex CLI 双方の認証が消える)。**管理ラベルを持たない実行中コンテナは停止も削除もせず、受入基準17 に従って名前を表示して残す** |
| FR-env-03-6 | 正常系 | WHEN `claude-dev login-codex` を実行したとき、システムは一時コンテナでデバイス認証を行い、完了後に **codex の認証情報を、Claude の認証と混ざらない形で共有ボリュームへ保存**しなければならない(保存する対象と置き場は 02/03 が定める) |
| FR-env-03-7 | 正常系 | WHEN コンテナを起動したとき、システムは **codex を再ログインなしで使える状態にしなければならず、その認証の実体はプロジェクトディレクトリ配下に置かれなければならない**(利用者から見えるのはこの2つで、コピーと参照の方法は 02 が定める) |
| FR-env-03-8 | 正常系 | WHILE コンテナが起動している間、システムは**コンテナ内で更新された codex の認証を、次に起動するコンテナから使える状態へ反映**しなければならない(トークンリフレッシュの伝播。反映の周期は 02 が定める) |
| FR-env-03-9 | 正常系 | WHILE コンテナが稼働している間、システムは **codex の設定とセッション履歴をコンテナ固有に保たなければならない**(別プロジェクトのコンテナと混ざらないこと。どのファイルがこれに当たるかは 02/03 が定める) |
| FR-env-03-10 | 境界値 | IF 共有ボリューム側に codex 認証が存在しないならば、システムは何もコピーせずに起動を完了しなければならない(未ログインのままコンテナを使える) |
| FR-env-03-11 | 境界値 | IF 共有された認証をコンテナ内ユーザーの権限では読み書きできない状態であるならば、システムは**その状態を解消してから処理を進めなければならない**(握りつぶして先へ進んではならない。解消の方法は 02/03 が定める) |
| FR-env-03-12 | 異常系 | IF 利用者が認証を完了せずにログイン操作を終えたならば、システムは共有ボリュームを変更してはならない(次回起動は未ログインのままとなる) |
| FR-env-03-13 | 異常系 | IF ログイン操作が端末を持たない環境で実行されたならば、システムは非0の終了コードで失敗しなければならない(黙って未認証のまま成功を返さない) |
| FR-env-03-14 | 正常系 | WHEN `claude-dev logout` または `claude-dev reset` を実行したとき、システムは**削除対象を列挙してから**確認を求め、`y` または `Y` 以外の入力では何も削除せずに終了コード 0 で終わらなければならない。**列挙には削除するすべての資源を種別ごとに含めなければならず、`reset` では加えてセッション由来の資源の名前(コンテナ / ネットワークの種別つき)を含めなければならない**(`FR-env-01` 受入基準25。**列挙対象の全体は `docs/02-design/logging.md`「破壊的操作の削除対象の確認」が正である**)。**利用者が「何が消えるか」を消える前に見られる唯一の機会であるため、列挙した後に増えた資源を、確認を取り直さずに削除してはならない**(列挙と削除のあいだに作られたものは次回の実行が回収する) |
| FR-env-03-15 | 境界値 | IF `claude-dev logout` または `claude-dev reset` が標準入力を TTY として持たない環境で実行され、かつ `--yes` が指定されていないならば、システムは**何も削除せずに中止**し、`--yes` の指定方法を表示して終了コード 1 で終わらなければならない(黙って 0 を返してはならない) |
| FR-env-03-16 | 正常系 | WHERE `--yes` が指定された場合、`logout` / `reset` は確認を求めずに削除を実行しなければならない |
| FR-env-03-17 | 正常系 | WHEN `logout` / `reset` が削除対象を**集合として列挙する**とき、Claude コンテナは本システムの**管理ラベルを持つものに限らなければならない**(中継コンテナ・docker-proxy・共有ボリューム・**共有ネットワーク**・イメージは**本システムが名前を決めている資源なので、名前で識別する**。名前の規則は 02 の契約が定める。**`reset` はこれに加えてセッション由来のコンテナとネットワークを削除対象にし、それらは名前も固定接頭辞も持たないため所有者ラベルで識別する** — `FR-env-01` 受入基準25。識別の方法は 02 の契約が定める。**`logout` はセッション由来の資源を削除対象にしない**(`D0-env-05` 項2))。管理ラベルを持たない Claude コンテナは削除せず、その名前と「本変更より前に起動した可能性がある」ことを表示して残さなければならない |
| FR-env-03-18 | 異常系 | IF `logout` または `reset` の削除対象のうち1つ以上が削除できなかったならば、システムは**消えなかった資源を1件ずつ列挙**し、終了コード 1 で終わらなければならない。**「削除しました」「完了」と表示してはならない** |
| FR-env-03-19 | 境界値 | IF `logout` の削除対象が0件(**管理ラベルを持つコンテナ(停止中を含む)が無く**、プロジェクト配下の認証コピーも無く、**かつ共有ボリュームが空であることを確認できた**)ならば、システムは確認を求めずに、削除対象が無いことを表示して終了コード 0 で終わらなければならない。**共有ボリュームが空であることを確認できなかったならば、この経路に入ってはならない**(確かめていない状態を「空」と同一視しない。そのときは受入基準14 の列挙と確認を経て削除へ進み、消去を確認できなければ受入基準18 に従う)。**この経路に入る場合であっても、管理ラベルを持たない稼働中の Claude コンテナがあるならば、その名前と、それが稼働している限り認証が共有ボリュームへ書き戻されることを表示しなければならない**(受入基準17 と受入基準3 の帰結。表示しなければ利用者は `logout` の効果が戻る理由に到達できない) |
| FR-env-03-20 | 正常系 | WHEN `claude-dev logout` を実行したとき、システムは共有ボリュームに加えて**カレントディレクトリのプロジェクト配下にコピーされた認証**(Claude と codex の両方。対象ファイルは 02/03 が定める)も削除し、**削除したパスを表示**しなければならない。**他のディレクトリのコピーには触れてはならない** |
| FR-env-03-21 | 境界値 | IF カレントディレクトリにプロジェクト配下の認証コピーが存在しないならば、`logout` はその項目をスキップして処理を続行しなければならない(存在しないことを失敗として数えない) |
| FR-env-03-22 | 正常系 | WHILE `claude-dev reset` を実行している間、システムは**プロジェクトディレクトリ配下のファイル**(利用者が置いた設定と、起動時にコピーされた認証。対象は 02/03 が定める)を削除してはならない(`reset` は対象を絞る引数を持たず、どのディレクトリを触るべきか決められないため。`logout` との非対称は `D0-env-08` 項4 が明示する) |
| FR-env-03-23 | 異常系 | IF `logout` または `reset` が削除の途中で `INT` または `TERM` を受けたならば、システムは**進行中の1件を終えてから中断**し、**そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙**して**終了コード 130** で終わらなければならない。**「削除しました」「完了」と表示してはならない**(1件の削除を途中で切ると、より中途半端な状態が残る。`D0-env-08` 項5 の「失敗を握りつぶさない」は中断時にも及ぶ) |
| FR-env-03-24 | 境界値 | IF `claude-dev logout` が Claude コンテナを削除したならば、システムは**そのコンテナが所有していたセッション由来の資源を、以後の `claude-dev stop` の削除対象にしてはならず**(所有者を照合する値が失われるため。`FR-env-01` 受入基準23 と同じ根拠)、**それらの資源は `claude-dev reset` でのみ削除できる状態にしなければならない**(`logout` 自身はセッション由来の資源を削除しない — `D0-env-05` 項2)。**この状態を「削除できなかった資源」として表示してはならない**(受入基準18 の対象ではない。意図して範囲の外に置いたものである) |
