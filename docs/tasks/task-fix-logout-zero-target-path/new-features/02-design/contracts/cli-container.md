## エラーケース

| 条件 | 期待する振る舞い |
|---|---|
| 共有ボリュームに認証が無い | 何もコピーせず起動を完了する(未ログインのまま使える) |
| ホストの git 設定 / gh 設定が無い | そのマウントを省いて起動する |
| SSH 鍵が選択されていない | agent ソケットを渡さず、指定方法を案内して起動する |
| Docker ソケットが無い(macOS) | `DOCKER_HOST` を設定せずに起動する |
| 環境変数が想定外の値 | **上表の「想定外の値のときの扱い」に倒し、起動を止めない**。既定が無効の変数(`CLAUDE_DEV_VM` / `CLAUDE_DEV_VNC`)は無効のまま、既定が有効の変数(`CLAUDE_DEV_DOOD_PORTSYNC`)は**有効のまま**になる |
| 公開ポートが競合して起動に失敗した | ブラウザ確認資産を使う場合に限り、**稼働していない作りかけのコンテナだけを削除して**別のポートを取り直して再試行する(上限 20 回)。上限に達したか、競合以外の失敗なら、エラーを表示して終了コード 1 で終わる |
| **コンテナ名が衝突して起動に失敗した**(同名のコンテナが既に存在する) | **既存のコンテナを削除しない。** 同名のコンテナが稼働中であることと、別ディレクトリの同名プロジェクトである可能性を表示し、**再試行せずに**終了コード 1 で終わる。同名の稼働中コンテナは利用者の作業中セッションでありうるため、後片付けの対象にしてはならない |
| **CPU 仮想化デバイスを渡す指定(`--kvm`)をしたが、そのデバイスが無い** | **警告を出して続行する**(渡せるデバイスだけを渡す) |
| **VM モードの指定(`--vm` / `--vm-fresh`)をしたが、CPU 仮想化デバイスが無い** | **中止して終了コード 1 で終わる。** ソフトウェアエミュレーションでは実用的な速度が出ないため、VM 無しで続行させるのではなく、利用者に VM モードでない起動を選ばせる |
| ゲスト VM の**起動**に失敗した(デバイスはあるが provision / ブートが失敗) | **VM 無しで続行する**(起動そのものは失敗させない)。調査手段を案内する |
| 常駐セッションの起動が待ち時間内に完了しない | コンテナは起動したまま残し、状況と再実行の方法を案内して**終了コード 0** で戻る(黙って接続失敗にしない) |
| macOS で SSH の TCP ブリッジのソケットが用意できない | **有限時間で諦めて**(待ち時間の値は 03 が持つ) agent 転送なしで続行する |
| **ロックを取得できない**(同じキーを別の操作が保持している) | **待たない。** 保持している操作の名前とプロセス ID、再実行の方法を stderr へ出し、**削除も作成も一切行わずに**終了コード 1 で終わる |
| **ロックが、既に存在しないプロセスに保持されたまま残っている** | その事実を表示してからロックを引き継ぎ、処理を続ける(永久に取得できない状態を作らない) |
| **集合として列挙する削除の対象に、管理ラベルを持たない Claude コンテナがある** | そのコンテナは**削除しない**。名前と「本変更より前に起動した可能性がある」ことを表示して残す(規則 A)。**削除する集合が空(`logout` の削除対象が0件)の場合も同じく表示する** — 削除しないことと、残したという事実を伏せることは別である(`FR-env-03` 受入基準19) |
| **`stop <name>` の対象コンテナが管理ラベルを持たない** | その1件は**削除する**。管理ラベルを持たないことを表示する(規則 B) |
| **`logout` / `reset` が標準入力を TTY として持たない環境で `--yes` 無しに実行された** | **何も削除せずに中止**し、`--yes` の指定方法を表示して終了コード 1 で終わる。**`stop <name>` はこの行の対象ではない**(利用者が名前で1件を明示的に指した削除であり、確認を求めない = 規則 B。**根拠は `D0-env-08` 項3 が明示する `stop` の免除**であって項1 ではない — 項1 はラベルの要否についての例外である)。`--yes` を受け付けるのも `logout` / `reset` だけである |
| **`claude-dev stop <name>` の `<name>` が `[A-Za-z0-9._-]` 以外を含む** | **何も削除せず**、受理できない文字を含むことを表示して終了コード 1 で終わる(ロックを取る前に検証する) |
| **`stop <name>` の対象コンテナが `claude-dev.project-dir` ラベルを持たない、または既に存在しない** | **compose 資源の削除を行わない。** 一意化名のハッシュ源(起動ディレクトリの絶対パス)はこのラベルにしか無く、推測して作った名前で削除すると別ディレクトリを巻き込む(`docs/issues/024` の欠陥そのもの)。compose 資源が残っている可能性と手動で片付ける方法を表示して続行する(`FR-env-01` 受入基準21)。**本体コンテナの削除・`fwd-*` の片付け・遊休判定はこの制限を受けず、そのまま行う** |
| **`stop <name>` の対象コンテナが `claude-dev.project-dir` ラベルを持たない、または既に存在しない(セッション由来の資源について)** | **セッション由来の資源の削除も行わない**(`FR-env-01` 受入基準23)。所有者ラベルの値は起動ディレクトリの絶対パスであり、その値はこのラベルにしか無い。**推測して作った値で削除すると別セッションの資源を巻き込む** — compose の一意化名と同じ理由である。片付けを行わなかったことは compose と同じ1つの案内にまとめてよい |
| **`stop` の時点で旧い名前(ハッシュ無し)の compose 資源が残っている** | **削除しない。** 旧名は別ディレクトリと衝突しうるため対象に含めてはならない。可能性があることと、確認・手動削除の方法を表示して続行する(案内に載せる具体的なコマンドは 03 が持つ) |
| **削除中に `INT` / `TERM` を受けた**(Ctrl-C など) | **進行中の1件を終えてから中断する**(1件の削除を途中で切ると中途半端な状態が残る)。**そこまでに削除した資源と、未削除のまま残った資源を1件ずつ列挙**し、**終了コード 130** で終わる(SIGINT の慣行値)。「削除しました」「完了」の文言は出さない。ロックは中断時にも必ず解放される(解放の手段は 03 が持つ) |
| **セッション由来の資源(コンテナ / ネットワーク)の削除に失敗した** | **握って続行する**(`FR-env-01` 受入基準24)。`stop` は `D0-env-08` 項5 の対象外であり、片付けの途中で止まるとより中途半端な状態が残る。**`reset` では握らない**(`logout` / `reset` は項5 の対象なので、消えなかった資源を列挙して終了コード 1 で終わる) |
| **使用中のためセッション由来のネットワークを削除できない** | **`stop` は握って続行する**(compose 既定ネットワークと同じ扱い。`FR-env-01` 受入基準11・24)。**`reset` は握らない** — 上の行と同じく `D0-env-08` 項5 の対象なので、消えなかった資源として列挙して終了コード 1 で終わる(`FR-env-01` 受入基準24 は `reset` を対象外と明記し、`FR-env-03` 受入基準18 が受ける) |
| **セッション由来の資源が1件も無い** | **その旨を表示しない**(`FR-env-01` 受入基準27。対象が無いことを毎回表示しない) |
| **セッション由来の資源を引く問い合わせそのものが失敗した** | **削除の失敗とは別に扱う**。`stop` は**片付けを行わずに続行**し、引けなかったことを表示する(遊休判定と同じく安全側へ倒す。推測で削除しない)。`reset` は**失敗として記録し**、消えなかった資源としてまとめて列挙して終了コード 1 で終わる(`D0-env-08` 項5)。**`logout` はこの一覧を削除ではなく「残したものの列挙」からの除外にだけ使う**ので、引けなかったときは**除外を行わずに列挙を表示し、セッション由来のコンテナが混じっている可能性があることを表示して処理を続ける**(削除に影響しないため失敗には数えない)。**列挙が空で返ったこと(0件)と、問い合わせが失敗したことを同一視してはならない** |
| **`logout` が共有ボリュームが空かどうかを確かめられなかった**(中身を読む手段が起動できなかった、**または起動できたが列挙そのものが失敗した**) | **「空」と判定してはならない。** 削除対象0件の経路(`FR-env-03` 受入基準19)に入らず、受入基準14 のとおり削除対象を列挙して確認を求め、削除へ進む。確かめられなかったことを表示する。**列挙が空で返ったこと(0件)と、確かめられなかったことを同一視してはならない** — 上の「セッション由来の資源を引く問い合わせそのものが失敗した」行と、下の「遊休判定に使う Docker への問い合わせが失敗した」行と同じ倒し方である。消去できたかどうかの判定は次の行が受ける |
| **共有ボリュームの中身を消したが、削除後の列挙に何か残っていた** | 残っていたパスを列挙して終了コード 1 で終わる。**判定は「削除後の列挙結果」で行い、削除コマンドの終了コードでは行わない**(削除に使う操作の終了コードは「消えたか」を表さないため。理由の詳細は 03 が持つ)。**列挙そのものができなかった場合も「消去を確認できなかった」として同じ扱いにする**(空出力を成功と読み替えない) |
| **`logout` / `reset` の削除対象のうち1つ以上が削除できなかった** | 消えなかった資源を1件ずつ列挙し、終了コード 1 で終わる。**成功時の文言を出してはならない** |
| **遊休判定に使う Docker への問い合わせが失敗した**(ネットワークが存在しない / `docker` が応答しない) | **遊休でないと判定して docker-proxy を残す**(安全側へ倒す)。判定できなかったことを表示する。`FR-env-01` 受入基準9 は「稼働中なら止めるな」であり、判定不能を「遊休」と読み替えてはならない |
