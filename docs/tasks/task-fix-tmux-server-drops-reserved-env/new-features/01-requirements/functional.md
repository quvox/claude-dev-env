## FR-env-07 Docker アクセスの制限

- 対応要求: RQ-env-04 / AC-03
- **分割可否: 段階可(理由: 段階的に近づくのは条項 `FR-env-07-5`(compose 資源の一意化)だけで、`FR-env-01` と同じ一意化による。段階性の根拠も `FR-env-01` と同じである。判断の記録は `D1-split-01`。**他の12条項は不可分**)**
- 内容: コンテナ内から Docker を使えるが、ホストを危険に晒す操作は拒否されること。
  **そのために本システムが渡す設定が、コンテナ内で起動したどのプロセスからも効くこと**
  (起動経路を問わない。受入基準13)。
  **コンテナ内から作られた資源に所有者が分かる印が付くこと**(`D0-env-08` 項8。
  片付ける側の要件は `FR-env-01` 受入基準22〜31)。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-07-1 | 正常系 | WHILE コンテナが稼働している間、システムはコンテナに**ホストの Docker 生ソケットをマウントしてはならず**、コンテナ内からの Docker 操作を**必ず検査を行う中継を経由**させなければならない(中継先の指定方法とエンドポイントは 02 の契約が定める) |
| FR-env-07-2 | 正常系 | IF リクエストがホストバインドマウント(`/workspace` 配下を除く)・privileged・ホストのネットワーク/プロセス空間の共有を含むならば、システムはそれを拒否しなければならない |
| FR-env-07-3 | 正常系 | WHERE 呼び出し元の `/workspace` 配下の bind である場合、システムは実ホストパスへ書き換えて許可しなければならない(既定有効。環境変数で切替可能) |
| FR-env-07-4 | 正常系 | WHILE docker-proxy が稼働している間、システムは docker-proxy を**ホストに公開してはならず、Claude コンテナからのみ到達できる**ようにしなければならない(到達経路の作り方は 02 の契約が定める) |
| FR-env-07-5 | 正常系 | WHEN 複数プロジェクトのコンテナで同時に `docker compose` を実行したとき、システムは**生成されるネットワーク名・コンテナ名を衝突させてはならない**(**起動ディレクトリ名が正規化後に一致するプロジェクト同士でも衝突しないこと**。一意化の方法は 02 の契約が定める。`FR-env-01` 受入基準19 と同じ一意化を指す) |
| FR-env-07-6 | 境界値 | IF bind のパスが `..` を含み、正規化するとプロジェクトディレクトリの外を指すならば、システムはそれを拒否しなければならない |
| FR-env-07-7 | 境界値 | IF 呼び出し元コンテナを特定できないならば、システムは `/` 始まりの bind をすべて拒否しなければならない(名前付きボリュームのみ許可) |
| FR-env-07-8 | 異常系 | IF リクエストのボディが解釈できないならば、システムはそれを**中継しなければならない**(独自解釈で誤って弾かない。最終判断は Docker Engine が行う。**この帰結は `D0-sec-05` の委任範囲内で選んだもので、残存リスクは `docs/issues/005` が追跡する**) |
| FR-env-07-9 | 異常系 | IF 上流の Docker Engine への中継に失敗したならば、システムは**中継が失敗したことを表す応答を返し**、ログへ記録しなければならない(応答の形式は 02 の契約が定める) |
| FR-env-07-10 | 異常系 | IF 起動時に Docker ソケットが存在しないならば、docker-proxy は起動を中止しなければならない(不正な状態で待ち受けない) |
| FR-env-07-11 | 正常系 | WHEN コンテナ作成要求・ネットワーク作成要求・**ボリューム作成要求**を中継するとき、システムは**呼び出し元セッションを特定できた場合に限り**、そのセッションを所有者として示す**管理ラベル**を要求へ付与して中継しなければならない(ラベルの**名前・値・個数**は 02 の契約が定める)。**要求のそれ以外のフィールドを変更してはならない**(`D0-env-08` 項8。**ボリューム作成要求を対象に加えたのは、そのセッションが作ったボリュームを名前ではなく所有者で見分けるためである** — 名前で決めると別ディレクトリのデータを巻き込みうる) |
| FR-env-07-12 | 境界値 | IF 呼び出し元セッションを特定できない、またはリクエストのボディが解釈できないならば、システムは**所有者ラベルを付与せずに中継**しなければならず、作成要求を拒否してはならない(受入基準8 と同じ「判定できない入力は通す」に揃える。**その資源は `FR-env-01` 受入基準22・28 の片付け対象から外れる**) |
| FR-env-07-13 | 正常系 | WHILE コンテナが稼働している間、システムは**本システムが使う環境変数**を、**そのコンテナ内で起動したどのプロセスからも参照できる状態**に保たなければならない(**起動経路を問わない** — 利用者がどの入口からプロセスを起こしたかによって、参照できたりできなかったりしてはならない。どの名前が本システムのものかは 02 の契約が定める) |

## FR-env-14 プロジェクトごとの環境変数の受け渡し

- 対応要求: RQ-env-07 / AC-08
- **分割可否: 不可分**(理由: 渡せる変数と渡せない変数が混ざる状態は、利用者から見て「書いた値が
  効いているかどうか分からない」状態であり、何も渡さない状態より価値が高いとは言えない)
- 内容: プロジェクトごとに用意した**プロジェクト環境ファイル**(用語集)の内容を、そのプロジェクトの
  コンテナへ環境変数として渡せること。**秘密の値が版管理へ入らないこと**(`D0-sec-11`)。
  **渡した値が、コンテナ内で起動したどのプロセスからも参照できること**(起動経路を問わない。受入基準11)。
  **本システム自身が使う名前を利用者の指定で差し替えられないこと**
  (`request.md`「やらないこと」7)。**指定の書式と、本システムが使う名前の集合は 02 の契約が定める。**

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-14-1 | 正常系 | WHERE プロジェクト直下の設定でプロジェクト環境ファイルの場所が指定された場合、システムはそのファイルに書かれた組を、そのプロジェクトのコンテナへ環境変数として渡さなければならない(設定の置き場・指定の書式・ファイルの書式は 02/03 が定める) |
| FR-env-14-2 | 正常系 | WHILE コンテナが稼働している間、システムは渡した環境変数を**そのプロジェクトのコンテナの中だけ**で見える状態に保たなければならない(別プロジェクトのコンテナからは見えない) |
| FR-env-14-3 | 正常系 | WHEN プロジェクト環境ファイルを渡して起動したとき、システムは**渡した値そのものを端末にも起動ログにも常駐プロセスのログにも出力してはならない**(`D0-sec-11` 項4。名前を出すことは許す。値を出さない規則の正は 02 のログ仕様である) |
| FR-env-14-4 | 正常系 | WHEN プロジェクト環境ファイルの場所が指定されたとき、システムはそのファイルを**版管理の追跡から外さなければならない**。外せなかった場合は、外せなかったことを表示して起動を続けなければならない(`D0-sec-11` 項2) |
| FR-env-14-5 | 境界値 | IF プロジェクト直下の設定にプロジェクト環境ファイルの指定が**無い**ならば、システムは環境変数を渡さずに起動しなければならず、**そのことを表示してはならない**(指定していないことは正常な省略であり、毎回表示しない) |
| FR-env-14-6 | 異常系 | IF 指定されたプロジェクト環境ファイルが**存在しない**ならば、システムは環境変数を渡さずに起動を続け、**そのファイルを読めなかったことを表示**しなければならない(起動を止めない) [DS-02] 起動を止めずに続行する — 理由: 補助機能の失敗が主機能(コンテナ起動)を止めないことは本システムの一貫した倒し方であり、`NFR-avail-03` がその成功率を 100% と定めている / 見直す条件: 環境変数が渡らないまま起動して利用者が気づけない事故が観測されたとき |
| FR-env-14-7 | 境界値 | IF プロジェクト環境ファイルに**組として解釈できない行**が在るならば、システムはその行だけを採用せず、**採用しなかった行が何行目か**を表示して、残りの行で起動を続けなければならない |
| FR-env-14-8 | 境界値 | IF プロジェクト環境ファイルに**本システムが使う名前**が書かれているならば、システムはその1件だけを採用してはならず、**採用しなかった名前**を表示して起動を続けなければならない(どの名前が本システムのものかは 02 の契約が定める。理由は `request.md`「やらないこと」7 が持つ) |
| FR-env-14-9 | 境界値 | IF 指定された場所が**プロジェクトディレクトリの外**を指すならば、システムはその指定を採用してはならず、受理しないことと受理する範囲を表示して、環境変数を渡さずに起動を続けなければならない [DS-04] 受理する範囲をプロジェクトディレクトリの中に限る — 理由: 外を指せるとコンテナへ渡る値の出どころがプロジェクトの外に散り、`D0-sec-11` 項2 の「版管理の追跡から外す」が効かない / 見直す条件: 複数プロジェクトで1つのプロジェクト環境ファイルを共有したいという要望が出たとき |
| FR-env-14-10 | 異常系 | IF 同じ名前が**2回以上**書かれているならば、システムは**後に書かれたほうを採用**し、採用しなかった名前を表示しなければならない [DS-04] 後勝ちにする — 理由: 利用者が1つのファイルを編集して値を差し替える使い方でそのまま動き、行を消し忘れても最後に書いた値が効く / 見直す条件: 複数のプロジェクト環境ファイルを指定できるようにするとき(ファイルをまたぐ優先順を別に決める必要が生じる) |
| FR-env-14-11 | 正常系 | WHILE コンテナが稼働している間、システムは渡した環境変数を、**そのコンテナ内で起動したどのプロセスからも参照できる状態**に保たなければならない(**起動経路を問わない** — 利用者が作業する端末から起動したツールでも参照できること) |
