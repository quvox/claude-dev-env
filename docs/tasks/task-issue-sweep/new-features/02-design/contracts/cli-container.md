### DSN-env-01 所有権は「起動時に付けたラベル」で表し、名前とイメージでは表さない

- 内容: **Claude コンテナ**には作った時点で `claude-dev.managed` / `claude-dev.role` /
  `claude-dev.project-dir` を付け、破壊的操作が集合として列挙する削除はこのラベルを根拠にする。
  **固定名または固定接頭辞を持つ資源にはラベルを付けない**(名前で識別できるため。下の
  「識別の手段は資源ごとに違う」)。**名前から所有権が読み取れない資源にはラベルを付ける** —
  Claude コンテナがその1つ目で、**セッション由来の資源が2つ目である**(`DSN-env-04`)。
- 理由: 所有権の根拠になりうる候補は「名前」「イメージ」「ラベル」の3つである。Claude コンテナだけは
  名前が起動ディレクトリ名から決まるため一意でなく(`NFR-scale-01` / `docs/issues/028`)、
  イメージは `latest` が動くとそれ以前のコンテナを取りこぼす(2026-08-04 に実機観測。経緯は `docs/histories/2026-08-04-fix-destructive-scope.md`)。
  **逆に固定名を持つ資源にラベルを足すと、既存の資源がラベルを持たないという移行問題を、必要も
  無いのに作り込むことになる。**
- 却下した案:
  - **イメージ ID の履歴を並べて `--filter ancestor` に渡す** — 削除済みイメージから作られた
    コンテナを依然取りこぼす。取りこぼしの原因を減らすだけで、無くせない。
  - **コンテナ名の規約(命名の一意化)で表す** — 利用者に見える名前が変わり、既存コンテナの
    移行手順が必要になる(`docs/issues/028`)。本契約はそれを伴わずに成立する。
  - **`docker inspect` で起動引数を見て判定する** — 起動経路が増えるたびに判定条件が増える。
  - **すべての資源にラベルを付けて統一する** — 固定名の資源にとっては移行問題を増やすだけで、
    得られる情報が無い。
- 影響: **管理ラベルが付く前に起動された Claude コンテナはラベルを持たない。** 規則 A の対象から外れるため、
  `logout` / `reset` はそれを消さずに名前を表示して残す。利用者は `claude-dev stop <name>`(規則 B)で
  1件ずつ止めるか、`docker rm -f` で手動削除する。**遊休判定(規則 C)はラベルに依存しない**ため、
  ラベルの無い既存コンテナが稼働している間も docker-proxy は保護される。
  移行が完了する条件は「ラベルを持たない Claude コンテナが1つも残っていないこと」である。
  `logout` / `reset` が残したものを名前で列挙して表示するので、利用者はその表示が空になったことで
  移行の完了を判別できる(既存の他コマンドの表示は変えない)。
- 関連: `D0-env-08` / `D0-env-10` / `FR-env-01` 受入基準 9・14・15 / `FR-env-03` 受入基準 17 /
  `DSN-env-04`(同じ考え方をセッション由来の資源へ広げたもの)

### DSN-env-02 排他は「プロジェクト単位」と「共有資源単位」の2段に分け、待たない

- 内容: `start` / `stop` / `logout` / `reset` / `login` / `login-codex` の**6コマンド**は上の
  「排他(ロックキー)」の表に従ってロックを取る。取得できなければ待たずに終了コード 1 で終わる。
- 理由: 保護すべき競合が2種類ある。(1) 同じコンテナ名を対象にする `start` ⇄ `stop` の競合、
  (2) 共有ボリュームと docker-proxy を対象にする `start` の認証コピー ⇄ `logout` / `reset` の競合
  (**認証が空のままコンテナが起動する**という、利用者が気づけない失敗を生む。経緯は `docs/histories/2026-08-04-fix-destructive-scope.md`)。
  1つのロックに束ねると別プロジェクトの `start` が互いに待つことになり、`NFR-scale-01`
  (5プロジェクト同時起動)を損なう。
  **待たない**のは、CLI が対話的に使われる前提で、固まるより失敗して理由を示すほうが回復が速いため。
- 却下した案:
  - **1つのグローバルロックにする** — 別プロジェクトの同時起動が直列化し、`NFR-scale-01` を損なう。
  - **待つ(タイムアウト付きで再試行する)** — `logout` は稼働中コンテナを消してから認証を消すため
    保持時間が長く、待ち時間の上限を決められない。
  - **排他を入れず「同時に実行しない」を前提として明文化する** — 前提を守らせる手段が無く、
    破ったときの失敗が静かである(**2026-08-04 に実際に起きた事象そのもの**。経緯は `docs/histories/2026-08-04-fix-destructive-scope.md`)。
- 関連: `D0-env-08` 項6 / `D0-env-09` / `FR-env-01` 受入基準 16・17 / `NFR-scale-01`

### DSN-env-03 compose プロジェクト名にパスのハッシュを足して一意にする

- 内容: `COMPOSE_PROJECT_NAME` を `<正規化名>-<絶対パスの SHA-256 先頭6桁>` にする。
  `stop` の compose 片付けはこの一意な名前だけを対象にする。
- 理由: **`DSN-env-04` の導入により、compose 資源にも docker-proxy が所有者ラベルを付けるように
  なった。それでも一意化を残すのは、所有者ラベルが付く前に作られた compose 資源を引く手段が
  一意化名しか無いからである**(移行期の取りこぼしを減らすために両方を使う。`D0-env-08` 項7・項8)。
  一意化を導入した当初の理由は次のとおりで、それは今も成り立つ。
  従来の正規化(`[a-z0-9_-]` 以外を `-` に置換)は非可逆で、
  `~/work/My.App` と `~/other/my-app` が同じ `my-app` に落ちるため、一方の `stop` が他方の
  実行中サービスを削除しうる(データの破壊に至りうる。経緯は `docs/histories/2026-08-04-fix-destructive-scope.md`)。
  絶対パスはプロジェクトを一意に決める唯一の値なので、それをハッシュ源にする。
- 却下した案:
  - **`stop` が削除前に対象名を列挙して確認を取るだけにする** — 名前の非一意性という根本が残るので、
    確認を読み飛ばした利用者は同じ被害に遭う。日常操作である `stop` に確認を足す代償も大きい。
  - **`stop` の compose 片付けをやめる** — `FR-env-01` 受入基準6 と `D0-env-05` のライフサイクルの
    決定に反し、compose コンテナが孤児として残り続ける。
  - **コンテナ名そのものを一意化する**(`docs/issues/028`) — 利用者に見える名前と 11 の呼び出し元が
    動く。compose 名の一意化はそれを伴わずに `024` を閉じられる。
  - **ハッシュだけにする**(正規化名を捨てる) — `docker ps` の出力から人がプロジェクトを見分けられない。
- 影響: **一意化名が導入される前に作られた compose 資源は古い名前を持つため `stop` の対象から外れる**
  (下の「compose 資源の識別」と上の「エラーケース」)。`docker ps` に現れる compose のコンテナ名・
  ネットワーク名が変わる(`<正規化名>_default` → `<正規化名>-<ハッシュ>_default`)。
- 関連: `D0-env-08` 項7 / `NFR-scale-01` / `FR-env-01` 受入基準6・19 / `docs/histories/2026-08-04-fix-destructive-scope.md`

### 遊休判定(docker-proxy と `claude-dev-net` を削除してよい条件)

**`claude-dev-net` に接続している稼働中コンテナの集合から、名前が `claude-dev-docker-proxy` の
ものと名前が `fwd-` で始まるものを除いた結果が空**のときだけ、docker-proxy と `claude-dev-net` を削除してよい。
**`reset` にも同じ条件が掛かる**(`reset` はラベルを持たない Claude コンテナを残すため、無条件に消すと
残したコンテナの中から Docker が使えなくなる)。

**この条件が `claude-dev-net` について効くのは `reset` だけである。** `stop` と `logout` は
**遊休かどうかにかかわらず `claude-dev-net` を削除しない**(そもそも削除する経路を持たない)ので、
この判定が両者に対して決めるのは docker-proxy を削除してよいかだけである
(`FR-env-01` 受入基準9。**02 の操作範囲を 01 より広げてはならない**)。

- **イメージ名・イメージ ID を判定に使ってはならない**: `docker ps --filter ancestor=<名前>` は
  その名前が**今**指しているイメージ ID から作られたコンテナにしか一致しないため、イメージを
  再ビルド・再取得するとそれ以前に起動したコンテナを数え落とす(`FR-env-01` 受入基準9 の違反。
  2026-08-04 に実機観測。経緯は `docs/histories/2026-08-04-fix-destructive-scope.md`)。
- **管理ラベルを判定に使ってはならない**: 管理ラベルが付く前に起動された既存コンテナはラベルを持たないため、
  数え落として同じ違反を起こす。ネットワークへの接続は起動経路によらず必ず成立する
  (「渡す起動オプション」の「ネットワーク」は必須項目である)ため、判定の根拠として最も広い。
- 除外を名前だけで行うのは、`fwd-` 接頭辞と docker-proxy の固定名がラベルの有無に関係なく
  成立するためである。判定全体がラベルから独立するので、**既存コンテナも新規コンテナも同じに数える**。
- **VM モードのコンテナも同じに数える**(VM モードでも Claude コンテナ自身は `claude-dev-net` に
  接続する。compose がゲスト内で完結するだけである)。
- **`login` / `login-codex` の一時コンテナも `claude-dev-net` に接続するため、この判定は
  それらを「稼働中」として数える**(名前が付いていないので除外できない)。結果は
  「ログイン操作の最中は docker-proxy を消さない」であり、**過剰に数える=消さない側**なので
  受入基準9 を破らない。次の `stop` が回収する。

### compose 資源の識別(プロジェクト名の一意化)

コンテナ内の `docker compose` が作る資源は、**所有者ラベル**(`DSN-env-04`)と
**一意化した `com.docker.compose.project` の値**の**2つで識別する**。
どちらも本システムが付けられる: 作成要求は必ず docker-proxy を通るので所有者ラベルは
docker-proxy が注入し、compose プロジェクト名はホスト CLI が `COMPOSE_PROJECT_NAME` で決める。

**2つ持つのは移行のためである**: **所有者ラベルが付く前に作られた compose 資源を引く手段は
一意化名しか無い**(`D0-env-08` 項7・項8)。逆に `docker compose` を経由しない `docker run` の
資源には `com.docker.compose.project` が付かないので、一意化名だけでは足りない。
本節が定めるのは後者、**一意化名の作り方**である。

**`COMPOSE_PROJECT_NAME` = `<正規化名>-<ハッシュ短縮値>`**

| 部分 | 定義 |
|---|---|
| 正規化名 | 起動ディレクトリ名を小文字化し、`[a-z0-9_-]` 以外の1文字を `-` に置換した値(**人が読める部分をコンテナ名に残すため**、ハッシュだけにはしない) |
| ハッシュ短縮値 | **起動ディレクトリの絶対パス**(`pwd` の値)の **SHA-256 の先頭6桁**(16進小文字) |

- ハッシュの入力は**絶対パス**である(ディレクトリ名ではない)。これにより
  `~/work/My.App` と `~/other/my-app` は正規化名が同じ `my-app` でも別の値になる。
- 6桁(24ビット)にした理由: 同時に扱うプロジェクト数は数十のオーダーで、**同時に 100 プロジェクトを扱っても衝突確率は約 0.03%**(誕生日問題。`docs/pendings.md` P-005 と同じ根拠)
  一方、コンテナ名として読める長さに収まる。**桁数を変えると既存の compose 資源が対象から外れる**
  ので、変える場合は移行期の扱いを併記する。
- **衝突は検出しない**(2026-08-04 に人間が受容。`docs/pendings.md` **P-005**)。
  異なる絶対パスが同じ先頭6桁になった場合、その2ディレクトリでは一方の `stop` が他方の
  compose 資源を削除しうる(`docs/histories/2026-08-04-fix-destructive-scope.md` が解消した事象と同じものが、確率は桁違いに低い形で残る)。
  **この一意化が保証するのは「100 プロジェクトを同時に扱っても衝突確率が約 0.03% に収まること」までであり、
  衝突がゼロであることは保証しない**(絶対パスをハッシュ源にしているため、正規化名が同じでも
  別の値になるが、先頭6桁の一致は起こりうる)。解消が必要になる条件と選択肢は P-005 が持つ。
- 実装は Linux と macOS で**同じ値**を出さなければならない(`D0-scope-03`)。
  コマンド名が OS で違う点は 03 の実装上の判断が扱う。
- **`stop` はハッシュ源(起動ディレクトリの絶対パス)を `claude-dev.project-dir` ラベルから読む。**
  `stop` の入力は `NAME` だけで絶対パスを持たないため、**本体コンテナを削除するとこの値は失われる**
  (読む時機の固定は 03 が持つ)。**ラベルが無い/対象コンテナが存在しない場合は compose の片付けを
  行わず、手動手順を案内する**(推測でハッシュを作ると別ディレクトリを巻き込む)。
- **`stop` の compose 片付けはこの一意な名前だけを使う**。これで別ディレクトリの compose 資源を
  巻き込む経路が閉じる(経緯は `docs/histories/2026-08-04-fix-destructive-scope.md`)。
- **ハッシュ短縮値を持たない古い名前(`<正規化名>` だけ)の compose 資源が既存環境に残っている場合、
  それは `stop` の片付け対象から外れる**(その名前を作った時点の実装が一意化していなかった)。
  `stop` はその可能性と、確認・手動削除の方法を案内する(`D0-env-08` 項7。案内の具体的な
  コマンドは 03 が持つ)。
  **古い名前を対象に含めてはならない**: それをすると衝突する別ディレクトリを巻き込む今の欠陥が
  そのまま残る。
## 渡す環境変数

**真偽を表す変数は厳密一致で判定する**が、**既定が有効か無効かで見る値が違う**: 既定が無効のものは
**`1` に厳密一致したときだけ有効**(`true` / `yes` / `TRUE` は無効)、既定が有効のものは
**`0` に厳密一致したときだけ無効**(それ以外の任意の値は有効のまま)。どちらに属するかは下表の
「型・値域」に書く。**真偽を表す変数**の判定はすべて受け側(entrypoint)が行い、**値の検証で起動を止めることはしない**。**ホスト側から与えられた値を CLI が付与前に検証する変数が1つだけある**(下表の `CLAUDE_DEV_SSH_BRIDGE_PORT`)。それも起動は止めない。

| 変数 | 型・値域 | 付与するのは誰か | 必須 | 既定値 | 想定外の値のときの扱い |
|---|---|---|---|---|---|
| `DOCKER_HOST` | `tcp://<ホスト名>:<ポート>` 形式の URL | CLI(ホストに Docker ソケットがあるときだけ) | 条件付き | 付与しない | 形式を検証しない。到達できなければコンテナ内から Docker が使えないだけで、起動は続く。**VM モードでは entrypoint が上書きする** |
| `COMPOSE_PROJECT_NAME` | 小文字英数と `_` `-` のみ | CLI | **必須** | `<正規化名>-<起動ディレクトリの絶対パスのハッシュ短縮値>`。正規化名は起動ディレクトリ名を**小文字化してから** `[a-z0-9_-]` 以外の1文字を `-` に置換した値、ハッシュ短縮値は**絶対パスの SHA-256 の先頭6桁(16進小文字)**。詳細は下の「compose 資源の識別(プロジェクト名の一意化)」 | 付与しない経路が無いので発生しない。**ハッシュを足すことで、正規化後に衝突する別ディレクトリが同じ値にならない**(`NFR-scale-01`) |
| `CLAUDE_DEV_VM` | `1` のみが有効 | CLI(VM モード指定時) | 任意 | 付与しない(= 無効) | **`1` 以外はすべて無効**として扱う |
| `VM_PORTS` / `VM_MEM` / `VM_SMP` / `VM_DISK` / `VM_SWAP` | 文字列(ゲスト VM のパラメータ) | CLI(VM モードで、かつホスト側の同名変数が空でないときだけ転送) | 任意 | 付与しない(ゲスト側の既定に従う) | 値を検証しない。ゲスト VM の起動に失敗した場合は VM 無しで続行する |
| `CLAUDE_DEV_DOOD_PORTSYNC` | `0` で無効、それ以外は有効 | 利用者(CLI は付与しない) | 任意 | 未設定 = 有効 | **`0` の厳密一致のときだけ無効**。他の値は有効として扱う |
| `CLAUDE_DEV_VNC` | `1` のみが有効 | **イメージの `ENV`**(CLI は付与しない) | 任意 | ブラウザ確認資産を含むイメージでは `1` | `1` 以外はすべて無効として扱う |
| `CLAUDE_DEV_SSH_BRIDGE_PORT` | **1〜65535 の整数**(10進表記) | CLI(**macOS のみ**) | 条件付き | 付与しない | **CLI は付与する前に値を検証する**: 同名のホスト側変数で中継ポートが指定され、その値が 1〜65535 の整数でなければ**採用せず**、受理できない値であることと受理する範囲を表示して **agent 転送なしで続行する**(`FR-env-04-8`)。**「SSH agent 転送が有効である」と読める表示を出さない。** 付与された値そのものは受け側で検証しない。非空なら TCP ブリッジの接続先として使う。ソケットが用意できなくても起動は続く |
| `SSH_AUTH_SOCK` | コンテナ内の固定パス | CLI(**Linux のみ**、ホストに agent ソケットがあるとき) | 条件付き | 付与しない | 受け側はソケットの実在で判定する。無ければ agent 転送なしで続行する |
| `NODE_OPTIONS` | Node の起動オプション文字列 | CLI | **必須** | `--max-old-space-size=4096` | 付与しない経路が無い |
| `container` | `docker` | **イメージの `ENV`**(起動時ではない) | **必須** | `docker` | コンテナ内であることの判定マーカー。上書きは想定しない |

**VM モードと DooD ポート同期は排他**である: VM モードのときポート同期は起動しない
(ポート同期はホスト共有 daemon 経路のときだけ意味を持つため)。

## エラーケース

| 条件 | 期待する振る舞い |
|---|---|
| 共有ボリュームに認証が無い | 何もコピーせず起動を完了する(未ログインのまま使える) |
| ホストの git 設定 / gh 設定が無い | そのマウントを省いて起動する |
| SSH 鍵が選択されていない | agent ソケットを渡さず、指定方法を案内して起動する |
| Docker ソケットが無い(macOS) | `DOCKER_HOST` を設定せずに起動する |
| 環境変数が想定外の値 | **上表の「想定外の値のときの扱い」に倒し、起動を止めない**。既定が無効の変数(`CLAUDE_DEV_VM` / `CLAUDE_DEV_VNC`)は無効のまま、既定が有効の変数(`CLAUDE_DEV_DOOD_PORTSYNC`)は**有効のまま**になる |
| 公開ポートが競合して起動に失敗した | ブラウザ確認資産を使う場合に限り、**稼働していない作りかけのコンテナだけを削除して**別のポートを取り直して再試行する(上限 20 回)。上限に達したか、競合以外の失敗なら、エラーを表示して終了コード 1 で終わる |
| **コンテナ名が衝突して起動に失敗した**(同名のコンテナが既に存在する) | **既存のコンテナを削除しない。** 同名のコンテナが稼働中であることと、別ディレクトリの同名プロジェクトである可能性を表示し、**再試行せずに**終了コード 1 で終わる。同名の稼働中コンテナは利用者の作業中セッションでありうるため、後片付けの対象にしてはならない |
| **CPU 仮想化デバイスを渡す指定(`--kvm`)をしたが、そのデバイスが無い** | **警告を出して続行する**(渡せるデバイスだけを渡す) |
| **VM モードの指定(`--vm` / `--vm-fresh`)をしたが、CPU 仮想化デバイスが無い** | **中止して終了コード 1 で終わる。** ソフトウェアエミュレーションでは実用的な速度が出ないため、VM 無しで続行させるのではなく、利用者に VM モードでない起動を選ばせる |
| ゲスト VM の**起動**に失敗した(デバイスはあるが provision / ブートが失敗) | **VM 無しで続行する**(起動そのものは失敗させない)。調査手段を案内する |
| 常駐セッションの起動が待ち時間内に完了しない | コンテナは起動したまま残し、状況と再実行の方法を案内して**終了コード 0** で戻る(黙って接続失敗にしない) |
| macOS で SSH の TCP ブリッジのソケットが用意できない | **有限時間で諦めて**(待ち時間の値は 03 が持つ) agent 転送なしで続行する |
| **macOS で agent 転送の中継ポートがホスト側から指定され、その値が 1〜65535 の整数でない** | **その指定を採用しない。** 受理できない値であることと受理する範囲を表示し、agent 転送なしで起動を続行する(`FR-env-04-8`)。**「SSH agent 転送が有効である」と読める表示を出してはならない** |
| **ロックを取得できない**(同じキーを別の操作が保持している) | **待たない。** 保持している操作の名前とプロセス ID、再実行の方法を stderr へ出し、**削除も作成も一切行わずに**終了コード 1 で終わる |
| **ロックが、既に存在しないプロセスに保持されたまま残っている** | その事実を表示してからロックを引き継ぎ、処理を続ける(永久に取得できない状態を作らない) |
| **集合として列挙する削除の対象に、管理ラベルを持たない Claude コンテナがある** | そのコンテナは**削除しない**。名前と「管理ラベルが付く前に起動した可能性がある」ことを表示して残す(規則 A)。**削除する集合が空(`logout` の削除対象が0件)の場合も同じく表示する** — 削除しないことと、残したという事実を伏せることは別である(`FR-env-03` 受入基準19) |
| **`stop <name>` の対象コンテナが管理ラベルを持たない** | その1件は**削除する**。管理ラベルを持たないことを表示する(規則 B) |
| **`logout` / `reset` が標準入力を TTY として持たない環境で `--yes` 無しに実行された** | **何も削除せずに中止**し、`--yes` の指定方法を表示して終了コード 1 で終わる。**`stop <name>` はこの行の対象ではない**(利用者が名前で1件を明示的に指した削除であり、確認を求めない = 規則 B。**根拠は `D0-env-08` 項3 が明示する `stop` の免除**であって項1 ではない — 項1 はラベルの要否についての例外である)。`--yes` を受け付けるのも `logout` / `reset` だけである |
| **`claude-dev stop <name>` の `<name>` が `[A-Za-z0-9._-]` 以外を含む** | **何も削除せず**、受理できない文字を含むことを表示して終了コード 1 で終わる(ロックを取る前に検証する) |
| **`stop <name>` の対象コンテナが `claude-dev.project-dir` ラベルを持たない、または既に存在しない** | **compose 資源の削除を行わない。** 一意化名のハッシュ源(起動ディレクトリの絶対パス)はこのラベルにしか無く、推測して作った名前で削除すると別ディレクトリを巻き込む(**2026-08-04 の `task-fix-destructive-scope` が解消した欠陥そのもの**。経緯は `docs/histories/2026-08-04-fix-destructive-scope.md`)。compose 資源が残っている可能性と手動で片付ける方法を表示して続行する(`FR-env-01` 受入基準21)。**本体コンテナの削除・`fwd-*` の片付け・遊休判定はこの制限を受けず、そのまま行う** |
| **`stop <name>` の対象コンテナが `claude-dev.project-dir` ラベルを持たない、または既に存在しない(セッション由来の資源について)** | **セッション由来の資源の削除も行わない**(`FR-env-01` 受入基準23)。所有者ラベルの値は起動ディレクトリの絶対パスであり、その値はこのラベルにしか無い。**推測して作った値で削除すると別セッションの資源を巻き込む** — compose の一意化名と同じ理由である。片付けを行わなかったことは compose と同じ1つの案内にまとめてよい |
| **`stop` の時点で旧い名前(ハッシュ無し)の compose 資源が残っている** | **削除しない。** 旧名は別ディレクトリと衝突しうるため対象に含めてはならない。可能性があることと、確認・手動削除の方法を表示して続行する(案内に載せる具体的なコマンドは 03 が持つ) |
| **削除中に `INT` / `TERM` を受けた**(Ctrl-C など) | **進行中の1件を終えてから中断する**(1件の削除を途中で切ると中途半端な状態が残る)。**そこまでに削除した資源と、未削除のまま残った資源を1件ずつ列挙**し、**終了コード 130** で終わる(SIGINT の慣行値)。「削除しました」「完了」の文言は出さない。ロックは中断時にも必ず解放される(解放の手段は 03 が持つ) |
| **セッション由来の資源(コンテナ / ネットワーク)の削除に失敗した** | **握って続行する**(`FR-env-01` 受入基準24)。`stop` は `D0-env-08` 項5 の対象外であり、片付けの途中で止まるとより中途半端な状態が残る。**`reset` では握らない**(`logout` / `reset` は項5 の対象なので、消えなかった資源を列挙して終了コード 1 で終わる) |
| **使用中のためセッション由来のネットワークを削除できない** | **`stop` は握って続行する**(compose 既定ネットワークと同じ扱い。`FR-env-01` 受入基準11・24)。**`reset` は握らない** — 上の行と同じく `D0-env-08` 項5 の対象なので、消えなかった資源として列挙して終了コード 1 で終わる(`FR-env-01` 受入基準24 は `reset` を対象外と明記し、`FR-env-03` 受入基準18 が受ける) |
| **セッション由来の資源が1件も無い** | **その旨を表示しない**(`FR-env-01` 受入基準27。対象が無いことを毎回表示しない) |
| **セッション由来の資源を引く問い合わせそのものが失敗した** | **削除の失敗とは別に扱う**。`stop` は**片付けを行わずに続行**し、引けなかったことを表示する(遊休判定と同じく安全側へ倒す。推測で削除しない)。`reset` は**失敗として記録し**、消えなかった資源としてまとめて列挙して終了コード 1 で終わる(`D0-env-08` 項5)。**`logout` はこの一覧を削除ではなく「残したものの列挙」からの除外にだけ使う**ので、引けなかったときは**除外を行わずに列挙を表示し、セッション由来のコンテナが混じっている可能性があることを表示して処理を続ける**(削除に影響しないため失敗には数えない)。**列挙が空で返ったこと(0件)と、問い合わせが失敗したことを同一視してはならない** |
| **`logout` が削除対象の Claude コンテナ(管理ラベルを持つもの)の集合を引けなかった** | **「0件」と判定してはならない。** 削除対象0件の経路(`FR-env-03` 受入基準19)に入らず、受入基準14 のとおり列挙して確認を求め、削除へ進む。引けなかったことを表示し、**そのことを「消えなかった資源」として記録して終了コード 1 で終わる**(`D0-env-08` 項5。`reset` がセッション由来の資源の列挙の失敗を同じ倒し方で扱うのと揃える)。**引けなかった集合の中に削除対象が残っている可能性を、成功と同じ終了コードで隠してはならない** — 引けた結果が0件だったこととは別である |
| **`logout` が共有ボリュームが空かどうかを確かめられなかった**(中身を読む手段が起動できなかった、**または起動できたが列挙そのものが失敗した**) | **「空」と判定してはならない。** 削除対象0件の経路(`FR-env-03` 受入基準19)に入らず、受入基準14 のとおり削除対象を列挙して確認を求め、削除へ進む。確かめられなかったことを表示する。**列挙が空で返ったこと(0件)と、確かめられなかったことを同一視してはならない** — 上の「セッション由来の資源を引く問い合わせそのものが失敗した」行と「削除対象の Claude コンテナの集合を引けなかった」行、下の「遊休判定に使う Docker への問い合わせが失敗した」行と同じ倒し方である(**判定不能を安全側へ倒し、0件と同一視しない**)。消去できたかどうかの判定は次の行が受ける |
| **共有ボリュームの中身を消したが、削除後の列挙に何か残っていた** | 残っていたパスを列挙して終了コード 1 で終わる。**判定は「削除後の列挙結果」で行い、削除コマンドの終了コードでは行わない**(削除に使う操作の終了コードは「消えたか」を表さないため。理由の詳細は 03 が持つ)。**列挙そのものができなかった場合も「消去を確認できなかった」として同じ扱いにする**(空出力を成功と読み替えない) |
| **`logout` / `reset` の削除対象のうち1つ以上が削除できなかった** | 消えなかった資源を1件ずつ列挙し、終了コード 1 で終わる。**成功時の文言を出してはならない** |
| **遊休判定に使う Docker への問い合わせが失敗した**(ネットワークが存在しない / `docker` が応答しない) | **遊休でないと判定して docker-proxy を残す**(安全側へ倒す)。判定できなかったことを表示する。`FR-env-01` 受入基準9 は「稼働中なら止めるな」であり、判定不能を「遊休」と読み替えてはならない |
