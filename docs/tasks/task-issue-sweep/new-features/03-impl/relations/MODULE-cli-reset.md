# MODULE-cli-reset 全リセット

## 目的

環境を作り直したいときに、本システムが作った Docker 資源と、**本システムを通して作られた
Docker 資源**をまとめて消す(FR-env-01)。認証も共有ボリュームごと消える(FR-env-03)。

`stop` が1つのセッション分を片付けるのに対し、`reset` は**所有者を問わず**すべてのセッション由来の
資源を対象にする(`DSN-env-04` の規則 D。`FR-env-01` 受入基準25)。

## 処理の流れ

1. 引数を解析する(`--yes` のみ。それ以外は無視する)。
2. `MODULE-cli-common-lock` で**共有資源単位**のロック(キー `shared`、操作名 `reset`)を取る。
   取得できなければ**削除を一切行わずに**非0で終わる(`FR-env-01` 受入基準16)。
3. 削除対象を列挙して表示する。**コンテナ・`fwd-*`・セッション由来の資源・ボリューム・イメージは
   実在するものだけを1行ずつ挙げる**が、**docker-proxy と `claude-dev-net` の2つは実在を確かめずに
   常に「(遊休のときだけ)」という但し書き付きの候補行として出す**。
   実在しなければ手順7・8 で `skipped` になり失敗には数えない。
   - **Claude コンテナ**: 管理ラベル `claude-dev.managed=1` を持つものだけ(契約 `CTR-cli-container` の
     規則A)。**イメージからの逆引きは使わない。** 管理ラベルを持たないものは削除対象に入れず、
     その名前と「管理ラベルが付く前に起動した可能性がある」ことを別枠で表示する
     (`FR-env-03` 受入基準17)。**「停止中のものは列挙していない」ことも表示する。ただし実装が出すのは手順9 の最終報告であり、
     手順3 の確認の列挙では出さない**(確認で中止した経路ではこの1行が出ない)。
     列挙は `claude-dev-net` の接続情報から行うので稼働中しか分からない
     (`02-design/system.md` の SCR-01「残した資源」/ `docs/issues/055`)。
   - **`fwd-*` 中継コンテナと docker-proxy**: 名前(接頭辞 `fwd-` / 固定名
     `claude-dev-docker-proxy`)で識別する。ラベルを見ない。**docker-proxy の削除は手順7 の
     遊休判定を通ったときだけ**。
   - **セッション由来の資源**(規則 D): ラベル `claude-dev.role=spawned` を持つ**コンテナと
     ネットワーク**を、**所有者を問わず**すべて挙げる(`FR-env-01` 受入基準25)。
     **名前付きボリュームは対象にしない**(`D0-env-05` 項2)。
     **この列挙の問い合わせが失敗した場合(非0で返る)は、失敗として記録し、その旨を一覧に
     出す**(契約 `CTR-cli-container`「エラーケース」)。**手順4 の確認で `y` 以外が入力されて
     終わるときも、引けなかった事実は表示する**(何も削除しないので終了コードは 0 のままとする
     — 削除していない以上「消えなかった資源」は無い)。削除まで進んだ場合は手順9 の列挙に含める。
   - **ボリューム**: `claude-dev-auth` / `claude-dev-history` / `claude-dev-config` と
     `claude-dev-chrome-*`、**および VM モードのゲストディスク `claude-dev-vm-*`**(名前が本システムの
     ものであることは名前で一意に決まるため、ラベルによる絞り込みの対象にしない。
     `claude-dev-vm-*` を含めるのは、契約 `CTR-cli-container`「識別の手段は資源ごとに違う」が
     この接頭辞を本システムの共有ボリュームとして挙げており、`reset` が「ホスト全体を初期状態へ
     戻す」操作だからである。**`D0-env-05` 項2 が「削除しない」と定める名前付きボリュームは
     セッション由来の資源を指すのでこれには当たらない**)。
   - **ネットワーク**: `claude-dev-net`(**ただし削除は手順7 の遊休判定を通ったときだけ**)。
   - **イメージ**: `claude-dev-claude` / `claude-dev-claude-vnc` / `claude-dev-docker-proxy`。
4. 確認を取る(`FR-env-03` 受入基準 14〜16)。
   - 手順3 の一覧を表示して `(y/N)` を求める。`y` / `Y` 以外の入力なら**何も削除せず**
     終了コード 0 で終わる。
   - **標準入力が TTY でなく、`--yes` も指定されていないなら中止する**: `--yes` の指定方法を
     表示して終了コード 1 で終わる。自動実行で「何もしなかった」ことに
     気づけるようにするためである(`FR-env-03` 受入基準15)。
   - `--yes` が指定されていれば確認を飛ばす。
5. 手順3 の**コンテナ**を削除し、**1件ごとに終了コードを記録する**(`|| true` で握るだけにしない)。
6. **セッション由来の資源を削除する**(`FR-env-01` 受入基準25)。**コンテナ → ネットワーク**の順で
   行う(使用中のネットワークは削除できない)。**1件ごとに終了コードを記録する**。
   - **削除対象は手順3 で列挙した集合をそのまま使い、ここで引き直さない。**
     `FR-env-03` 受入基準14 が「利用者が『何が消えるか』を消える前に見られる唯一の機会」と定める
     以上、**手順3〜手順4 の対話中に作られた資源を、列挙を経ずに消してはならない**
     (手順5 のコンテナ削除が手順3 の集合を使うのと同じ扱いである)。列挙後に作られた資源は
     次回の `reset` が回収する。
   - 削除は コンテナ = `docker rm -f`、ネットワーク = `docker network rm`(列挙の仕方は手順3)。
   - **列挙の問い合わせそのものが失敗した場合(非0で返る)は、失敗として記録し手順9 の列挙に
     含める**(契約 `CTR-cli-container`「エラーケース」。`reset` は `D0-env-08` 項5 の対象なので、
     引けなかったことを握って「完了」と表示してはならない。**0件で返ったことと問い合わせが
     失敗したことを同一視してはならない**)。
   - **削除した資源の名前を種別つきで1行ずつ表示する。0件なら表示しない**
     (`FR-env-01` 受入基準26・27)。
   - **`stop` と違い、失敗は握らない**: `reset` は `D0-env-08` 項5 の対象なので、記録した失敗は
     手順9 の列挙に含める(`FR-env-01` 受入基準24 の「続行する」は `stop` にだけ掛かる)。
   - 手順5 で消えた Claude コンテナが所有していた資源も、**ここでは所有者を問わないので同じ列挙に
     入る**(所有者のコンテナが先に消えていても引ける。ラベルは資源自身に付いているため)。
7. **docker-proxy と共有ネットワーク `claude-dev-net` は遊休判定を通してから消す**
   (契約 `CTR-cli-container` の規則C。`FR-env-01` 受入基準9)。
   `claude-dev-net` に接続している稼働中コンテナから、名前が `claude-dev-docker-proxy` のものと
   名前が `fwd-` で始まるものを除いた集合が**空のときだけ**両方を削除する。
   **手順3 でラベルを持たない Claude コンテナを残しているため、この判定は空にならないことがある。**
   空でなければ docker-proxy と `claude-dev-net` を残し、**残した理由(稼働中のコンテナ名)と
   「完全な初期化にはなっていない」ことを表示**して、残りの削除(ボリューム・イメージ)を続行する。
   判定の問い合わせが失敗したときは遊休でないと判定して残す(安全側)。
   **手順6 を手順7 より前に置くのは固定である**: セッション由来のコンテナが `claude-dev-net` に
   接続していると、順序が逆のとき「稼働中のコンテナがある」と数えて共有資源を残してしまう。
8. **ボリューム → イメージ**の順に削除し、**1件ごとに終了コードを記録する**。
   全体の順序は コンテナ → **セッション由来の資源** → docker-proxy と `claude-dev-net`(遊休なら)
   → ボリューム → イメージ で固定する(使用中の参照を先に外す)。
9. 記録した失敗が1件以上あれば、**消えなかった資源を1件ずつ列挙**し、終了コード 1 で終わる。
   **このとき**成功時の文言(「全リセット完了」)は出さない(`FR-env-03` 受入基準18)。
   **手順7 で意図して残した docker-proxy と `claude-dev-net` は「失敗」に数えない**
   (残すと決めたものである)。
   **終了コード 1 で終わる場合も、`exit` する前に手順3 で削除対象から外したラベル無しコンテナの
   名前と「停止中のものは列挙していない」限界を表示する**(`02-design/logging.md`「残したものの
   表示は削除の成否で条件づけない」。`FR-env-03` 受入基準17 は表示を成否で条件づけていない)。**失敗が0件なら完了を表示して 0 で終わる**: 手順7 で共有資源を
   削除できた(= 遊休だった)なら「全リセット完了」、残したなら「削除を完了しました
   (共有資源を残したため、完全な初期状態には戻っていません)」を出す。
10. **削除中に `INT` / `TERM` を受けた場合**は、進行中の1件を終えてから中断し、
   **そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙**して**終了コード 130** で終わる
   (契約の「エラーケース」)。成功時の文言は出さない。
11. ロックを解放する(`trap` により異常終了時も解放される)。

## 呼び出され方

- 契機: 利用者が `claude-dev reset [--yes]` を実行したとき。
- 前提条件: なし。**対象を絞る引数は無く、常にホスト全体の claude-dev 資源(管理ラベルを持つもの)が
  対象**である(カレントディレクトリは関係しない)。
- 引数:

| 引数 | 型 | 必須 | 制約 | 実装が行う検証 |
|---|---|---|---|---|
| `--yes` | フラグ | 任意 | 確認プロンプトを飛ばす。**端末を持たない環境で実行する唯一の手段**である | 存在するかどうかだけを見る(値は取らない) |
| 上記以外の引数(位置引数 / 未知のフラグ) | — | — | **すべて無視する** | 検証しない |

**確認プロンプトが受理する入力**(`--yes` が無く、標準入力が TTY のときだけ出す。
`read -p "実行しますか？ (y/N) " -n 1 -r`。**1文字だけ読む**。現行実装の読み方を変えない
= `D0-scope-02`。`logout` も同じ読み方に揃える):

| 入力 | 結果 |
|---|---|
| `y` / `Y` | 削除を実行する |
| それ以外の1文字(`n` / Enter / 空 / 任意の文字) | 「キャンセルしました」と表示して `exit 0`。**何も削除しない**(`FR-env-03` 受入基準14) |
| **非 TTY(標準入力がパイプ・リダイレクト)で `--yes` が無い** | **プロンプトを出さずに中止**し、`--yes` の指定方法を表示して **`exit 1`**(`FR-env-03` 受入基準15)。**`yes y \| claude-dev reset` のように標準入力へ流し込む形は受け付けない**(端末を持たない環境で実行する手段は `--yes` だけである) |

- 認可: CLI を実行できるホストユーザ。

## 連携先と連携内容

### MODULE-cli-common-lock

- 何のために呼ぶか: `start` の**認証コピーから `docker run` の完了まで**の区間と重なって、
  認証コピー済みのコンテナが直後に消される・認証が空のまま起動する(`docs/histories/2026-08-04-fix-destructive-scope.md`)のを防ぐため。
  共有ボリュームとイメージまで消す操作なので共有資源単位のキーを取る。
  `start` が同じキーを `docker run` の完了まで保持する(`MODULE-cli-start` 判断9)ので、
  **`reset` はコンテナ作成との競合まで防げる**。
- 何を渡すか: キー `shared` と操作名 `reset`。
- 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: **何も削除せず**、保持している操作名と再実行の方法を表示して非0で終わる。

### MODULE-cli-common-container-exists

- 何のために呼ぶか: 列挙した各コンテナが削除の直前に実在するかを確かめ、既に消えているものを
  「削除できなかった」と誤って数えないため(手順5)。
- 何を渡すか: コンテナ名。 / 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: 「存在しない」と判定され、その1件は削除をスキップする
  (**失敗としては数えない**)。

### MODULE-cli-common-image-exists

- 何のために呼ぶか: 削除対象のイメージを列挙するとき、存在しないイメージを対象に入れないため
  (手順3)。`docker rmi` は存在しないイメージに対して非0を返すので、入れると常に失敗扱いになる。
- 何を渡すか: イメージ名(`claude-dev-claude` / `claude-dev-claude-vnc` / `claude-dev-docker-proxy`)。
  / 何を受け取るか: 終了ステータス。
- **失敗したときどうなるか**: 「存在しない」と判定され、そのイメージは削除対象から外れる。

### MODULE-cli-common-destructive

- 何のために呼ぶか: 削除の予定・成功・失敗を1件ずつ記録し、最後にまとめて列挙するため
  (`FR-env-03` 受入基準18)。あわせて `INT` / `TERM` を進行中の1件を終えてから受けるため(同23)。
- 何を渡すか: 手順3 で列挙した削除対象の表示名と、`destructive_rm` へ渡す削除コマンド。
  呼び出し順は `destructive_plan`(手順3 の対象を出そろえる。`claude-dev:2045`-`:2055`)→
  `destructive_arm_interrupt`(`:2056`)→ `destructive_rm` → 区切りごとの
  `destructive_abort_if_interrupted`(最後は `:2157`)→ `destructive_report`。
  **`plan` が先である** — 中断の遅延を仕掛けるのは、対象が出そろって実際の削除に入る直前でよい。
- 何を受け取るか: 記録された結果。**`destructive_rm` は成否によらず 0 を返す**ので、
  削除できたかどうかは `_DESTRUCTIVE_DELETED` の要素数が増えたかで判定する(判断17)。
- **失敗したときどうなるか**: 削除コマンドが失敗しても呼び出し元は落ちず、失敗が記録される。
  中断要求が来ていれば次の検査点で `exit 130` になり、**この機能がプロセスを終える**。

### MODULE-cli-common-net-other-running-containers

- 何のために呼ぶか: docker-proxy と `claude-dev-net` を消してよいかの遊休判定に使う集合を得るため
  (手順7)。
- 何を渡すか: なし(対象ネットワークは定数)。
- 何を受け取るか: `claude-dev-net` に接続している稼働中のコンテナ名。空なら遊休である。
- **失敗したときどうなるか**: 非0が返る。**遊休でないと判定して両方を残し**、判定できなかったことと
  「完全な初期化になっていない」旨を表示して残りの削除を続行する(安全側)。**残したものは
  失敗に数えない。**

### MODULE-cli-common-spawned-resources

- 何のために呼ぶか: セッション由来の資源を**所有者を問わず**列挙するため(手順3・6)。
- 何を渡すか: 種別(`container` / `network`)と、ラベルフィルタ式 `claude-dev.role=spawned`。
  **所有者の値では絞らない**(`reset` は対象を絞る引数を持たないホスト全体の操作である。
  `FR-env-01` 受入基準25)。
- 何を受け取るか: 資源の名前を1行ずつ。
- **失敗したときどうなるか**: 非0が返る。**握らずに失敗として記録し**、手順9 の列挙に含めて
  `exit 1` で終わる。**0件で返ったことと問い合わせが失敗したことを同一視しない。**

## 戻り値・副作用

| 種別 | 内容 |
|---|---|
| 戻り値 | **0**(列挙した削除対象がすべて消えたか、意図して残したものだけが残ったとき)。**1**: ロックを取得できない / 端末が無く `--yes` も無い / **削除できなかった資源が1件以上ある**。**130**: **受けた区間で決まり、3つに分かれる**。(i) 手順2 の `acquire_lock` から `destructive_arm_interrupt`(`claude-dev:2056`)まで = **即座に 130**(`acquire_lock` は取得を試みる前に `trap '_release_all_locks; exit 130' INT TERM` を張る。`claude-dev:452`。取得に失敗して終わる経路もこの区間に入る)。(ii) そこから最後の `destructive_abort_if_interrupted`(`claude-dev:2157`)まで = **遅延中断**で、進行中の1件を終えてから次の検査点で 130。(iii) **それ以降は 130 にならない** — 旗が立つだけで再検査が無いため、手順9 の結果表示とロック解放を経て 0 または 1 で終わる。**0**: 確認プロンプトで `y`/`Y` 以外を入力した(何も削除しない) |

### 並行性

**共有資源単位のロックを全区間で保持する**(`CTR-cli-container` の「排他(ロックキー)」)。
**待たない**ので、取得できなければ何も削除せずに終了コード 1 で終わる。
削除は次の順で行い、**各ステップは失敗を1件ずつ記録して次へ進む**(握りつぶさない)。

1. 管理ラベルを持つ Claude コンテナ → 2. `fwd-*` → 3. **セッション由来の資源
(コンテナ → ネットワーク)** → 4. **遊休なら** docker-proxy と `claude-dev-net` →
5. 共有ボリューム3本と `claude-dev-chrome-*` と **`claude-dev-vm-*`** → 6. イメージ3本

| 同時に起きること | 実際の結果 |
|---|---|
| 他プロジェクトのコンテナが稼働中 | **管理ラベルを持つものは削除する**(確認プロンプトで対象を列挙してから)。**ラベルを持たないものは削除せず名前を表示して残す**。**そのため docker-proxy と `claude-dev-net` は遊休判定を通らず残り、「完全な初期化になっていない」ことを表示する** |
| **他プロジェクトのセッションがコンテナ内から資源を作っている** | **所有者を問わず削除する**(`reset` は「ホスト全体を初期状態へ戻す」操作であり、対象を絞る引数を持たない)。削除対象は手順3 の確認で列挙されるので、利用者は消える前に見られる |
| `reset` と `start` | **同じキーのロックで直列化される**。`start` は認証コピーからコンテナ作成の確定まで保持するので、**認証コピー済みのコンテナが直後に消される経路は閉じた**(`docs/histories/2026-08-04-fix-destructive-scope.md`) |
| `reset` と `login` / `login-codex` | **同じキーのロックで直列化される**。ログインは対話の全区間で保持するため、その間 `reset` は取得できずに終了コード 1 で終わる |
| `reset` を2つ同時 | **後発はロックを取得できず、何も削除せずに終了コード 1 で終わる** |
| **`reset` と、稼働中セッションの中で走っている `docker run`** | **保護されない。** ロックはホスト CLI のプロセス間だけで有効で、コンテナ内の Docker クライアントは対象外である。手順6 の列挙の直後に作られた資源は消し残る |
| 利用者が直接 `docker rm -f` / `docker volume rm` する | **保護されない**(ロックはホスト CLI のプロセス間だけで有効) |

## 異常系

| 条件 | 実際の振る舞い | 呼び出し元への影響 |
|---|---|---|
| **共有資源単位のロックを取得できない** | 保持している操作名と PID、再実行の方法を stderr へ出し、**何も削除せずに** `exit 1` | `start` の認証コピー〜コンテナ作成の区間と重なる削除を防ぐ(`docs/histories/2026-08-04-fix-destructive-scope.md`) |
| **標準入力が TTY でなく `--yes` も無い** | **プロンプトを出さずに中止**し、`--yes` の指定方法を stderr へ出して `exit 1`。**何も削除しない** | 端末を持たない環境で `reset` を実行する手段は `--yes` だけである(`FR-env-03` 受入基準15) |
| 確認プロンプトで `y` / `Y` 以外を入力した | 「キャンセルしました」と表示して `exit 0`。**何も削除しない** | なし(受入基準14) |
| **管理ラベルを持たない Claude コンテナがある** | **削除対象に入れない。** 名前と「管理ラベルが付く前に起動した可能性がある」ことを表示して残す | 他プロジェクトの作業中セッションを落とさない(受入基準17) |
| **所有者ラベルを持たないセッション由来の資源がある**(`DSN-env-04` の導入より前に作られたもの、またはボディを解釈できない要求で作られたもの) | **削除対象に入らない。列挙もできないので表示もしない** | ホストに残り続ける。利用者が `docker ps -a` で自力で見つけて消す(「既知の制限」) |
| **セッション由来の資源を引く問い合わせが失敗した**(`docker ps` / `docker network ls` が非0) | **握らない。** 失敗として記録し、手順9 の列挙に含めて `exit 1`。**0件と区別する** | 引けなかったことに気づける(契約「エラーケース」) |
| **セッション由来の資源の削除に失敗した**(使用中のネットワークなど) | **握らない。** 1件ごとに記録し、手順9 で消えなかった資源として列挙して `exit 1`(`stop` の受入基準24 とは扱いが違う。`reset` は `D0-env-08` 項5 の対象である) | 残骸に気づける(受入基準18) |
| **`claude-dev-net` に接続している稼働中コンテナが残っている** | **docker-proxy と `claude-dev-net` を残し**、残した理由(コンテナ名)と**「完全な初期化になっていない」**旨を表示して、ボリューム・イメージの削除を続行する。**残したものは失敗に数えない** | 残したコンテナの中から Docker が使え続け、名前解決も壊れない(`FR-env-01` 受入基準9) |
| **遊休判定の問い合わせが失敗した** | **遊休でないと判定して docker-proxy と `claude-dev-net` を残す**。判定できなかったことと「完全な初期化になっていない」旨を表示して続行する | 安全側に倒れる |
| 削除対象のボリュームやイメージが存在しない | 列挙の時点で対象から外す(`docker volume inspect` / `MODULE-cli-common-image-exists` で実在を確かめる)。**失敗に数えない** | 存在しないものを「削除できなかった」と誤って数えない |
| 削除対象のコンテナが削除の直前に既に消えていた | `MODULE-cli-common-container-exists` が偽になり、その1件はスキップする。**失敗には数えない** | なし |
| **1件以上の削除に失敗した**(使用中のボリュームなど) | 消えなかった資源を**1件ずつ列挙**して `exit 1`。**「全リセット完了」を出さない** | 残骸に気づける(受入基準18) |
| **削除中に `INT` / `TERM` を受けた** | **進行中の1件を終えてから**中断し、そこまでに削除した資源と未削除のまま残った資源を1件ずつ列挙して **`exit 130`**。成功の文言を出さない | 中途半端な状態が可視化される(受入基準23) |
| **1件以上の削除に失敗し、かつ管理ラベルを持たない Claude コンテナがある** | 消えなかった資源の列挙に加えて、**`exit 1` する前に**残したコンテナの名前と「停止中のものは列挙していない」限界も表示する | 削除に失敗した実行でも、残したコンテナが在るという事実が利用者に伝わる(受入基準17 は表示を成否で条件づけていない) |
| VM モードのボリューム `claude-dev-vm-<name>` | **削除対象に含まれる**(手順3 のボリューム列挙。削除前の確認でも列挙されるので、`--yes` を付けない実行では利用者が中止できる) | ゲストディスクが消える。ゲスト内にだけ置いたデータは戻らない |
| **VM モードのゲスト内で作られた資源** | **削除対象に含まれない**(ホストの Docker に現れないので所有者ラベルも付かない) | ゲストを消せば一緒に消える |
| macOS の専用 agent / ブリッジ | **削除対象に含まれない**(掃除は `ssh-keys reset` が担う) | 残骸が残る |
| プロジェクト側の `.claude/` `.codex/` `.claude-dev.yaml` | **削除対象に含まれない**(`FR-env-03` 受入基準22。`logout` との非対称は `D0-env-08` 項4 が明示する) | 認証ファイルのコピーはプロジェクト配下に残る |
