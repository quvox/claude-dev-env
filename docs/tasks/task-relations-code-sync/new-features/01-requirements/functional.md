## FR-env-01 コンテナのライフサイクル管理

- 対応要求: RQ-env-01 / AC-01
- 内容: プロジェクトごとに隔離コンテナを起動・再接続・停止・一覧できること。SSH 切断後も作業が
  維持されること。**破壊的操作(`stop` / `logout` / `reset`)が他プロジェクトの資源を巻き込まないこと**
  (`D0-env-08`。共有 docker-proxy と共有ネットワークの停止条件は受入基準9)。
  **共有ボリュームまたは docker-proxy を触るサブコマンドが互いに排他されること**(同項6)。

受け入れ基準(EARS):

| # | 種別 | 基準 |
|---|---|---|
| 1 | 正常系 | WHEN `claude-dev start` を実行したとき、システムはカレントディレクトリを `/workspace` にマウントしたコンテナ(既定はブラウザ確認あり)を起動し、tmux にアタッチしなければならない |
| 2 | 正常系 | WHERE `--no-vnc` が指定された場合、システムはブラウザ確認資産を持たない軽量イメージを使わなければならない |
| 3 | 正常系 | WHILE コンテナが起動している間、SSH 切断や tmux デタッチが起きてもコンテナは動作を継続しなければならない |
| 4 | 正常系 | WHEN 同一ディレクトリで `claude-dev start` を再実行したとき、システムは既存コンテナへ再接続しなければならない(tmux セッションが無ければ再作成する) |
| 5 | 正常系 | WHEN `claude-dev list` を実行したとき、システムは実行中セッションの一覧(noVNC URL とフォワード状況を含む)を表示しなければならない |
| 6 | 正常系 | WHEN `claude-dev stop <name>` を実行したとき、システムは当該コンテナを削除し、当該コンテナ内から起動された compose コンテナ群と当該プロジェクトの compose 既定ネットワークを削除し(名前付きボリュームは保持する)、全 Claude コンテナが停止したときは docker-proxy も停止しなければならない |
| 7 | 境界値 | IF tmux の起動待ちが上限(既定 30 秒 / VM モード 420 秒)を超えたならば、システムは終了コード 0 で状況を案内して終わらなければならず、コンテナを削除してはならない(コンテナは稼働を続け、再実行の再接続経路で合流できる) |
| 8 | 境界値 | IF 停止対象のコンテナが存在しないならば、システムは削除をスキップし、その旨を表示して終了コード 0 で終わらなければならない |
| 9 | 境界値 | IF ホスト上に稼働中の Claude コンテナが1つ以上残っているならば、**`stop` / `logout` / `reset` は** docker-proxy を停止してはならず、**`reset` は共有ネットワーク `claude-dev-net` も削除してはならない**(`reset` は残した理由と**完全な初期化になっていない**ことを表示して残りの削除を続行する)。**`stop` と `logout` は遊休かどうかにかかわらず `claude-dev-net` を削除しない**ので、この基準がネットワークについて課す条件は `reset` にだけ効く(`D0-env-08` 項2 の条件は3コマンド共通だが、`claude-dev-net` を削除する経路を持つのは `reset` だけである)。**この判定は、対象コンテナが本システムの管理ラベル(`D0-env-08`)を持つかどうか、およびどのイメージ ID から作られたかに依存してはならない**(イメージを再ビルド・再取得した後に起動していたコンテナを数え落としてはならない。管理ラベルを持たない既存コンテナも稼働中として数える) |
| 10 | 異常系 | IF 前提コマンド(`docker` / `jq`、macOS では `socat` も)が不足しているならば、システムは不足を列挙して導入方法を案内し、終了コード 1 で終わらなければならない |
| 11 | 異常系 | IF compose 既定ネットワークが他から使用中で削除できないならば、システムは処理を続行しなければならない(停止全体を失敗させない。これは `D0-env-08` 項5 が明示する例外である) |
| 12 | 異常系 | IF `claude-dev start` のコンテナ作成が**同名のコンテナが既に存在すること**を理由に失敗したならば、システムはその既存コンテナを削除してはならず、**同名のコンテナが稼働中であること**と**別ディレクトリの同名プロジェクトである可能性**を表示して、終了コード 1 で終わらなければならない(再試行してはならない) |
| 13 | 境界値 | IF コンテナ作成の失敗後に後片付け(作りかけのコンテナの削除)を行うならば、システムは対象が稼働中でないことを確かめてから削除しなければならない。**稼働中のコンテナは、作成の失敗理由を問わず削除してはならない** |
| 14 | 正常系 | WHEN `claude-dev start` が Claude コンテナを作成するとき、システムは本システムが作ったことと起動元のホスト側絶対パスを示す**管理ラベル**を付与しなければならない(名前と値は `CTR-cli-container` が定める。**Claude コンテナ以外の資源にはラベルを付けない**。名前が固定であり名前で識別できるため) |
| 15 | 境界値 | IF `claude-dev stop <name>` の対象コンテナが管理ラベルを持たないならば(管理ラベルが付く前に起動されたコンテナなど)、システムはそのコンテナを削除しつつ、**管理ラベルを持たないことを表示**しなければならない(名前で1件を指した削除は `D0-env-08` 項1 の例外である) |
| 16 | 異常系 | IF `start` / `stop` / `logout` / `reset` / `login` / `login-codex` のいずれかが、同じプロジェクト名または同じ共有資源(共有ボリューム・docker-proxy)を対象として既に実行中ならば、システムは**待たずに**、保持している操作の名前と再実行の方法を表示して終了コード 1 で終わらなければならない。**このとき、取得できなかったロックが守る資源に対する削除も作成も行ってはならない**(プロジェクト単位のロックが守るのは当該コンテナとそのプロジェクト配下の生成物、共有資源単位のロックが守るのは共有ボリューム**の中身**・docker-proxy・**共有ボリュームを読んで作られたコンテナ**である。**冪等に作られる共有資源の「用意」は保護対象ではない**: イメージのビルドと、共有ネットワーク `claude-dev-net`・共有ボリューム3本そのものの作成。既に在れば何も起きず、無いときに作られるのは中身の無い器だけであるため) |
| 17 | 境界値 | IF 排他のためのロックが、既に存在しないプロセスに保持されたまま残っているならば、システムはその事実を表示してからロックを引き継いで処理を続行しなければならない(永久に取得できない状態を作ってはならない) |
| 18 | 境界値 | IF `claude-dev stop <name>` の `<name>` が `[A-Za-z0-9._-]` 以外の文字を含むならば、システムは**何も削除せず**、受理できない文字を含むことを表示して終了コード 1 で終わらなければならない(排他のロックはこの名前をパス要素として使うため、`/` や `..` を含む名前を受理してはならない) |
| 19 | 境界値 | IF 別のディレクトリで起動されたセッションの compose 資源が存在するならば、`stop` はそれを削除してはならない。**起動ディレクトリ名が正規化後に一致する場合も削除してはならない**(compose プロジェクト名は起動ディレクトリの絶対パスを含めて一意化する。方法は `CTR-cli-container` が定める) |
| 20 | 境界値 | IF 本要件の一意化より前に起動された compose 資源が残っているならば、`stop` はそれを削除してはならず、**残っている可能性と手動で片付ける方法を表示**しなければならない(旧い名前は別ディレクトリと衝突しうるため対象に含めない) |
| 21 | 境界値 | IF `claude-dev stop <name>` の対象コンテナが管理ラベル `claude-dev.project-dir` を持たない、または既に存在しないならば、システムは**compose 資源の削除を行ってはならず**、compose 資源が残っている可能性と手動で片付ける方法を表示しなければならない(compose 一意化名は起動ディレクトリの絶対パスから作られ、その値はこのラベルにしか無い。**推測して削除すると別ディレクトリを巻き込む**) |
