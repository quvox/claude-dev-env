## FR-env-12 同梱エージェント CLI(Claude Code / Codex CLI)

- 対応要求: RQ-env-03 / AC-06
- **分割可否: 不可分**
- 内容: コンテナ内で Claude Code と Codex CLI の双方が、追加のセットアップなしに使えること。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-12-1 | 正常系 | WHEN 配布イメージをビルドするとき、システムはブラウザ確認あり/なしの**両方**の配布イメージに Claude Code と Codex CLI の双方を同梱しなければならない |
| FR-env-12-2 | 正常系 | WHEN コンテナ内で `codex` を実行したとき、システムは同梱した Codex CLI を起動しなければならない。コマンドは対話シェル・非対話シェル・`docker exec` のいずれからも解決できなければならない |
| FR-env-12-3 | 正常系 | WHEN 配布イメージをビルドするとき、システムはエージェント CLI を具体バージョンでピン留めして導入しなければならず、起動時や実行時のダウンロードに依存してはならない |
| FR-env-12-4 | 正常系 | WHEN codex が既定設定でシェルコマンド(疎通確認は `/bin/true`)を実行したとき、システムはそれを終了コード 0 で完了させなければならない。**コマンド自身の失敗と、Codex サンドボックスが起動できないことによる失敗を区別**し、後者を起こしてはならない(**Codex サンドボックスの既定バックエンドが使えない環境でも成立させる。どの手段で成立させるかは 02 が定める**) |
| FR-env-12-5 | 正常系 | WHEN コンテナを起動するとき、システムは Codex サンドボックスの既定設定 3 鍵(`sandbox_mode = "danger-full-access"` / `approval_policy = "never"` / `[features] use_legacy_landlock = true`)をコンテナ起動時に置かなければならない |
| FR-env-12-6 | 正常系 | WHEN codex が `--sandbox read-only` のようにサンドボックスを明示指定して起動されたとき、システムはそのコマンド実行を成功させなければならない(読み取りは成功し、書き込みは拒否される) |
| FR-env-12-7 | 正常系 | WHILE コンテナが稼働している間、システムは Codex サンドボックスを動作させるためにコンテナの seccomp/AppArmor プロファイルを緩めてはならない |
| FR-env-12-8 | 境界値 | IF 起動時に codex の設定ファイルが既に存在するならば、システムは既に書かれている鍵と値を書き換えてはならず、受け入れ基準5の 3 鍵のうち**書かれていない鍵だけを追記**しなければならない(同じ設定で何度起動しても結果が変わらないこと) |
| FR-env-12-9 | 境界値 | WHERE `workspace-write` が指定された場合は本要件の対象外とし(**対象外とする理由は `D0-dist-04` 項6 が持つ**)、書き込みを伴う自動化は既定設定で実行する |
| FR-env-12-10 | 異常系 | IF 既存の設定ファイルが解釈できない、または追記内容が検証に通らないならば、システムは既存ファイルを書き換えてはならず、警告だけを出して起動を続行しなければならない |
| FR-env-12-11 | 異常系 | IF 既定設定の生成・追記に失敗したならば、システムはコンテナの起動を止めてはならない(codex を使わない利用者の起動を妨げない) |
| FR-env-12-12 | delete | 廃止する。旧内容は「本要件の対象は開発者が対話的に codex を使うことであり、オーケストレーターが worker/レビューアーとして codex を常用することは対象外とする(`D0-orch-17` 未決)」。オーケストレーターと `D0-orch-17` の双方が消えるため、対象外を宣言する相手が存在しない。**番号 12 は欠番のままにし、再利用しない** |

## FR-env-08 VM モード(オプトイン)

- 対応要求: RQ-env-05
- **分割可否: 不可分**
- 内容: bind/compose/privileged が要る重い Docker 案件を、Claude コンテナを特権化せずに扱えること。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-08-1 | 正常系 | WHERE `claude-dev start --vm` が指定された場合、システムはゲスト VM を起動し、その中でネイティブ Docker を利用可能にしなければならない |
| FR-env-08-2 | 正常系 | WHERE VM モードで起動した場合、システムは VM モードでも `/workspace` を同一パスで共有(ライブ反映)し、Claude コンテナを privileged 化してはならない |
| FR-env-08-3 | 正常系 | WHILE VM モードでない間、システムは既定の軽量構成(DooD + docker-proxy)で動作しなければならない |
| FR-env-08-4 | 正常系 | WHILE VM モードで動作している間、システムは**資源逼迫**(用語集が定義する状態)を検知し、**利用者が見ている tmux のステータス行へ警告を表示**しなければならない(**この基準が課すのは VM モード側のこの表示だけである**。検知の周期と、検知結果を他の表示へ渡す方法は 02/03 が定める) |
| FR-env-08-5 | 境界値 | IF `--vm` **または `--vm-fresh`** が指定されたが `/dev/kvm` が利用できないならば、システムは起動を中止し終了コード 1 で終わらなければならない(`--kvm` 単独指定は対象外で、警告を出して続行する) |
| FR-env-08-6 | 境界値 | WHEN VM を停止するとき、システムはゲストの正常終了を優先し、それが失敗または利用不能な場合にだけ強制終了へフォールバックしなければならない |
| FR-env-08-7 | 異常系 | IF ゲスト VM の起動に失敗したならば、システムは失敗を明示したうえで既定の DooD 経路を維持しなければならない(VM は使えないが Docker は使える) |
| FR-env-08-8 | 異常系 | IF 再構築が指示されたならば、システムは取得済みのベースイメージを保持しなければならない(完全な作り直しは利用者の明示指定に限る) |
