## FR-env-05 ネットワーク隔離とファイアウォール

- 対応要求: RQ-env-01 / AC-01
- 内容: レビュー前コードの外向き通信を制御すること。**塞ぐ対象は「ブロック対象ドメイン」**
  (用語集に定義。**設定で与えられるドメイン集合**であり、集合の中身は要件で固定しない。
  既定の内訳は `MODULE-firewall-init` が列挙する)。

受け入れ基準(EARS):

| # | 種別 | 基準 |
|---|---|---|
| 1 | 正常系 | WHEN コンテナを起動したとき、システムはコンテナ内でファイアウォールを設定しなければならない |
| 2 | 正常系 | WHILE コンテナが稼働している間、システムはコンテナ間通信を専用ネットワーク `claude-dev-net` 上で行わなければならない |
| 3 | 正常系 | WHEN ファイアウォールを再適用したとき、システムは既存のルールの有無にかかわらず同じ結果にならなければならない(冪等) |
| 4 | 境界値 | IF ブロック対象ドメイン(**設定に列挙されたドメイン**)の名前解決に失敗したならば、システムはその1件だけをスキップして残りの適用を続けなければならない(当該ドメインは塞がれないまま残る) |
| 5 | 異常系 | IF ファイアウォールの適用に失敗したならば、システムはコンテナの起動を中止してはならず、警告を起動ログへ出力したうえで起動を継続しなければならない |
| 6 | 異常系 | IF 適用直後の到達性スモークテストで想定外の結果(**設定に列挙したドメインのいずれかへ到達できた**、または Anthropic API へ到達できない)が出たならば、システムは警告行を出力しなければならない(起動は継続する) |
| 7 | 正常系 | WHEN ファイアウォールの適用を終えたとき、システムは**設定に列挙したドメインの件数と、実際に登録できた宛先 IP の件数**を起動ログへ出力しなければならない(受入基準4 でスキップが起きたことを利用者が数で判別できるようにするため) |

## FR-env-08 VM モード(オプトイン)

- 対応要求: RQ-env-05
- 内容: bind/compose/privileged が要る重い Docker 案件を、Claude コンテナを特権化せずに扱えること。

受け入れ基準(EARS):

| # | 種別 | 基準 |
|---|---|---|
| 1 | 正常系 | WHERE `claude-dev start --vm` が指定された場合、システムはゲスト VM を起動し、その中でネイティブ Docker を利用可能にしなければならない |
| 2 | 正常系 | WHERE VM モードで起動した場合、システムは VM モードでも `/workspace` を同一パスで共有(ライブ反映)し、Claude コンテナを privileged 化してはならない |
| 3 | 正常系 | WHILE VM モードでない間、システムは既定の軽量構成(DooD + docker-proxy)で動作しなければならない |
| 4 | 正常系 | WHILE VM モードで動作している間、システムは**資源逼迫**(用語集に定義。ゲスト VM の QEMU プロセスの CPU 使用率が割り当て上限に対して 60% 以上である状態が 15 秒周期で 12 回連続して観測された状態)を検知し、**ヘルスファイルへ `STATE=WARN` を書き、tmux のステータス行へ警告を表示**しなければならない(**この基準が課すのは VM モード側の2つの出力だけである**。用語集「資源逼迫」が挙げるダッシュボードのバナー表示は、同じヘルスファイルを読むオーケストレーター側の描画であり `FR-orch-08` が担う) |
| 5 | 境界値 | IF `--vm` **または `--vm-fresh`** が指定されたが `/dev/kvm` が利用できないならば、システムは起動を中止し終了コード 1 で終わらなければならない(`--kvm` 単独指定は対象外で、警告を出して続行する) |
| 6 | 境界値 | WHEN VM を停止するとき、システムはゲストの正常終了を優先し、それが失敗または利用不能な場合にだけ強制終了へフォールバックしなければならない |
| 7 | 異常系 | IF ゲスト VM の起動に失敗したならば、システムは失敗を明示したうえで既定の DooD 経路を維持しなければならない(VM は使えないが Docker は使える) |
| 8 | 異常系 | IF 再構築が指示されたならば、システムは取得済みのベースイメージを保持しなければならない(完全な作り直しは利用者の明示指定に限る) |

## FR-orch-02 外部制御ループとコントローラ常駐

- 対応要求: RQ-orch-01 / AC-05
- 内容: 継続/停止をコードで判定し、端末が壊れても実行が失われないこと。

受け入れ基準(EARS):

| # | 種別 | 基準 |
|---|---|---|
| 1 | 正常系 | WHILE 実行モードで動作している間、システムは継続/停止をコード(外部制御ループ)で判定しなければならない(LLM の裁量に委ねない) |
| 2 | 正常系 | WHEN `orchestrate` でコントローラを起動したとき、システムはコントローラを tmux セッション `orch-<project>-main` の `dashboard` ウィンドウで常駐させ、worker とブレインストーミングを同セッションの独立ウィンドウとして管理しなければならない |
| 3 | 正常系 | WHILE 反復が進む間、システムは worker へ渡す**タスク固有の文脈**を次の4種だけで構成しなければならない: (a) plan のゴールと完了条件、(b) 当該タスクの説明と完了条件、(c) **完了した依存タスクの結果要約**(成果物そのものは渡さない)、(d) 前回試行のフィードバック。**リポジトリ全体を渡してはならない**(**全プロンプトに共通して前置・後置される要素はこの4種に数えない**: `ORCHESTRATOR.md` の前置は `FR-orch-08` 受入基準5、VM モードの周知は `FR-env-08`、結果の出力形式の指示は契約 `CTR-orchestrator-prompt` がそれぞれ別に要求する) |
| 4 | 境界値 | IF セッションは存在するがコントローラのプロセスが存在しないならば、システムはそれを空き殻とみなして作り直さなければならない(生存と誤判定してはならない) |
| 5 | 異常系 | IF 対象コンテナが起動していないならば、システムは自動で起動してから続行するか(Linux)、起動を促して終了コード 1 で終わらなければならない(macOS) |
