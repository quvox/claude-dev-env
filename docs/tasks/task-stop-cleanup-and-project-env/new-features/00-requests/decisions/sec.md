## D0-sec-11 プロジェクトの秘密の値は env ファイルに置き、版管理の追跡から外す

- 区分: 決定
- 決めた日: 2026-08-19
- 内容:
  1. **置き場**: プロジェクトごとにコンテナへ渡す秘密の値(社内サービスのトークン、接続文字列)は、
     **`D0-env-11` が定める env ファイルに置く**。プロジェクト直下の設定ファイル
     (`.claude-dev.yaml`)には置かない。
  2. **追跡から外す**: 本システムは、指定された env ファイルを**版管理の追跡から外す**。
     既に認証ファイルについて同じことを行っており、その手段と同じもので行う
     (手段の具体は 02/03 が定める)。**外せなかった場合も起動は止めず、外せなかったことを表示する。**
  3. **ガードレール**(置く側が守る):
     - **設定ファイル(`.claude-dev.yaml`)に秘密の値を書かない。** このファイルは
       `claude-dev ssh-keys` が書き出すもので、リポジトリに入る前提である。
     - **env ファイルをリポジトリへ追加しない。** 追跡から外す仕組みは事故を減らすためのもので、
       既に追跡下に入ってしまったファイルまでは戻さない。
  4. **出力しない**: 本システムは、渡した環境変数の**値そのものを端末にも常駐プロセスのログにも
     出さない**。名前を出すことは許す(採用しなかった名前の表示に要る)。
     出力の規則の正は `02-design/logging.md` である。
  5. **スコープ**: 本決定は「秘密の値が版管理へ入りにくいこと」までである。
     **ホストのファイルシステム上での暗号化や、秘密情報の管理サービスとの連携は含まない**
     (`P-004` が既に受容している「認証情報がホストのプロジェクトディレクトリ配下に平文で存在する」
     のと同じ信頼境界の内側に、もう1種類のファイルが増えるという理解である)。
- 理由: `RQ-env-07` を入れると、**秘密の値の置き場をこちらから用意することになる**。
  用意する以上、どこへ置けばよいかと、置いたものがどこまで守られるかを決めておかないと、
  利用者は設定ファイルへ直接書き、それがリポジトリへ入る。
  同じ形を `D0-dist-05` 項3 が同梱する実行ファイルについて既に採っており、
  **公開されたものは回収できない**という同じ理由に立っている。
  値をログへ出さないことを明記するのは、この製品のログ方針が既に
  「認証情報の中身を出さない」を課しており、その射程に新しい値の種類が入るためである。
- 却下した案:
  - **秘密を扱うことそのものを禁じ、利用者の責任に委ねる**(2026-08-19 に人間が採らなかった) —
    決まりが無いと利用者は設定ファイルへ直接書く。禁じても置き場を示さなければ守れない。
  - **秘密の値と秘密でない値でファイルを分ける** — 何が秘密かの線引きを利用者が毎回行うことになり、
    線を引き損ねた1件がリポジトリへ入る。全部を追跡の外に置くほうが守りやすい。
  - **ホストのファイルシステム上で暗号化する** — 復号鍵の置き場を新しく抱える。
    `P-004` が受容している信頼境界(ホストのホームディレクトリの内側)を超える資産ではない。
- 見直す条件: (a) プロジェクトディレクトリを他者と共有する・配布する運用が入ったとき
  (`P-004` の解消条件と同じ契機である)/ (b) 複数の利用者が同じホストを共有するとき /
  (c) 秘密情報の管理サービスを導入したとき(項1 の置き場が変わる)。
