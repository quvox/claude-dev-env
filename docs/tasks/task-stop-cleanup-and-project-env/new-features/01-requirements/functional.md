## FR-env-01 コンテナのライフサイクル管理

- 対応要求: RQ-env-01 / AC-01
- **分割可否: 段階可(理由: 段階的に近づくのは条項 `FR-env-01-19`(別ディレクトリの compose 資源を巻き込まない)だけである。compose 資源をプロジェクトごとに一意にしなければ**全プロジェクトが同じ名前を共有して必ず巻き込む**のに対し、一意化が部分的でも取り違えの余地が減った分だけ利用者の作業が守られる。判断の記録は `D1-split-01`。**他の 33 条項は不可分**)**
- 内容: プロジェクトごとに隔離コンテナを起動・再接続・停止・一覧できること。SSH 切断後も作業が
  維持されること。**破壊的操作(`stop` / `logout` / `reset`)が他プロジェクトの資源を巻き込まないこと**
  (`D0-env-08`。共有 docker-proxy と共有ネットワークを残す条件は受入基準9)。
  **共有ボリュームまたは docker-proxy を触るサブコマンドが互いに排他されること**(同項6)。
  **`stop` と `reset` が、そのセッションのコンテナ内から作られた資源(セッション由来の資源)を
  片付けること**(`D0-env-05` 項2。どの資源を対象とするかは `D0-env-08` 項8。**識別の方法は
  02 の契約が定める**)。**名前付きボリュームは既定では消さず、利用者が明示したときだけ消すこと**
  (同項2。明示の手段と、残っていることの示し方は受入基準28〜33 が定める)。

## FR-env-07 Docker アクセスの制限

- 対応要求: RQ-env-04 / AC-03
- **分割可否: 段階可(理由: 段階的に近づくのは条項 `FR-env-07-5`(compose 資源の一意化)だけで、`FR-env-01` と同じ一意化による。段階性の根拠も `FR-env-01` と同じである。判断の記録は `D1-split-01`。**他の11条項は不可分**)**
- 内容: コンテナ内から Docker を使えるが、ホストを危険に晒す操作は拒否されること。
  **コンテナ内から作られた資源に所有者が分かる印が付くこと**(`D0-env-08` 項8。
  片付ける側の要件は `FR-env-01` 受入基準22〜27)。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|

| FR-env-07-3 | 正常系 | WHERE 呼び出し元の `/workspace` 配下の bind である場合、システムは実ホストパスへ書き換えて許可しなければならない(既定有効。環境変数で切替可能) |

## FR-env-14 プロジェクトごとの環境変数の受け渡し

- 対応要求: RQ-env-07 / AC-08
- **分割可否: 不可分**(理由: 渡せる変数と渡せない変数が混ざる状態は、利用者から見て「書いた値が
  効いているかどうか分からない」状態であり、何も渡さない状態より価値が高いとは言えない)
- 内容: プロジェクトごとに用意した**プロジェクト環境ファイル**(用語集)の内容を、そのプロジェクトの
  コンテナへ環境変数として渡せること。**秘密の値が版管理へ入らないこと**(`D0-sec-11`)。
  **本システム自身が使う名前を利用者の指定で差し替えられないこと**
  (`request.md`「やらないこと」7)。**指定の書式と、本システムが使う名前の集合は 02 の契約が定める。**

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-14-1 | 正常系 | WHERE プロジェクト直下の設定でプロジェクト環境ファイルの場所が指定された場合、システムはそのファイルに書かれた組を、そのプロジェクトのコンテナへ環境変数として渡さなければならない(設定の置き場・指定の書式・ファイルの書式は 02/03 が定める) |
| FR-env-14-2 | 正常系 | WHILE コンテナが稼働している間、システムは渡した環境変数を**そのプロジェクトのコンテナの中だけ**で見える状態に保たなければならない(別プロジェクトのコンテナからは見えない) |
| FR-env-14-3 | 正常系 | WHEN プロジェクト環境ファイルを渡して起動したとき、システムは**渡した値そのものを端末にも起動ログにも出力してはならない**(名前を出すことは許す。値を出さない規則の正は 02 のログ仕様である) |
| FR-env-14-4 | 正常系 | WHEN プロジェクト環境ファイルの場所が指定されたとき、システムはそのファイルを**版管理の追跡から外さなければならない**。外せなかった場合は、外せなかったことを表示して起動を続けなければならない(`D0-sec-11` 項2) |
| FR-env-14-5 | 境界値 | IF プロジェクト直下の設定にプロジェクト環境ファイルの指定が**無い**ならば、システムは環境変数を渡さずに起動しなければならず、**そのことを表示してはならない**(指定していないことは正常な省略であり、毎回表示しない) |
| FR-env-14-6 | 異常系 | IF 指定されたプロジェクト環境ファイルが**存在しない**ならば、システムは環境変数を渡さずに起動を続け、**そのファイルを読めなかったことを表示**しなければならない(起動を止めない) [DS-02] 起動を止めずに続行する — 理由: 補助機能の失敗が主機能(コンテナ起動)を止めないことは本システムの一貫した倒し方であり、`NFR-avail-03` がその成功率を 100% と定めている / 見直す条件: 環境変数が渡らないまま起動して利用者が気づけない事故が観測されたとき |
| FR-env-14-7 | 境界値 | IF プロジェクト環境ファイルに**組として解釈できない行**が在るならば、システムはその行だけを採用せず、**採用しなかった行が何行目か**を表示して、残りの行で起動を続けなければならない |
| FR-env-14-8 | 境界値 | IF プロジェクト環境ファイルに**本システムが使う名前**が書かれているならば、システムはその1件だけを採用してはならず、**採用しなかった名前**を表示して起動を続けなければならない(どの名前が本システムのものかは 02 の契約が定める。理由は `request.md`「やらないこと」7 が持つ) |
| FR-env-14-9 | 境界値 | IF 指定された場所が**プロジェクトディレクトリの外**を指すならば、システムはその指定を採用してはならず、受理しないことと受理する範囲を表示して、環境変数を渡さずに起動を続けなければならない [DS-04] 受理する範囲をプロジェクトディレクトリの中に限る — 理由: 外を指せるとコンテナへ渡る値の出どころがプロジェクトの外に散り、`D0-sec-11` 項2 の「版管理の追跡から外す」が効かない / 見直す条件: 複数プロジェクトで1つのプロジェクト環境ファイルを共有したいという要望が出たとき |
| FR-env-14-10 | 異常系 | IF 同じ名前が**2回以上**書かれているならば、システムは**後に書かれたほうを採用**し、採用しなかった名前を表示しなければならない [DS-04] 後勝ちにする — 理由: 利用者が1つのファイルを編集して値を差し替える使い方でそのまま動き、行を消し忘れても最後に書いた値が効く / 見直す条件: 複数のプロジェクト環境ファイルを指定できるようにするとき(ファイルをまたぐ優先順を別に決める必要が生じる) |
