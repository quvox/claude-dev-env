## UC-01 プロジェクトを隔離コンテナで開発開始

- 形式化した受け入れ基準: AC-01, AC-08(代替フロー A5)
- アクター: 開発者
- 目的: 自分のリポジトリを隔離環境で Claude Code 開発する
- 事前条件: 初回セットアップと Claude のログインが済んでいる
- 事後条件: プロジェクト専用コンテナで Claude Code が動作している
- 関連要件: FR-env-01, FR-env-02, FR-env-03, FR-env-04, FR-env-05, FR-env-08, FR-env-11, FR-env-12, FR-env-14, NFR-sec-01

基本フロー:

1. 開発者がプロジェクトディレクトリで `claude-dev start` を実行する。
2. システムはカレントディレクトリを `/workspace` にマウントしたコンテナを起動し、UID/GID 追従・
   認証コピー・**選択済み SSH 鍵だけの agent 転送(秘密鍵ファイルはマウントしない。FR-env-04)**・
   ファイアウォール適用・(ブラウザ確認ありなら)VNC/Chrome の起動・tmux の開始を行う。
3. システムは noVNC の接続 URL を表示し、tmux にアタッチする。
4. 開発者が tmux 内で `claude` を実行する。

代替フロー:

| # | 分岐条件 | 振る舞い |
|---|---|---|
| A1 | `--no-vnc` が指定された | ブラウザ確認資産を持たない軽量イメージで起動する |
| A2 | 同一ディレクトリで再実行した | 既存コンテナへ再接続する(tmux セッションが無ければ再作成する) |
| A3 | Codex CLI を使う | 手順4で `claude` の代わりに(または並行して)`codex` を実行する(UC-06) |
| A4 | `--vm` が指定された | ゲスト VM を起動し、その中のネイティブ Docker を使う(FR-env-08) |
| A5 | プロジェクト直下の設定でプロジェクト環境ファイルの場所が指定されている | 手順2 で、そのファイルに書かれた組を環境変数としてコンテナへ渡す。本システムが使う名前は採用せず、採用しなかった名前を表示する(FR-env-14) |

例外フロー:

| # | 例外条件 | 振る舞い |
|---|---|---|
| E1 | 前提コマンドが不足している | 不足を列挙して導入方法を案内し、終了コード 1 で終わる |
| E2 | プロジェクト直下に使う鍵の設定が無い | 端末があれば鍵選択、無ければ空で作成して起動を続ける(SSH 転送なし) |
| E3 | ファイアウォールの適用に失敗した | 警告を出して起動を継続する |
| E4 | noVNC のポートが競合した | 別ポートで再試行する(上限は 02 が定める)。上限超過は終了コード 1 |
| E5 | tmux の起動待ちが上限を超えた | 状況を案内して終了コード 0 で終わる(コンテナは稼働を続ける) |
| E6 | 指定されたプロジェクト環境ファイルが存在しない | 環境変数を渡さずに起動を続け、読めなかったことを表示する(FR-env-14) |

## AC ⇄ UC カバレッジ

| AC ID | 形式化した UC | 未対応の理由 |
|---|---|---|
| AC-01 | UC-01 | - |
| AC-02 | UC-02 | - |
| AC-03 | UC-03 | - |
| AC-06 | UC-06 | - |
| AC-08 | UC-01(代替フロー A5・例外フロー E6) | - |
| AC-07 | なし | **成果物(イメージの中身)の検証であり、通しで実行する利用者の旅程を持たない**。操作は保守者だけで完結し(用意 → ビルド → 中身の確認)、**開発者がその同梱物を使う場面は `UC-01` の基本フローそのもの**で、この基準が新しい旅程を足すわけではない。UC を立てるとそこから E2E シナリオを導くことになるが(02 のテスト戦略は UC を E2E の唯一の上流としている)、確認すべきはビルド成果物であって操作の通し実行ではない。`FR-env-09`(イメージ配布)が同じ理由で UC を持たない先例である |
