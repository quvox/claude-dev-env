### DSN-env-04 の適用

セッション由来の資源(コンテナ・ネットワーク・**名前付きボリューム**)に所有者ラベルを付けるのは
この契約の帰結である
(判断そのものと、ラベルの名前・値・付与する資源の種類は
`docs/02-design/contracts/cli-container.md` の `DSN-env-04` が正)。
docker-proxy は**印を付ける側**であり、**印を読んで削除するのはホスト CLI 側**である
(`MOD-cli-stop` / `MOD-cli-reset`)。したがってこの契約が負うのは
「特定できたときは必ず付ける・特定できなくても拒否しない・他のフィールドを変えない」の3つだけで、
**どの資源を削除するかの判断はここには無い**。

この契約が `DSN-dp-01`(判定できない入力は通し、判定できる危険だけを止める)と両立する理由:
所有者ラベルの付与は**拒否判定を1つも変えない**。付与できなかった要求は付与せずに通るので、
`AC-03` が保証する「危険な操作は拒否される」の範囲は `DSN-env-04` の導入の前後で同一である。
代わりに、付与できなかった資源は片付けの対象から外れる — その残存は
`FR-env-07` 受入基準12 が明示し、`MODULE-docker-proxy-serve` の「既知の制限」が追跡する。

## 通信の形

| 項目 | 内容 |
|---|---|
| 経路 | `DOCKER_HOST` が指す HTTP エンドポイント(`claude-dev-net` 内のみ。ホストへ公開しない) |
| 対象 | Docker Engine API のすべてのパス(透過中継) |
| 検査の対象 | コンテナ作成要求のボディ、**ネットワーク作成要求のボディ**、**ボリューム作成要求のボディ**、コマンド実行(exec)作成要求のボディ、および要求パス |
| 結果 | 許可(透過)/ 書き換えて許可 / **所有者ラベルを付与して許可** / 拒否 |

## 検査する要素と判定

| 要素 | 条件 | 判定 |
|---|---|---|
| 要求パス | 版接頭辞(`/v1.45` 等)を除いた先が `/swarm` / `/plugins` / `/configs` / `/secrets` のいずれかで始まる | **メソッドを問わず拒否**(ボディを見ない。クラスタ管理・プラグイン・機密の操作面をまるごと閉じる) |
| バインドマウント | 作業領域(`/workspace`)配下 | **書き換えて許可**(実ホストパスへ変換する。既定有効。`CLAUDE_DEV_ALLOW_WORKSPACE_BINDS` を `0`/`false`/`no`/`off` にすると全面拒否へ倒す) |
| バインドマウント | 上記以外のホストパス | **拒否** |
| バインドマウント | 正規化すると呼び出し元のプロジェクトディレクトリ外を指す(`..` による脱出) | **拒否** |
| バインドマウント | 呼び出し元コンテナを特定できない | `/` 始まりをすべて**拒否**(名前付きボリュームのみ許可) |
| 特権(privileged) | 有効 | **拒否** |
| ネットワークモード | ホストのネットワーク空間の共有 | **拒否** |
| PID モード | ホストのプロセス空間の共有 | **拒否** |
| ユーザー名前空間 | ホストのユーザー名前空間の共有 | **拒否** |
| 追加ケーパビリティ | 危険なケーパビリティ(`SYS_ADMIN` / `SYS_PTRACE` / `SYS_RAWIO` / `SYS_MODULE` / `DAC_READ_SEARCH`。大文字化して突き合わせる) | **拒否** |
| デバイスの割り当て | 1件でも指定されている | **拒否** |
| 特権(exec) | コンテナ内でのコマンド実行を特権で要求 | **拒否** |
| **所有者ラベル** | **コンテナ作成要求(`POST /containers/create`)・ネットワーク作成要求(`POST /networks/create`)・ボリューム作成要求(`POST /volumes/create`)**(版接頭辞 `/v<version>` の有無を問わない)で、**呼び出し元セッションを特定できた**(= 呼び出し元 Claude コンテナを引き当てられ、**そのコンテナが `claude-dev.project-dir` ラベルを持ち、その値が空文字でない**。定義の正は `CTR-cli-container` の `DSN-env-04`) | **所有者ラベルを付与して許可**(`claude-dev.role` と `claude-dev.owner-project-dir` の2つ。名前と値は `CTR-cli-container`「管理ラベル」が正。**値は呼び出し元コンテナの `claude-dev.project-dir` ラベルをそのまま写す** — `/workspace` のマウント元ではない)。**要求のそれ以外のフィールドは変えない**。**利用者が同じキーを指定していた場合は上書きする**。**この付与は `CLAUDE_DEV_ALLOW_WORKSPACE_BINDS` の値によらず行う** — bind の書き換えとは別の判定であり、bind を全面拒否へ倒した環境でもセッション由来の資源は片付けられなければならない(`FR-env-07-11` / `DSN-env-04`) |
| **所有者ラベル** | **呼び出し元セッションを特定できない**(コンテナを引き当てられない、`claude-dev.project-dir` を持たない、**またはその値が空文字である**)**、またはボディが解釈できない** | **付与せずに許可**(拒否しない。`FR-env-07-12`)。その資源は `stop` / `reset` の片付け対象から外れる |
| 上記を含まない要求 | — | **許可**(透過) |

判定の順序: **要求パスの遮断を最初に行う**。複数の拒否条件に当たったときは、利用者が最も
踏みやすい「作業領域外の持ち込み」の理由を優先して返す(ボディの検査の並びは 03 が持つ)。
**所有者ラベルの付与は拒否判定を1つも変えてはならない** — 付与の成否が拒否/許可の結果に
影響してはならず、拒否される要求に印は付かない。
**ネットワーク作成要求とボリューム作成要求はもともと拒否判定を1つも持たない**ので、所有者ラベルの付与だけを行う。
**ボリューム作成要求を対象に加えたのは 2026-08-19 である**(`D0-env-05` 項2 の改訂で名前付きボリュームが
片付けの対象になったため。`CTR-cli-container` の `DSN-env-04`)。**ボリューム作成要求のボディは
`Labels` を最上位に持つので、コンテナ作成要求・ネットワーク作成要求と同じ注入で足りる。**
**名前を指定せずに作られるボリューム(匿名ボリューム)はこの契約の射程に入らない** —
その作成要求は発行されず、Docker がコンテナ作成の中で直接作るためである。
**その片付けをどう行うかは `CTR-cli-container` の規則 D が定める**(印に頼らない)。

## エラーケース

| 条件 | 期待する振る舞い |
|---|---|
| 拒否に該当する | `403 Forbidden` を返し、拒否理由を本文に含める(本文は `blocked: <理由>` の平文) |
| ボディが解釈できない | **中継を許可する**(独自解釈で誤って弾かない。最終判断は Docker Engine が行う)。**所有者ラベルも付与できない**ので、その資源は `stop` / `reset` の片付け対象から外れる(`FR-env-07-12`) |
| **呼び出し元セッションを特定できない**(呼び出し元コンテナを引き当てられない / そのコンテナが `claude-dev.project-dir` ラベルを持たない / **その値が空文字である**) | **所有者ラベルを付与せずに中継する**(作成を拒否しない)。**bind の書き換えとは判定が別である**: bind は `/workspace` のマウント元があれば書き換えられるので、**ラベルを持たない Claude コンテナからの要求は「bind は書き換わるが所有者ラベルは付かない」状態になる**。これは意図した組み合わせで、片付けられない資源が生じることは `FR-env-07` 受入基準12 が明示する |
| **ボリューム作成要求で呼び出し元セッションを特定できない** | 上の行と同じ扱いにする(**付与せずに中継し、作成を拒否しない**)。その名前付きボリュームは `stop` / `reset` の片付け対象から外れ、**`--volumes` を指定しても消えない**。この残存は `FR-env-07-12` が明示する |
| **所有者ラベルの付与そのものに失敗した**(付与の処理が途中で失敗した場合を含む) | **元のボディのまま中継する**(作成を拒否しない。`D0-env-08` 項8 / `D0-sec-05`「判定できない入力は通す」と揃える) |
| **利用者が `claude-dev.owner-project-dir` / `claude-dev.role` と同じキーのラベルを指定していた** | **docker-proxy の値で上書きする**(所有者の判定が利用者の入力で狂うと、別セッションの資源を消しうる) |
| 上流への中継に失敗した | 502 を返し、ログへ記録する |
| 起動時に Docker ソケットが無い | 待ち受けを開始せず終了する |
