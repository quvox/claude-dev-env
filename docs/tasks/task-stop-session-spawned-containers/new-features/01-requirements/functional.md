## FR-env-01 コンテナのライフサイクル管理

- 対応要求: RQ-env-01 / AC-01
- **分割可否: 段階可(理由: 段階的に近づくのは条項 `FR-env-01-19`(別ディレクトリの compose 資源を巻き込まない)だけである。compose プロジェクト名を一意化しなければ全プロジェクトの既定名が `workspace` に一致して**必ず**巻き込むのに対し、一意化が部分的でも取り違えの余地が減った分だけ利用者の作業が守られる。判断の記録は `D1-split-01`。**他の 26 条項は不可分**)**
- 内容: プロジェクトごとに隔離コンテナを起動・再接続・停止・一覧できること。SSH 切断後も作業が
  維持されること。**破壊的操作(`stop` / `logout` / `reset`)が他プロジェクトの資源を巻き込まないこと**
  (`D0-env-08`。共有 docker-proxy と共有ネットワークの停止条件は受入基準9)。
  **共有ボリュームまたは docker-proxy を触るサブコマンドが互いに排他されること**(同項6)。
  **`stop` と `reset` が、そのセッションのコンテナ内から作られた資源(セッション由来の資源)を
  片付けること**(`D0-env-05` 項2。対象と識別の方法は `D0-env-08` 項8 と `CTR-cli-container`)。

## FR-env-03 認証の共有とセッション分離

- 対応要求: RQ-env-03 / AC-01 / AC-06
- **分割可否: 不可分**
- 内容: 一度のログインで全コンテナが認証を共有し、セッションと設定はコンテナごとに独立すること。
  同梱する両方のエージェント CLI(Claude Code / Codex CLI)について成り立つこと。
  **認証を削除する操作(`logout` / `reset`)が、確認なしに他プロジェクトの作業を落としたり、
  削除できていないのに成功を表示したり、消したつもりの認証をプロジェクト配下に残したりしないこと**
  (`D0-env-08` 項3〜5)。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-03-1 | 正常系 | WHEN `claude-dev login` を実行したとき、システムは一時コンテナで対話認証を行い、完了後に認証ファイル(`.credentials.json` / `.claude.json`)を `claude-dev-auth` ボリュームへ保存しなければならない |
| FR-env-03-2 | 正常系 | WHEN コンテナを起動したとき、システムは認証ファイルを共有ボリュームから**プロジェクトディレクトリ配下(`/workspace/.claude/`)へ**コピーし、コンテナ内のホームからは symlink で参照させなければならない(`D0-auth-03`) |
| FR-env-03-3 | 正常系 | WHILE コンテナが起動している間、システムは 30 秒ごとに認証ファイルの変更を検知し、共有ボリュームへ書き戻さなければならない |
| FR-env-03-4 | 正常系 | WHILE コンテナが稼働している間、システムはセッション・設定(`settings.json` / `projects/` / `sessions/`)をコンテナ固有に保たなければならない |
| FR-env-03-5 | 正常系 | WHEN `claude-dev logout` を実行したとき、システムは共有ボリュームの認証情報を削除し、**管理ラベルを持つ**実行中コンテナを停止しなければならない(共有ボリューム全体を空にするため Claude Code と Codex CLI 双方の認証が消える)。**管理ラベルを持たない実行中コンテナは停止も削除もせず、受入基準17 に従って名前を表示して残す** |

## FR-env-07 Docker アクセスの制限

- 対応要求: RQ-env-04 / AC-03
- **分割可否: 段階可(理由: 段階的に近づくのは条項 `FR-env-07-5`(compose プロジェクト名の一意化)だけで、`FR-env-01` と同じ機構(`DSN-env-03`)による。段階性の根拠も `FR-env-01` と同じである。判断の記録は `D1-split-01`。**他の11条項は不可分**)**
- 内容: コンテナ内から Docker を使えるが、ホストを危険に晒す操作は拒否されること。
  **コンテナ内から作られた資源に所有者が分かる印が付くこと**(`D0-env-08` 項8。
  片付ける側の要件は `FR-env-01` 受入基準22〜27)。

受け入れ基準(EARS):

| 条項 ID | 種別 | 基準 |
|---|---|---|
| FR-env-07-1 | 正常系 | WHILE コンテナが稼働している間、システムはコンテナに Docker 生ソケットをマウントしてはならず、`DOCKER_HOST=tcp://claude-dev-docker-proxy:2375` 経由で使わせなければならない |
| FR-env-07-2 | 正常系 | IF リクエストがホストバインドマウント(`/workspace` 配下を除く)・privileged・ホストのネットワーク/プロセス空間の共有を含むならば、システムはそれを拒否しなければならない |
| FR-env-07-3 | 正常系 | WHERE 呼び出し元の `/workspace` 配下の bind である場合、システムは実ホストパスへ書き換えて許可しなければならない(既定有効。環境変数で切替可能) |
| FR-env-07-4 | 正常系 | WHILE docker-proxy が稼働している間、システムは docker-proxy をホストに公開せず、`claude-dev-net` 内でのみアクセス可能にしなければならない |
| FR-env-07-5 | 正常系 | WHEN 複数プロジェクトのコンテナで同時に `docker compose` を実行したとき、システムは compose プロジェクト名を**起動ディレクトリの絶対パスを含めて**一意化し、生成されるネットワーク名・コンテナ名を衝突させてはならない(**起動ディレクトリ名だけでは正規化後に衝突するため一意にならない**。方法は `CTR-cli-container` が定める。受入基準は `FR-env-01` 受入基準19 と同じ一意化を指す) |
| FR-env-07-6 | 境界値 | IF bind のパスが `..` を含み、正規化するとプロジェクトディレクトリの外を指すならば、システムはそれを拒否しなければならない |
| FR-env-07-7 | 境界値 | IF 呼び出し元コンテナを特定できないならば、システムは `/` 始まりの bind をすべて拒否しなければならない(名前付きボリュームのみ許可) |

| FR-env-07-9 | 異常系 | IF 上流の Docker Engine への中継に失敗したならば、システムは 502 を返しログへ記録しなければならない |
| FR-env-07-10 | 異常系 | IF 起動時に Docker ソケットが存在しないならば、docker-proxy は起動を中止しなければならない(不正な状態で待ち受けない) |
| FR-env-07-11 | 正常系 | WHEN コンテナ作成要求またはネットワーク作成要求を中継するとき、システムは**呼び出し元セッションを特定できた場合に限り**、そのセッションを所有者として示す**管理ラベル**を要求へ付与して中継しなければならない(ラベルの**名前・値・個数**は `CTR-cli-container` が定める)。**要求のそれ以外のフィールドを変更してはならない**(`D0-env-08` 項8) |
| FR-env-07-12 | 境界値 | IF 呼び出し元セッションを特定できない、リクエストのボディが解釈できない、**または所有者ラベルの付与そのものに失敗した**ならば、システムは**所有者ラベルを付与せずに中継**しなければならず、作成要求を拒否してはならない(受入基準8 と同じ「判定できない入力は通す」に揃える。**その資源は `FR-env-01` 受入基準22 の片付け対象から外れる**) |
